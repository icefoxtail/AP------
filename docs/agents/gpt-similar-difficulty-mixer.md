# GPT 유사시험지 다중 세트·난도 믹서 운영계약 v1.0

> 제정: 2026-11-24 · 적용: `icefoxtail/AP------` 원본 기출 기반 **GPT 채팅창 유사시험지 제작** 및 유사2·3·4·5 추가 세트. 고1·고2를 포함하되 특정 학교·연도에 한정하지 않는다.
>
> 목적: 잘 조율된 원본 시험지의 **문항별 난도·시험지 전체 난도 곡선**을 보존하면서, 같은 개념을 서로 다른 조건·질문·판단으로 경험시키는 여러 세트를 생산한다. 숫자만 바뀐 다섯 장도, 모든 문제를 심화시킨 다섯 장도 만들지 않는다.

## 1. 새 GPT 채팅 작업자 필독·우선순위

1. 최신 사용자 요청과 원본 시험지/해당 기존 유사 세트의 실제 JS를 먼저 확인한다. **기존 유사가 있다는 이유로 원본을 건너뛰지 않는다.** 유사1이 있으면 새 세트는 유사2이고, 이어지는 세트는 빈 번호·기존 학생 공급/예약 상태를 확인해 결정한다. 기존 세트의 이름이나 내용을 덮어쓰지 않는다.
2. [루트 AGENTS](../../AGENTS.md), [현행 룰북](../rules/RULEBOOK_CURRENT.md), [ALIVE Master v9.1](../../alive/01_CANONICAL/ALIVE_MASTER_RULEBOOK_v9.1_STABLE.md) §6·7·9·11·13·14·17·19·22·23, [ALIVE 유사·심화 Spec](../../alive/04_VISUAL/ALIVE_SIMILAR_ADVANCED_VISUAL_REGEN_SPEC_v1.0.md) §2·3·4·16~18·22·28을 **실제로 열어 읽는다**. 그림이 있으면 관련 시각 규격도 읽는다.
3. [QID9 사고 경험 설계](../../alive/06_EXECUTION/ALIVE_GPT_QID9_ONE_SOURCE_CURRENT.md)의 `RPM Primary L3 고정 → L4·조건·판단 경험 확장`을 설계 참고로 쓴다. 이 계약은 **유사시험지**용이며 별도 QID9의 9슬롯 생산·승인 의무를 새로 강제하거나 변경하지 않는다.
4. [메타 작성 규칙](metadata.md), [보기·정답 정본](similar-choices.md), [GPT 예약 안내](gpt-reservation.md), 실제 출력 형식 계약을 해당 작업에 맞게 읽는다. 사용자 최신 지시와 현행 룰북이 우선이다. 과거 `STRICT_VARIANT` 전용 프롬프트를 발전형 유사 작업에 그대로 적용하지 않는다.
5. 첫 진행 보고에는 **읽은 문서/미확인 문서, 원본·기존 유사 세트, 적용 MODE, 시험지 난도 기준, 이번 세트의 변형 전략**을 짧게 명시한다. 문서 링크만 보거나 이전 채팅의 읽음 보고만 믿고 숙독했다고 하지 않는다.

## 2. 핵심 잠금과 변경 범위

**잠금:** 원본 `sourceQid`, 학교·연도·교육과정, 현재 과정에서의 핵심 개념, 실제 RPM Primary L3, 핵심 결정적 풀이 단계, 객관식/서답형 형식, 문항 번호·배점·시험지 전체 문항 수, 해당 문항의 난도 역할.

**허용되는 변화:** 조건 제시 방식, 주어진 정보와 미지수의 위치, 질문 대상, 자연스러운 수학적 표현/상황, 오답을 유발하는 실제 사고 경로, 기존 L3 아래 L4·Condition·이미 배운 CrossConcept의 필요한 역할. 새로운 L3/상위 교육과정이 주목표가 되면 원본 대응 발전형으로 채택하지 않는다.

**모드 구분:**

| 실제 문항 | ALIVE 분류 | 판정 |
| --- | --- | --- |
| 수치·상수·변수명만 변경 | `STRICT_VARIANT` | 이번 다중 경험 세트의 **기본 제작 대상 아님**. 별도 명시 요청일 때만 |
| 같은 핵심 `solutionGraph`·풀이 진입·판단 수, 조건 표현/정보 구성은 의미 있게 변화, 원본과 난도 동치 | `EXAM_FOLLOWUP / CONFIRMATION` | **기본값**. 숫자만 바뀌었으면 불합격 |
| 원본 핵심 판단을 남기고 실제 중간 판단 `+1`, 질문 목표 또는 진입 변화, ALIVE A~F 한 가지 이상 | `EXAM_FOLLOWUP / ADVANCED` | 선별 적용. 계산만 길어지는 가짜 심화 불합격 |

`TYPE_BANK` 구조변형은 같은 L3 아래 독립 유형은행을 만들 때의 별도 작업이다. 다중 기출 유사시험지를 그 모드로 무단 재분류하지 않는다. 이름에 `강화`를 붙였다는 이유로 심화로 판정하지 않고 실제 풀이 경로로 구분한다.

## 3. 난도 믹서 — `SOURCE_BALANCED` 기본 프로필

**원본의 잘 설계된 난도를 목표 분포로 삼는다.** 세트 번호가 올라가도 자동으로 어려워지지 않는다. 다음 수치는 GPT 채팅창 발전형 유사시험지의 **기본 안전 프로필**이며, 마스터가 해당 시험지에 명시한 목표가 있으면 조정한다.

1. **문항별 난도 잠금:** 원본과 새 문항을 각각 직접 풀어 현행 정수 `difficultyBucket=1..5` 운영 기준으로 독립 판정한다. 기본 합격은 `variantBucket == sourceBucket`. 원본의 `level(하/중/상)`을 1~5로 환산하거나 새 문항에 `level`을 새로 생성하지 않는다. 원본 bucket이 불확실하면 풀이 근거로 재판정하고, 여전히 불확실한 칸은 추정값 대신 미확정 사유를 남긴다.
2. **시험지별 구성:** `CONFIRMATION` **최소 80%**, `ADVANCED` **최대 20%**. 이는 심화 *상한*이지 채워야 할 할당량이 아니다. 자연스럽고 난도가 유지되는 심화가 없으면 **전부 확인형이어도 된다**. 숫자갈이만 한 문제는 기본적으로 0개를 목표로 한다.
3. **심화 선택:** 원본 `difficultyBucket` 1~3에서만 우선 검토한다. 원본 4~5, 서답형 핵심 변별문항, 조건 분기나 시각 해석이 이미 과한 문항에는 기본적으로 판단 단계를 추가하지 않는다. 원본이 1단계 단순 공식 적용형이면 억지 심화 대신 다양한 확인형을 우선한다.
4. **상승 차단:** 심화로 새 판단이 생겨도 실제 1~5 등급이 올라가면 `SOURCE_BALANCED`에는 넣지 않는다. 확인형으로 재설계하거나 별도 명시 요청이 있을 때만 상위 난도 프로필에서 다룬다. ALIVE 심화 분류와 1~5 bucket 증가를 동일시하지 않는다.
5. **시험지 곡선 유지:** 문항별 bucket을 지키므로 1~5 분포·고난도 위치·문항 배점 역할이 보존되어야 한다. 심화 문항을 한 구간에 연속 배치하지 않고 전반·중반·후반의 실제 난도 곡선을 재점검한다. 원본보다 전체 풀이 시간·해석 부담이 뚜렷이 증가하면 심화 비율을 **상한보다 더 낮춘다**.
6. **우선순위:** 수학적 성립 > 교육과정 > 원본의 핵심 유형·난도 역할 > 학생의 새로운 사고 경험 > 세트 간 다양성. 비율을 맞추려고 부자연스러운 조건·새로운 고학년 개념·억지 서술을 넣지 않는다.

## 4. 유사1~5 다양성 관리 — 숫자 아닌 ‘사고 경험’ 비교

각 원본 `sourceQid`에 대해 **원본 + 기존 유사1~N을 같은 번호로 나란히 읽는다**. 유사 세트가 많아질수록 비교 대상이 늘며, 기존 유사 존재를 전체 시험지 skip 조건으로 쓰지 않는다. 같은 조건 변경이나 같은 질문 목표를 단순 수치만 바꿔 반복하지 않는다.

문항별 내부 **Experience Ledger** 최소 기록:

`sourceExamPath · sourceQid · existingVariantRefs · lockedPrimaryL3 · decisiveCore · mode/followupKind · conditionStructure · solutionEntry · questionTarget · solutionGraphSignature · addedDecision · AtoF(if ADVANCED) · originalBucket · newBucket · trapSignature · semanticDuplicateResult · reason`

- 기본형, 조건 재배치, 목표 역산, 표현 전환, 추가 판단, 조건 경계/예외 등 **실제 수학적 경험이 다른 후보**를 펼친 뒤 자연스러운 것을 선택한다. 유사2/3/4/5의 역할은 *다양성 계획*이지 각각 난도 상승의 계단이 아니다.
- 동일 `solutionEntry`, 조건 구조, 질문 대상, 핵심 함정이 사실상 같다면 수치·이름이 달라도 ‘새 사고 경험’으로 세지 않는다. 단, 확인형의 핵심 풀이 구조 동일성 자체는 고정 요건이므로 이것만으로 중복 불합격 처리하지 않는다.
- 문항 형식·원본 L3·원본 난도를 지킬 수 있는 의미 있는 변화가 없다면 억지 개선으로 채우지 않고 그 번호에 대해 재설계 사유를 보고한다. 다른 단원 문제로 대체하지 않는다.
- 기존 세트의 파일·UID·검수 결과를 존중하고 새 `_유사N`을 별도 산출한다. 원본과 유사1~N의 수학적 결함은 이 작업 범위에서 임의 수정하지 않는다.

## 5. GPT 채팅창 제작 순서와 검수

1. **시험지 preflight:** 원본 JS/그림, 해당 과정·교육과정, 원본 문항 수/배점/형식, qid별 `difficultyBucket` 및 시험지 1~5 분포를 확인한다. 기존 유사 전 세트도 찾고 실제 해당 qid의 발문·해설을 읽는다.
2. **전체 믹서 설계:** 문항별 `CONFIRMATION/ADVANCED` 후보와 변형 축을 먼저 배치한다. 원본 bucket=4~5를 고정하고 시험지의 심화 상한·난도 곡선을 점검한다. 어려운 원본을 더 어렵게 하지 않는다.
3. **한 문항씩 역설계:** 원본 fingerprint → 잠글 L3/핵심 판단 → 변경할 조건·질문/필요한 추가 판단 → 목표 답/풀이 그래프 → 수치 역산 → 한국 학교 시험에 자연스러운 발문·보기 → FREEZE.
4. **학생 입력만 독립 검산:** 생성 의도/정답을 가린 최종 발문·보기·필수 그림만 보고 다시 풀고 정답 유일성·보기 5개·교육과정·정답/해설 일치를 확인한다. 숫자 증가만으로 심화라고 주장하지 않는다. 필수 외부 검증이 미실행이면 완료/PASS로 보고하지 않는다.
5. **난도·중복 gate:** `sourceBucket` 대조, 모드별 ALIVE fidelity, 기존 유사와 semantic duplicate, 시험지 전체 80/20 상한과 난도 곡선, 보기 누설/정답 배분을 최종 검사한다. 수치형 선지는 [최신 보기 정본](similar-choices.md)에 따라 크기순·실제 오답 경로를 지키며 정답 분포를 검사한다.
6. **산출·인계:** 사용자가 지정한 일체형 Markdown 구조(`json:exam`, Q01…, `json:plan`, `json:meta`)·Drive/Git 반입 경로를 그대로 지킨다. 확정되지 않은 내부 믹서/검수 필드를 학생 문제 JSON에 억지로 추가하지 않고 별도 Ledger/sidecar에 남긴다. 실제로 하지 않은 반입·렌더·독립 검산·Git 병합은 `NOT_RUN`으로 구분한다.

## 6. 세트 완료 판정 및 새 대화 시작 문구

완료하려면 **(a)** 원본과 문항 번호/배점/수 일치, **(b)** 1~5 난도 분포와 고난도 역할 보존, **(c)** 심화 비율 상한, **(d)** 원본 L3·교육과정 유지, **(e)** 기존 유사 세트와 의미 있는 차이, **(f)** 발문만으로 정답 독립 검증, **(g)** 전 문항 메타·필요 시 plan 및 내부 Ledger, **(h)** 실제 저장/반입 상태가 각각 확인되어야 한다.

새 ChatGPT 프로젝트 채팅의 첫 지시에는 다음 한 문장을 넣을 수 있다.

> `icefoxtail/AP------`의 `AGENTS.md`와 `docs/agents/gpt-similar-difficulty-mixer.md`를 실제로 열어 읽고, ALIVE `EXAM_FOLLOWUP`의 `SOURCE_BALANCED` 기본 믹서(문항 난도 유지, 확인형 중심, 심화 최대 20%, 기존 유사1~N 구조 중복 회피)를 적용하라. 사용자 최신 지시와 저장소 현행 정본의 충돌이 있으면 먼저 구분하여 보고하라.

**적용 범위 경계:** 이 문서는 신규 GPT 유사시험지 **제작용 운영계약**이다. 기존 `STRICT_VARIANT` 자료, 별도 QID9 Generated Bank, 원본 기출 수정, AI Studio의 이미 실행 중인 고정 프롬프트/예약을 자동으로 개정하거나 재승인하지 않는다. 각 실제 작업의 최신 명시 지시를 우선한다.
