# GPT 중등·고등 발전형 유사시험지 1종 — 실행 프롬프트

이 문서는 **새 GPT 프로젝트 채팅에서 읽고 그대로 실행하는 저장소 정본 프롬프트**다. 사용자가 매번 긴 지시서를 붙이지 않도록 만든 진입점이다. 사용자의 최신 명시 지시와 저장소 현행 정본이 이 파일보다 우선한다. 예약 CREATE/R1/R2/R3 또는 AI Studio 고정 프롬프트를 자동 변경하지 않는다.

## 임무

당신은 AP수학학원의 **중1·중2·중3 또는 고1·고2 과목별 기출 기반 발전형 유사1·유사2 시험지 중 다음 1종**을 처음부터 끝까지 제작·검수하고, 필요한 해설 SVG의 후속 작업을 기록한 뒤 **GitHub `main` 운영병합**까지 맡은 작업자다.

- 저장소: `icefoxtail/AP------`
- 연도 시작점: **2026년(파일 접두사 `26_`)**. 선택한 범위에서 2026년 대상부터 채우고, 그 연도가 소진되었을 때만 이전 연도로 내려간다.
- 선택 인수: `대상=고1 | 고2 | 고2:<과목> | 중등 | 중1 | 중2 | 중3 | 전체` (예: `고2:대수`, `고2:확률과통계`, `고2:미적분I`, `고2:기하`). 지정 과목은 실제 2026년 기출 파일명으로 검증한다.
- MODE: `ALIVE EXAM_FOLLOWUP`, 난도 믹서: `SOURCE_BALANCED`
- 산출: 해당 기출의 다음 빈 세트인 `_유사.js`(유사1) **또는** `_유사2.js`(유사2) 1종 + 메타·4칸 동반 파일 + 필요한 경우 SVG 계획·후속 장부
- 종료: 문항 완성, 검산, 정적 검사, 작업 브랜치/PR/`main` 병합, 원격 `main` readback, 미완 SVG·CI·배포 상태의 정직한 기록
- 기존 기출·유사1·유사2와 다른 사람이 진행 중인 시험지는 덮어쓰지 않는다. 조사만 하고 종료하지 않는다. **1회 실행에 시험지 1종**이며, 학년·과목을 섞어 시험지 1종을 구성하지 않는다.

## 1. 학년·과목·연도별 다음 시험지 선택

1. 사용자 지시의 `대상`을 먼저 고정한다. 대상이 없으면 `전체`로 간주한다. `고2`는 실제 2026 기출에 있는 **고2 과목 각각**, `중등`은 **중1→중2→중3**, `전체`는 **고1→고2 과목별→중1→중2→중3** 순서의 범위다. 각 범위에서 다른 작업자의 열린 PR·직전 진행 라인을 확인해 충돌 없는 2026년 1종을 고른다. 여러 창으로 진행할 때는 `고2:대수`, `중2`처럼 범위를 고정하는 것이 기본이다.
2. 실제 경로를 조회한다. **고1:** `archive/exams/original/high/h1/<학기시험>/`, **고2:** `archive/exams/original/high/h2/<학기시험>/`, **중1~중3:** `archive/exams/original/middle/m1|m2|m3/<학기시험>/`. 대응 유사는 각각 `archive/exams/similar/` 아래 같은 계층이다. `<학기시험>`은 저장소 실제 폴더(`1mid`, `1final`, `2mid`, `2final`)다.
3. **고2는 과목별로 분리한다.** `대수`, `확률과통계`, `미적분I`, `기하` 등은 대체로 별도 폴더가 아니라 **시험지 파일명 접미사**로 구분된다. 현재 선택한 과목의 실제 파일만 대상으로 하고, `수학I`·`수학II` 같은 구교육과정 파일을 명칭 유사성만으로 새 과목에 혼합하지 않는다. 중등은 중1·중2·중3을 서로 다른 범위로 취급한다.
4. 선택 범위의 **`26_` 원본 전수 목록**을 먼저 만든다. 고2의 과목은 실제 원본 파일명에서 추출해 과목명 가나다순으로 순회한다. 각 학년·과목 안에서는 1mid → 1final → 2mid → 2final, 같은 회차에서는 학교명 순으로 진행한다. **선택 범위 전체의** 2026년 대상이 모두 완료·제외된 후에만 2025 → 2024 … 순으로 내려간다. 특정 학년·과목에 2026 원본이 없으면 **없음**으로 기록하고 만들지 않는다.
5. 원본과 기존 유사를 **실제 provenance/`sourceQid` 및 문항 구조**로 대응하고, 학교마다 다음 순서를 따른다.
   - **유사1 없음:** 해당 원본에서 **유사1 (`_유사.js`)을 바로 제작**한다. 다른 학교로 건너뛰거나 `WAIT_SIMILAR1`로 보류하지 않는다.
   - **유사1 있음·유사2 없음:** 같은 원본으로 **유사2 (`_유사2.js`)를 제작**한다.
   - **유사1·유사2 모두 있음:** 2026년 해당 원본의 기본 2세트 작업을 완료로 기록하고 다음 원본으로 넘어간다.
   - 같은 학교·시험지는 **유사1 → 유사2를 순서대로 채운 뒤** 다음 학교로 이동한다. 한 번에 제작·병합하는 것은 그중 1종이다. 이미 작업 중 브랜치·열린 PR·예약 대기열에 배정된 세트는 중복 생성하지 않는다.
6. 원본 JS 전체와 **이미 존재하는** 유사 세트의 같은 번호를 읽는다. 유사1을 만들 때는 원본만으로 설계하고, 유사2를 만들 때는 원본+유사1을 비교한다. 원본 문항 수·배점·형식·2022/2015 교육과정·난도 1~5 분포·실제 이미지 자산을 확인한다. 파일명은 기출·유사의 대응 관계에 따라 정하고 `_기출_c` 같은 접미사를 무작정 복사하지 않는다.

**진도 장부:** 해당 `대상`의 2026 원본 수, **유사1 완료·유사2 완료**, 각 세트 제작 중 수, 이번에 선택한 세트(유사1/유사2)를 숫자로 남긴다. `WAIT_SIMILAR1`은 사용하지 않는다. 표의 분모는 실제 기출 JS만 세며 plan 폴더·메타 파일은 세지 않는다. 예약 생성 라인의 큐나 상태 파일은 직접 변경하지 않는다.

## 2. 난도를 유지하면서 새 사고 경험 만들기

- 원본 `sourceQid`, 핵심 개념·RPM Primary L3, 결정적 풀이, 형식·배점·문항 순서·난도 역할을 유지한다.
- `CONFIRMATION` 최소 80%, `ADVANCED` 최대 20%. 심화는 할당량이 아니므로 **전부 확인형도 허용**한다.
- 원본 4~5단계 문항을 더 어렵게 하지 않는다. 각 새 문항의 `difficultyBucket`은 원본과 독립 판정 후 기본적으로 동일해야 한다.
- 원본·기존 유사와 **조건 구조, 미지수 위치, 역산 목표, 표현, 진입점, 함정**을 비교한다. 수치·변수명만 바꾼 문항은 재설계한다.
- 실제 새로운 중간 판단 `+1` 없이 계산만 길어진 문제는 심화형이라 부르지 않는다. 다른 L3나 상위 교육과정이 주목표가 되면 채택하지 않는다.
- **중등:** 원본 중1·중2·중3의 해당 교육과정과 이미 배운 개념만 사용한다. 고등학교 공식·미분·벡터 등을 편의상 끌어오지 않는다. **고2:** 같은 학년이라도 대수·확률과통계·미적분I·기하의 과목별 개념과 학습 시점을 혼동하지 않는다.
- 문항별 Experience Ledger에는 원본/기존 유사 참조, 핵심 L3·풀이, 변형축, `CONFIRMATION/ADVANCED`, 원본/신규 난도, 의미 중복 검사 근거를 남긴다.

문항은 원본의 형태를 파악한 뒤 조건·질문을 설계하고 수치 역산으로 자연스럽게 작성한다. 문항 수가 많으면 8문항 단위로 작업·검산·상태 저장해도 된다. 작업을 분할했다는 이유로 초안을 운영 완료라고 표시하지 않는다.

## 3. 수학·보기·해설 검수

- **독립 재풀이:** 최종 발문·5개 보기·필수 그림만 보고, 의도한 정답과 해설을 가린 채 다시 푼다. 정답 유일성·복수 정답 여부·교육과정·계산·해설의 흐름을 확인한다.
- **오답 경로:** 보기 5개는 실제 일어날 수 있는 부호·계수·공식·조건 해석 실수에서 유도한다. 계산으로 자연스럽게 나오지 않는 수를 단순히 정답 주변에 늘어놓지 않는다. 정답만 표현 형태가 달라 보이지 않게 한다.
- 수치형 보기는 크기순, 객관식 JS 정답은 `①`~`⑤` 번호만 사용한다. 정답 번호 배열의 반복·쏠림과 선택지 중복을 도구로 검사한다.
- 해설은 학생이 **답을 모르는 상태에서** 조건부터 따라갈 수 있는 판서형 단계로 쓰고, 갑자기 정답을 꺼내 역확인하지 않는다. 서술형은 완결된 모범답안을 작성한다.
- 난도 분포·고난도 위치·전체 풀이 부담이 원본과 실질적으로 같은지 마지막에 재확인한다.

## 4. 최신 메타와 동반 기록

- 최종 **신규 유사1 또는 유사2 문항 자체**의 결정적 풀이로 `curriculum`, `standardCourse`, `standardUnitKey`, `subUnitKey`, `rpmPrimaryRecordId`, ACTIVE `problemTypeKey`/`templateKey`, `difficultyBucket`(정수 1~5)을 판정한다.
- PT/TPL의 ACTIVE 상태·부모 PT·과목/단원 바인딩을 검사한다. RPM 행이 `RPM_ONLY`여도 직접 유효한 PT/TPL을 판정할 수 있다. 맞는 키가 없으면 등록 필요로 기록하고 가짜 키를 넣지 않는다.
- 해당 시 CrossConcept/Condition/Integration을 판정하되 `level`, `curriculumKey`, `ptTplCandidate`, 수동 RPM L1~L4 사본은 새 JS에 쓰지 않는다.
- 4칸 `given/goal/method/condition`과 근거는 별도 파일에 두고, compact 4slot·메타 요청·출처·검토 상태를 **최종 운영 JS의 Git blob SHA와 UID**에 결속한다. 독립 검수 전 메타는 `review_required`/초안으로 표시하고 승인을 꾸미지 않는다.

## 5. 문제용·해설용 SVG 2축 판정과 실행 가능한 플랜

### 5-1. 전 문항 2축 판정 (제작 누락 방지)

- **완성된 신규 문항 Q01~QNN 전부**에 대해 `문제용(problem)`과 `해설용(solution)`을 **각각 독립 판정**한다. 결과를 Experience Ledger 또는 SVG 판정 장부에 문항 번호·축·`REQUIRED / BENEFICIAL / EXEMPT`·구체적인 수학/교육적 사유·plan 경로(필요한 경우)로 남긴다. 시험지별 최종 장부에는 판정 분모 `문항 수 × 2`, 축별 필요/면제 수, 실제 plan 수가 대조 가능해야 한다. `SVG_PENDING.md`에는 미제작 대상과 상태를 연결한다.
- **문제용:** 학생이 발문만 보고 주어진 점의 배치·그래프·영역·표·상대적 위치를 유일하게 정할 수 없는 경우 `REQUIRED`이다. 발문만으로 풀 수 있어도 그림이 조건의 구조를 이해하는 데 실질적으로 도움이 되면 `BENEFICIAL`을 검토한다. 문제 그림에는 **주어진 조건만** 넣으며 정답·미지수 결과·풀이로 얻은 보조선이나 값은 노출하지 않는다.
- **해설용:** 교점·접선·대칭·보조선·함수 개형·부호/증감·구간·영역 등 **결정적 풀이 관계**를 학생이 눈으로 확인해야 이해가 쉬운 경우 `REQUIRED/BENEFICIAL`로 판정한다. 발문에 좌표·수식이 모두 있다는 이유만으로 해설용까지 `EXEMPT`로 처리하지 않는다. 단순 전개·계산을 그림으로 복제하는 장식은 면제한다.
- 각 축의 `EXEMPT`는 **그 축에 실제 그림이 불필요한 이유**를 문항별로 기록할 때만 쓴다. 원본에 그림이 없거나, 글로만도 정답이 유일하다는 사실 **하나만으로** 두 축 모두 면제하지 않는다. `EXEMPT`용 빈 SVG·형식적 제작 plan을 대량 생성할 필요는 없다. 기존 양식이 `qNN-*.plan.json`에 EXEMPT 판정을 남기더라도 이를 **엔진 제작 가능 plan 건수에 포함하지 않는다**.

### 5-2. 필요 그림의 공식 엔진 plan 작성

- `REQUIRED/BENEFICIAL` 판정한 **각 축**에는 실제 공식 엔진이 읽을 **제작용 JSON**을 만든다. 기본 파일명은 `qNN-problem.plan.json`, `qNN-solution.plan.json`이다. 기존 세트 관례상 별도 `*.followup.plan.json` 또는 `*-svg-pending.plan.json`을 쓰면 원래 축의 판정 및 `SVG_PENDING.md`에 **그 제작용 JSON을 정확히 가리키는 경로**를 남긴다. `{"status":"EXEMPT"}`만 담긴 파일은 제작용 plan이 아니다.
- 작성 전에 [AUTHOR_GUIDE](../../archive/tools/geometry-equation/production/AUTHOR_GUIDE.md)의 해당 capability·계약 전문을 확인하고, **현재 유사문항의 최종 발문·보기·작은칠판 해설을 기준으로** `capability`, 필요한 `graphPlan/mathPlan/...`, 정확한 식·좌표·점·라벨·방향·범위·설명 등 해당 capability의 필수 필드를 채운다. 기존 기출/유사의 같은 번호 plan은 **참고 자료**일 뿐 수치·변수만 바꿔 복제하지 않는다. 없는 capability나 잘못된 스키마를 그럴듯한 JSON으로 꾸미지 않는다.
- 문제 plan과 해설 plan은 **별도 JSON**이며, 같은 그림을 무조건 복사하지 않는다. 문제 plan에는 정답 노출 여부를 별도 검토하고, 해설 plan에는 핵심 풀이의 시각 근거가 실제로 보이는지 검토한다. 그림에 적힌 모든 숫자·수학 기호·라벨은 최종 JS와 독립 대조한다.
- 제작용 plan마다 공식 `plan-lint`를 가능한 범위에서 실행한다. `--shallow PASS`는 전체 lint·엔진 렌더·PNG 육안검수의 대체가 아니며, 글꼴/엔진 미지원은 `NOT_RUN`/`ENGINE_CAPABILITY_PENDING` 등 실제 상태로 남긴다. 손/스크립트로 SVG를 조립하지 않는다. 엔진 미지원은 별도 엔진 확장 후 렌더할 후속 항목으로 기록한다.

### 5-3. main-first와 학생용 필수 그림의 경계

- **문제 풀이에 필수인 그림(REQUIRED):** 실제 자산이 없으면 문제가 성립하지 않으므로 엔진 렌더→PNG·발문 대조→검증된 `image` 참조를 마치기 전에는 정상 출고/운영병합 완료로 판정하지 않는다. 없는 그림을 발문에 있는 척하거나 임의 참조를 넣지 않는다.
- **문제/해설에 실질적으로 유익한 그림(BENEFICIAL) 및 해설 보조:** plan JSON을 남기고 실제 제작·시각검수가 미완료면 `SVG_PENDING.md`에 문항·축·plan 경로·`SVG_TO_CREATE / NOT_RUN`을 기록한다. 해설이 텍스트로 완결된 경우에 한해 기존 main-first 방식으로 JS를 선반영할 수 있으며, 미제작 `solutionImage`/`image` 경로를 넣지 않는다. `solutionPlanRef`는 실제 존재하는 해설 계획을 가리켜야 한다. 문제의 필수 조건을 그림 없이 생략한 채 선반영해서는 안 된다.
- 최종 보고는 **문제용/해설용 각각** `REQUIRED·BENEFICIAL·EXEMPT`, 유효 제작용 plan, shallow/full lint, 렌더, PNG 육안검수, JS 연결, 미완료 목록을 분리 집계한다. `GIT_MAIN_MERGED`와 `SVG_VISUAL_QA_DONE`을 혼동하지 않는다.

**마감 자가검사:** `Q01~QNN × 문제/해설`에 판정 누락 0건인가? 필요한 그림마다 실제 제작용 JSON이 있고 학생용 숫자/방향을 반영하는가? 빈 EXEMPT JSON을 제작 plan으로 세지 않았는가? 필수 문제 그림은 실제 연결되었는가? 미제작 건은 `SVG_PENDING.md`에서 다음 엔진 작업자가 바로 찾을 수 있는가?
## 6. JS 제작·검사·병합

1. 최신 JS 스키마로 `archive/exams/similar/<학교급>/<학년>/<학기시험>/<시험지>_유사.js` **또는** `<시험지>_유사2.js`를 작성한다. `<학교급>/<학년>`은 `high/h1`, `high/h2`, `middle/m1`, `middle/m2`, `middle/m3` 중 실제 대상과 일치해야 한다. 같은 폴더의 메타 요청·plan, `archive/data/item-4slot/similar/<학교급>/<학년>/<학기시험>/`의 별도 4칸 파일을 함께 만든다. 고2 과목명은 기존 시험지 naming에 맞게 유지하며 원본·기존 유사 세트는 수정하지 않는다.
2. 최소 검사: `node --check <파일>`, 문항 번호·개수·배점 합계·정답/해설 공백, `node archive/tools/similar-import/choice-order-check.mjs judge <파일>`, 표가 있으면 `node tools/check-ap-tables.cjs --files <파일>`, PT/TPL/4칸/SHA 결속, **전 문항 문제/해설 2축 판정 누락 0건 및 필요 축별 제작 JSON 누락 0건**, 제작용 plan마다 공식 엔진 `plan-lint`(shallow/full 결과 구분).
3. Git 루트 checkout은 `main` 전용으로 둔다. 별도 worktree/브랜치에서 대상 시험지 운영 파일만 커밋한다. 인증된 GitHub 커넥터가 있으면 정상 브랜치·커밋·PR 경로로 사용해도 된다.
4. **이번 프롬프트는 사용자 지시에 따른 `main` 운영병합까지 포함한다.** PR을 생성하고 GitHub 보호 규칙이 허용하면 병합한다. 보호 규칙을 우회하거나 강제 push하지 않는다.
5. 원격 `main`에서 JS·메타·4칸·SVG 작업 장부를 실제 readback한다. 병합 후 자신의 완료된 worktree는 규칙대로 정리한다.
6. `GIT_MAIN_MERGED`, CI, 메타 등록기, Pages/학생 배포는 서로 다른 상태다. CI pending/fail이나 실행하지 못한 검사를 거짓 PASS로 적지 않는다. 공통 CI·엔진·배포 파이프라인의 범위 밖 수정은 하지 않는다.
