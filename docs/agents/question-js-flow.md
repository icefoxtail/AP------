# 문항 JS 작업 정본 — 발문에서 게시까지 한 흐름

2026-11-24 제정(원장 지시: "발문 해설 메타 svg까지 한 흐름으로 정리해 놓은 정본, 기출과 유사 등 모든 작업에 공통으로"). 기출·유사·교과서·문제집·유형 채우기·생성 문항 어느 작업이든, 어느 실행기(Claude·GPT·Gemini·DeepSeek)든 문항 JS를 만들거나 고칠 때는 이 문서를 처음부터 끝까지 읽고 그 순서대로 한다.

- **이 문서의 자리:** 규칙 한 줄 모음은 [RULEBOOK_CURRENT.md](../rules/RULEBOOK_CURRENT.md), 이 문서는 그 규칙을 **문항 하나가 지나가는 순서**로 늘어놓은 것이다. 단계마다 세부는 링크한 영역 문서가 정본이고, 여기와 다르면 영역 문서를 고쳐 맞춘다. 이유: 규칙이 영역 문서 열 개와 라인별 지시서에 흩어져, 같은 문항을 두고 라인마다 다르게 일했다.
- **작업 지시서는 이 문서를 가리킨다.** 지시서에 규칙을 다시 풀어 쓰지 않고 "이 문서의 몇 단계"와 그 작업만의 범위·완료 기준만 적는다. 이유: 지시서마다 규칙을 옮겨 적다가 빠지거나 옛 문구가 남았다.
- **판단 기준은 하나다:** 학생이 문제를 풀고 해설을 따라갈 수 있는가. 값이 있으면 쓰고, 막는 것은 실제 결함뿐이다(쉽게·넓게·빠르게·변화하게).

## 한 장 흐름

| 단계 | 하는 일 | 끝났다는 증거 | 세부 정본 |
| --- | --- | --- | --- |
| 1. 파일·문항 모양 | 파일 이름·자리, 필드 채우기 | 파일이 열리고 문항 수·id가 맞음 | 이 문서 1절 |
| 2. 발문·보기 | 옮기기, 원문 오류 최소 수정, (유사) 보기 짓기 | 직접 풀어 답이 하나로 나옴 | [common.md](common.md), [similar-choices.md](similar-choices.md) |
| 3. 정답·해설 | 직접 풀기 → 정답 → 판서형 해설 → 검산 | 다른 방법으로 한 번 더 확인 | 이 문서 3절 |
| 4. 표 | 파이프 표로 쓰기 | 표 검사 FAIL 0 | [table-engine.md](table-engine.md) |
| 5. 메타 | 단원 → 유형(PT·TPL) → 난이도 → 4칸 | 등록 도구 dry-run 통과 | [metadata.md](metadata.md) |
| 6. 그림 | 필요 판정 → plan → 엔진 렌더 → PNG 확인 | 그림을 직접 봄 | [visual-svg.md](visual-svg.md) |
| 7. 검사·PR·게시 | 파일 검사, PR, 병합, 등록, 릴리스 | main 반영, 배포는 따로 기록 | [exam-release.md](exam-release.md) |
| 8. 고칠 때 | 최소 수정, 무엇을 고쳤는지에 따라 뒤처리 | 고친 내용이 화면에 보임 | [common.md](common.md) |

그림과 메타는 문항을 막지 않는다. 문항(발문·보기·정답·해설)이 맞으면 먼저 들어가고, 그림·빈 메타는 뒤따라 채운다. 이유: 학생이 기출과 해설을 바로 써야 한다(2026-11-24).

## 1. 파일과 문항의 모양

- **자리와 이름:** 원본은 `archive/exams/original/<학교급>/<학년>/<학기칸>/`, 유사는 `archive/exams/similar/` 아래 같은 구조다. 파일 이름은 `<연도 2자리>_<학교>_<학기>_<시험>_<학년>_기출.js`, 유사는 끝이 `_유사.js`·`_유사2.js`…이고 같은 이름이 이미 있으면 번호를 올린다. 시험지별 소형 메타(`.meta-…json`)와 4칸(`.4slot.json`)은 JS 옆에 둔다.
- **파일 뼈대:** `window.examTitle = "<파일 이름에서 .js를 뺀 것>";` 과 `window.questionBank = [ … ];` 두 개다. JSON처럼 쓰되 문자열 안의 역슬래시는 두 번(`\\dfrac`), 줄바꿈은 `\n`이다.
- **문항 하나에 꼭 있는 것:** `id`(1부터 정수), `content`(발문), `choices`(객관식 5개 문자열, 서술·단답은 `[]`), `answer`, `solution`, `questionType`, `standardCourse`, `standardUnitKey`·`standardUnit`, `subUnitKey`·`subUnit`, `category`, `layoutTag: "grid"`, `wide: false`, `tags: []`.
  - 발문은 `content`에 쓴다. 옛 파일의 `question`·`stem`은 읽기만 한다(결속 지문은 `content` → `question` → `stem` 순으로 읽는다: `archive/exam-source-reader.js`).
  - 수식은 `$…$`, 분수는 `\\dfrac`. 객관식 정답은 `①`~`⑤`, 단답·서술형은 값(`$\\dfrac{36}{7}$`)을 같은 학년의 이미 있는 파일 형식대로 쓴다.
  - 배치 필드(`layoutTag`·`wide`·`imageSize`·`solutionImageSize`)는 기본값만 쓴다. 배치와 그림 크기는 엔진이 정하고, 한 그림만 키울 때 `imageScale`·`solutionImageScale`(30~100)을 쓴다.
- **새 문항에 쓰는 메타 칸(최소 한 벌):** `curriculum`, `rpmPrimaryRecordId`, `problemTypeKey`·`templateKey`, `difficultyBucket`(정수 1~5). **쓰지 않는 칸:** `level`(하/중/상), `rpmPrimaryL1~L4`, `curriculumKey`, 맨 `L1~L4`, `ptTplCandidate`. `originalCategory`는 원본 기출에 적힌 글자만 적고 유사·생성 문항은 비운다. 이유: 같은 값을 여러 칸에 쓰면 칸끼리 어긋난다([metadata.md](metadata.md) "새 문항 메타는 최소 한 벌").
- **그림 칸:** 문제 그림은 `image`(또는 발문 안 `<img>`), 해설 그림은 `solutionImage`(+`solutionImageAlt`·`solutionImageCaption`). 파일은 `archive/assets/images/<시험지키>/`에 두고 JS에는 `assets/images/<시험지키>/<파일>`로 적는다. 시험지 폴더 안에 두면 R2로 올라가지 않아 학생 화면에서 깨진다([exam-pipeline.md](exam-pipeline.md) "시험지 이미지 올리기").

## 2. 발문과 보기

- **처음 만들 때(CREATE·첫 반입)만 원본 대조가 필수다.** 추출이 끝난 발문·보기·수식은 JS와 실제 그림을 기본 입력으로 쓰고, 필요한 문항만 원문과 대조한다.
- **원문 오류는 최소 수정으로 문항이 성립하게 한다.** 숫자·부호 하나, 보기 하나를 고쳐 풀리게 만들고, 정답·해설·보기를 함께 맞춘 뒤 사후 보고한다. "판단 불가·원본 확인 대기"로 남기지 않고 사용자에게 원본 확인을 부탁하지 않는다. 검수 분류는 "수정함 / 오탐" 둘뿐이다([common.md](common.md) 맨 위 절).
- **발문에 답이나 풀이 힌트를 덧붙이지 않는다.** 원문에 없는 조건을 넣어야 풀리면 그것이 최소 수정이고, 보고 대상이다.
- **유사·생성 문항의 보기는 새로 짓는다**([similar-choices.md](similar-choices.md)가 정본이다). 수 보기는 크기순, 정답 자리를 먼저 정하고 오답을 그 주위로, 정답 번호 배열은 모델이 아니라 스크립트가 뽑는다, 정답만 꼴이 다르지 않게, 오답은 말이 되는 값으로. 확인은 `archive/tools/similar-import/choice-order-check.mjs`. 원본 기출의 보기는 실제 시험지 그대로 둔다. 이유: 혼자 순서가 어긋난 보기가 정답이라는 것을 학생이 알아챘다(2026-11-19).
- **유사는 원본과 같은 단원·같은 수준의 새 문제다.** 다른 단원이거나 교육과정 밖이거나 확 어려워진 문항만 결함으로 본다. 서술형은 "…을 구하는 과정을 서술하시오."로 끝낸다([aistudio-similar.md](aistudio-similar.md) "반입 검수").

## 3. 정답과 해설

순서는 **직접 풀기 → 정답 적기 → 해설 쓰기 → 검산**이다. 저장된 정답·다른 모델의 답은 내가 푼 뒤에 본다.

1. **직접 푼다.** 발문·보기·그림만 보고 푼다. 그림은 파일을 실제로 열어 본다.
2. **정답.** 객관식은 답이 보기 안에 하나만 있어야 한다. 원본이 복수 정답이면 유사도 그럴 수 있다.
3. **해설은 작은 칠판 판서 수준으로 쓴다.**
   - 한 줄에 한 단계. 중간 계산을 건너뛰지 않는다. 학생이 혼자 읽고 따라올 수 있어야 한다.
   - **풀이는 조건에서 답으로 간다. 답을 먼저 놓고 거꾸로 확인하지 않는다.** "$\dfrac17$과 비교한다"처럼 어디서 나왔는지 알 수 없는 값을 꺼내 차를 계산해 맞음을 보이는 해설은 결함이다. 그 값이 나오는 길(치환 → 번분수 꼴 → 산술평균과 기하평균의 관계 등)을 순서대로 쓴다. 이유: 2026-11-24 원장 지적(25 순천고 고1 2학기 기말 19번과 그 유사) — 학생은 답을 모르는 상태에서 푼다.
   - 해당 학년·과목 교육과정 안의 방법만 쓴다(중학 문항에 고등 개념, 공통수학에 미분 금지). 쓰는 정리는 이름을 적는다("산술평균과 기하평균의 관계에 의하여").
   - 객관식은 왜 그 보기가 답인지까지, 증명·서술형은 모범 답안으로 쓴다. 결론은 한 번만 쓴다.
   - 정답만 맞고 두세 줄로 끝나는 해설은 결함이다.
   - 표는 4절, 그림은 6절의 길로만 넣는다. 해설 글에 `[그림: …]` 같은 제작 메모·영어 메모·raw TeX 설명을 남기지 않는다.
4. **검산.** 답을 조건에 넣어 보거나 다른 방법으로 한 번 더 확인한다. 해설의 마지막 값과 `answer`가 같은지 본다.

## 4. 표

표는 AP Table Engine이 그린다. 파이프 표로 쓰고 셀의 수식은 `$…$`, class·style·border는 쓰지 않는다. 확률분포표·분할표도 SVG가 아니라 이 표로 쓴다. 인계 전 `node tools/check-ap-tables.cjs --files <파일>`로 FAIL 0을 확인한다([table-engine.md](table-engine.md)).

## 5. 메타

순서는 **단원 → 유형(PT·TPL) → 난이도 → 4칸**이다. 세부와 도구는 [metadata.md](metadata.md)가 정본이다.

- **단원:** `standardUnitKey`·`subUnitKey`는 마스터테이블에 실제 있는 키만 쓴다. 라벨은 키에서 정해지므로 마스터 글자를 그대로 옮긴다.
- **유형:** 문항과 해설의 결정 단계를 읽고 직접 판정한다. 키는 등록부에 ACTIVE이고, TPL의 상위가 고른 PT이며, 그 학년·과목에 연결돼 있어야 한다. 학년이 달라도 같은 형태면 기존 키를 재사용하고 그 학년 연결을 추가한다. 맞는 키가 없으면 가까운 키에 붙이지 않고 `registryChanges`로 새 키를 만들거나 "새 키 필요"로 보고한다.
- **난이도:** 정수 `difficultyBucket` 1~5만 쓴다. 정의·공식을 바로 쓰면 1이고, 줄 수·서술형·배점·계산량은 올리는 이유가 아니다. 애매하면 낮게 잡는다.
- **4칸:** 발문과 해설을 읽고 판정한다. 가벼운 길이 있으면 채우고, 문항을 막는 조건으로 쓰지 않는다.
- **모델 하나가 채운 값은 초안 등급(`DRAFT_SINGLE_MODEL`)으로 표시한다.** 초안도 선정·필터·화면에 그대로 쓰인다. 이미 승인된 값은 덮어쓰지 않는다(빈 칸만 채운다).
- **등록 길:**
  - 새 시험지(유사 반입 등)는 하네스가 요청을 만든다: `archive/tools/similar-import/JUDGMENT_GUIDE.md`.
  - 유형만 채울 때는 `archive/tools/meta-foundation/build-type-judgment-requests.mjs` → `archive/tools/meta-foundation/register-type-judgment.mjs`. 유형(PT)은 이미 승인이고 세부 유형(TPL)만 비었으면 `--append-template`(2026-11-24)이다.
  - 공용 `question_metadata.json`은 손으로 고치지 않는다(git에는 조각 `archive/data/question-metadata/v1/`만 있고, 필요하면 `node archive/tools/meta-foundation/question-metadata-format.mjs assemble`로 조립한다).
  - PR에는 등록 도구 dry-run이 통과한 것만 넣는다. 등록 요청의 종류를 새로 만들었으면 `tests/archive-pr-native-preview.test.mjs`의 관련 테스트도 돌린다. 이유: 2026-11-24 새 요청 종류가 PR의 등록 미리 검증에서 걸렸는데 그 테스트를 안 돌려 병합 직전에야 드러났다.
- **메타는 발문과 보기에 묶인다.** 해설·정답·그림을 고쳐도 판정은 유지된다. 발문·보기를 고치면 8절의 뒤처리를 한다.

## 6. 그림

세부와 흐름은 [visual-svg.md](visual-svg.md), 작성 규칙은 [AUTHOR_GUIDE](../../archive/tools/geometry-equation/production/AUTHOR_GUIDE.md)가 정본이다.

1. **필요 판정(문제 그림·해설 그림 따로).** 완성된 문항마다 두 축 각각 `REQUIRED / BENEFICIAL / EXEMPT`와 구체적 사유를 Ledger/시각 검토 장부에 기록한다. 원본에 있다는 이유만으로 복사하지 않고, 없거나 텍스트만으로 정답이 나온다는 이유만으로 면제하지 않는다. 학생 풀이·결정적 해설 이해에 실제 도움이 되는 그림은 만들되, 단순 계산 중복·장식은 면제한다. `EXEMPT`용 빈 SVG나 형식적 제작 JSON을 만들지 않는다. 유사 작업의 판정 분모·필요 plan 확인은 [GPT 유사 실행 §5](gpt-similar-exam-execution-prompt.md#5-문제용해설용-svg-2축-판정과-실행-가능한-플랜)를 따른다.
2. **새 SVG는 저장소 엔진으로만 만든다.** 손으로 쓴 SVG, 스크립트로 조립한 SVG는 넣지 않는다. 스캔에서 깨끗하게 잘라 넣는 원본 그림(PNG)은 그대로 쓴다. 엔진이 못 그리면 손으로 메우지 않고 엔진 기능을 넣는다(그동안 그 문항은 그림 없이 둔다). 엔진 기능은 별도 PR로, 켰을 때만 동작해 기존 그림이 바이트로 같게 넣고, 골든 게이트의 REGRESSED·CLIPPED·NOT_RUN이 0이어야 한다.
3. **plan을 쓴다.** plan은 외부 모델이 쓴다(DeepSeek → Gemini `agy` → Codex 순, 셋 다 한도면 원장님께 묻는다). Claude(Sonnet)는 plan을 쓰지 않고 렌더·확인·게시를 맡는다(대량 흐름과 모델 순서: [visual-svg.md](visual-svg.md) "현행 흐름 (2026-11-24)"). 문제 그림에는 발문의 값만 넣고 정답·풀이 보조선을 넣지 않는다. 해설 그림은 풀이 과정의 정보를 최대로 넣는다(정답이 보여도 된다). 기존 1:1 수치변형 경로에서만 원본·기존 유사 plan을 검증 후 참조·변형할 수 있다. **GPT 발전형 `EXAM_FOLLOWUP/SOURCE_BALANCED`에서는 기존 plan을 참고만 하고 완성된 새 발문·해설에 맞춰 구조부터 재설계한다. 단순 수치 치환 복사는 금지한다.** 필요한 축마다 실제 capability와 수학 정보가 있는 엔진 제작용 JSON을 작성하고 EXEMPT 판정 파일을 제작 plan으로 세지 않는다. 면 채움은 꼭 필요할 때만, 여러 선은 색·선 종류로 구분하고, 빽빽한 라벨은 지우지 않고 지시선으로 뺀다. 렌더 전 `archive/tools/geometry-equation/ops/claude-batch/plan-lint.cjs`로 형식을 거른다.
4. **렌더한다.** `archive/tools/geometry-equation/production/render-plan.mjs`. 게시 관문은 점수 90점이고, 틀린 값·문제 그림의 정답 노출·필수 값 누락·깨짐·잘림은 점수와 무관하게 막는다.
5. **PNG를 직접 본다.** 발문·정답·해설의 값과 대조한다. 표시 크기는 `archive/figure-size.css`의 단 폭 비율(문제 75%, 해설 80%)과 휴대폰 390px이다. 렌더하지 않은 그림을 PASS로 적지 않는다(`NOT_RUN`). 문제 풀이의 필수 그림은 렌더·검증·연결 전 정상 출고하지 않고, 해설 보조·비필수 그림은 정확한 후속 plan과 `SVG_PENDING.md`를 남길 때만 JS 선반영 상태를 따로 표시한다.
6. **붙인다.** 1절의 그림 칸과 자리 규칙대로 넣고, 해설 그림 장부는 전용 도구로만 쓴다. 기존 그림을 바꿀 때는 새 파일 이름을 쓰거나 `?v=`를 올린다.

통과한 그림은 모아 두지 않고 바로 게시한다. 실패한 그림만 다시 한다.

## 7. 검사·PR·게시

- **넘기기 전 검사(문항 작업자가 직접):**
  1. `node --check <파일>`과, 파일을 열어 `questionBank` 길이·`id`가 기대와 같고 빈 `answer`·`solution`이 없는지 본다.
  2. 표가 있으면 표 검사, 유사·생성이면 보기 순서 검사.
  3. 메타 요청이 있으면 등록 도구 dry-run.
  4. 그림이 있으면 PNG 확인.
  - 전체 테스트(`tools/run-tests.js`)와 런타임 검사는 문항 작업에서 돌리지 않는다(병합 직전 한 번, PR CI가 돌린다).
- **보고:** 한 일, 원문 수정 목록(파일·번호·무엇을), 풀지 못한 문항과 사유, 메타(비어 있던 수 → 채운 수 → 거부·새 키 필요), 그림(만든 수·`EXEMPT`·보류), 실행한 검사와 `NOT_RUN`.
- **PR:** 시험지 JS·메타·등록 요청이 든 PR은 **자료 PR**이다. 등록기가 쉴 때 한 건씩 넣는다. 도구·화면·문서 PR은 바로 넣는다. 검수를 통과한 변경은 물려받은 CI 빨강을 기다리지 않고 병합하되, **내 PR이 만든 실패는 고친다.** 병합은 병합 창구가 하고, 반입 작업자가 임의로 병합하지 않는다.
- **게시까지의 길:** 병합 → main 등록기가 메타·문항 목록을 등록 → 릴리스가 학생 사이트를 배포한다. 병합됐다고 학생 화면에 보이는 것이 아니다. 병합과 배포는 따로 기록한다.
- **화면 파일을 새로 붙였으면** `tools/archive-pages-release-manifest.json`에 올린다. 이유: 2026-11-24 새 스크립트를 목록에 안 넣어 릴리스가 두 번 실패했다.

## 8. 이미 들어온 문항을 고칠 때

- **순서:** 최소 수정 → 직접 검산 → 정답·해설·보기를 함께 맞춤 → 사후 보고. 원본 대조는 있으면 쓰는 참고다. 작은 수정(해설 한 문항 등)은 지시서·검수 왕복 없이 바로 고쳐 PR로 낸다.
- **같은 문항의 유사도 본다.** 기출 해설의 결함은 그 문항을 변형한 유사에 같은 꼴로 들어 있는 경우가 많다. 기출을 고치면 같은 번호의 유사 파일들을 열어 같이 고친다. 이유: 2026-11-24 19번 해설 결함이 유사1에 그대로 있었다.
- **무엇을 고쳤는지에 따라 뒤처리가 다르다.**

  | 고친 것 | 뒤처리 |
  | --- | --- |
  | 해설·정답·그림 | 없음. 메타 판정은 유지된다. 그림은 새 파일 이름 또는 `?v=`. |
  | 발문·보기(수학 내용은 같음: 오탈자·표기·원문 복원) | 바뀐 문항 목록을 내고 `archive/tools/meta-foundation/build-text-binding-rebinds.mjs --revisions`로 재결속 기록을 추가한다. |
  | 발문·보기(문제가 달라짐: 조건·요구·정답이 바뀜) | 유형·난이도를 다시 판정해 등록한다. |
  | 문항을 지우거나 순서를 바꿈 | 하지 않는다. 번호(자리)가 문항의 식별값이다. 꼭 필요하면 재번호 대신 그 자리의 문항을 교체한다. |

- **고친 내용은 어디서나 보인다.** 저장한 문제지·학생 출제본·서버 PDF는 열 때 지금의 문항 내용을 덮어 보여 준다(`apmath/student/current-question-content.js`의 덮어쓰기 규칙). 그래서 문항을 고치는 일을 미루거나 파일을 고정해 둘 이유가 없다. 문항·시험지 파일을 바이트로 고정하는 보류나 검사를 만들지 않는다.
- **봉인 문서·기존 영수증·승인 기록의 기존 항목은 고치지 않는다(추가만).**
