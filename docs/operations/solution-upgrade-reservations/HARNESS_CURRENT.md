# 고등 학생용 해설 업그레이드 — 예약 4라인 공통 하네스

> 적용: 고1·대수·미적분Ⅰ·확률과 통계의 기존 기출/유사/교과서 JS. 이 문서는 공통 진입점이며 현행 `AGENTS.md`, `docs/rules/RULEBOOK_CURRENT.md`와 해설·SVG 영역의 정본을 대체하지 않는다. 규칙이 충돌하면 상위 정본과 사용자의 최신 지시를 따른다.

## 1. 고정 목표와 책임

- 목표는 **기존 해설 중 학생이 따라 풀기 어려운 문항을 찾아 필요한 것만 개선**하는 것이다. 모든 해설을 재작성하거나 수정 건수를 목표로 하지 않는다.
- **2026-11-21 사용자 변경: MD 우선 작업 라인.** 한 번 실행할 때 현재 우선순위 시험 구분의 **해당 과목 전체 시험지 목록을 먼저 수집**하고, 가능한 한 많은 시험지의 전 문항 해설을 빠르게 스캔해 **여러 개선 문항을 배치로 선별**하며, 개선할 해설이 있으면 **실제 학생용 수정 해설 전체를 MD로 작성해 과목별 작업 브랜치에 커밋**한다. 후보 보고만 남기고 종료하지 않는다. JS 출고는 별도의 검수 단계로 미룬다.
- 우선 결함: 교육과정 외 개념, 잘못된 수학, 핵심 논리 점프, 계산·조건·경우 누락, 불필요하게 어려운 풀이, 학생이 이해하기 어려운 설명. [학생용 해설 정본](../../rules/01_CANONICAL/JS아카이브_학생용해설_운영규칙_v1.md)의 코드와 게이트를 적용한다.
- `solution`은 학생이 재현할 수 있는 **작은 칠판** 흐름으로 쓴다. 두 번째 풀이가 실질적으로 이해를 돕는 경우에만 같은 `solution` 안에 자연스럽게 추가한다. 현행 JS에 없는 상세해설 필드를 임의로 만들지 않는다.
- `content`, `choices`, `answer`, 문제 `image`, 기존 승인 메타, 기존 `solutionImage`는 기본 보호한다. 오류를 찾으면 별도 `HOLD`/defect로 남긴다. 승인된 `solution` 변경에서 요구하는 원본 고정 해시 갱신 등은 `common.md`의 공식 절차를 따른다.
- **새 SVG·손 SVG·우회 스크립트는 절대 만들지 않는다.** 해설이 수학적으로 검증된 후 그림이 필요하면 SVG 엔진용 수학 사실과 plan을 작성하고 별도 엔진 라인으로 넘긴다. 엔진 렌더·PNG 독립 검수·게시는 SVG 라인이 담당한다. 필수 시각자료가 미완료면 시험지의 최종 시각 PASS를 선언하지 않는다.
- 기존 source identity와 전체 문항 denominator를 확정한다. `id`/문항 번호만으로 다른 시험지의 문항을 결속하지 않는다.

## 2. 라인과 시간 (Asia/Seoul)

| course key | 매시 시작 | 대상 |
| --- | --- | --- |
| `h1` | 10분 | 고1 공통수학1·2 |
| `algebra` | 20분 | 대수(수1) |
| `calculus1` | 30분 | 미적분Ⅰ(수2) |
| `probstat` | 40분 | 확률과 통계 |

**처리 대상 종류의 절대 우선순위:** `기출(original) → 유사(similar) → 유형 → 교과서 → 문제집`. 담당 과목의 기출 처리 대상이 남아 있으면 유사·유형·교과서·문제집으로 넘어가지 않는다. 기출은 `archive/exams/original/high/`의 현행 JS, 유사는 `archive/exams/similar/high/`의 현행 JS, 이후 유형·교과서·문제집은 실제 운영 소스에서 찾는다.

**시험지 선택 우선순위(시험 구분이 연도보다 먼저):** ① **`2학기 기말` 전 연도를 최신→과거 순으로 끝까지** 처리 ② `1학기 중간` 전 연도를 최신→과거 ③ `1학기 기말` 전 연도를 최신→과거 ④ `2학기 중간` 전 연도를 최신→과거. 예: 2025년 2학기 기말 → 2024년 2학기 기말 → 2023년 2학기 기말 → … → 2025년 1학기 중간 → 2024년 1학기 중간 → …. **한 연도의 네 시험을 먼저 끝내는 연도 우선 정렬은 금지**한다. 기출 전체에 이 순서를 적용하고, 학기별 구분이 있는 유사시험지도 같은 순서를 적용한다. 연도·학기·시험 구분이 없는 유형·교과서·문제집은 확인 가능한 발행·반입 연도 내림차순을 우선하고 동률은 안정적인 경로/파일명 순으로 처리한다. 없는 회차는 건너뛴다. 이 순서를 임의의 난이도·파일 수정시간·학교 이름순으로 바꾸지 않는다.

### 2-A. 자료가 없을 때의 자동 폴백 — '없음'은 종료 조건이 아니다

**각 자료 종류 안에서 시험 구분을 끝까지 순회하는 상태 기계**를 적용한다. 기출(original)은 [2학기 기말(전 연도 최신→과거), 1학기 중간(전 연도 최신→과거), 1학기 기말(전 연도 최신→과거), 2학기 중간(전 연도 최신→과거)]의 순서다. 현재 구분에 해당 과목 시험지가 **모든 연도에 걸쳐 하나도 없거나**, 이미 검사·처리한 시험지만 남아 **미처리 대상이 없으면**, 같은 실행 안에서 즉시 다음 시험 구분으로 이동한다. 예를 들어 대수/미적분Ⅰ의 2학기 기말이 없으면 **1학기 중간을 실제 검색**한다. 그것도 없으면 1학기 기말, 이어 2학기 중간으로 진행한다. 네 구분을 모두 탐색한 후에만 유사(similar)로 이동하고, 유사에서도 시험 구분이 있으면 동일한 폴백을 수행한다. 이후 유형→교과서→문제집을 순회한다.

- **학교 하나/연도 하나/폴더 하나에서 파일이 없다는 결과는 해당 시험 구분 전체가 비었다는 뜻이 아니다.** 우선 `archive/exams/original/high/`의 실제 인덱스/하위 경로와 현행 소스 목록을 살피고, 고2·고3 폴더에 있는 수학Ⅰ/수학Ⅱ 등 교육과정 명칭과 `standardCourse`·단원 정보를 확인해 담당 과목을 판정한다. 경로명/파일명만으로 과목을 잘못 배제하지 않는다.
- 후보가 아예 없는 시험 구분은 'EMPTY_BUCKET'으로 기록하고 다음 구분으로 **계속 진행**한다. 시험지는 있지만 해설 수정 대상이 0개라면 'SCREENED_PRELIMINARY'로 체크 범위를 남기고 **같은 구분의 다음 시험지**, 더 없다면 다음 구분으로 진행한다. 두 상태 모두 `SAVE_BLOCKED`나 전체 작업 완료의 근거가 아니다.
- **회당 스캔 시험지 1~3개 상한은 폐지한다.** 폴더/학교/연도별 소스를 먼저 목록화하고, 시간이 허용하는 만큼 **여러 시험지의 모든 문항 해설**을 빠르게 검토한다. 빈 구분은 다음 구분으로 넘어간다. 전체 목록이 길어 한 번에 못 끝나면 시험지·문항 단위 커서를 저장해 다음 예약이 이어받는다.
- 재개 기록에는 `자료 종류 → 시험 구분 → 최신 미처리 연도/경로 → 문항` 커서를 남긴다. 다음 실행은 이를 읽고 이어간다. 종료 보고에는 실제 검색한 구분, 비어 있던 구분, 다음 목표를 명시한다. 저장소 전체 탐색 자체가 권한·도구 장애로 불가능할 때만 정확한 장애를 보고한다.


`h2`/`h3` 폴더나 파일명만으로 과목을 추측하지 말고 실제 `standardCourse`, 교육과정/단원, 시험지명을 확인한다. 불확실한 교과 구분은 건너뛰고 명시한다. 중등은 제외한다. 시험을 앞둔 학생에게 필요한 **최신년도 2학기 기말 기출**이 최우선인 것이 이 순서의 이유다.

각 라인은 **자기 과목의 진행 상태와 작업 브랜치**만 쓰고, 서로 다른 라인이 공통 진행 JSON을 동시에 갱신하지 않는다. 같은 파일의 이미 진행 중인 작업이 확인되면 중복 수정을 하지 않는다. 원격 `main`의 최근 상태를 먼저 보고, 기록된 완료본과 `questionUid`/source fingerprint를 대조한다. 브랜치 충돌·쓰기 권한 부재·미완료 승인 작업은 건너뛰거나 `HOLD`로 기록하고 다른 라인의 변경을 덮어쓰지 않는다.

매시 시작 시각을 10분씩 벌려도 실행 종료는 보장되지 않는다. 외부 작업·렌더와 충돌할 경우 완료 예상 시간을 지어내지 말고 안전하게 중단/보류한다.

## 3. 하네스 시작 게이트: 링크 열람이 아니라 본문 읽기

1. 현재 소스와 적용할 Git commit SHA를 고정하고, `node tools/solution-upgrade-reservation/preflight.mjs --course <course>`를 실행한다. 실행기가 Node/Git을 제공하지 않으면 `docs-manifest.json`의 같은 상대 경로를 **그 Git commit에서 직접 열어** 읽고 `NOT_RUN`을 기록한다.
2. `docs-manifest.json`의 `core` 문서 전부의 실제 본문을 읽는다. `AGENTS.md`가 요구하는 직접 적용 추가 문서와 하위 `AGENTS.md`도 읽는다. 링크 존재·문서 목록 출력·요약만으로 필독을 대체하지 않는다.
3. 각 문서의 실제 SHA-256과 원문 속 적용 규칙 한 문장 이상을 `read-receipt.json`에 기록한다. Node 실행 가능한 경우 `node tools/solution-upgrade-reservation/preflight.mjs --course <course> --receipt <read-receipt.json>`이 문서 해시와 인용문이 실제 본문에 있는지 검사해야 한다. 이 검증은 **읽기 증거 검증**일 뿐 내용 이해 자체를 기계적으로 증명하지 못한다.
4. Golden 2~3개 및 관련 Negative sample을 현행 calibration 문서대로 실제 판독한다. 타인 결과를 통과 근거로 삼지 않는다.
5. 실제 source/문항/해설을 읽지 못하거나 문서 열람·교육과정 확인이 불가능하면 `PASS`가 아니라 `NOT_RUN`/`EVIDENCE_DEBT`/`HOLD`로 남기고 수정·커밋을 중단한다.

**식 전개 샘플 필독:** [`BOARD_SOLUTION_SAMPLES_CURRENT.md`](BOARD_SOLUTION_SAMPLES_CURRENT.md)의 **학생용 solution 예시 5개와 앞의 작성 원칙을 실제로 읽는다.** 이 예시는 자체 Golden/Negative sample을 대체하거나 문항의 정답·수학적 권위가 되지 않는다. 한국어 코멘트는 발상·범위·조건의 이유에만 쓰고, 중요한 계산은 실제 등호 전개로 이어라.

## 4. 예약 실행 — 학생용 수정 해설을 MD로 실제 저장 (2026-11-21 최신 지시)

이 절이 아래의 옛 JS 직접 수정/완전 검수 후 저장 방식보다 우선한다. **현재 4개 예약라인은 운영 JS를 직접 수정하지 않고 MD 초안만 저장한다.**

1. 먼저 자기 작업 브랜치(work/solution-upgrade-h1, -algebra, -calculus1, -probstat 중 담당 것)와 docs/operations/solution-upgrade-reservations/staged/과목키/ 경로를 읽어 기존 MD 진행 상태를 복원한다. 같은 문항의 DRAFT_STAGED를 중복 생성하지 않는다.
2. §2의 시험지 유형 우선 → 연도 내림차순을 유지하되, **현재 대상 버킷의 해당 과목 전체 시험지 인벤토리**를 먼저 수집한다(모든 학교/연도/하위 폴더). 실제 원본 JS의 전 문항 문제·정답·기존 해설을 빠르게 스캔하고 sourceIdentityKey/원본 blob으로 결속한다. **시험지 수·문항 수의 인위적 상한을 두지 않는다.** 전체 목록을 한 번에 못 읽으면 문항/시험지 커서를 기록한다. 다른 학교의 같은 문항 번호로 결속하지 않는다.
3. **2단계 배치:** (A) 여러 시험지를 훑어 확인된 교육과정 외 풀이, 논리 점프, 계산/조건 생략 문항을 근거와 함께 우선순위 큐에 수집한다. (B) 큐에서 **여러 문항의 학생용 수정 해설 전체를 연속 작성**하고 각각 독립으로 수학 검산한다. 등호/부등호 전개와 꼭 필요한 발상/조건 설명을 넣는다. **한 문항만 커밋하고 종료하지 않는다.** 후보가 정말 한 문항뿐이거나 외부 실행 제한이 걸린 경우에만 1건 결과가 가능하며, 그때는 전체 스캔 범위/남은 후보/제한 사유를 기록한다. 좋은 시험지는 스캔 장부에 체크하고 다음 시험지로 진행한다.
4. 담당 브랜치의 docs/operations/solution-upgrade-reservations/staged/과목키/에 **SCAN_LEDGER.md**로 시험지 인벤토리·스캔 완료/미완료·개선 후보·다음 커서를 저장한다. 실제 개선 해설은 **시험지별 MD(여러 qid 포함 가능)** 또는 문항별 MD로 여러 건 누적한다. 각 문항의 source identity/전체 풀이/검산을 독립 기록하고 GitHub create_file/update_file로 **여러 결과물을 커밋**한 뒤 원격 readback한다. 스캔 장부만 쓰고 완료했다고 주장하지 않는다.
5. MD 필수 항목: DRAFT_STAGED / NOT_PRODUCTION / REVIEW_REQUIRED; 원본 JS 경로/blob SHA/sourceIdentityKey/문항번호/답; 기존 해설의 결함; **제안 학생용 solution의 전체 수식과 풀이**; 필요한 경우 두 번째 풀이/SVG_REQUEST; 독립 확인한 수학적 사실과 실제 NOT_RUN/보류 게이트; 나중에 JS로 옮길 때 필요한 출고 검수.
6. **최종 품질 기준은 유지한다.** Golden/Negative, 원본 문제·정답 독립 검증, SVG 엔진과 이미지 대조, JS 보호 필드 diff, 문법, exam/sol/ans 학생 화면 렌더는 MD를 실제 JS에 반영하기 전 별도 QA에서 그대로 수행한다. 현재 MD 초안에 대해서는 미실행을 정확히 표기하고 최종 PASS/JS 출시/PR 병합이라 주장하지 않는다. 이미지 조건을 확인할 수 없으면 추측하지 않고 HOLD한다.
7. **전체 해당 과목 시험지 인벤토리 구축과 다건 개선 MD 작성이 한 회차의 목표다.** 20~30초가 지났다는 이유나 첫 문항 커밋 직후에 자발적으로 종료하지 않는다. 여러 후보가 확인되면 가능한 동안 계속 풀어 **여러 풀이를 저장**한다. 시간이 모자라면 진행 상태를 MD에 저장해 다음 예약이 이어받게 한다. **SAVE_BLOCKED는 MD도 실제로 쓸 수 없는 권한/근거/도구 장애일 때만** 사용한다. 결과 보고에는 해당 MD 경로, qid, 실제 커밋 링크와 남은 검증을 쓴다.

이 MD는 사용자가 명시적으로 허용한 임시 실행 초안이며, Git 운영 main에 초안만 병합하지 않는다. 원시 캡처·로그·증거는 기존 Git/Drive 분리 규칙을 따른다.

### 4-A. 학생이 중간에 멈추는 논리 점프를 없애는 작성 기준

- **수학적으로 맞는 해설과 학생이 따라갈 수 있는 해설은 다르다.** `정리하면`, `계산하면`, `대입하면`, `따라서`만으로 중요한 식 변형·발상·조건 판단을 건너뛰지 않는다. 이런 연결어 자체를 금지하는 것이 아니라, 그 앞에 필요한 계산을 실제로 보여 준다.
- 결정적인 변형에는 필요한 만큼 **괄호 전개 → 동류항 이동/묶기 → 인수분해/약분 → 조건 확인 → 결과**를 한 줄씩 쓴다. 예를 들어 `p(10-p)=q(10-q)`에서 갑자기 `p+q=10`으로 이동하지 않는다.
- 실제 학생용 전개 예: `10p-p²=10q-q² → 10p-10q=p²-q² → 10(p-q)=(p-q)(p+q)`. 이어 `p≠q`이므로 `p-q≠0`임을 밝힌 뒤 양변을 나누어 `p+q=10`을 얻는다. 부호·정의역·등호 성립·경우 배제를 결론에 쓸 때도 그 이유를 보인다.
- 식을 **왜 세웠는지**를 먼저 쉬운 말로 설명한다. 좌표 삼각형 넓이라면 기준이 되는 큰 삼각형과 빼는 부분의 밑변·높이를 써서 출발한다. 판별식·근과 계수의 관계 등에서 학생이 연결을 이해하기 어렵다면 교육과정 내 더 직접적인 방법을 주풀이로 삼는다.
- 답만 맞거나 수식이 많다는 이유로 `KEEP`하지 않는다. 해설의 핵심 전환을 학생이 이전 줄에서 재현할 수 있는지 확인한다. 반대로 학생에게 자명한 사칙연산까지 무조건 늘리지 않으며, **결정 단계 누락 0**을 목표로 적절한 판서 밀도를 유지한다.
- 판정 기록에는 특히 `학생이 멈추는 원문 구절/식`, `누락된 중간 단계`, `개선된 변형 단계`를 나란히 남긴다. 두 번째 풀이·그래프는 실질적 도움일 때만 추가하고 SVG는 §5의 엔진 인계만 한다.


### 4-B. 배치 처리량과 완료 조건

- 스캔과 개선을 혼동하지 않는다: `인벤토리 시험지 수 / 실제 전 문항 스캔 시험지 수 / 확인 문항 수 / 개선 후보 수 / 완성 solution 수 / MD 커밋 수 / 미처리 잔량`을 매회 수치로 보고한다.
- 하나의 시험지에 결함이 여러 개면 여러 문항을 한 MD에 넣어도 된다. 여러 시험지에 결함이 있으면 한 시험지만 고치고 끝내지 않는다. **후보 수보다 작성 품질이 중요**하지만, 명확한 후보가 여러 개 있는데도 한 건만 저장하면 미완료로 기록하고 다음 실행에서 즉시 잔량을 이어받는다.
- `SCAN_LEDGER.md`에 소스 경로, 원본 SHA, 각 시험지 스캔 상태(`PENDING/SCANNED/CANDIDATES/DRAFTED`), 후보 문항·사유, 다음 우선순위 커서를 남긴다. 파일이 커지면 시험지별/연도별 장부로 분할하되 중복이 없게 한다. **장부만 작성한 실행은 해설 개선 완료가 아니다.**
- 전체 대상 수가 실행 시간보다 크면 **여러 시험지를 스캔하고 다건 풀이를 작성할 만큼 균형을 잡아** 중간 커밋한다. 근거 없는 '전체 스캔 완료' 또는 시간을 보장한 수치를 주장하지 않는다. 모든 항목을 실제로 읽은 범위만 완료로 표시한다.

### 4-C. 시험지당 '첫 후보 1건' 중단 금지 — 전 문항 판정

**시험지 하나를 선택했으면 1번부터 마지막 문항까지 문제·정답·현재 solution을 실제로 읽고 각 문항을 `KEEP / UPGRADE / HOLD / UNREAD`로 판정한다.** 특정 문항에서 결함을 찾았다고 곧바로 그 문제만 작성하고 다음 시험지로 넘어가지 않는다. 하나의 시험지에서 확인되는 모든 개선 후보의 qid·중간 논리 점프·제안 방식까지 한 번에 수집한다. 수학적으로 맞는 풀이도 중요한 식 전개/조건 설명이 빠졌으면 UPGRADE이다.

- **`PAPER_SCAN_COMPLETE`**: 그 시험지의 전체 문항 수와 모든 qid별 실제 판정 및 근거가 장부에 존재할 때만. JSON 파싱/키워드 탐지만으로 이 상태를 선언하지 않는다.
- **`PAPER_DRAFT_COMPLETE`**: UPGRADE 대상으로 선정한 문항의 학생용 새 풀이 본문을 *전부* MD로 저장·readback했을 때만. 작성 중인 문항이 남았으면 `DRAFT_IN_PROGRESS`로 표시하고 **다음 예약에서 같은 시험지를 우선 재개**한다.
- 1개 시험지에서 후보가 1개뿐이라고 보고하려면 전체 문항별 판정 표와 나머지 KEEP/HOLD 근거를 남긴다. **개수 채우기를 위해 좋은 풀이를 억지로 고치지는 않는다.** 반대로 5개, 10개가 발견되었는데 1개만 썼다면 해당 시험지를 완료했다고 보고할 수 없다.
- 예약 보고 형식: **시험지별 문항 총수 / 실제 검토 수 / UPGRADE 수 / MD 작성 수 / 미작성 후보 qid**. 후보가 여러 개인 시험지는 qid를 나열하고 실제 커밋된 수량을 밝힌다. 여러 시험지를 훑더라도 먼저 선별한 시험지의 미완료 개선 후보를 유실하지 않는다.

## 5. SVG 엔진 플랜 인계 게이트 (조건부)

그림이 필요하다고 판단한 문항에서만 `--svg`를 추가하여 시작 문서와 해당 그래프/도형 형태 가이드를 실제로 읽는다. SVG plan 스키마는 `archive/tools/geometry-equation/production/AUTHOR_GUIDE.md`가 정본이며, 읽지 않은 채 `plan.json` 구조를 지어내지 않는다. 기존 `ops/golden`의 같은 형태 통과 예시를 참고한다.

- 해설 변경 뒤 **현재 문항·정답·수학적 독립 검산이 일치한 사실**로 `item.json`(sourcePath/ordinal), `plan.json`, 필요시 `publish.json` 초안을 구성한다.
- 그래프에서 표현해야 할 함수식·정의역·교점·점근선·부호·영역·경계, 사용된 주/보조 풀이, 학습 목적, 화면에 보여줄 실제 값을 분명히 한다.
- 엔진 plan을 썼으면 `node archive/tools/geometry-equation/ops/claude-batch/plan-lint.cjs <plan.json>`을 실행할 수 있을 때 실행하고 결과를 남긴다. 계획 검증만으로 그림 생성이나 SVG 검수가 완료된 것이 아니다.
- plan 형식·수학적 사실이 확정되지 않으면 `SVG_REQUEST` 수준의 인계 메모만 작성한다. 이 경우 엔진 호환 `plan.json`을 만들었다고 주장하지 않는다.
- 실제 SVG 생성, 렌더, PNG 시각 검수, 게시와 figure ledger 변경은 기존 SVG 엔진 라인의 권한이다. 해당 문항의 그림 작업은 완료 전까지 OPEN으로 남긴다.

## 6. 안전한 시작·중단

- Git 쓰기 권한 또는 브랜치 준비가 없으면 운영 JS를 변경하지 않고 MD 작성/커밋이 가능한지 확인한다. MD마저 실제로 저장할 수 없을 때만 SAVE_BLOCKED 사유를 보고한다. 저장하지 못한 결과를 완료/커밋으로 보고하지 않는다.
- 동일한 source identity가 이미 완료됐거나 다른 작업자가 진행 중이면 중복 수정하지 않는다. 기존 예약 라인과 Drive 이관 라인의 브랜치를 건드리지 않는다.
- 교육과정 프로필/정답/SVG 필수 조건이 충돌하면 안전하게 `HOLD` 처리하고 정확한 문제를 보고한다.
