# 고등 학생용 해설 업그레이드 — 예약 4라인 공통 하네스

> 적용: 고1·대수·미적분Ⅰ·확률과 통계의 기존 기출/유사/교과서 JS. 이 문서는 공통 진입점이며 현행 `AGENTS.md`, `docs/rules/RULEBOOK_CURRENT.md`와 해설·SVG 영역의 정본을 대체하지 않는다. 규칙이 충돌하면 상위 정본과 사용자의 최신 지시를 따른다.

## 1. 고정 목표와 책임

- 목표는 **기존 해설 중 학생이 따라 풀기 어려운 문항을 찾아 필요한 것만 개선**하는 것이다. 모든 해설을 재작성하거나 수정 건수를 목표로 하지 않는다.
- **2026-11-21 최신 사용자 변경: 시험지 1장 심층 판정·MD 우선.** 한 예약 실행은 **우선순위 시험지 한 장만** 붙잡고, 모든 문항의 문제·정답·기존 solution을 실제 읽어 **KEEP / UPGRADE / HOLD / UNREAD의 구체적 근거**를 남긴다. 개선 문항은 그 시험지에서 필요한 만큼 전부 찾고 실제 학생용 새 풀이를 MD로 작성한다. 한 번에 못 끝나면 **다음 예약에서도 같은 시험지부터** 이어간다. 한 장을 제대로 끝내기 전 다른 시험지로 넘어가지 않는다. JS 출고는 후속 검수 단계다.
- 우선 결함: 교육과정 외 개념, 잘못된 수학, 핵심 논리 점프, 계산·조건·경우 누락, 불필요하게 어려운 풀이, 학생이 이해하기 어려운 설명. [학생용 해설 정본](../../rules/01_CANONICAL/JS아카이브_학생용해설_운영규칙_v1.md)의 코드와 게이트를 적용한다.
- `solution`은 학생이 재현할 수 있는 **작은 칠판** 흐름으로 쓴다. 두 번째 풀이가 실질적으로 이해를 돕는 경우에만 같은 `solution` 안에 자연스럽게 추가한다. 현행 JS에 없는 상세해설 필드를 임의로 만들지 않는다.
- `content`, `choices`, `answer`, 문제 `image`, 기존 승인 메타, 기존 `solutionImage`는 기본 보호한다. 오류를 찾으면 별도 `HOLD`/defect로 남긴다. 승인된 `solution` 변경에서 요구하는 원본 고정 해시 갱신 등은 `common.md`의 공식 절차를 따른다.
- **새 SVG·손 SVG·우회 스크립트는 절대 만들지 않는다.** 해설이 수학적으로 검증된 후 그림이 필요하면 SVG 엔진용 수학 사실과 plan을 작성하고 별도 엔진 라인으로 넘긴다. 엔진 렌더·PNG 독립 검수·게시는 SVG 라인이 담당한다. 필수 시각자료가 미완료면 시험지의 최종 시각 PASS를 선언하지 않는다.
- 기존 source identity와 전체 문항 denominator를 확정한다. `id`/문항 번호만으로 다른 시험지의 문항을 결속하지 않는다.

## 2. 네 작업자·전역 과목 순서 (Asia/Seoul)

**네 예약은 이제 과목별 전용 라인이 아니라 공통 대기열 작업자**다. 제어 규칙의 정본은 [`GLOBAL_QUEUE_CURRENT.md`](GLOBAL_QUEUE_CURRENT.md)이며, 반드시 실제 본문을 읽고 실행한다.

| 매시 시작 | lane ID | MD 저장 브랜치 |
| --- | --- | --- |
| 10분 | `lane10` | `work/solution-upgrade-lane-10-20261121` |
| 20분 | `lane20` | `work/solution-upgrade-lane-20-20261121` |
| 30분 | `lane30` | `work/solution-upgrade-lane-30-20261121` |
| 40분 | `lane40` | `work/solution-upgrade-lane-40-20261121` |

**과목 전체 순서:** **① 고1 공통수학1·2 → ② 대수(수학Ⅰ) → ③ 확률과 통계 → ④ 미적분Ⅰ(수학Ⅱ) → ⑤ 미적분Ⅱ(구 미적분 대응) → ⑥ 기하.** 한 과목의 모든 자료 종류·시험 구분이 완료될 때만 다음 과목으로 넘어간다. 같은 과목 단계에서 다른 작업자가 서로 다른 시험지를 담당할 수 있지만 **같은 시험지를 중복 작업할 수 없다.**

각 과목 안의 자료 종류: **기출(original) → 유사(similar) → 유형 → 교과서 → 문제집**. 기출/학기별 유사는 **2학기 기말 전 연도 최신→과거 → 1학기 중간 전 연도 최신→과거 → 1학기 기말 전 연도 → 2학기 중간 전 연도** 순서다. 한 연도의 네 시험을 먼저 끝내지 않는다. 없는 버킷은 실제 검색 결과를 남기고 다음 버킷으로 폴백하며, 다음 과목/시험 구분으로 조기 이동하지 않는다.

`h2`/`h3` 폴더나 파일명만으로 과목을 추측하지 말고 실제 `standardCourse`, 교육과정/단원, 시험지명을 확인한다. 대수↔수학Ⅰ, 미적분Ⅰ↔수학Ⅱ, 미적분Ⅱ↔구 미적분 등 개정 전후 명칭을 살핀다. 불확실한 경우 `CLASSIFICATION_HOLD`로 기록하고 사용자 지시 없이 임의 분류하지 않는다. 중등 제외.

**점유 규칙:** 공유 `work/solution-upgrade-global-queue-20261121` 브랜치의 `claims/<courseKey>/<sourceBlobSha>.json`을 **GitHub `create_file`로 독점 생성하고 readback에 성공한 시험지만** 시작한다. 충돌/이미 존재 오류가 나면 덮어쓰지 않고 대기열을 다시 읽는다. 다른 작업자의 `IN_PROGRESS` 시험지는 건드리지 않는다. 이전에 자신이 점유한 미완료 시험지를 가장 먼저 재개한다. 완료·진행 상태 변경은 claim 파일의 현재 blob SHA를 확인한 후 owner만 한다. 한 번에 시험지 한 장을 끝까지 읽는 §4 규칙은 유지한다.

매시 시작 시각을 10분씩 벌려도 실행 종료·비중복이 보장되지 않는다. **점유 파일 성공 여부**가 비중복 판단의 근거이고, 10분 간격 자체는 잠금이 아니다. 작업자가 모두 점유한 시험지만 남아 있으면 조기 다음 과목 진입이 아니라 `WAIT_FOR_CLAIMS`로 보고한다.

## 3. 하네스 시작 게이트: 링크 열람이 아니라 본문 읽기

1. 현재 소스와 적용할 Git commit SHA를 고정하고, `node tools/solution-upgrade-reservation/preflight.mjs --course <course>`를 실행한다. 실행기가 Node/Git을 제공하지 않으면 `docs-manifest.json`의 같은 상대 경로를 **그 Git commit에서 직접 열어** 읽고 `NOT_RUN`을 기록한다.
2. `docs-manifest.json`의 `core` 문서 전부의 실제 본문을 읽는다. `AGENTS.md`가 요구하는 직접 적용 추가 문서와 하위 `AGENTS.md`도 읽는다. 링크 존재·문서 목록 출력·요약만으로 필독을 대체하지 않는다.
3. 각 문서의 실제 SHA-256과 원문 속 적용 규칙 한 문장 이상을 `read-receipt.json`에 기록한다. Node 실행 가능한 경우 `node tools/solution-upgrade-reservation/preflight.mjs --course <course> --receipt <read-receipt.json>`이 문서 해시와 인용문이 실제 본문에 있는지 검사해야 한다. 이 검증은 **읽기 증거 검증**일 뿐 내용 이해 자체를 기계적으로 증명하지 못한다.
4. Golden 2~3개 및 관련 Negative sample을 현행 calibration 문서대로 실제 판독한다. 타인 결과를 통과 근거로 삼지 않는다.
5. 실제 source/문항/해설을 읽지 못하거나 문서 열람·교육과정 확인이 불가능하면 `PASS`가 아니라 `NOT_RUN`/`EVIDENCE_DEBT`/`HOLD`로 남기고 수정·커밋을 중단한다.

**식 전개 샘플 필독:** [`BOARD_SOLUTION_SAMPLES_CURRENT.md`](BOARD_SOLUTION_SAMPLES_CURRENT.md)의 **학생용 solution 예시 5개와 앞의 작성 원칙을 실제로 읽는다.** 이 예시는 자체 Golden/Negative sample을 대체하거나 문항의 정답·수학적 권위가 되지 않는다. 한국어 코멘트는 발상·범위·조건의 이유에만 쓰고, 중요한 계산은 실제 등호 전개로 이어라.

## 4. 예약 실행 — 한 시험지 전 문항의 이유가 남는 심층 감사 (2026-11-21 최신 지시)

이 절은 **이전의 다시험지 빠른 스캔/1~3장 선별/다건 배치 처리량 지시보다 우선**한다. 현재 4개 예약 작업자는 **각자 점유한 실제 시험지 한 장**만 깊이 판정하고, 운영 JS가 아니라 MD 감사 기록과 완성 개선 해설을 **작업자별 브랜치**에 저장한다.

### 4-A. 시험지 고정과 재개

1. 먼저 §2의 **공유 점유 브랜치**에서 자신의 lane ID가 소유한 `IN_PROGRESS` claim을 찾고, 자신의 **lane 작업 브랜치**의 `docs/operations/solution-upgrade-reservations/staged/<courseKey>/` MD를 연다. **미완료 시험지를 최우선 재개**한다. 초안 하나가 있다고 완료가 아니다.
2. 미완료 점유가 없을 때에만 §2의 **전역 과목 우선순위와 시험 구분 순서**로 미점유 시험지 한 장을 선택한다. `GLOBAL_QUEUE_CURRENT.md`의 **독점 claim 생성·readback**을 먼저 수행한다. 다른 lane과 충돌하면 다음 미점유 후보를 선택하고, 점유가 확정되기 전에는 해설 작업을 시작하지 않는다. source 경로·blob·문항 수를 고정한다.
3. 기존 유사한 원본(동일 학교/문항 번호)이 아니라 **고정한 실제 JS의 그 문항**을 읽어야 한다. 원본 `standardCourse`와 교육과정 범위를 확인하고 그래프/도형 조건을 실제 볼 수 없으면 그 문항을 `HOLD`로 남긴다.

### 4-B. 문항마다 읽은 흔적·판정 이유를 기록

새 필독 형식은 [`DEEP_QUESTION_AUDIT_TEMPLATE_CURRENT.md`](DEEP_QUESTION_AUDIT_TEMPLATE_CURRENT.md)다. **이 파일을 실제 읽고** 한 시험지의 `<sourceKey>_DEEP_AUDIT.md`에 문항 1번부터 끝까지 하나씩 기록한다.

각 문항의 **필수 5가지**:

1. **원문 읽은 흔적:** qid/소스 식별자, 원문 조건의 실제 수치·식·범위, 원본 정답, **기존 solution의 결정적 식/문장 1~3줄을 원문 그대로**, 그래프가 있다면 실제 판독 상태.
2. **해설의 핵심 연결:** 문제에서 어떤 첫 식을 세우는지 → 그다음 어떤 변형·조건·경우 구분을 하는지 → 어떻게 답이 나오는지. 독립 검산 결과와 학생용 설명의 충분함을 구분한다.
3. **KEEP 이유:** 기존 풀이의 **어떤 특정 등식**이 핵심 단계를 설명하고, 누락된 범위·부호·경우가 왜 없는지 설명한다. `적절함`/`문제 없음`/`충분히 친절함`만 쓰는 기록은 무효.
4. **UPGRADE 이유:** 학생이 멈추는 **정확한 원문 전환 A→B**, 빠진 중간 계산·논리·교육과정 외 개념, 왜 재현하기 어려운지와 **바꿀 수식 중심 접근**을 적는다. **수정 학생용 solution 전체**를 그 문항 아래에 실제 작성하고 독립 검산한다. 두 번째 풀이가 더 쉬울 때만 추가한다.
5. **HOLD/UNREAD 이유:** 그림·정답·문제 원본 접근 불가 등 정확한 결손과 재개 경로를 적는다. 읽지 않은 문항을 KEEP으로 세지 않는다.

**중요:** 문항 수십 개를 JSON으로 파싱한 것이 수십 해설을 읽었다는 증거가 아니다. 키워드·문장 길이만으로 KEEP/UPGRADE를 정하지 않는다. 각 문항의 `문제 조건 + 기존 solution 인용 + 구체적 판정 이유`가 없으면 읽기 완료로 간주하지 않는다.

### 4-C. 끝까지 쓰는 학생용 해설 기준

- **문장 수가 아니라 중간 등호의 밀도가 친절함의 기준**이다. 학생이 `정리하면`, `계산하면`에서 멈추는 전환은 `괄호 전개 → 항 이동 → 인수분해/약분 → 0으로 나누지 않는 조건 → 범위/부호/경우 확인 → 답`을 실제 식으로 이어 쓴다.
- 식을 왜 처음 세우는지는 필요한 한두 문장으로 설명한다. 정의역/역함수/합성함수/그래프 문제에서는 **무엇을 미지수로 놓았는지, 어느 그래프의 교점인지, 해를 다시 원래 변수로 찾아야 하는지**를 잊지 않는다.
- 이차방정식·근과 계수 관계 등 간결한 방법을 쓰더라도 **그 방법이 적용되는 조건을 학생이 따라갈 수 있어야** 한다. 교육과정 외 풀이가 발견되면 교육과정 안의 직접적인 풀이로 교체한다.
- 새 SVG는 만들지 않는다. 그림이 더 친절한 경우에만 §5의 SVG 엔진 계획을 별도 인계한다. 기존 그림을 확인 못 했으면 `VISUAL_HOLD`로 남기고 가짜 좌표·시각 PASS를 만들지 않는다.

### 4-D. 파일 저장·중단·완료 게이트

1. 한 시험지의 감사 MD에 문항별 **KEEP/UPGRADE/HOLD/UNREAD** 섹션을 만든다. 한 번에 전 문항을 못 끝낼 때도 **이미 읽은 qid와 실제 기록을 커밋**하고 `next_qid`·미작성 UPGRADE 목록을 남긴다. 다음 예약은 **같은 시험지의 미완료 항목부터** 이어간다.
2. 원본 `solution`이 충분하면 왜 유지하는지를 쓰고 별도 억지 재작성을 하지 않는다. 개선 후보가 1개뿐이라면 다른 모든 문항의 구체적인 KEEP/HOLD 기록이 있어야 그 주장을 인정한다.
3. UPGRADE인 모든 문항의 **복사 가능한 학생용 전체 풀이**를 감사 MD 또는 연결된 문항별 MD에 기록한다. 해당 시험지의 다른 후보를 누락하지 않는다. 여러 qid를 한 MD에 저장해도 각각 원본 ID/수학 검산/후속 게이트를 분리한다.
4. GitHub **본인 lane 작업 브랜치**에 MD를 실제 `create_file/update_file`로 커밋하고 **원격 readback**한다. `SCAN_LEDGER.md`에는 그 시험지 상태와 다음 cursor만 요약한다. 공유 claim은 owner만 현재 SHA를 확인해 갱신한다. 원본 JS·`content/choices/answer`·기존 SVG·승인 메타·main을 수정하지 않는다.
5. `EXAM_AUDIT_COMPLETE`: 총 문항 전체를 실제 읽고, 각 문항에 원문 근거와 판정 이유가 저장된 때만. `EXAM_DRAFT_COMPLETE`: 모든 UPGRADE의 학생용 수정 solution이 실제 저장·검산된 때만. **두 조건 모두 충족하기 전 다음 시험지로 이동하지 않는다.** `HOLD`의 추가 확인 항목은 정확히 공개하고 출고 PASS로 오인하지 않는다.
6. 실행 제한으로 중단되면 `IN_PROGRESS`와 남은 문항·이유를 저장한다. `SAVE_BLOCKED`는 실제 소스/쓰기 권한/도구 장애로 MD 저장조차 할 수 없을 때만. 원시 문제/정답 불확실성은 `HOLD`. **한두 문항만 보고하고 전체 시험지 완료라고 말하지 않는다.**
7. 최종 운영 JS 반영 전에 별도 Golden/Negative, 독립 정답·교육과정 검증, 관련 SVG 엔진/그림 대조, 원본 보호 필드 diff·문법·학생 화면 exam/sol/ans 렌더를 전부 수행한다. MD 초안 단계에서는 미실행을 `NOT_RUN`으로 정확히 적고 PASS/출고/병합이라고 말하지 않는다.

**매회 보고:** 시험지 한 장의 파일명/전체 문항 수/증거 있는 개별 판정 문항 수/KEEP·UPGRADE·HOLD·UNREAD 수/학생용 완성 해설 qid·수/남은 qid/실제 MD 링크·커밋/다음 재개 위치. **인벤토리 수량은 스캔 완료 문항 수로 세지 않는다.**

기존에 만든 2025 팔마고 스캔 장부와 개별 MD는 **예비 자료**다. 새 템플릿의 원문 인용·조건별 판정 근거가 완비되어 있는지 재확인하기 전 `EXAM_AUDIT_COMPLETE`를 부여하지 않는다.

## 5. SVG 엔진 플랜 인계 게이트 (조건부)

그림이 필요하다고 판단한 문항에서만 `--svg`를 추가하여 시작 문서와 해당 그래프/도형 형태 가이드를 실제로 읽는다. SVG plan 스키마는 `archive/tools/geometry-equation/production/AUTHOR_GUIDE.md`가 정본이며, 읽지 않은 채 `plan.json` 구조를 지어내지 않는다. 기존 `ops/golden`의 같은 형태 통과 예시를 참고한다.

- 해설 변경 뒤 **현재 문항·정답·수학적 독립 검산이 일치한 사실**로 `item.json`(sourcePath/ordinal), `plan.json`, 필요시 `publish.json` 초안을 구성한다.
- 그래프에서 표현해야 할 함수식·정의역·교점·점근선·부호·영역·경계, 사용된 주/보조 풀이, 학습 목적, 화면에 보여줄 실제 값을 분명히 한다.
- 엔진 plan을 썼으면 `node archive/tools/geometry-equation/ops/claude-batch/plan-lint.cjs <plan.json>`을 실행할 수 있을 때 실행하고 결과를 남긴다. 계획 검증만으로 그림 생성이나 SVG 검수가 완료된 것이 아니다.
- plan 형식·수학적 사실이 확정되지 않으면 `SVG_REQUEST` 수준의 인계 메모만 작성한다. 이 경우 엔진 호환 `plan.json`을 만들었다고 주장하지 않는다.
- 실제 SVG 생성, 렌더, PNG 시각 검수, 게시와 figure ledger 변경은 기존 SVG 엔진 라인의 권한이다. 해당 문항의 그림 작업은 완료 전까지 OPEN으로 남긴다.

## 6. 안전한 시작·중단

- Git 쓰기 권한 또는 브랜치 준비가 없으면 운영 JS를 변경하지 않고 MD 작성/커밋이 가능한지 확인한다. MD마저 실제로 저장할 수 없을 때만 SAVE_BLOCKED 사유를 보고한다. 저장하지 못한 결과를 완료/커밋으로 보고하지 않는다.
- 동일한 source identity가 이미 완료됐거나 다른 작업자가 진행 중이면 중복 수정하지 않는다. 기존 예약 라인과 Drive 이관 라인의 브랜치를 건드리지 않는다.
- 교육과정 프로필/정답/SVG 필수 조건이 충돌하면 안전하게 `HOLD` 처리하고 정확한 문제를 보고한다.
