## 1. 각 문항의 필수 기록 형식 — 1번부터 마지막까지 반복

### QNN — KEEP | UPGRADE | HOLD | UNREAD

1. **원본 확인 / 읽은 흔적**
   - qid, `sourceIdentityKey` 원문 값(없으면 NOT_PRESENT), source ordinal, 원본 blob SHA:
   - 핵심 문제 조건을 원문 수치·식·범위 그대로 빠짐없이 적기 (조건이 하나뿐이면 그대로 하나, 임의 추가 금지):
   - 원본 정답:
   - 기존 `solution`에서 결정적인 **실제 식/문장 1~3줄**을 정확히 발췌:
   - 관련 그래프/그림을 판독했는지, 그 자료와 좌표/부호/경계:
2. **해설의 핵심 경로**
   - 학생이 처음 세워야 할 식 → 핵심 변형 → 경우/정의역/부호 확인 → 답의 순서로 기존 풀이가 연결되는지 적는다.
   - 독립 검산한 사실과 방법(정답이 맞는지의 확인 vs 기존 설명이 친절한지의 판단은 구분).
3. **판정과 구체적 이유**
   - **KEEP**: 기존 해설의 어느 실제 식이 결정적인 변형을 보여 주는지, 조건/경우 누락이 왜 없는지. `짧아서 쉬움`, `충분함`, `문제 없음` 같은 추상 문구만 쓰면 무효.
   - **UPGRADE**: 학생이 멈추는 **정확한 원문 전환 A→B**, 빠진 중간식·조건·교육과정 밖 개념, 왜 학생이 해당 변형을 재현하기 어려운지, 바꿀 주풀이/두 번째 풀이 선택 이유. 문장이 아닌 **완성된 수정 해설 전체**를 바로 아래에 포함한다.
   - **HOLD**: 그림·원본·정답·교육과정·충돌 정보 중 무엇을 실제로 확인할 수 없었는지, 해결에 필요한 문서/이미지/담당 엔진을 구체적으로 적는다.
   - **UNREAD**: 실제 문항·solution을 못 읽은 경우다. 판정/완료 수에 포함하지 않고 다음 실행에서 반드시 재개한다.
4. **UPGRADE일 때만 실제 학생용 solution (복사해 JS에 옮길 수 있는 전체 풀이)**
   - 왜 첫 식을 세우는지 한두 문장.
   - 등호/부등호로 식을 **한 줄씩** 전개. 생략된 계산, 나눌 수 있는 조건, 정의역·부호·등호 성립 조건, 최종 답.
   - 필요하면 두 번째 풀이. 그림은 만들지 말고 `SVG_REQUEST`와 엔진 계획 인계.
   - 독립 대입/역검산 및 남은 출고 검증(`NOT_RUN`) 기록.
5. **현재 상태**: `READ_EVIDENCED` / `DRAFT_STAGED` / `VISUAL_HOLD` / `QA_NOT_RUN` 등. 실물 파일 readback/커밋 URL.

## 2. 현행 원문에 맞춘 판정 기록 예시

### 예시 A — KEEP (2025 팔마고 22번: 역함수와 합성함수)

- 문제: `f(x)=1/2 x-1/2`, `g(x)=4x+7`; (1) 역함수 (2) `f⁻¹∘h=g`에서 일차함수 h를 찾음.
- 기존 풀이의 실제 핵심: `2y=x-1` → `x=2y+1`, 이어 `(f⁻¹∘h)(x)=2(ax+b)+1=2ax+2b+1`, `2a=4`, `2b+1=7`.
- 판정: **KEEP(예비)**. 역함수의 변수 교환, 합성함수의 전개, 계수 비교가 모두 식으로 나와 있다. 2a=4에서 a=2, 2b+1=7에서 b=3을 구하는 단계는 학생이 바로 이어갈 수 있는 일차방정식이다. 조건 x∈실수/일차함수도 충족. 새 서술을 늘려도 결정적 빈틈이 줄지 않음.
- 그림 요구 없음. 최종 Golden/학생 화면 검수는 **NOT_RUN**이므로 운영 PASS 아님.

### 예시 B — UPGRADE (2025 팔마고 21번: 평균 속력)

- 문제: 100 km/h로 12분, 이어 70 km/h로 x시간 이동. 평균 속력 y, x의 구간 0.8~5.8에서 최댓값·최솟값.
- 기존 해설의 실제 전환: `y=(70x+20)/(x+1/5)` → **`이를 정리하면 y=70+6/(x+1/5)`**.
- 판정: **UPGRADE**. 이 유리식 변형이 증가/감소 판정의 핵심인데, 분자를 어떻게 나눴는지 해설에서 생략했다. 친절하게 만드는 핵심은 설명 문장을 늘리는 것이 아니라 다음 등식을 넣는 것:

\[
\begin{aligned}
70x+20&=70x+14+6=70\left(x+\frac15\right)+6,\\
y&=\frac{70\left(x+\frac15\right)+6}{x+\frac15}
=70+\frac6{x+\frac15}.
\end{aligned}
\]

- **완성된 대체 solution**과 x 양끝 대입 검산은 [기존 실제 MD](staged/h1/BATCH_2025_2final_20261121_01.md)에 있다. 이 예시의 몇 줄만 복사하여 완료로 처리하지 말 것.

## 3. 시험지 종료 보고와 허용 상태

- 시험지 총 문항 수 / **실제로 읽은 문항 수** / KEEP / UPGRADE / HOLD / UNREAD (합이 총 문항 수와 같아야 함).
- 각 KEEP/UPGRADE/HOLD에는 위 **원문 사실+기존 solution 발췌+판정 이유**가 있는지 전수 확인.
- 모든 UPGRADE qid에 **완성 수정 풀이와 독립 검산**이 기록되었는지.
- 관련 문제그림이 필수인 문항은 실제 확인 여부. 못 보면 HOLD, 임의 좌표·그래프 생성 금지.
- `EXAM_AUDIT_COMPLETE`: 모든 문항을 읽고 판정했으며 근거 기록이 빠진 문항이 없을 때만. HOLD는 열어 둔다.
- `EXAM_DRAFT_COMPLETE`: 모든 UPGRADE 문항의 실제 전체 수정 해설이 커밋·readback됐을 때만. HOLD/후속 QA는 별도 표시.
- `IN_PROGRESS`: 위 조건 미충족. 동일 시험지를 **다음 예약 실행에서 우선 재개**한다.
- **초안만 운영 main에 병합 금지.** JS·정답·보기·SVG를 변경하지 말고 후속 Golden/Negative·수학·SVG/렌더 QA에서 따로 출고한다.

## 4. 금지되는 가짜 '읽은 흔적'

- `정답 일치`, `기존 해설 적절`, `짧지만 이해 가능`, `문제 없음`만 적는 KEEP.
- 문제를 실제로 읽지 않고 문항번호·solution 길이·특정 연결어 개수로 판정.
- 다른 연도/학교의 같은 번호 문항에서 가져온 근거.
- 원문에 없는 수식·조건·그림 정보 발명.
- `검토 완료 20/20`이라고 쓰면서 실제로는 대표 2문항만 기록.
- 후보를 고르는 데 모든 시간을 쓰고 완성 개선 MD 없이 종료한 것을 '해설 업그레이드 완료'라 보고.
