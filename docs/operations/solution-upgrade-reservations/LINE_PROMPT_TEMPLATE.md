# 예약 작업 공통 프롬프트 — 실행할 때 과목 변수만 바인딩

다음 문구는 `course`만 바꿔 4개의 매시간 독립 예약에 사용한다. 소스/해설/그림의 실제 작업을 수행할 수 없으면 불완전한 성공 보고 대신 `NOT_RUN`·`SAVE_BLOCKED`를 기록한다.

```text
icefoxtail/AP------ 저장소의 고등 학생용 기존 해설 업그레이드 라인이다. 담당 과목은 <COURSE_LABEL>, course key는 <COURSE_KEY>이다. 한 번 실행할 때 해당 과목의 아직 처리되지 않은 기출·유사·교과서 시험지 정확히 1개를 맡는다. 중등은 건드리지 않는다.

작업 시작 시 현재 Git main의 docs/operations/solution-upgrade-reservations/HARNESS_CURRENT.md와 docs-manifest.json, tools/solution-upgrade-reservation/preflight.mjs의 실제 본문을 먼저 읽고, 하네스에 지정된 필독 문서 원문 전체와 Golden/Negative 샘플을 읽고 영수증을 남겨라. 링크만 확인하거나 예전 대화 요약으로 대체하지 마라. 하네스 파일이 없거나 필수 문서를 읽을 수 없으면 임의의 일반 규칙으로 작업하지 말고 정확한 장애를 보고하라.

실제 JS 원본의 문항·정답·해설·이미지를 qid별로 확인하고 SOURCE↔SOLUTION identity를 결속하여 모든 문항에 KEEP/UPGRADE/HOLD 및 근거를 부여한다. 교육과정 밖 풀이, 결정적인 논리 점프, 이유 없는 공식 도입, 계산/조건/경우 생략, 학생에게 불친절한 해설만 개선한다. KEEP 문항은 바꾸지 않는다. UPGRADE는 학생이 재현할 수 있는 작은 칠판 흐름으로 solution만 최소 수정하고, 더 쉬운 대표 풀이를 선택한다. 정말 교육적 가치가 있을 때만 다른 풀이를 함께 보여 준다. 문제, 보기, 정답, 기존 그림과 승인 메타는 보호한다.

SVG/그래프가 학생 이해에 필요하면 해설을 독립 검산한 후 하네스의 조건부 SVG 문서와 AUTHOR_GUIDE 및 형태별 guide/Golden을 실제 읽고 엔진용 item/plan/publish 초안을 작성한다. SVG 파일은 직접 생성하지 말고 엔진 라인에 인계한다. 문서와 형식 검증 없이 plan.json이라고 주장하지 않는다. 필수 그림의 실제 렌더·검수가 끝나기 전에는 해당 시각 게이트를 PASS로 닫지 않는다.

해설 업그레이드 후 필수 수학·교육과정·동일성·보호 필드·렌더 검증을 수행하고, 자기 과목 브랜치에 저장한다. 다른 라인의 작업·브랜치·공유 데이터를 덮어쓰지 말고 main에 직접 커밋하지 않는다. 쓰기 권한이나 검증 환경이 없으면 추측으로 완료 처리하지 않는다. 파일/문항별 근거, 수정 결과, SVG 인계, 검사 상태, 실제 commit/PR 링크를 간결히 보고한다. 처리한 시험지는 상태를 지속 저장하여 다음 실행에서 다시 선택하지 않는다.
```

## 실행 확인

1. 위 Git 문서가 실제 원격에 존재하는지 URL readback 한다.
2. 예약별 시간대 `Asia/Seoul`, `FREQ=HOURLY`, 분 단위를 확인한다.
3. 첫 실행은 정본 읽기, 수정 필드 차이, Git 쓰기 및 실제 검증 증거를 중심으로 점검한다.
4. Git 쓰기 경로가 실제로 불가하면 해당 라인을 무의미하게 반복 실행하지 말고 운영자에게 장애를 알린다.
