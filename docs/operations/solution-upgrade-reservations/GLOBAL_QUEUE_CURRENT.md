# 고등 해설 심층감사 — 4개 예약창 공통 대기열 및 시험지 점유 규칙

> 2026-11-21 최신 사용자 지시. **네 개 예약창은 더 이상 특정 과목 전용이 아니다.** 10·20·30·40분 창 모두 동일한 과목 우선순위를 공유한다. **한 시점에는 시험지 하나만 처리하지만, 전 문항 감사·완성 풀이 MD·claim 완료 직후 같은 실행에서 다음 시험지로 이동해 계속 반복한다.** 원본 JS 수정이 아니라 별도 작업 브랜치에 MD 감사와 완성 풀이를 저장한다. 출고/운영 병합은 후속 QA.

## 1. 변경 불가 전역 우선순위

**과목 전체 순서 (각 과목을 끝낸 뒤 다음 과목):**

1. `h1` — **고1 공통수학1·2**
2. `algebra` — **대수** (2015 수학Ⅰ 대응 포함)
3. `probstat` — **확률과 통계**
4. `calculus1` — **미적분Ⅰ** (2015 수학Ⅱ 대응 포함)
5. `calculus2` — **미적분Ⅱ** (2015 미적분 대응 포함; 실제 소스 교육과정 확인)
6. `geometry` — **기하**

각 과목 안에서는 **기출(original) → 유사(similar) → 유형 → 교과서 → 문제집** 순서. 기출과 학기별 유사는 시험 구분을 연도보다 먼저 비교한다: **2학기 기말(최신→과거 전 연도) → 1학기 중간(최신→과거 전 연도) → 1학기 기말 → 2학기 중간**. 해당 과목의 시험 구분이 실제로 없다면 다음 구분으로 자동 폴백한다. 학교/연도 하나의 파일 부재가 버킷 전체 부재를 뜻하지 않는다.

**과목 단계는 섞지 않는다.** 고1이 전체 자료 종류까지 다 끝나지 않았다면 대수로 갈 수 없다. 단, **같은 고1 단계 안에서 서로 다른 시험지**는 점유가 겹치지 않을 때 다른 예약창에서 동시에 감사를 진행할 수 있다. 상위 시험 구분의 시험지가 미완료라면 하위 시험 구분이나 다음 과목은 대기한다.

`archive/exams/original/high/` 등 실제 현행 JS에서 교육과정/단원/`standardCourse`를 읽어 과목을 판정한다. 폴더 `h2/h3`나 파일명만으로 대수·미적분Ⅰ·미적분Ⅱ·기하를 판단하지 않는다. 특히 교육과정 개정 전후 과목 별칭을 교차 확인한다. 애매한 문항은 제외로 단정하지 말고 `CLASSIFICATION_HOLD`에 근거를 남긴다. 중등은 제외한다.

## 3. 시험지 점유(Claim) — 중복 시작 방지

1. 각 창은 **자신의 기존 `IN_PROGRESS` claim이 있으면 그것부터** 읽고 진행한다. 남은 문항·기존 MD 경로를 확인하고 같은 시험지를 완성할 때까지 다른 시험지를 잡지 않는다.
2. 없으면 공유 점유 브랜치의 `claims/`를 읽고, §1에서 **전체 현재 우선순위 단계**를 결정한다. 원본 파일 전체 목록에서 이미 완료된 것, 다른 창이 진행 중인 것을 제외하고 **가장 앞의 미점유 시험지 한 장**을 고른다.
3. 해당 원본 JS의 실제 `sourcePath`, `Git blob SHA`, 문항 수와 교육과정을 확인한다. 공유 브랜치의 **`claims/<courseKey>/<sourceBlobSha>.json`** 경로가 있는지 다시 확인한 뒤, GitHub `create_file`로 **새 파일 생성만** 시도한다. 내용에는 `ownerLane`, `workerBranch`, `sourcePath`, `sourceBlobSha`, `sourceTerm`, `sourceYear`, `courseKey`, `status=IN_PROGRESS`, `auditPath`, `nextQid`를 기록한다.
4. 같은 claim 경로를 다른 창이 먼저 생성해 409/422/이미 존재 오류가 나면 **절대 덮어쓰지 않는다.** 공유 브랜치를 다시 읽고 **다음 미점유 시험지**를 선택해 시도한다. **동시에 시작했다는 이유로 과목을 앞당기지 않는다.**
5. 이미 다른 창이 가진 `IN_PROGRESS` claim은 재할당하지 않는다. 완료된 claim도 삭제/재작성하지 않는다. 오래된 claim의 강제 점유 해제, 다른 창의 브랜치 덮어쓰기, 자동 시간 초과 후 탈취는 금지한다. 소스 blob이 바뀌었거나 sourcePath가 중복되면 기존 claim을 확인하고 충돌을 HOLD한다.
6. **원자성 주의:** `create_file`이 독점 생성에 성공한 사실만 점유 근거다. 파일을 그냥 읽거나 로컬에서 선택했다고 확보된 것이 아니다. 원격 readback으로 owner/source를 재확인한 후에만 실제 해설 작업을 시작한다.

## 4. 시험지 하나를 끝까지 읽는 감사 작업

- 원본 `question/choices/answer/solution`을 **1번부터 끝 문항까지** 직접 읽고 [심층 감사 서식](DEEP_QUESTION_AUDIT_TEMPLATE_CURRENT.md)에 따라 **문항별 실제 문제 조건·기존 solution의 결정적 식/문장·KEEP/UPGRADE/HOLD 이유**를 기록한다.
- 개선 대상은 해당 시험지에서 **모두** 찾아 학생이 재현할 수 있는 수식 중심의 완성된 새 `solution`을 MD에 쓴다. 교육과정 외 풀이를 쓰지 않는다. 그림은 별도 SVG 엔진으로 인계하고 직접 생성하지 않는다.
- 출력 MD: `docs/operations/solution-upgrade-reservations/staged/<courseKey>/<sourceKey>_DEEP_AUDIT.md` (각 lane 자신의 작업 브랜치). 개별 문항 수정 MD를 분리해도 감사 문서에서 정확히 링크한다.
- 매 실행 중간에도 해당 MD를 작업 브랜치에 커밋하고 원격 readback을 확인한다. 한 시간 안에 끝내지 못하면 claim은 `IN_PROGRESS`로 남기고 `nextQid`와 미완료 UPGRADE를 함께 갱신한다. **다음 예약에서도 같은 창이 같은 시험지부터 재개**한다.
- 시험지 감사 완료 조건: **모든 문항의 문제·해설 판독 흔적과 수학적 KEEP/UPGRADE/HOLD 이유 존재**. 수정 초안 완료 조건: **모든 UPGRADE 문항의 완성 solution/독립 검산/MD 커밋 존재**. 두 조건이 모두 충족된 경우 claim을 `AUDIT_DRAFT_COMPLETE`로 업데이트하고 커밋 SHA 및 MD 경로를 기록한다. **그 직후 같은 실행에서 전역 우선순위의 다음 미점유 시험지를 독점 claim하여 반복한다.** 필수 그림 검증이 남았다면 `VISUAL_HOLD`와 미완료 QA를 명시한다. **출고 PASS는 절대 아님.**
- 시험지 확인 불가/실제 블로커라면 `BLOCKED`와 근거를 기록한다. 임의로 DONE 처리하거나 다른 과목을 시작하지 않는다. 권한/도구 장애가 있으면 정확한 오류 보고만 한다.

## 5. 과목 단계 진입/전환의 안전 조건

- **작업 순환 규칙:** `claim → 전 문항 근거 감사 → 필요한 모든 새 풀이 작성·검산 → MD commit/readback → claim 완료 → 다음 claim`을 **같은 예약 실행에서 반복**한다. `예약 1회=시험지 1장` 제한·첫 문항 처리 후 중단·20~30초 자발적 종료는 금지한다. 실제 플랫폼 실행 제한이 생기면 진행 상태를 안전하게 저장한 뒤 다음 실행에서 재개한다.

- 작업자 하나가 자신의 시험지를 끝냈다고 과목 전체가 끝난 것은 아니다. **현행 소스 목록에서 그 과목에 아직 미점유 시험지가 있는지 + 기존 claim에 미완료 시험지가 있는지** 확인한다.
- 현재 시험 구분에서 **미점유가 0개이고 모든 claim이 `AUDIT_DRAFT_COMPLETE`**가 되어야 다음 시험 구분으로 이동한다. 해당 자료 종류의 모든 시험 구분 완료 후 다음 자료 종류로, 그 과목의 다섯 자료 종류 완료 후 다음 과목으로 이동한다.
- 자료 종류나 과목에서 실제 소스 파일이 아예 없다면 `EMPTY_BUCKET` 증거를 남기고 다음 버킷으로 간다. 파일 하나/폴더 하나 없음으로 전체를 종료하지 않는다.
- 모든 claim이 점유 중이거나 미완료이고 다음 미점유 시험지가 없다면 **`WAIT_FOR_CLAIMS`**로 종료한다. 같은 시험지를 중복 수정하거나 다음 단계로 건너뛰지 않는다.
- 필요한 소스 목록·문항 identity·쓰기 권한이 불분명하면 `HOLD`, `NOT_RUN` 또는 `SAVE_BLOCKED`를 정확히 기록한다. 근거 없는 전체 완료/다음 과목 전환은 금지한다.
