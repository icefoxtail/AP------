# Git footprint and evidence retention

The repository keeps Git history for durable source, production assets, and the small receipts needed to explain a result. Rebuildable full catalog copies, conflict snapshots, patches, and browser capture output belong in ignored local or CI output folders. A receipt should point to the canonical source and record its relevant revision or hash; it should not embed a second full catalog merely to prove what was checked.

`tools/check-git-growth.mjs` checks only files changed from the chosen Git base, staged changes, and visible untracked additions. It compares blob object IDs, so same-size rewrites of very large analysis files are caught. The aggregate counts each distinct new Git blob at its full size, and reuses already reachable in-base blobs without counting them twice. Unchanged legacy blobs are grandfathered. Force-added ignored files are included when staged.

The initial bounds are 2 MiB for changed `archive/analysis/` files, 8 MiB for recognizable transient outputs, and 32 MiB total added bytes across the remaining changed blobs. The explicit production lanes are `archive/assets/images/` and `assets/images/`. The canonical production projections `archive/data/archive2-catalog.json` and `archive/data/question_metadata.json` are path-specific large-data exceptions because the runtime consumes those exact files. These exceptions do not apply to snapshots or alternate copies.

Do not ignore `archive/analysis/` as a whole: existing workflows consume exact receipt paths there. `.gitignore` covers the known rebuildable conflict-snapshot directories, while CI checks any force-added or newly named large analysis file. Preserve small freeze, review, and validation receipts in their established paths.

Run the focused check locally with `node tools/check-git-growth.mjs --base <branch-or-commit> --head HEAD`. Pull request CI compares against `origin/main`; push CI checks against the event's prior commit and fails closed when an initial push has no prior commit because that requires a full-history audit. This guard reports a failing CI status, but the current `main` branch is not protected by a repository rule, so it cannot prevent an authorized direct push from writing the blob before CI reports the failure. When a durable receipt needs an unusually large payload, keep the payload in the canonical production lane or external build artifact and leave a small hash-bound receipt in Git.
