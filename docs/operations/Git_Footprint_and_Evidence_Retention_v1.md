# Git production scope and Drive evidence retention

status: CURRENT / user-directed production-only Git scope
updated: 2026-10-16

Git carries production source and assets, runtime/build/test tools, current contracts, and the small byte-bound evidence authorities that active offline consumers need. Raw review archives, full catalog copies, conflict snapshots, browser captures, backups, logs, and intermediate outputs belong in the separately verified Drive evidence vault and the ignored local cache.

The current offline hot lane is `archive/data/evidence-authority/v1/`. Its versioned `index.json` maps exact original-path aliases to baseline commit/path, Git blob SHA-1, raw SHA-256, size, role, and current consumers; consult the index and ROOT receipt for current alias counts and bytes. It includes QID9 visual/RPM authorities, H15-M1 authorities and baselines, source snapshots bound to ROOT-authority hashes, the locked Codex M2 roster, and the active M2 q19/q24 adjudication, freeze, validator, and visual dependencies. These bytes remain supporting evidence; their presence does not certify semantic review or permit a quality gate to be skipped.

Cold evidence uses the `archive-analysis-pack/v1` ZIP members and an external `archive-analysis-fullpath-index/v1` sidecar. The ROOT receipt binds the sidecar and every pack to Drive IDs, parent, names, MIME types, sizes, SHA-256 values, verified readback, and the baseline. The full path index and packs stay outside Git. The complete Drive upload and downloaded-byte readback have been verified against the sidecar. This cleanup change removes 23,507 tracked paths (5,328,935,027 bytes); 1,371 materialized originals remain on disk as ignored copies, and the verified Drive vault retains the full source cohort. Rollout status is tracked in [PR #525](https://github.com/icefoxtail/AP------/pull/525). The earlier blanket-ignore prohibition is superseded by the user's production-only storage instruction after that verification.

The resolver accepts only explicit cold roots: `archive/analysis/`, `archive/_generated/`, `output/`, `reports/`, `render_review/`, `artifacts/`, `archive-work/`, `evidence/`, `archive/evidence/`, and `스캔_인테이크_산출물/`. The sidecar and ROOT receipt must list the same subset. The reader rejects current hot-authority aliases and the exact runtime-published generated inputs from `archive/data/archive2-canonical-input-manifest.json`. `archive/data/`, production source/assets, `tools/`, `archive/tools/`, `docs/`, applications, workflows, and code roots are never cold. Historical per-run scripts and source snapshots inside the audited cold roots may be archived as proof when the current-code audit finds no active consumer; file suffix alone does not decide retention.

`tools/archive-cold-evidence.mjs` accepts only explicit cold roots, rejects all index-declared hot aliases and the exact published generated canonical inputs, verifies the external index and Drive object identity, validates safe ZIP structure and CRCs, reconstructs chunked objects, and checks each raw object size, SHA-256, and Git blob SHA-1 before caching it under `.codex/archive-analysis-drive-cache/`. It contains no OAuth credentials and does not add a network prerequisite to GitHub CI. ROOT may fetch raw proof on demand; workers still inspect the actual inputs and complete their assigned review. Missing or corrupt proof remains unavailable and cannot be represented as PASS.

For a manual offline restore, download the receipt-named full-path index and ZIP packs from the verified Drive vault into local files, then run `node tools/archive-cold-evidence.mjs --receipt archive/data/archive-analysis-drive-root-receipt.v1.json --index-file <local-index.json> --pack-dir <local-pack-directory> --original-path <exact-original-path>`. The command verifies Drive bindings and exact bytes before writing one object into the ignored cache. It prints `RAW_BYTES_HASH_VERIFIED`, never a review or quality status. Drive credentials and signed download URLs remain outside the repository.

Git footprint CI blocks new or modified raw analysis/output artifacts and recognizes the versioned authority lane as an explicit exception. CI reports a failing status after a push; the current `main` branch has no repository protection rule, so a direct write can land before that result appears. Keep that limit visible in reports. Preserve the three exact published generated inputs and all production source/assets.

## Continuing work after the history migration

Use `git clone -c core.autocrlf=false <repository-url> <new-directory>` for a byte-exact working copy. The explicitly frozen Golden/Negative sample paths also have `-text` attributes so a Windows clone cannot change their hash-bound bytes.

After the approved history rewrite, start new work from a fresh clone of the rewritten `main`. Do not merge, rebase, or cherry-pick an entire branch that still contains the pre-rewrite graph: those commits can reintroduce archived raw objects even when the resulting tree is identical. To recover still-needed work, make a fresh branch from rewritten `main` and cherry-pick only the specific new commits whose changes have been reviewed against that base. The local recontamination guard is intended to reject outgoing history that contains commits recorded as rewritten; it does not replace the fresh-clone/narrow-cherry-pick rule.

Cold proof is preserved in the verified Drive vault and retrieved through `tools/archive-cold-evidence.mjs` using the checked-in ROOT receipt, the downloaded sidecar, and the required local ZIP pack(s). A missing pack or failed byte/hash check means the proof is unavailable; do not reconstruct it from old Git objects or report a review PASS. The ROOT receipt's `historyRewrite: false` field records the earlier evidence-preservation event only; it is not a statement that the current Git history has not been rewritten.
