## 검증과 보존

761 UID·문항 수/순서·source 구문, 허용 메타 필드, 학생용 payload 및 compact의 source blob/문항 순서를 검사했다. **보호 내용 변경 0, 로컬 게이트 실패 0**이다. 기준 main 대비 source 메타는 29파일 615문항에서 달라졌으며, 4칸 compact는 전 761문항을 결속했다. 작성자 외 시험지당 3문항 이상이라는 현행 표본 요건을 32시험지 모두 충족했다. 기본·확장 표본 슬롯 합계는 101, 신규 검토분의 독립 확인 문항 합집합은 132개다. 신규분 난도/legacy 예외 97건은 독립 근거를 결속했다.

새 검토 20시험지의 직접 인용 3,278건은 현행 4칸 validator FAIL 0이다. 기존 정상 검토는 정확한 판본에서 재사용했다. 후보의 같은 칸 상위 개념과 영문 선언도 확인했고, 새 검토분 누락 및 재사용분의 추가 4곳을 보완했다. 읽기/그림 근거는 [author-read-proof-index.json](author-read-proof-index.json)에 있으며 이미지 bytes는 원래 Git 자산과 대조했다. 정답·해설·이미지 파일·공유 정본·production inbox는 수정하지 않았다.

## Codex가 먼저 할 일

1. [verification.json](verification.json)의 UID별 등록 대기 묶음과 현재 source를 기준으로 공식 identity/source fingerprint, metadata, runtime의 결속을 정리한다. registry 자체의 로드 오류와 개별 문항의 exact binding/공란/후보 정의 부채는 구분한다.
2. [제안 색인](proposals/index.json)의 정의·부모·구별 기준·지원 UID를 대조해 기존 키 재사용 → 연결 보완 → 새 TPL → 새 PT 순으로 중복을 조정하고 공식 등록한다. RPM 출판사 leaf 공백은 native 신설과 별도 처리한다.
3. 원본 2015 과정의 machine 경로를 유지하고 최신 2022 부모 참조를 별도로 소비한다. 이번 2015 작도·합동 부모 보완은 [후속 근거](followups/2015-machine-parent)에 기록했다.
4. 부모 게시 보류 3건을 처리한다: 25왕운 중간 Q14, 25팔마 중간 Q7, **25연향 중간 Q13**. 앞의 두 건은 [보존 교정안](proposals/preserved-source-publication-corrections.json), Q13은 [동시 main 인계 메모](followups/concurrent-main-q13-handoff.json)를 따른다. Q13의 우리 브랜치 의미 교정 snapshot은 최신 main의 보류 문서와 일치한다. unified parent 검사까지 맞추기 전에 게시 완료로 표시하지 않는다.
5. 아래 미판정 1건의 원자료를 확보하고, 별도로 기록된 기존 내용 부채를 정식 내용 수정 절차에 넘긴다. 이 단계에서는 새 해설이나 전체 R1/R2/R3를 덧붙이지 않았다.
