# M2 current renderer continuity v1

This opt-in transports an already reviewed M2 metadata request to an independently inspected current rendering. It grants no metadata value, mathematical QA, difficulty judgment, or additional review pass. The existing M3 renderer contracts remain separate.

## Exact authority and source boundary

`sourceReview.m2RendererProof` uses `archive-reviewed-m2-current-renderer-continuity-v1` and an immutable Git commit plus raw SHA reference to `archive-independent-m2-current-renderer-review-v1`. The durable witness is stored at `.archive-meta-register/evidence/m2-current-renderer-<id>/independent-review.json`.

Only partial FINAL_QA requests from settled `m2-s2-meta-review-v1` rows are eligible. The request must keep exactly one existing semantic opt-in: proposal finalization v3 or native retained fields v1. Both the frozen request and its exact selected UID/ordinal inventory remain bound; every approved `after` field except the two actual renderer fingerprints is unchanged. Source-only preservation, identity-only registration, new registry changes, and the M3 renderer opt-in cannot be combined with this contract.

Four immutable source snapshots establish the transport:

1. The production source before the independent visual update.
2. The production source after that update.
3. The frozen candidate containing the already approved metadata append.
4. The current candidate containing the identical metadata append.

The two production/candidate comparisons must show the same exact four-field presentation transition: scalar local PNG `image` to SVG, absent `imageAlt` to a plain string, absent `imageSize` to `full`, and `grid` or `subjective-2up` `layoutTag` to `fullwidth`. Every other selected question property is identical within each comparison, and the metadata append is identical across both sides. Source counts, Git blobs, raw SHA values, selected whole-object hashes, and the exact unchanged metadata patch digest are checked.

Both production-to-candidate metadata axes preserve the entire student payload. Every appended property is an exact value explicitly present in the frozen request's approved `after`; derived fingerprints cannot serve as source append fields. Truthfully rehashing a production stem, answer, or solution difference does not authorize restoring or changing it.

The semantic validation view is the exact frozen Git question, whose full student payload matches the immutable native review. It is not a fabricated merge of fields. The ordinary proposal-finalization or retained-fields validator must still accept this view and supplies every approved value. Issued fingerprints and runtime records bind the actual current question.

## Independent observation and assets

The independent witness confirms preserved labels, given values, given geometry relations, choice order, absence of new inference or answer hints, and unchanged solution bytes. It does not assert pixel identity or identical decorative markings. Each row records `preservedGivenConditions`, `presentationChanges`, and `noNewInferenceOrAnswerHint` in a structured `observed` object.

Every referenced original and current problem/solution asset is inventoried by exact path, Git blob, and raw SHA. Approval and item evidence references include every asset and the separate frozen request copy. Immutable native/prefigure/production/current asset bytes are compared; live bytes are read again on replay. Dynamic or nested SVG content and external dependencies are rejected. Only the independently inspected primary image changes; all other renderer assets remain exact.

## Issuance, reuse, and proof deletion

The existing durable `.source-review-binding.json` stores the exact request and the M2 continuity component together with its original semantic component. Native reuse replays the sealed request, original native authority, independent witness, source snapshots, and actual current assets. An older AutoMeta cursor is accepted only after that replay succeeds and its full student payload SHA matches the authenticated prefigure SHA. A caught-up cursor does not exempt the proof.

Claim detection grants no approval. For the exact M2 UID/source pairs, a read-only index of witness versions in the actual HEAD ancestry retains the proof obligation when mutable receipt repairs, row markers, sidecar digests, sidecars, or witnesses are removed together. Committed deletion or an empty replacement does not erase an earlier witness version. Unmerged branches are not scanned. Only immutable Git inventory is cached by root and HEAD; live evidence and current registry/source/asset validation are never cached as successful. Missing Git context or unreadable inventory fails closed for a candidate M2 row.

An ordinary source-only descendant must revalidate the same prior native receipt and keeps the original visual obligation. No additional semantic fields, renderer formats, or approval modes are inferred.
