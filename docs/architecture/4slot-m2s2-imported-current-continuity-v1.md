# Imported M2-S2 current-source continuity v1

This is an opt-in transport for an already imported complete M2-S2 final-exam
four-slot vector. It neither authors slot terms nor approves source metadata,
curriculum, PT/TPL, cross concepts, conditions, difficulty, or mathematical QA.
It does not expand the existing native-M2, M3-v1, or M3-v2 contracts.

## Separate authority and byte-binding axes

The `currentM2ImportedContinuity` evidence group binds a strict
`m2-s2-imported-current-four-slot-continuity-v1` carrier. It contains immutable
Git references to the prior compact and source, original native vector/source,
authoring queue, existing import review/operator, raw input inventory, actual
observer document, optional negative ROOT followup, and any already-bound
metadata-only request.

Every reference requires a full commit, safe repository path and raw SHA-256.
Source, asset and dictionary references also bind their Git blob. Current
source, assets, dictionary and durable evidence must match live bytes. Reference
validation runs before runtime-cache reuse; it is not a historical-pass waiver.

The complete original vector is reconstructed by the existing importer and
current dictionary. The queue joins the source path, full denominator and
original source blob. The native raw bytes and original `reviewedBy` remain
unchanged. Only the existing immutable import-review `replaceQuote` operations
for a selected source's method evidence can be replayed. Other operation types
are outside this contract. Every original item and quote is then checked by
the existing full native validator against the current source. Missing terms,
quotes, items, or declared candidates fail closed.
The original observation's existing-import-quote-amendment marker is retained
only on the exact ordinal already covered by those immutable operations. It
cannot stand in for a new quote judgment or a body-transcription review.

Existing source metadata differences are recorded as per-field presence and
value hashes between the prior and actually observed immutable source. They
are opaque inputs: no metadata field is copied into the four-slot output and
no validity of a metadata value is inferred from these hashes. Unlisted fields
or further current drift are rejected.

An optional metadata-only candidate overlay is separate from the observed
renderer snapshot. It can change only `courseKey`, `curriculumKey`, or
`crossConceptKeys`, must preserve the entire student payload, and must match the
exact source blob, selected UID/ordinal set and `after` fields of an existing
immutable FINAL_QA request. This is a transport binding to that request, not a
replacement for its native/proposal/registrar approval checks. Those checks
remain mandatory in the original metadata registration path. No other field,
new difficulty value or guessed curriculum is admitted through this overlay.
The original inbox reference is read from its immutable Git commit. A separate
durable evidence copy must have exactly the same bytes and remain present in
the working tree. Consuming the inbox cannot erase this binding or prevent a
future build; deleting or altering the durable copy is rejected.

## Current observations and explicit hold

The raw input inventory binds every prior/current whole question and student
payload. Actual rows must have their original observer, UID, ordinal, unchanged
vector, card hash and complete prior/current asset sets. Asset comparison is a
multiset equality; duplicate/missing substitutions are invalid. The current
immutable candidate assets, observed Git assets and live bytes must agree.

An unchanged row requires exact student payload and exact complete referenced
asset set. Its unrelated existing metadata may differ only according to the
same immutable metadata-delta inventory. It is not described as a whole-object
unchanged row.

Ordinary transport accepts only the named presentation fields and an optional
single static local image suffix after the byte-exact existing content. It
does not accept changed choices, answer, solution, proof prose, table source,
or added conditions. SVGs must be static and self-contained. SMIL, script,
foreign objects, external references, stylesheet imports, CSS animation,
escaped CSS dependencies, and unbound image references are rejected.

Separate from image appending, an already-present single `img` token may be
replaced only when the original actual observer explicitly recorded
`detail.contentDeltaLimitedToImageMarkup=true`. Every character before and
after that token must remain exact. Both tokens must be actual rendered HTML
image elements with local, fully bound assets. Only quoted `src`, `alt`, and
static `style` attributes are accepted; duplicate attributes, event handlers,
entities, quoting escapes, dynamic CSS, comments, script-contained or
attribute-contained fake images are rejected. This admits the four observed
SINHEUNG23 image-markup substitutions, not body or proof transcription.

The explicit negative row requires both the raw current observer's negative
decision and ROOT's separate exact negative followup. Its original slot vector
stays in the compact, with `4slot-m2s2-imported-current-renderer-hold-v1`; it is
absent from active runtime and Consumer results. No negative decision is
reinterpreted as a mathematical error or as a source correction approval.

The carrier binds a complete disjoint partition and the complete prior compact.
There is no partial-submit or subset shortcut. A held marker, source binding,
original evidence, reviewer, slot or candidate cannot be silently dropped or
replaced. HEAD-only full ancestry retains issued transport/hold obligations
after working-tree deletion, committed deletion and merge-history deletion.
The pass-local inventory caches only immutable obligations, never successful
approval results. Missing Git history is a refusal, not an ordinary fallback.
