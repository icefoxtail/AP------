# M2 finalized CC provider current renderer transport v1

This opt-in transports an already reviewed M2 FINAL_QA request across an independently observed problem-and-solution presentation change. It supplies no metadata, definition, mathematical QA, difficulty, or four-slot approval. Existing M2 and M3 renderer contracts remain unchanged.

## Admission and immutable authority

The request remains `PARTIAL_UIDS`, has one or two selected UIDs, and contains exactly one add-only ACTIVE cross-concept definition in the canonical plane-geometry shard. Its supporting UID set must equal the request's selected set. Every item retains its original `archive-native-proposal-finalization-v1` authority. The ordinary native review and finalization validators must still authenticate every final value and the complete original definition after the presentation view has been verified.

Each selected item explicitly supplies `sourceReview.m2ProviderRendererProof`, using schema `archive-reviewed-m2-provider-current-renderer-continuity-v1`, an immutable review commit, and the exact raw-SHA witness reference. The witness must be independent of the native reviewer and transport author. It binds the exact frozen request, native row, registry change, four source snapshots, and complete old/current asset inventories.

The four source axes are production before/current and the frozen/current candidates. Both presentation deltas must match. Both metadata deltas must match, preserve the complete student payload, and contain only values explicitly present in the frozen request's `after`. The frozen candidate must retain the exact native reviewed and committed student payload. The current request and live source must match the inspected current candidate.

## Narrow presentation change

The only permitted changed fields are `image`, `imageAlt`, `imageSize`, `layoutTag`, `solutionImage`, `solutionImageAlt`, and `solutionImageCaption`. This contract requires the observed PNG-to-SVG problem change, distinct SVG-to-SVG solution change, absent-to-`tall` image hint, and grid-to-fullwidth layout transition. All other question fields remain exact. New captions and the current solution must be supported by the unchanged written explanation; the current problem must not add an inference or answer hint.

Every old and current referenced asset is tied to immutable Git bytes and a live evidence reference on both the approval and selected item. Only the observed problem/solution pair may change. SVG script, embedded/external content, SMIL animation, stylesheet imports, XML stylesheet processing instructions, event handlers, and dynamic keyframes are rejected. A static observation cannot authorize later dynamic output.

## Issued proof and runtime reuse

The registrar seals the exact opt-in in its existing durable source-review binding. Runtime reuse replays the sealed request, original native/finalization authority, four snapshots, and current source/asset bytes. The old cursor is accepted only when the actual native replay returns the issued provider proof and its native student-payload digest matches that cursor.

Claim discovery is an obligation detector, never an approval. It uses only the actual HEAD's full ancestor history and keeps the proof requirement visible after working-tree, committed, or merge deletion of every live marker and witness. Git lookup failure fails closed. Only immutable inventory is cached; no approval or live-byte verification result is cached. Source-only descendants retain the original proof obligation.

## Verification boundaries

`tests/archive-m2-provider-current-renderer.test.mjs` exercises the official registrar, exact old/current cursor reuse, source-only descendants, original definition authentication, truthful source/witness tampering, dynamic SVG dependencies, and combined provenance deletion. Actual item registration and student Consumer verification remain separate gates. A local targeted Consumer result does not replace the final union catalog, immutable shadow, or exact-head CI.
