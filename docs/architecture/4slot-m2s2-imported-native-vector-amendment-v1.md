# Imported M2S2 native vector amendment

Status: explicit successor to `m2-s2-imported-current-four-slot-continuity-v1`.

This contract carries existing ROOT-accepted native four-slot values into a
complete compact that already has a valid imported-current transport. It issues
no new mathematical, difficulty, metadata, term or four-slot judgment. The first
intended input is E021/E022/E023: 71 items, 13 previously approved vector changes,
one existing renderer HOLD, and two unchanged broad-ID/candidate fallbacks.
Those counts describe the proposed input, not a completed registration.

## Separate authorities

1. The literal immutable prior compact and its original carrier remain the
   authority for the complete imported vector, original import quote amendments,
   actual current renderer observations, negative observations and metadata
   overlay. The unchanged v1 validator replays that literal document against the
   real current source, assets, dictionary and identity map on every invocation.
   The adapter never synthesizes a prior compact from the candidate.
2. The native four-slot document, full review, independent sample and ROOT
   acceptance are immutable original authority. Their raw SHA-256 and Git blob
   identities must agree with the main owner proof. ROOT acceptance binds the
   exact source, review, four-slot and sample hashes. A sample review is not
   relabeled as an independent full-exam review.
3. The main owner compact, current renderer proof and existing native-vector
   transport proof bind the exact old/new values and original native entries.
   The owner observation/contact documents retain their own attribution. Their
   full UID/ordinal/asset joins are checked; this adapter does not claim a new
   visual inspection.

The prior compact may be an immutable side reference, as in v1's existing
historical reader. Its raw bytes and complete authority are replayed rather than
inferred from ancestry. The owner compact, new carrier and durable native copy
commits must be real HEAD ancestors. The owner main source is exactly the source
observed by v1. The live source is exactly v1's
current source, which may include v1's separately bound approved metadata
overlay. This distinction preserves the existing E023 overlay without treating
its values as new four-slot authority.

## Explicit evidence and carrier

The active compact has one new group, `evidence.currentM2ImportedNativeAmendment`:

| Key | Bound content |
| --- | --- |
| `carrier` | The immutable `m2-imported-native-vector-amendment.json` document |
| `nativeFourSlotCopy` | A durable raw copy identical to the original native four-slot Git bytes |
| `currentRenderer` | The exact main owner's current-renderer proof |
| `nativeVectorTransport` | The exact main owner's existing-approved-vector transport proof |

The old top-level `currentM2ImportedContinuity` group is replaced only by this
explicit successor. Its literal document, carrier and evidence remain available
and are fully replayed. Existing item HOLD objects remain byte-for-byte equal,
including their original carrier, observation and ROOT-negative references.

The carrier schema is `m2-s2-imported-native-vector-amendment-v1`, with scope
`EXACT_EXISTING_APPROVED_NATIVE_VECTOR_TRANSPORT_ONLY`. Its closed fields bind:

- the source, exam and full question denominator;
- the literal prior compact and prior carrier;
- the main compact, main source, main renderer and native-vector proofs;
- the original native four-slot, review, ROOT acceptance and independent sample;
- the native source, actual current source and dictionary;
- the durable native raw copy;
- the exact changed rows, unchanged candidate fallbacks and held rows;
- six zero-valued counters: new semantic, difficulty, math and slot approvals,
  source writes and asset writes.

Full file references use `commit`, `path`, `gitBlobSha1`, and `sha256`.
Document references use `commit`, `path`, and `sha256`. A durable native copy
does not replace native authority: both original Git bytes and the live copy
must be available and equal. Its deletion, substitution or drift rejects the
entire file before runtime cache reuse.

## Exact full-file boundaries

Every source row must join exactly one canonical UID, source ordinal and display
number. The prior compact, candidate compact, main compact, original native,
review and source arrays must have the same complete denominator. Partial
submission is outside this contract.

For each changed row, all four resulting slots must equal the official native
projection under the exact existing dictionary. The owner transport must retain
the literal original native entries and exact before/after item hashes. No
candidate, format, reviewer, original evidence or unrelated header may change.
The original native is also passed to the official four-slot validator against
the real current source on each invocation; a historical validation verdict is
not reused.

The two existing broad-ID fallbacks are exceptions to equality with the newer
native projection, not new approved values. A fallback must equal the literal
prior item in full. Its original author entry, original item hash, current
native specific entry and candidate label must match the owner proof. Candidate
approval remains `NOT_GRANTED`, ordinary-search eligibility remains unchanged,
and no HOLD is invented or released.

An originally held item cannot also carry a vector amendment. Its full vector
and complete HOLD object stay exact. Source-content holds recorded in original
native authority and owner evidence are retained as historical authority; this
contract cannot release them or promote a positive renderer observation over a
separate ROOT negative.

The candidate is compared with one exact construction from the literal prior:
replace the explicit evidence group, install only the main owner's approved
slot values, and put back each unchanged original HOLD. This is a validation
comparison, not a reconstructed input supplied to v1.

## Existing owner observation versions

The immutable owner renderer evidence may use the existing
`m2-s2-narrow-renderer-observations-v2` document or the separately checked
`m2-s2-narrow-renderer-observations-v1` document. Both retain the same exact
source, reviewer, contact manifest, complete contact join, native authority,
current asset, full denominator and HOLD boundaries. The v2 reader is unchanged.

The v1 reader is closed to its original keys and actual observation scope.
Source/asset mutation, metadata or registry approval, new full mathematical QA,
and original content HOLD release must all be zero. Original registration and
student deployment remain `NOT_RUN`; contact and distinct UID counts must match
the exact contact manifest, with no added renderer contacts.

Every v1 row requires actual before/current image viewing, current stem reading,
and SVG markup/accessibility text reading. A solution row also requires its
current caption and unchanged written solution comparison. That solution-only
key is absent on problem rows and is not synthesized as `true`. Nonempty original
observation text and the existing renderer-continuity-only decision are required.
The absent v2 source/choices/answer/solution assertion is not invented or used to
replace any v1 reading flag. These flags describe the original observations;
they authorize no new metadata, mathematics, vector, or HOLD release.

## History and freshness

Each builder pass discovers typed amendment claims along actual HEAD ancestry
using full history. This inventory alone is pass-local; it contains no approval
verdicts. A later tree must retain the new marker, historical held identities
and exact amended item hashes. Removing every marker and proof, replacing a
carrier with an empty document, reverting to the old v1 compact, or deleting the
witness through a merge cannot make the file ordinary again. An unmerged review
branch cannot impose obligations on another branch. Git/inventory failure is
fail-closed for this M2S2 scope.

Every invocation rereads original Git bytes, live proofs and native copy,
source, dictionary, current assets and identity. The existing v1 source and
asset guards run before the new authority is applied. Main owner asset and
contact bindings are also checked. Builder input hashing includes the new code,
live evidence digests and immutable obligation digest, and all strict validation
occurs before any previous runtime-index reuse.

## Unsupported transitions

This contract does not release E022 Q12 or any other renderer HOLD, repair source
content or assets, approve unknown terms, change metadata, replace the original
reviewer, generalize body transcription, accept a changed source snapshot, or
replace original native authority with a successful registration result. Such
changes need their own explicit authority and contract. Existing v1 inputs with
no amendment obligation retain their original behavior.
