# Exact M2-S2 display repair after an existing renderer HOLD

This is a separate opt-in successor, not a change to ordinary continuity or
native review. It closes one explicitly reviewed display discrepancy in a
complete existing compact. It does not approve a new slot, difficulty,
metadata value, mathematical method or written solution.

The original negative remains correct for its original source and asset bytes.
Its raw document stays available and byte-identical after the successor.

## Two original authority chains

`currentM2DisplayRepairClosure.origin` is exactly one of:

| Origin | Mandatory original replay |
| --- | --- |
| `CURRENT_V1` | The literal immutable compact and every input of current M2-S2 continuity v1. |
| `IMPORTED_NATIVE_AMENDMENT` | The literal imported-v1 compact, original import operations and quote checks, followed by the literal existing-approved native-vector amendment. |

The imported route retains every existing native amendment, original broad-ID
fallback, unapproved candidate, format, reviewer, metadata overlay and other
compact field. Its historical prior must actually contain the amended compact
and the source snapshot named by that amendment. An unamended compact or a
reconstructed mixture of old carrier and new rows is rejected.

The closed `validateHistoricalFile(root, fullReference, helpers)` APIs read the
literal compact from Git. They replay the original validators against the
original immutable snapshot. They accept no caller-supplied reader or skip
flag. Original native quote, schema and dictionary validation still runs
against current source prose. That prose is protected by the new repair's
whole-question checks.

Historical replay returns the exact operation documents that it required as
local inputs. The successor must list all of them as `historicalEvidenceRefs`,
and each listed document must still match immutable and live bytes. This
includes original negative observations and native amendment copies. Old
source and asset bytes are read from their original Git snapshots; an old
same-path SVG is never relabeled as the current repaired SVG.

## Closed carrier and binding

The group has exactly `origin`, `carrier` and `observationBinding`.
The carrier path ends in `m2-current-display-repair-closure.json` and has
schema `m2-s2-exact-display-repair-closure-v1`, scope
`EXACT_EXISTING_NEGATIVE_DISPLAY_REPAIR_ONLY`.

Its fields are:

- Schema, scope, origin, kind, transport author, exam, source and full count.
- Literal historical compact, exact current source, observation binding and
  complete historical live-evidence references.
- One canonical UID/source ordinal/display-number tuple, exact selected asset
  references and the stable hash of the complete preserved item array.
- Zero new semantic approvals, difficulty approvals, mathematical QA, slot
  values, source writes and asset writes.

The binding path ends in `m2-display-repair-observation-binding.json`, with
schema `m2-exact-display-repair-observation-binding-v1`. Its exact fields name
the source, selected tuple, kind, immutable ROOT observation, raw candidate
report, independent mechanical read, independent image/XML read, independent
actual observation and actual image references.

Source, compact, image and raw observation references contain full commit,
repository-relative path, Git blob ID and raw SHA-256. Carrier references
contain full commit, relative path and raw SHA-256. Git tree entries must be
regular blobs. Live symlink substitutions, unavailable objects, unmerged new
carriers, and current bytes that differ from their bound commit fail closed.

The observer's original scratch paths are historical labels. The validator
does not open, rewrite, map or infer files from those paths. Only the explicit
bounded Git references in the new binding are executable inputs. Their SHA,
source/UID joins and image properties must match the untouched raw reports.
Original locator reports are not independent approval authorities.

ROOT and independent actual observations remain separate. A transport author
cannot stand in for either observer. A pending candidate report remains
pending in its original bytes; the independent observations supply the later
limited acceptance. Neither observer report claims completed registration.

## Three exact repair kinds

### `NATIVE_PROBLEM_DISPLAY_RESTORE`

Exactly `image`, `imageAlt`, `imageSize` and `layoutTag` change. The presence
and value of every changed field must equal the original accepted native
question. The complete student payload becomes equal to that native question.
The native PNG is immutable and matches current Git and live bytes. The
original missing-right-angle negative and actual ROOT and independent visual
observations must identify the same selected question and bytes.

### `NATIVE_PROBLEM_AND_SOLUTION_DISPLAY_RESTORE`

The same four fields plus `solutionImage`, `solutionImageAlt` and
`solutionImageCaption` change. Their exact native presence and values are
required. Written solution text does not change. The native problem PNG,
solution SVG, exact render capture and original area-label negative are
separately bound. This kind can follow the existing native amendment without
dropping any of its full-file obligations.

### `DERIVED_FOUR_MARKER_CLARIFICATION`

This is not a native-image restoration. The native question had no image.
The current derived figure remains in the question. The original stem prefix
is byte-identical and exactly one actual static `img` token remains. Only its
`alt` attribute changes; its source, other attributes, surrounding content,
choices, answer, written solution and metadata stay exact.

The SVG loses exactly four independently listed blue single-stroke `line`
elements. Each has the fixed blue stroke, width and round cap and all its
original coordinate attributes. The four purple double-stroke lines remain
exact. Apart from the one `desc` text replacement, deleting those exact
elements must reproduce the complete current SVG bytes. Other geometry,
labels, colors, markup, dependencies or active content are rejected. This
byte-level restriction is stricter than a general equivalent XML rewrite.

## Complete denominator and history

Every source ordinal has exactly one current canonical UID. Prior, native,
current and compact counts match. The selected whole question changes only
as the selected kind permits. All peer whole objects and their current Git,
original Git and live assets remain exact. The source prefix and suffix
outside the selected object also remain byte-identical.

The expected output is the entire literal prior compact, with only its source
blob, the new group and removal of the exactly selected HOLD changed. A second
held question, omitted row, other vector change, reviewer change, candidate
change, header change or metadata edit fails closed.

Three history inventories remain separate: original current/imported
continuity, native amendment and exact display repair. They use actual HEAD
ancestry with full merge history. The successor must cover every relevant
original negative and carrier exactly. It must also preserve all amendment
row hashes. Deleting markers, a native copy, observations, the carrier, or an
entire committed proof cannot fall back to an ordinary positive compact. Only
immutable inventory is cached within a build; no approval result is cached.

The complete validator runs before runtime cache reuse. Source, dictionary,
identity, assets and live proof digests participate in the existing builder
input hash and final input-stability checks. This contract produces no source,
asset, native review, metadata, identity or registry writes.

## Registration gate

A code test result or an observer's acceptance is not a production registration
result. Actual carrier publication, exact current input binding, bounded
builder dry/write/check and Consumer verification are separate steps owned by
the remote writer. This contract alone does not claim that any production
HOLD has been released.
