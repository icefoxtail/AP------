# Exact native PNG and first solution line repair successor

This is a separate, explicit successor to
`m2-s2-current-four-slot-continuity-v1`. It closes one previously recorded
negative renderer observation only when an immutable owner repair and a
separate actual ROOT observation establish the exact accepted correction.
The ordinary v1 transport and its hold behavior remain unchanged. This is not
a general hold release, source normalization, mathematical re-review, private
partial import, or permission to change four-slot values.

## Inputs and authority

The compact retains its complete original `evidence.currentM2Continuity`
group and adds `evidence.currentM2RepairClosure`. The new group has exactly
three immutable `{commit, path, sha256}` references: `carrier`, `ownerReview`
and `rootObservation`. The carrier path ends in
`m2-current-four-slot-repair-closure.json`.

The carrier schema is **m2-s2-exact-native-rhs-repair-closure-v1**, with scope
**EXACT_NATIVE_PROBLEM_AND_APPROVED_FIRST_SOLUTION_LINE_REPAIR**. It binds:

- The literal historical full compact, including its original hold, and the
  current owner's full compact, each by exact commit/path/blob/SHA.
- The complete current source and denominator, the selected UID/ordinal/
  displayed-number tuple, and the exact original negative references.
- The immutable native problem PNG and the selected current asset inventory.
- The existing owner r2 proposal/review and the separate ROOT observation.

All six counters are zero: `newSemanticApprovals`, `newDifficultyApprovals`,
`newMathQa`, `newSlotValues`, `sourceWrites` and `assetWrites`. A marker is only
a request to validate this contract. It is never an approval in itself.

The historical compact is replayed through the entire existing v1 validator.
Its original source, assets, dictionary and typed evidence are read from its
immutable issued snapshot instead of pretending that they are the current
source. Native full-vector projection, original ROOT acceptance, independent
sample, full UID join, actual old observations, exact partition and the
negative hold all remain mandatory. This historical replay has no standalone
current-registration effect.

The old typed carrier, original typed observation, negative ROOT closure and
their raw observation files also remain exact live inputs. The new owner and
ROOT records cannot overwrite or delete them. Current HEAD ancestry is still
read with `--full-history`. Every negative obligation for the source must be
the exact single selected tuple and exact bound historical closure. An omitted,
additional, changed or unavailable historical obligation fails closed.

## Narrow accepted source change

The owner review must be the existing explicit native RHS restoration v2
schema and decision. It retains the existing native source, full four-slot
file, native review, ROOT acceptance and independent sample. The exact
selected native item, its primary-method and decisive-step statements, and
its stable SHA are compared with that original native review. No new method
or slot is derived from the repair document.

The only changed question fields are exactly `image`, `imageAlt`, `imageSize`,
`layoutTag` and `solution`. The existing owner proposal supplies the literal
set values and an object of removed field names with their exact prior values.
Applying those declared operations must reconstruct the whole current question.
In this immutable r2 proposal, `set.solution` is the closed transition object
`{before, after}`. Its two complete strings must equal the literal historical
and current solutions respectively; only `after` is copied into the source
view. A direct string, missing key, additional key or mismatched old/new value
is rejected. This representation does not add a second solution edit.
The current image is the exact original native PNG, including its Git blob,
raw SHA and PNG signature; the unsupported old alt text is absent.

The written solution change is the owner's exact approved first-line
replacement. Its old and new raw UTF-8 hashes match the ROOT observation.
The old prefix is followed by a line break, and every byte after that prefix
is unchanged. The source stem, answer, choices, remaining solution, metadata
and every other field are preserved. Every unselected question is a whole
object match with the validated historical source. All referenced current
assets are fresh-read and equal the immutable current snapshot; peer assets
and the retained solution asset also equal the historical snapshot. Only the
restored selected problem PNG takes its bytes from the exact native authority.

Every original format, slot vector, candidate list, normal blank and
`reviewedBy` value is preserved. The current owner's compact must be exactly
the historical full compact with its declared source binding, original hold
removed and exact owner continuity reference added. The final compact adds
only the preserved historical group and the new repair group to that owner
compact. No partial denominator or extra slot edit is accepted.

## Actual observation boundary

The ROOT observation remains the literal
`m2s2-root-exact-native-rhs-repair-observation-v1` record. Its current source,
native authority, owner proof, actual viewed PNG, selected UID and whole-file
denominator are all bound. Its referenced mechanical report is also an exact
immutable and live input. ROOT differs from the owner reviewer and transport
authors.

The recorded scope is actual viewing of the native/current problem PNG,
reading the current first solution line, and checking the stated RHS
premises and the inference against that image. The record distinguishes a
derived equality from a given mark. The existing solution SVG was read as
markup only. `solutionSvgImageViewed` and `browserRenderingRun` must remain
false, as must all new metadata, slot and difficulty approval claims.

The observation's own `registrationHoldReleased=false` and
`registrationResult=NOT_RUN` remain unchanged. The later formal successor
validation is the separate technical registration decision; it does not
rewrite what the earlier observation actually did.

## Builder, repeated runs and refusal

The obligation inventory passes its immutable entries to this helper before
runtime cache reuse. The helper must close those exact entries and perform
the full checks above. The new helper bytes enter `BUILDER_SHA`; its live
evidence digests enter the existing input fingerprint. Every run still reads
current source, assets and proof bytes. No successful approval result is
cached by this contract.

Deleting the successor marker, deleting the old group or sidecars, committing
their deletion, or merging a branch that drops them cannot turn the current
source into an ordinary approved compact. The old negative obligation remains
in immutable ancestry. A different repair, a new source change, another held
UID or an altered current renderer requires its own explicit authority.

## Verification and production boundary

`tests/item-4slot-m2s2-current-repair-closure.test.cjs` uses a small synthetic
repository with a previously valid mixed v1 full vector. It verifies the exact
successor, unchanged vectors and peers, Consumer inclusion of the corrected
UID, write/check replay, and fail-closed source/proposal/native/ROOT/history/
live-input mutations, including cold and warm deletion cases. The existing
v1/runtime/M3 negative contracts remain separate regression gates.

Actual E017 registration additionally requires the immutable published owner,
ROOT and carrier snapshots; exact production full-file builder, Consumer and
replay; independent code review; and normal publication gates. Synthetic
tests are not an actual production registration or fresh mathematical QA.
