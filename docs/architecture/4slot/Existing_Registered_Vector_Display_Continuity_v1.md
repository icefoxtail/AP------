# Existing registered four-slot vector display continuity v1

This is a separate continuation of a previously published `REGISTERED` vector. It does not issue FINAL_QA, ACTIVE curriculum authority, new mathematical review, new slot judgments, new semantic approval, difficulty changes, or identity reconciliation. The existing registered-renderer and explicit-HOLD paths retain their contracts.

## Entry and historical authority

Each selected UID has one retained JSON input at `.archive-meta-register/4slot-existing-vector-continuity/<questionUid>.json`, with schema `archive-four-slot-existing-registered-vector-continuity-v1` and scope `EXISTING_REGISTERED_VECTOR_ONLY`. Input objects and immutable references have closed key sets; null, unknown keys, duplicate identities and mixed continuation types are refused. An immutable reference is exactly `{commit, path, gitBlobSha1, sha256, bytes}`.

The historical index must come from an ancestor of both the current checkout and the current source commit. Its selected row must actually be `REGISTERED`, carry no independent semantic claim, and have no selected or whole-file pending entry. The index, historical compact, source, metadata and identity are tied to the same historical commit. Whole-bank UID, ordinal, source-number and denominator joins are checked against current identity. Legacy identity rows whose status property was absent are supported only with that same historical/current own-absence; explicit null and a changed status are rejected.

The original native four-slot document, accepted root review, independent document, scoped amendment when applicable, dictionary and source references are reread from Git. The official dictionary/compact projection is replayed for the entire bank. A scoped amended native document may support an unchanged member only when the original member and every unamended item remain exact and the declared amended members have their existing independent provenance. This route cannot promote a native proposal or manufacture a new independent review.

The current compact remains equal to the historical compact. Only the existing orphan-reconciliation source header may follow the exact current source, and only within the separately checked orphan path below. All item vectors, review provenance and dictionary bytes remain unchanged. The selected metadata and identity rows remain whole-row exact to their historical issued values.

## Current source and rendered surfaces

The full current source container is bound to immutable Git bytes and the live file. The selected question may differ from the published historical question only in these declared display fields:

- Problem: `content`, `image`, `imageAlt`, `imageSize`, `layoutTag`.
- Solution display: `solutionImage`, `solutionImageAlt`, `solutionImageCaption`, `solutionImageSize`.

Every own-property change is enumerated and hashed. Answer, choices, solution text, source approval flags and all other fields remain exact. All native, historical and current assets referenced by the selected question are inventoried, including recursively referenced local SVG assets. Remote or missing dependencies, extra inventory entries and same-path live byte changes are refused. The native/historical protected student payload and asset bytes must remain exact.

Content changes require exact UTF-8 edit intervals, old/new hashes and unchanged remaining bytes. `IMAGE_MARKUP_ONLY` permits only the declared image/container markup intervals. `ORIGINAL_IMAGE_PROCESS_TRANSCRIPTION` additionally requires the exact original problem-asset reference and a separately authored review of that precise interval. It is not generic text stripping or payload normalization. No normalized source is written or passed into another authority validator.

Every changed surface requires a separate static display review and a complete actual UI/visual pair. The static document uses `archive-independent-existing-four-slot-display-review-v1`, freezes distinct given, original-observation and current-observation references in that order, and binds UID, ordinal, denominator, source references, whole-question hashes, changed fields, assets, original vector, metadata/identity hashes and any content edit intervals. Its decision is `ACCEPT_DISPLAY_CONTINUITY_ONLY`; all new-approval counts are zero. Static acceptance alone is insufficient.

## Actual UI and independent visual review

Technical capsule schema: `archive-four-slot-existing-vector-display-ui-v1`, status `TECHNICAL_PASS_VISUAL_REVIEW_PENDING`, execution owner `GITHUB_ACTIONS_SUPPORTED_CHROME`. Independent visual schema: `archive-independent-four-slot-display-ui-review-v1`. The two are separate immutable Git documents. Visual review repeats the exact technical reference, every logical case, the SHA-256 of its complete original capture object and every original PNG, with an explicit display-only acceptance decision. A technical PASS does not imply visual acceptance.

The closed cases are problem/exam at desktop 1365×1000 and mobile 390×844, and solution/sol at desktop 1440×1000. Every group includes all required viewports. Source and complete surface-asset references match the technical checkout and the selected live bytes. Fonts must actually be ready and the expected student family loaded; the exact checked response inventory is hashed. Source overlays, DOM writes and CSS writes are zero.

The capture object is transported without projection or reindexing from the actual shared capture functions:

- Problem: `archive-problem-scroll-coverage-v1`.
- Solution: `archive-solution-scroll-coverage-v1`.

Both require `UNCHANGED_VIEWPORT_ORIGINAL_SCROLL_TILES`, at most 8 original tiles, contiguous **1-based** indexes and exactly 32 CSS pixels of successive overlap. The entire own content interval, including the last tile, must be covered. Original document content/question geometry, fixed viewport, per-tile clip and scroll geometry, original DOM hash, positive before/after hit-test sample count, idle feedback and zero foreign obstruction/content hits are checked. Scroll-operation counts and the final scroll are tied to the original tile records. DOM/CSS/viewport mutations and composite images are refused. Global screenshot inventory and all per-case screenshot inventories must be exactly equal and contain no extras or aliases.

Problem and solution observations are separate surfaces. Private solution review documents, original PNGs and references remain in the root/registrar review lane; they do not belong in blind problem review packets or shared checkpoints.

## Writer, Consumer and deletion behavior

The ordinary builder invokes this verifier only for the explicit typed input or a previous output claim. It stores `EXISTING_REGISTERED_VECTOR_CONTINUITY` with the exact UID-named input path and SHA-256, while keeping `independentReviewClaim: false`. The Consumer accepts this binding only with that closed reference and rejects missing, foreign and mixed markers. Existing original-source, registered-renderer, partial, explicit-HOLD and nonselected behavior stays intact.

Typed entries and previous claims bypass the ordinary byte cache and are replayed. Each build rereads its immutable authorities and live selected inputs; the official writer rechecks observed digests before writing the derived index. Removing a retained input after issuance fails on a caught-up cursor. With no claim, the original stale payload/asset and orphan guards still apply. The route writes only the ordinary derived four-slot index; it does not change source, assets, native records, compact vectors, global metadata or identity.

## Validation scope

The dedicated regression suite uses explicitly synthetic real-Git fixtures. It covers prior issuance and ancestry, whole-vector and metadata/identity preservation, source and nested asset mutation, exact edit intervals, orphan identity, separate surfaces, original raw tile coverage, unknown/null fields, deletion and current/caught-up replay. These tests do not create or claim a public visual review. An actual release still requires the independently authored current static and actual UI/visual evidence and the normal official build/Consumer checks.
