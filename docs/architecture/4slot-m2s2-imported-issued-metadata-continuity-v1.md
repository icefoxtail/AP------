# Imported M2-S2 vector across issued metadata additions, v1

This opt-in preserves an existing full compact that already passed the imported
current continuity and native-vector amendment contracts. It does not issue
native metadata, select a four-slot value, release a HOLD, or review mathematics.
Its initial production intake is the E023 source transition whose seven rows
received the already-issued namespace and review-status fields.

## Separate immutable approval and current source binding

The new `currentM2ImportedMetadataContinuity` evidence group contains exact Git
references for a carrier, a durable copy of the consumed request, its issued
receipt, and the original native review copy. The carrier uses
`m2-s2-imported-issued-metadata-continuity-v1` and the closed scope
`PRESERVE_LITERAL_AMENDED_VECTOR_ACROSS_ISSUED_METADATA_ADDITIONS_ONLY`.

The existing compact is read literally from `priorValidatedCompactRef`. The
existing historical adapter replays its complete original v1 and native
amendment contracts. No prior compact or source is synthesized from the current
candidate. The literal amended prior cannot itself carry this successor or a
display-repair closure. All original evidence identified by the replay must
remain present, with exact immutable and live bytes.

The current compact equals that literal prior plus this one evidence group.
Its source header, all items, format, candidate terms, reviewedBy, old evidence,
and every registrationHold remain unchanged. Updating the header SHA is not this
operation. The ordinary builder still performs its existing source-baseline,
per-item payload, asset, identity and HOLD checks.

## Closed source transition

The full source denominator, order, UID/ordinal/display-number joins and compact
coverage must agree. Each changed whole question may only add these four
previously absent fields:

| Field | Required issued value |
|---|---|
| courseKey | M2-2 |
| reviewStatus | reviewed_pass |
| tagConfidence | approved_final_qa |
| tagStatus | reviewed_pass |

The four values must also equal the exact issued metadata and runtime rows.
The request's `after.courseKey` must agree. Every other field of each changed
question is unchanged; every unselected whole question is unchanged. A held
question cannot receive these additions through this contract. Student payload
hashes and asset-reference sets are checked for all rows as an additional guard.
All local asset bytes must equal the literal prior source snapshot, the current
source snapshot, current HEAD and the live file.

The carrier records all rows, not only the changed subset, using immutable
whole-question and student-payload digests plus the exact added-field list.
It also carries the full unchanged compact-items digest. These records contain
no question, answer or explanation prose.

## Already-issued native artifact binding

The original request is an immutable ancestor reference to its consumed inbox
path. Its durable document copy has exactly the same raw bytes. It is a partial
FINAL_QA request with reviewed metadata and an empty registryChanges array.
The actual registered receipt's request digest is the existing stable JSON
digest, not a new hash convention. Request/receipt identities, source raw and
Git blob, full denominator, partial count, approval and exact selected set agree.
The receipt's own commit contains the exact current source bytes. Current source
and receipt each match immutable reference, current HEAD and live bytes.

For each changed row, applied metadata, applied identity, runtime and source
review repair entries join exactly once. The entire explicit request-after
object agrees with both issued metadata and runtime; the immutable native
review's explicit after fields agree with that request. The native review copy
equals the original accepted native Git artifact already referenced by the
amendment. Both request and receipt sourceReview entries name that same native
review, source and UID, retaining `METADATA_SOURCE_BINDING_ONLY` and
`newMathematicalQa: false`.

This artifact check records an existing issuance. It is not a replacement for
the native registrar or its Consumer checks and does not create an additional
native approval. Native registry, metadata, identity and runtime files are not
written by this module. In particular, the source namespace/status addition
does not authorize a semantic value absent from the immutable native history.

## Deletion and cache boundaries

An exact carrier on actual HEAD ancestry establishes a source-specific
obligation. Discovery uses full merge history, including a carrier present only
in a merge parent. Removing the marker, all proof files, or restoring the old
source/compact does not remove that obligation. Missing Git/HEAD inventory fails
closed. This version allows one immutable successor carrier per source; it does
not implement a generic repeated rebind or future metadata migration.

Only immutable obligation discovery is cached within one build. The complete
historical approval replay and current source, receipt, native copy, request
copy, old evidence and asset checks run before runtime cache reuse on every
build. The new helper joins the builder's code fingerprint and evidence digest.
Existing schemas and generic source validation remain unchanged.

## CI and evidence scope

The four new `.test.cjs` modules are explicit requiredCommands in the existing
runner and match its existing item-4slot scoped selector. Each retains the
default 60-second command budget. Tests use small synthetic Git repositories;
their native reviews and receipts are fixtures, never production approvals.
The real E023 source/carrier input and any later official registration result
must be reported separately from those fixture results.
