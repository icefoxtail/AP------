## 3. 대조 문항을 유형과 실행 범위로 정리하기

전체 PDF를 다시 훑는 것부터 시작하지 않는다. 현행 320개 대조 문항과 8개 설계를 입력으로 삼아 배정된 소량 유형의 실제 원문·기존 장면·문제 조건·풀이를 대조한다. 검토되지 않은 페이지는 계속 미검토로 남긴다. 캐시가 없으면 인덱스의 정확한 Drive 원본과 페이지를 회수하며, 원문을 못 읽으면 `EVIDENCE_DEBT`로 반환한다.

### 3.1 실행 판정

| 판정 | 확정에 필요한 근거 | 다음 처리 |
|---|---|---|
| `REUSE` 재사용 | 기존 장면의 기준 조건·도형·풀이·답과 교재 유형이 맞고 실제 화면/조작이 목표를 충족 | 문항 참조·진입 링크를 연결. 기능을 새로 복제하지 않음 |
| `EXTEND` 기존 확장 | 같은 수학 원리·상태 모델을 유지하며 조건·보조선·단계·생성기 추가로 목표 충족 가능 | 정확한 부족 요소와 수정 파일만 지정 |
| `NEW_SCENE` 진짜 새 장면 | 관련 기존 장면을 대조했으나 필요한 도형 위상·조건 또는 학습 조작을 기존 모델로 설명할 수 없다는 근거 | 단원 내 작은 신규 장면 제안. 새 HTML·새 재생기부터 만들지 않음 |
| `EVIDENCE_DEBT` 근거 추가 필요 | 원문, 좌표, 정답, 교육과정 풀이 또는 현재 장면 연결 근거가 부족 | 부족한 근거·필요 페이지·다음 확인만 명시. 구현 완료로 세지 않음 |

기존 JSON의 `status`는 이 판정의 입력이다. 이를 자동 변환하지 않는다. `covered` 행도 완전 재현 판정이 필요할 때만 추가 대조하며, 다른 상태를 결함 또는 신설 확정으로 승격하지 않는다. 현재 2개 시제품의 완료 범위는 보존한다.

각 확정 유형은 `familyId`, `coverageRowIds`, `sourceRefs`, `existingLab/scene`, `decision`, `reason`, `missingLearningElement`, `parameterDomain`, `sameModel`, `acceptance`, `evidenceDebt`를 갖는 짧은 작업지시로 만든다. 이는 업무 필드 계약이며 별도 대형 DB 구축 지시가 아니다. ROOT가 현행 대응표와 인계에 필요한 결론만 반영한다. 원시 비교 메모·캡처는 Git 밖에 둔다.

### 3.2 같은 유형의 수치 쌍둥이

수학 관계, 도형 연결, 묻는 대상, 풀이의 핵심 단계가 같고 수치만 다르면 한 `familyId`와 「새 문제」 생성기로 묶는다. 원본 행 ID는 모두 유지해 같은 생성기와 연결한다. 고정점이 꼭짓점에서 변의 중점으로 바뀌거나, 경로·단면·비율 제약이 달라지는 경우는 단순 수치 변형으로 합치지 않는다.

생성기는 유효한 조건만 만들고, 문제·그림·라벨·현재 풀이·답을 하나의 모델에서 계산한다. 최소 1개 실제 새 문제 변형과 의미 있는 대표 경계를 검산한다. 난수 전수 조사를 추가하지 않으며, 생성기 식의 일반 성립 근거와 검사한 사례를 구분한다. 원문 숫자 일치가 필수가 아닌 재사용에서는 **유형 대응**임을 명시한다. 특정 원문을 그대로 재현한다고 주장할 때는 수치·조건까지 일치해야 한다.

## 4. 학생 학습·그림 계약

한 유형의 기본 흐름은 **문제 → 조작 → 관찰 → 관계 → 식 → 답**이다. `sameModel`은 현재 문제의 조건·수치·도형·풀이·정답이 한 상태를 참조한다는 수용 기준이지, 모든 파일에 같은 이름의 함수를 강제하는 리팩터링 지시가 아니다.

- 처음에는 주어진 것과 구할 대상만 보인다. 답·결정적인 미공개 값은 공개 단계 전에 칩·라벨·보기 강조·끝 카드로 새지 않는다. 탐구의 일반 공식과 문제의 정답 노출을 구분한다.
- 움직임은 관계를 보여 주어야 한다. 조각·면·호가 어디에서 왔는지 색과 이름으로 추적하고, 필요한 보조선의 이유를 한 줄로 설명한다. 식만 바뀌는 가짜 단계나 의미 없는 모션을 만들지 않는다.
- 「새 문제」 뒤 풀이·정답·초기화가 새 조건을 따른다. 다른 예제의 풀이 완료를 현재 문제의 답 공개 조건으로 강제하지 않는다. 탐구값과 문제 조건을 구분해야 한다면 화면에서 명확히 구분한다.
- 중1 학생용 풀이에는 배우지 않은 삼각비·호도법·근호 계산을 숨은 전제로 쓰지 않는다. 설계자가 좌표 검산에 사용하는 방법과 학생에게 보여 줄 풀이를 분리한다. 입체는 세운 기본 모습, 평행이동은 가로 방향, 회전·접기는 의미 있는 축을 사용한다.
- 분수는 DOM·버튼·칩·캔버스 최종 출력 모두 위아래 조판한다. π와 정확한 분수를 소수나 빗금으로 바꾸어 넘기지 않는다. 단위·대응 색·변화한 치수를 함께 확인한다.
- 영상은 기존 키트로 8~15초, 목표 12초·핵심 하나·자막 2~3줄을 유지한다. 대본이 길어지면 학습 단위를 나누며, 공개 전 답을 자막에 쓰지 않는다. 영상 끝의 직접 해 보기에서 실제 조작부가 보이고 눌려야 한다.
- 작은 화면에서도 현재 문제·핵심 그림·활성 단계의 식을 읽을 수 있어야 한다. PC·태블릿 양방향·폰에서 실제 pointer로 확인한다. 버튼 타깃 44px, 포커스/스크롤 후 고정 무대에 가려지지 않는지 확인하되 사소한 픽셀 차이를 P1로 과장하지 않는다.

## 5. 소량 wave와 확대 조건

모든 wave는 **다음 실행 지시를 받은 뒤** 적용한다. 처음에는 유형 2개 안팎의 작은 묶음으로 결과를 확인하고, 통과한 방식만 독립 단원으로 병렬 확장한다. 담당자는 같은 파일을 동시에 고치지 않는다. 단계마다 원문·장면 대조를 마친 항목만 다음 단계로 넘긴다.

| 단계 | 계획 범위 | 종료 조건 |
|---|---|---|
| 현재 문서·보고 마감 | 분수 2차 FAIL·잔여 21/252, 독립 학생 검수 정정, 현재 코드 freeze 기록 | 결과 보고 뒤 사용자 결정 대기. 추가 분류·수리·확장 시작 없음 |

W0의 다음 실행 지시가 주어지면 ROOT가 먼저 고정할 표적 파일은 `apmath/playground/next/labs/alg-trig-geometry.html`(혼합 설명의 π 분수), `common-functions.html`(부등호 뒤 음수 기울기 분수), `geom-parabola.html`(기호식·수치식이 함께 있는 분수), `calc1-integral.html`(원시함수 계수 배열과 설명식)이다. 앞 경로 뒤 세 파일도 같은 `labs/` 아래다. 공용 처리 문제라면 정확한 kit 파일과 필요한 이유를 별도로 고정한다. ROOT 또는 ROOT가 지정한 단일 소유자만 각 파일을 수정하며 중1 단원 작업자에게 범위 밖 쓰기 권한을 암묵적으로 주지 않는다. 252개 후보의 추가 판정 없이 범용 문자열 치환을 전체 소스에 적용하지 않는다.

## 6. 역할·파일 소유권

공동 작업 중이며 타인의 수정은 되돌리지 않는다. 아래 폴더 허용 범위 안에서도 매 지시서에 **정확한 파일 allowlist**를 적는다. 폴더 전체를 무제한 수정하는 허가는 아니다.

| 역할 | 쓰기 소유권 | 입력·산출물 |
|---|---|---|
| ROOT / 통합 담당 | 공용 `kit/`, `kit/apl-catalog.js`, `apmath/playground/manifest.json`, 실험실 진입 HTML, 공용 tests/tools, 대응표·현행 인계 | 범위·판정 수납, 필요한 통합만 직접 또는 한 명에게 독점 배정, 무거운 검사 직렬 실행 |
| 다각형 제작 | `apmath/playground/next/labs/g7-polygons/` 안의 배정 파일 | 해당 family 원문·장면 → 코드·모델 설명·검산·변경 요약 |
| 원과 부채꼴 제작 | `apmath/playground/next/labs/g7-circle-sector/` 안의 배정 파일 | 동일 |
| 다면체·회전체 제작 | `apmath/playground/next/labs/g7-polyhedra/`, `g7-solids/` 안의 배정 파일 | 동일. 두 폴더를 여러 작업자로 나누면 파일 충돌 없이 별도 소유권 부여 |
| 겉넓이·부피 제작 | `apmath/playground/next/labs/g7-surface-volume/` 안의 배정 파일 | 동일 |
| 독립 수학 검수 | 제작 코드 읽기 전용, ROOT가 지정한 ignored 검수 출력만 | 원문·학생 문제에서 독립 풀이 → 기대값, 논리·좌표·경계·새 문제 확인, PASS/FAIL/부채 |
| 독립 학생 UX 검수 | 제작 코드 읽기 전용, 지정 검수 출력만 | 실제 최신 화면/조작 근거 → 찾기·읽기·조작·관계·식·답 흐름과 P0/P1/P2 |

공용 키트 변경은 단원 작업자가 하지 않는다. 필요한 경로와 이유를 ROOT에게 반환한다. HTML 연결·카탈로그·manifest·영상 `SCENE_STATE` 검사표도 ROOT 한 명이 관리한다. 수학 검수자와 학생 UX 검수자는 해당 제작에 참여하지 않은 인스턴스로 배정한다. 고친 제작자와 검수자 역할을 합쳐 자기 PASS를 내지 않는다. 검수자가 결함을 수정했다면 그 수정의 최종 독립 검수는 다른 인스턴스가 맡는다.

작업자의 기본 권한은 지정 읽기·파일 편집이다. 셸 실행·테스트·서버·Git·배포·MCP·재위임은 기본 차단하고 ROOT가 필요한 명령만 실행한다. 검수자는 ROOT가 실행한 최신 실제 캡처와 수학 상태를 검토할 수 있으며, 필요하면 ROOT에게 정확한 조작·조건·뷰포트 한 묶음을 요청한다. 검수 보고에는 직접 본 것과 수납한 측정, 미실행을 구분한다.

분수 full audit의 전체 범위는 표기 점검 범위다. 도구의 최종 텍스트·캔버스 호출 검사가 모든 픽셀 가림이나 학습 이해를 입증하지 않는다. 현재 도구는 각 모드의 대표 상태와 문제 새 변형을 보며, 임의로 모든 풀이 중간 프레임을 검수했다고 주장하지 않는다. 변경한 문항의 중요한 중간 단계는 실제 화면 검수에서 별도로 확인한다. `--only`는 진단용 `PARTIAL`이며 전체 PASS에 사용할 수 없다.

현재 시제품 환경은 PC 칠판/종이 1440×900, 태블릿 세로 768×1024·가로 1024×768, 폰 390×844다. 신규 UI는 계약의 태블릿 820×1180도 필요 시 확인한다. 전체 scene-smoke의 기존 PC 기준 1280×820 등은 도구 설정 그대로 유지한다. 서로 다른 분모의 결과를 합쳐 하나의 전수 PASS로 만들지 않는다.

### ROOT가 실행할 일반 명령

아래는 **실행 지시 이후** 쓸 명령 예시다. 현재 문서 작성 과정에서는 실행하지 않았다. 유효한 서버·브라우저·의존성은 실제 환경에서 확인하며, 이미 ROOT 서버 `8817`이 살아 있다면 재사용한다. 새 서버가 필요하면 ROOT가 저장소 루트에서 `python -m http.server 8817 --bind 127.0.0.1`로 실행하고 자신이 시작한 PID만 정리한다.

```powershell
node apmath/playground/next/tools/g7-coverage-check.mjs --scene-index .codex/g7-video-qa/scene-index.json
node --test apmath/playground/next/tools/catalog.test.mjs apmath/playground/next/tools/video.test.mjs apmath/playground/next/tools/fraction.test.mjs
node apmath/playground/next/tools/scene-smoke.mjs http://127.0.0.1:8817/apmath/playground/next/labs/ --only g7-polygons
```

마지막 명령의 대상은 실제 변경 랩으로 바꾼다. 공용 변경의 전체 검사에는 `--only`·`--runs`를 붙이지 않는다. 실제 Chrome 수집 장면 목록이 오래되면 ROOT가 변경 후 현재 목록을 다시 수집하며, 코드 추정으로 파일을 채우지 않는다.

```powershell
node apmath/playground/next/tools/scene-smoke.mjs http://127.0.0.1:8817/apmath/playground/next/labs/
node apmath/playground/next/tools/fraction-browser-audit.mjs http://127.0.0.1:8817/apmath/playground/next/ --out reports/g7-fraction-current
```

두 무거운 명령을 동시에 실행하지 않는다. `reports/g7-fraction-current`는 ignored 증거 출력으로만 사용한다. 시스템 Chrome이 필요한 환경에서는 실제 실행 경로를 확인해 도구가 지원하는 `CHROME_PATH`를 설정하며 assert나 페이지 분모는 바꾸지 않는다. 카탈로그 변경 시 ROOT가 `node apmath/playground/next/tools/gen-manifest.mjs`를 한 번 실행한다. 병합이 별도 승인된 때에만 `node tools/run-tests.js`를 병합 직전 한 번 실행한다. Archive 런타임 파일을 바꾸지 않는 이번 계획에 무관한 Archive 재생성·전수 QA를 끼워 넣지 않는다.

## 12. 남은 결정과 현재 정지점
