# 0. 프로젝트 목적

도형의 방정식 전수 업그레이드에서 확립한 핵심 원칙을 함수 계열에 맞게 재사용한다.

1. 전체 scope를 먼저 inventory/manifest로 확정한다.
2. 학생이 해설만 보고 풀이를 재현할 수 있는지 전수 판정한다.
3. 논리 점프가 있는 해설만 보강한다.
4. 그래프·대응도·역함수 대칭·점근선·교점·영역·이동 등 시각적 이해가 핵심인 문항에는 검증된 해설용 SVG를 추가한다.
5. 이미 충분히 좋은 해설은 불필요하게 다시 쓰지 않는다.
6. 문제·answer·solution·solutionImage 사이의 수학적 불일치를 제거한다.
7. 고1 교육과정 밖 풀이를 금지한다.
8. 수정 담당과 검수 담당을 분리한다.
9. Codex는 로컬 AP 저장소에서 구현하고, GitHub에 반영된 결과는 ChatGPT가 독립 검수한다.
10. 전체 단원 완료 시에만 최종 릴리스 검수와 봉인을 수행한다.

핵심 목표는 `solutionImage` 수를 늘리는 것이 아니다.

> **학생이 풀이의 논리와 그래프의 의미를 동시에 재현할 수 있게 만드는 것**이 목표다.

# 5. 전수 재작성 대신 전수 판정

모든 target 문항을 먼저 다음 5상태 중 하나로 분류한다.

```text
KEEP
TEXT_UPGRADE
VISUAL_ADD
TEXT_AND_VISUAL_UPGRADE
SOURCE_REVIEW
```

## KEEP

- 독립 검산 PASS
- solution 계산 PASS
- 논리 점프 없음
- 교육과정 적합
- 학생 재현 가능
- 시각자료 없이도 충분
- answer 일치

수정하지 않는다.

## TEXT_UPGRADE

다음이 있으면 solution만 보강한다.

- 계산 과정 생략
- 조건 이유 생략
- 경우 나누기 누락
- 정의역/치역 조건 생략
- 역함수 존재 조건 생략
- 제곱 후 무연근 검토 누락
- 교점 개수 경계 설명 부족
- 핵심 추론을 “정리하면/계산하면”으로 건너뜀

## VISUAL_ADD

solution 논리는 충분하지만 그래프/도식이 학생 이해에 필요한 경우.

## TEXT_AND_VISUAL_UPGRADE

논리 보강과 시각자료가 둘 다 필요한 문항.

## SOURCE_REVIEW

- 문제 성립성 의심
- answer 의심
- 원본 그림과 발문 불일치
- 메타데이터 오분류
- 문제 image가 실제 조건을 충족하지 않음

자동 수정 금지.

# 9. 함수 계열 전용 논리 점프 검수

## 9.1 역함수

다음 문장을 아무 조건 없이 쓰는 것을 금지한다.

```text
함수와 역함수의 교점이므로 y=x 위에 있다.
```

근거가 있어야 한다.

- 해당 함수가 증가함수
- off-diagonal 교점 불가능 별도 증명
- 문제 조건상 직접 `f(x)=x`
- 독립 검증으로 확정

## 9.2 역함수 존재

반드시 확인:

```text
일대일
+
공역 = 치역
```

조각함수는:

- 각 구간 치역
- 경계값
- 치역 겹침
- 전체 공역 커버

까지 확인한다.

## 9.3 합성함수

`f(g(x))`에서:

- 먼저 `g(x)`의 값/범위
- 그 값이 f의 어느 조각에 들어가는지
- 새 구간 경계가 어디서 생기는지

를 명시한다.

## 9.4 무리함수 방정식

제곱 또는 `t=sqrt(...)` 치환 시:

- radicand ≥ 0
- t ≥ 0
- 원래 식의 우변 부호
- 제곱 후 무연근
- 끝점 포함

을 확인한다.

## 9.5 두/세/네 교점

판별식만으로 끝내지 않는다.

- 정의역
- 가지별 허용 구간
- 접하는 경우
- 끝점
- 중복 교점
- 서로 다른 교점 수

를 판정한다.

## 9.6 최대·최소

고1 범위에서 미분 금지.

허용:

- 식 변형
- AM-GM
- 구간 끝값 비교
- 역수의 크기 관계
- 기본 그래프 성질
- 고1 수준 부등식

함수 그래프는 먼저 다음 fact를 생성한다.

```text
domain
keyPoints
xIntercepts
yIntercepts
endPoints
openPoints
closedPoints
asymptotes
symmetryLine
inverseRelation
branchDirection
intersectionPoints
```

## 유리함수

가능하면:

```text
y = A + K/(x-h)
```

형태로 변환하여:

```text
verticalAsymptote = h
horizontalAsymptote = A
center = (h,A)
sign(K)
branchQuadrantsRelativeToCenter
```

를 먼저 확정한다.

## 무리함수

가능하면:

```text
y = a*sqrt(b(x-h)) + k
```

형태에서:

```text
startPoint
domainDirection
rangeDirection
reflection
translation
```

을 먼저 확정한다.

## 역함수

대응점은 실제로:

```text
(x,y) ↔ (y,x)
```

인지 자동 확인한다.

대량 작업에서는 작업 branch를 staging으로 사용하고 main에 반완성본을 계속 누적하지 않는다.
