# AP 학생 포털 인터랙티브 학습 확장 계획

**STATUS: HOLD / PLAN ONLY**  
**작성일:** 2026-09-10  
**적용 대상:** JS아카이브 / 학생 포털 / 향후 APMS 연계

---

## 1. 목적

현재 학생 포털에서는 학생이 시험지, 해설지, 정답지를 열람할 수 있다.

향후 태블릿 보급 및 학생용 디지털 학습 환경이 준비되면, 기존의 단순 문서 열람 방식에서 확장하여 **학생이 시험지 화면 안에서 직접 문제를 풀고, 문항별 모범풀이와 상세해설을 단계적으로 확인할 수 있는 인터랙티브 학습 구조**를 구현한다.

핵심 목표는 새로운 문제 데이터를 별도로 만드는 것이 아니라, **JS아카이브의 동일한 정본 문항 데이터를 학생용 뷰어에서 재사용**하는 것이다.

---

## 2. 현재 상태

현재 아카이브 문항은 기본적으로 다음 정보를 보유한다.

- `content`
- `choices`
- `answer`
- `solution`
- `image`
- `solutionImage`
- 향후 정식 도입 예정인 `writtenSolution`

`writtenSolution`은 기존 `solution`을 대체하지 않는다.

역할은 다음과 같이 구분한다.

- `writtenSolution`: 학생이 시험 답안지에 실제로 작성할 수 있는 모범답안
- `solution`: 개념, 이유, 풀이 방향까지 포함한 상세 학습 해설
- `solutionImage`: 좌표평면, 수직선, 도형, 그래프 등 시각적 이해를 위한 해설 SVG/이미지

---

## 3. 장래 학생 포털 기본 구조

학생이 시험지를 열었을 때 문항별로 다음 흐름을 제공한다.

```text
문제
↓
학생 직접 풀이 / 답 입력
↓
정답 확인 또는 채점
↓
[모범풀이 보기]
↓
writtenSolution
↓
[상세해설 보기]
↓
solutionImage + solution
```

기존의 전체 `시험지 / 정답지 / 해설지` 열람 기능은 유지한다.

즉, 전체 해설지를 보는 기존 방식과 문항 바로 아래에서 필요한 해설만 펼쳐보는 방식을 함께 제공한다.

---

## 4. 학생용 인터랙티브 뷰어 방향

기존 `archive/engine.html`에 학생 기능을 계속 추가하는 방식보다, 장기적으로는 **학생 포털 전용 Interactive Exam Viewer**를 두는 것을 우선 검토한다.

권장 구조:

```text
JS아카이브 정본 데이터
        │
        ├─ 교사용 Archive Engine
        │    └─ 시험지 / 정답지 / 해설지 / 인쇄 / PDF
        │
        └─ 학생용 Interactive Exam Viewer
             └─ 문제 풀이 / 답 입력 / 모범풀이 / 상세해설
```

원칙:

1. 문제 데이터를 학생 포털용으로 복제하지 않는다.
2. Archive JS를 단일 정본으로 유지한다.
3. 교사용 인쇄 렌더러와 학생용 인터랙티브 렌더러의 역할을 분리한다.
4. 학생용 기능 때문에 기존 시험지/PDF 렌더 안정성을 훼손하지 않는다.

---

## 5. 1단계 기능

패드 보급 후 가장 먼저 검토할 최소 기능은 다음과 같다.

### 객관식

- 선택지를 직접 클릭
- 학생 답 선택
- 채점 또는 정답 확인
- 문항별 `모범풀이 보기`
- 필요 시 `상세해설 보기`

### 단답형

- 답 입력란 제공
- 정답 확인
- 모범풀이 확인
- 상세해설 확인

### 서술형

초기에는 자동 판독이나 AI 채점 없이 시작한다.

- 학생이 별도 종이나 태블릿에 풀이
- 문제 화면에서 모범풀이 확인
- 상세해설 확인

---

## 6. 패드 보급 후 확장

태블릿 보급이 실제로 이루어진 뒤 다음 기능을 순차적으로 검토한다.

```text
화면 필기
→ 풀이 저장
→ 학생 재열람
→ 교사 확인
→ 모범답안 비교
→ 상세해설 확인
→ 필요 시 AI 풀이진단
```

초기에는 손글씨 인식이나 자동채점을 필수 기능으로 보지 않는다.

먼저 **학생이 문제를 풀고, 자신의 풀이와 모범답안을 비교하는 경험**을 안정적으로 만드는 것을 우선한다.

---

## 7. 시각 해설 방향

평면좌표, 내분, 점의 위치관계, 절댓값, 부등식, 도형의 이동 등은 텍스트 해설만으로 설명하지 않고 필요 시 `solutionImage`에 SVG 시각해설을 제공한다.

특히 다음 유형은 수직선 또는 좌표평면 렌더를 적극 사용한다.

- 선분 위/밖의 점 위치
- 내분비
- 점의 순서
- 좌표 변화량
- 거리 관계
- 평행/수직
- 대칭이동
- 구간과 범위
- 경우 분류

학생 포털에서는 다음 순서가 기본이다.

```text
모범답안
→ 시각 해설 SVG
→ 상세해설
```

단, 문항에 따라 SVG가 필요하지 않은 경우에는 텍스트만 제공할 수 있다.

---

## 8. `writtenSolution`과의 관계

학생 포털 인터랙티브 기능의 핵심 데이터는 `writtenSolution`이다.

`writtenSolution`의 목적:

> 학생이 이 풀이를 시험 답안지에 그대로 작성했을 때, 불필요하게 길지 않으면서도 논리적 누락 없이 만점을 받을 수 있는가?

학생 포털에서는 `writtenSolution`을 **모범풀이**로 표시한다.

기존 `solution`은 **상세해설**로 유지한다.

따라서 향후 UI 구조는 다음과 같이 통일할 수 있다.

```text
[정답]
[모범풀이] writtenSolution
[시각해설] solutionImage
[상세해설] solution
```

## 9. 당장 하지 않는 것

현재는 패드 보급 전이므로 아래 기능은 구현하지 않는다.

- 학생용 Interactive Exam Viewer 개발
- 화면 필기
- 손글씨 저장
- OCR
- AI 풀이 채점
- AI 자동 첨삭
- 학생별 풀이 이력 저장
- 실시간 교사 피드백
- 신규 학생용 스키마 대규모 확장

패드 도입 전에는 불필요한 유지보수 코드가 늘어나지 않도록 **계획만 보존하고 구현은 HOLD**한다.

## 10. 지금 진행할 것

현재 우선순위는 다음과 같다.

4. 학생 제출형 모범답안 작성 기준 확정
5. 시험지 단위로 `writtenSolution` 점진 확대

## 11. 재개 조건

다음 중 하나 이상이 실제로 발생하면 본 계획을 다시 검토한다.

- 학원 학생용 태블릿 보급 결정
- 학생이 웹에서 직접 문제를 풀어야 할 필요 발생
- `writtenSolution` 정식 규칙과 렌더 구조 확정
- 학생 포털 개편 착수
- 풀이 저장 또는 교사 확인 기능의 실제 운영 필요 발생

재개 시에는 바로 전체 기능을 만들지 않고 **시험지 1개 파일럿**부터 시작한다.

권장 첫 파일럿 범위:

```text
문제 보기
→ 답 선택/입력
→ 정답 확인
→ 모범풀이 펼침
→ 상세해설 펼침
```

AI, OCR, 필기 인식은 이 파일럿의 범위에서 제외한다.

---

## 12. 장기 확장 가능성

기본 인터랙티브 뷰어가 안정화된 이후에만 다음 확장을 검토한다.

- 학생 풀이 저장
- 오답 자동 수집
- 문항별 재도전
- 모범답안 비교
- 교사 코멘트
- AI 풀이진단
- 취약 유형 분석
- APMS 학습 이력 연동

장기적으로는 다음 학습 흐름을 목표로 할 수 있다.

```text
학생 자기 풀이
→ 답 제출
→ 채점
→ 모범답안
→ 시각해설
→ 상세해설
→ 재도전
```

---

## 13. 운영 원칙

이 계획의 핵심 운영 원칙은 다음과 같다.

1. **정본은 하나다.** 학생 포털용 문제 데이터를 별도 복제하지 않는다.
2. **`solution`을 버리지 않는다.** `writtenSolution`과 역할을 분리한다.
3. **시각화가 필요한 문제는 SVG로 직접 설명한다.**
4. **교사용 인쇄 엔진과 학생용 인터랙티브 뷰어를 가능한 한 분리한다.**
5. **패드 보급 전에는 구현하지 않는다.**
6. **재개 시 한 시험지 파일럿부터 검증한다.**
7. **AI는 마지막 단계다.** 먼저 학생 풀이 → 모범답안 → 상세해설 구조를 안정화한다.

## 14. 현재 결론

**STATUS: HOLD**

현재는 학생 포털 인터랙티브 기능을 구현하지 않는다.

먼저 아카이브 내부의 `solution`, `solutionImage`, `writtenSolution` 품질을 충분히 올린다.

패드 보급 또는 실제 학생용 디지털 풀이 수요가 생기면 이 문서를 기준으로 다시 시작한다.
