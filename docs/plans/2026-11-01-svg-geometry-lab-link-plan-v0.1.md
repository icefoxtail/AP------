# 문제·해설 SVG 그림 ↔ 중1 도형실험실 연결 계획서 (v0.1 초안)

작성일 2026-11-01 · 상태: 초안(실행 전) · 천천히 진행하는 장기 계획이다. 이 문서는 구현이 아니라 방향 정리다.

## 1. 목표

- 학생이 문제·해설 그림 옆의 "직접 움직여 보기" 버튼을 눌러 도형실험실을 열고, 같은 도형을 끌어서 조작해 본다. (예시: 해설 그림의 부채꼴 → 중심각을 직접 바꿔 보기)
- 좋은 점: 정지한 그림으로 이해가 안 되던 것을 눈으로 확인할 수 있다. 풀이를 읽은 뒤 "왜 그런지"를 스스로 확인한다.
- 한정: 중1(g7) 도형 단원, 실험실이 이미 있는 주제만. 모든 문항에 붙이지 않는다.

## 2. 현재 상태 (조사한 사실만)

- 도형실험실은 `apmath/playground/labs/g7/`에 있다. 파일: `points-lines.html`, `polygons-area.html`, `polyhedra.html`, `spatial-relations.html`, `nets-folding.html`, `입체도형의 겉넓이와 부피.html`, `원과_부채꼴_통합_마스터_스튜디오.html` 등. 학년 폴더 g8, g9 등도 같은 위치에 있다.
- 그리는 방식: `points-lines.html`은 Canvas 2D(`#boardCanvas`, `getContext('2d')`)로 그린다. 도형이 SVG가 아니라 실시간 Canvas 그림이다.
- 입력 파라미터: 확인된 것은 `원과_부채꼴_통합_마스터_스튜디오.html`의 `?start=basic`, `?start=transform`(시작 구역 선택)뿐이다. 도형 값(각도·길이)을 URL로 받는 곳은 표본에서 찾지 못했다.
- 문제·해설 그림: 시험지 데이터의 문항 필드 `image`, `solutionImage`(+ `imageAlt`, `solutionImageAlt`)를 `archive/engine.html`이 그린다(2326, 2361행 부근). 대체 텍스트는 `archive/svg-accessibility.js`가 고른다.
- SVG 해설 그림 엔진은 `archive/tools/geometry-equation/`이다. 현황·방식은 `HANDOFF_SVG_ENGINE.md`, 작성 규칙은 `production/AUTHOR_GUIDE.md`, 시험지 그림 원장은 `production/exam-figure-ledger.json`. 현재는 고1·기하 등 좌표·원뿔곡선·벡터 중심으로 확장 중이고, 중1 도형이 얼마나 덮이는지는 확인하지 못했다.
- 런타임 계약(`docs/rules/01_CANONICAL/Archive2_Runtime_Responsiveness_and_Original_Source_Contract_v1.md`): 원본은 `engine.html?data=exams/<file>&mode=exam|sol|ans`로 직접 열려야 하고, 클릭 이벤트에서 완성된 URL로 새 창을 연다(17행). 창 간 데이터 전달은 origin·sender·nonce를 검증한다(36행). 공통 JS와 HTML/새 창/iframe의 캐시 버전을 함께 올린다(45행).

EVIDENCE_DEBT
- 실험실 전체(g7 외 g8·g9)와 도형 값 URL 입력 지원 여부 전수 확인 안 함.
- 시험지 JSON의 `solutionImage`가 SVG 문자열인지 파일 참조인지, 그림 메타(도형 종류·값)가 따로 있는지 확인 안 함.
- 중1 문항 중 실험실과 짝이 되는 후보 수 미확인.
- `apmath/playground`(학생이 접속하는 주소·배포 경로)와 `archive`의 같은 출처 여부 미확인.

## 3. 연결 방식 후보

**A. URL 파라미터 (딥링크)**: 그림 옆 버튼이 `labs/g7/<실험실>.html?preset=<이름>` 또는 `?angle=60&r=5`로 열고, 실험실이 값을 읽어 초기 상태를 만든다.
- 장점: 가장 단순. 새 창이라 계약(클릭 시 완성 URL로 새 창)과 맞는다. 실험실마다 따로 붙일 수 있다.
- 단점: 실험실마다 파라미터 읽는 코드를 넣어야 한다. 값이 복잡한 도형은 URL이 길어진다. 해설 그림과 실험실의 도형이 완전히 같다는 보장은 없다.

**B. 공통 도형 기술 형식**: 그림 엔진과 실험실이 같은 JSON(도형 종류·값)을 읽는다.
- 장점: 그림과 실험실이 한 데이터에서 나와 불일치가 없다.
- 단점: 엔진(SVG)과 실험실(Canvas)을 모두 고쳐야 해서 가장 크다. 기존 승인 그림과 충돌 위험. 지금 단계에는 과하다.

**C. 실험실을 그림 안에 임베드(iframe)**: 해설 영역에 실험실을 직접 끼운다.
- 장점: 페이지를 떠나지 않는다.
- 단점: 휴대폰에서 좁고 터치 스크롤과 충돌한다. 출력(인쇄)·캐시 버전·창 간 전달 계약 부담이 크다. 실험실이 큰 전체 화면 구조라 부적합할 가능성이 높다.

**추천: A (URL 파라미터, 새 창).** 이유: 계약과 가장 덜 부딪히고, 실험실 1개와 문항 1~2개만으로 시범이 가능하며, 효과가 없으면 쉽게 걷어낼 수 있다. 시범이 성공하고 대상이 늘면 그때 B의 공통 형식을 `preset` 이름 표로 점진적으로 만든다.

## 4. 단계 계획

각 단계의 완료 기준은 "학생이 PC·휴대폰에서 열어 보고 이해할 수 있는가"이다. 수치 전수 측정은 하지 않고 대표 화면으로 확인한다.

1. **조사 마무리(읽기 전용)**: 위 EVIDENCE_DEBT 해소, 짝이 될 문항·실험실 후보 목록 작성.
2. **시범**: 실험실 1개(예: 원과 부채꼴 스튜디오) + 문항 1~2개. 실험실이 `preset`을 읽고, 해설 그림 옆에 버튼 하나를 둔다. 완료: PC·휴대폰에서 버튼 → 실험실이 같은 도형으로 열림 → 학생이 조작해 이해, 뒤로 돌아와도 원본 기출이 정상.
3. **확대 판단**: 시범 반응을 보고 실험실·문항을 늘릴지 사용자가 결정.
4. **(선택) 공통 형식**: 대상이 충분히 많을 때만 B를 검토.

## 5. 지켜야 할 것

- 원본 기출 링크(`engine.html?data=exams/<file>&mode=exam|sol|ans`)는 그대로 열려야 한다.
- 문제의 수학 값과 정답·해설은 바꾸지 않는다. 버튼 추가는 표시 변경일 뿐이다.
- 런타임 계약: 클릭 시 완성 URL로 새 창, 캐시 버전 동시 갱신, 병합 전 `node tools/check-archive2-runtime.cjs`, 흐름을 바꾸면 실제 Chrome 확인.
- 그림 정확성: 그림을 건드리면 `docs/agents/visual-svg.md` 절차를 따른다(source PNG 불변, 실제 렌더 확인, 학생 UI 연결 확인). 실험실 도형이 해설 그림과 값이 맞는지 사람이 직접 대조한다.
- 작업 방식: 수정과 검수는 서로 다른 Sonnet, 메인은 결과를 직접 확인(루트 CLAUDE.md).

## 6. 디자인 개선과의 관계

실험실 화면 디자인 다듬기는 새로 들이는 `/impeccable` 스킬(다른 작업자가 추가 중, 이번 조사 시점에는 `.claude/skills`에서 확인 못 함 = EVIDENCE_DEBT)로 하는 별도 작업이다. 연결 작업의 선행 조건이 아니며, 연결 뒤에 하거나 병행해도 된다. 다만 같은 실험실 파일을 동시에 고치면 충돌하니 같은 실험실에는 한 번에 한 작업만 한다.
