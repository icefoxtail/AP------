# 고1 단원별 기출 아카이브 설계·구현 계획서

- 작성일: 2026-08-05
- 상태: 1차 구현 완료 (로컬 데이터·화면·출력 검증 완료, 실계정 배정 E2E 확인만 남음)
- 대상: `archive/`의 교사용 JS 아카이브
- 1차 데이터 범위: 고1 학교 기출 `1학기 중간`, `1학기 기말`, `2학기 중간`
- 출력 방식: 기존 `mixed_engine.html` 재사용
- 학습 결과: 학생 직접 채점 후 틀린 번호 제출, 기존 OMR·오답 클리닉에 연결

## 1. 목표

고1 학교 기출 문항을 2022 개정 교육과정의 단원 순서로 자동 집계하여 아카이브에 `단원별 기출` 화면을 제공한다. 선생님은 단원 카드를 열어 자동 분할된 `문제지 1`, `문제지 2` 등을 일반 출력하거나 반·학생에게 출제할 수 있어야 한다.

새 시험지가 아카이브에 정상 등록되고 `question-index.js`가 갱신되면, 별도의 단원 문제지 생성 작업 없이 다음 항목이 자동으로 갱신되어야 한다.

- 단원별 문항 수
- 단원별 문제지 수
- 각 문제지의 문항 목록
- 출력 시점의 고유 문제지 식별자
- 혼합 문제지 블루프린트와 오답 분석용 원본 문항 연결

## 2. 확정 결정

1. 기능 위치는 시험지 보관함이 아니라 JS 아카이브로 한다.
2. 아카이브 분류 이름은 `단원별 기출`로 한다.
3. 학생은 정답지로 직접 채점한 뒤 틀린 문항 번호만 제출한다.
4. 학생 답안을 받아 자동 비교·채점하는 새 채점 방식은 만들지 않는다.
5. 한 단원의 전체 문항은 보여 주되 한 시험지로 출력하지 않고 자동 분할한다.
6. 권장 분할 크기는 약 40~50문항, 시스템상 절대 상한은 80문항으로 한다.
7. 가능한 한 같은 원본 시험지의 문항은 서로 다른 문제지로 갈라놓지 않는다.
8. 현재 공개 범위는 `2학기 중간까지`로 고정한다.
9. 이후 범위 확대는 설정값 변경으로 처리하며 엔진 수정이나 문제지 재생성은 요구하지 않는다.
10. `engine.html`, `mixed_engine.html`, `wrong_print_engine.html`은 기존 결함이 발견되지 않는 한 수정하지 않는다.

- 2022 개정 표시 단원으로 분류: 1,846문항

## 4. 데이터 범위와 포함 규칙

### 4.1 포함

- `question-index.js`에 등록된 문항
- `sourceFile`이 `original/high/h1/` 아래인 학교 기출
- 시험 구간이 `1mid`, `1final`, `2mid` 중 하나인 문항
- 원본 파일과 문항 번호를 확인할 수 있는 문항
- 2022 개정 표시 단원으로 직접 또는 별칭 매핑되는 문항

### 4.2 제외

- `types`, `similar`, `assessment`, 교재 문항
- `2final` 이후 시험 구간
- 빈 문항 레코드
- 원본 파일 또는 원본 문항 번호가 없는 문항
- 분류가 확정되지 않은 문항

제외된 정상 문항은 삭제하지 않고 `검토 필요` 집계에 남긴다. 교사용 화면에서 검토 문항 수와 원본 위치를 확인할 수 있어야 하며 일반 단원 문제지에는 포함하지 않는다.

### 4.3 범위 설정

범위는 코드 곳곳의 조건문으로 흩어놓지 않고 하나의 설정으로 관리한다.

```js
const HIGH1_UNIT_ARCHIVE_SCOPE = {
  id: 'h1-through-2mid-v1',
  grade: '고1',
  sourcePrefix: 'original/high/h1/',
  periods: ['1mid', '1final', '2mid'],
  targetQuestionsPerPaper: 50,
  hardMaxQuestionsPerPaper: 80
};
```

나중에 `2final`을 포함할 때는 `periods`와 범위 버전만 변경한다.

`H22-C-*`, `H22-C2-*` 키는 동일한 키로 통과시킨다. 행렬은 `H22-C-09`에 포함한다.

자동 매핑보다 수동 검토 결과를 우선한다. 예외 목록은 별도 오버라이드 객체로 관리하며 최소한 다음 교정 사항을 포함한다.

- `22효천고 1학기 기말 12번`: 근호의 대소 비교 문제이므로 `H22-C-06`

오버라이드 키는 사람이 읽는 제목이 아니라 `sourceFile + 원본 문항 번호` 조합을 사용한다.

## 7. 자동 분할 규칙

### 7.1 정렬

문항은 다음 순서로 안정 정렬한다.

1. 시험 구간: `1mid` → `1final` → `2mid`
2. 연도
3. 학교명 또는 원본 파일 경로
4. 원본 문항 번호

동일한 데이터에서는 항상 동일한 결과가 나와야 한다.

### 7.2 원본 시험지 묶음

한 단원 안에서 같은 `sourceFile`을 가진 문항을 하나의 묶음으로 만든다. 묶음 단위로 현재 문제지에 추가하여 목표 50문항에 가깝게 채운다.

- 묶음을 더했을 때 50을 조금 넘더라도 80 이하면 같은 문제지에 둘 수 있다.
- 현재 문제지와 다음 문제지 중 50에 더 가까운 쪽을 선택한다.
- 한 원본 묶음 자체가 80문항을 넘는 예외 상황에서만 원본 문항 번호 순으로 나눈다.
- 어떤 결과도 80문항을 초과하면 안 된다.

### 7.3 문제지 이름

- 단원 문항이 한 묶음이면: `여러 가지 방정식과 부등식`
- 둘 이상이면: `여러 가지 방정식과 부등식 · 문제지 1`, `문제지 2`, …

`권`, `파트`는 사용하지 않는다. 화면에서는 각 문제지에 문항 수와 포함 시험지 수를 함께 표시한다.

### 7.4 출력 스냅샷

동일한 `문제지 1`이라는 이름이 나중에 다른 문항 구성을 가질 수 있으므로 이름을 데이터 식별자로 사용하지 않는다.

스냅샷 식별자는 다음 값의 안정 직렬화 결과로 만든다.

- 범위 버전
- 표시 단원 키
- 순서가 고정된 `sourceFile + sourceQuestionNo` 목록

예시:

```text
unitpast:h1-through-2mid-v1:H22-C-06:8f31c92a7d
```

`mixed_engine.html`에는 이 키가 전달되고 서버에는 기존 규약대로 `MIXED:{key}`가 등록된다. 새 시험지가 추가되어 현재 분할이 바뀌어도 과거 문제지의 출제·오답 기록과 블루프린트가 덮어써지지 않아야 한다.

## 8. 화면 설계

### 8.1 아카이브 진입

기존 분류 선택 목록에 `단원별 기출`을 추가한다. 해당 분류를 선택하면 일반 시험지 카드 대신 전용 단원 카드를 렌더링한다.

별도 서비스처럼 보이지 않도록 기존 아카이브의 카드 폭, 여백, 색상, 반응형 기준을 따른다.

### 8.2 단원 카드

각 카드에는 다음을 표시한다.

- `공통수학1` 또는 `공통수학2`
- 2022 개정 단원 순서와 단원명
- 현재 문항 수
- 자동 분할된 문제지 수
- 범위 배지: `2학기 중간까지`

0문항인 단원은 숨기지 않고 비활성 상태로 표시한다. 향후 데이터가 들어오면 자동 활성화된다.

### 8.3 단원 상세

카드를 열면 문제지 목록을 표시한다.

- `문제지 1 · 48문항 · 4개 학교시험`
- `문제지 2 · 51문항 · 5개 학교시험`
- 포함 시험 구간 요약
- `일반 출력`
- `반·학생에게 출제`

전체 274문항을 한 번에 출력하는 버튼은 제공하지 않는다. 필요하면 여러 문제지를 순서대로 출력하도록 안내한다.

### 8.4 검토 필요

교사 로그인 상태에서만 `검토 필요` 카드를 표시한다.

- 미분류 문항 수
- 빈 레코드 수
- 원본 시험지와 문항 번호
- 감지된 기존 키 또는 임시 태그

1차 구현에서는 화면에서 단원 키를 수정하는 편집 기능까지 만들지 않는다. 원본 데이터 교정 후 인덱스를 재생성하면 자동 반영되게 한다.

## 9. 출력 및 출제 연결

### 9.1 문항 복원

문제지 버튼을 누르면 포함된 `sourceFile`을 한 번씩 순차 로드하고 인덱스의 문항 번호와 일치하는 원본 문항을 복원한다. 출력 객체에는 다음 필드를 반드시 유지한다.

```js
{
  ...originalQuestion,
  _sourceFile: sourceFile,
  _sourceQuestionNo: originalQuestion.id,
  _qKey: `${sourceFile}_${originalQuestion.id}`,
  standardUnitKey: mappedH22UnitKey,
  standardUnit: mappedH22UnitName,
  standardCourse: mappedH22Course
}
```

누락 문항이 하나라도 있으면 조용히 제외하지 않는다. 누락 목록을 보여 주고 출력을 중단한다.

### 9.2 믹서엔진 전달

복원한 문항 배열과 메타데이터를 기존 규약으로 저장한다.

- `localStorage['mixedQuestions_' + snapshotKey]`
- `localStorage['mixedMeta_' + snapshotKey]`
- `mixed_engine.html?key={snapshotKey}&qpp={값}`

메타데이터 제목에는 단원명과 문제지 번호를 포함한다. 문항 수가 길어도 정답·해설 출력은 기존 믹서엔진 기능을 그대로 사용한다.

### 9.3 일반 출력

일반 출력은 제출 QR 없이 믹서엔진을 연다. 서버 출제 등록과 학생 오답 수집은 수행하지 않는다.

### 9.4 AP 제출 QR 출력

기존 아카이브의 출제 대상 선택 화면을 재사용한다.

- 담당 교사 기준 반 조회
- 여러 반 선택
- 반 안의 일부 학생만 선택 가능
- 반별 `class_exam_assignments` 등록
- 제외 학생은 기존 exclusion 규약 사용
- 등록 성공 후 `submitQr=1`로 믹서엔진 열기
- 출력 전에 블루프린트 등록 가능 상태 확인

기존 대상 선택 흐름이 `engine.html` 호출로 고정되어 있다면, 대상 선택 UI 자체를 복제하지 않고 출력 콜백만 일반 시험지와 혼합 문제지가 선택할 수 있도록 좁은 어댑터를 둔다.

## 10. 학생 채점·오답관리 연결

현재 정책과 동작을 그대로 보존한다.

1. 학생이 정답지로 직접 채점한다.
2. 학생페이지에서 틀린 번호만 선택한다.
3. 제출 시 점수와 `wrong_answers`가 저장된다.
4. 제출 완료 후 일반 시험 OMR은 수정·재제출할 수 없다.
5. 교사는 반별 제출 현황과 문항별 정답률을 본다.
6. 문제지 블루프린트의 원본 파일·원본 번호·단원 키를 이용해 오답 클리닉을 만든다.

학생페이지에 아카이브 원본 파일 경로나 시험지 직접 열기 링크를 노출하지 않는다.
