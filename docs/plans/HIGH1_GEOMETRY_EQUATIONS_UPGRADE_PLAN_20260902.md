# 고1 도형의 방정식 단원 업그레이드 및 다중 독립 검수 계획

작성일: 2026-09-02
대상: 고1 도형의 방정식 관련 아카이브 문항
상태: 계획 수립

## 1. 계획 목적

고1 도형의 방정식 단원의 기존 문항을 시험지 하나씩 완료하는 방식이 아니라 단원 전체를 전수 분석·제작한 뒤, 서로 다른 독립 에이전트의 검수와 수정 루프를 반복하여 학생용 해설과 도형 시각화를 함께 업그레이드한다.

핵심 목표는 다음과 같다.

- 학생이 풀이를 재현할 수 있도록 논리 점프가 없는 해설 작성
- 풀이에 필요한 점·직선·원·접점·교점·이동 관계를 SVG로 시각화
- 해설과 SVG 사이의 수학적·교육적 불일치 제거
- 제작자 자체 점검과 독립 검수를 분리
- 수정이 발생할 때마다 이전 검수 결과를 무효화하고 새 산출물을 재검수
- 최종 마더 에이전트가 전체 단원 릴리스를 봉인

## 3. 전수 범위

현재 사용자용 고1 단원 카탈로그의 원본·고1 범위 기준으로 다음 문항을 전수 대상으로 삼는다.

| 표준 단원 | 문항 수 | 1차 작업 방향 |
|---|---:|---|
| H22-C2-01 평면좌표 | 102 | 해설 및 SVG 신규·보강 |
| H22-C2-02 직선의 방정식 | 87 | 해설 및 SVG 신규·보강 |
| H22-C2-03 원의 방정식 | 140 | 기존 작업물 전체 재감사 및 보강 |
| H22-C2-04 도형의 이동 | 96 | 해설 및 SVG 신규·보강 |
| 합계 | 425 | 전체 단원 검수 |

현재 기준으로 약 285문항은 신규 해설·SVG 집중 제작 대상이고, 원의 방정식 140문항은 기존 산출물을 포함한 전수 재감사 대상으로 본다.

유사문항 101개는 현재 사용자용 단원 카탈로그에 포함되지 않으므로 이번 1차 범위에서는 제외한다. 유사문항까지 포함하려면 별도 범위 확정과 manifest 재생성이 필요하다.

## 4. 작업 단위와 운영 방식

최종 검수 범위는 시험지 하나가 아니라 단원 전체다. 다만 제작과 검수 과정에서는 누락 방지를 위해 문항 ID와 5문항 배치 루프를 사용한다.

- 상위 작업 단위: 도형의 방정식 전체 단원
- 추적 단위: 출처 파일 × 표준 단원 × 문항 ID
- 제작 배치 단위: 5문항
- 검수 결과 단위: 개별 문항 FAIL/PASS와 전체 단원 집계
- 최종 릴리스 단위: 네 개 표준 단원을 합친 전체 범위

5문항 배치는 작업 편의를 위한 내부 루프이며, 검수 완료를 일부 시험지의 PASS로 간주하지 않는다. 전체 manifest의 모든 문항이 검수 대상에 포함되어야 한다.

## 5. 보호 범위와 수정 허용 범위

### 보호 필드

- 문제 본문
- 보기
- 정답
- 출처 및 기본 식별 정보

### 기본 수정 허용 필드

- 학생용 해설
- `solutionImage`
- 해설에 연결된 SVG 및 관련 시각 자산
- 필요 시 해설 표시용 메타데이터

문제·보기·정답 자체의 오류가 의심되면 임의로 고치지 않고 `SOURCE_DEFECT` 또는 `ANSWER_DEFECT`로 기록한다. 해당 필드의 수정은 별도 승인과 재검수 범위를 새로 확정한 뒤 진행한다.

## 6. 전체 실행 프로토콜

### 0단계. 전수 manifest 동결

전체 425문항에 대해 다음 정보를 고정한다.

- 문항 ID와 출처 파일
- 표준 단원과 세부 유형
- 기존 해설·SVG 존재 여부
- SVG 필수 여부
- 퇴화·공집합·실그래프 불필요 예외 여부
- 보호 필드와 수정 허용 필드

manifest가 동결된 뒤에는 새 문항을 임의로 추가하거나 검수 대상에서 제외하지 않는다.

### 1단계. 전수 해설·교육성 분석

전체 문항을 대상으로 다음을 확인하고 해설 개선안을 만든다.

- 학생이 중간 논리를 건너뛸 가능성이 있는 부분
- 점·직선·원·접점·교점의 정의 누락
- 조건을 식에 적용하는 과정의 생략
- 경우 나누기와 범위 조건의 누락
- 답은 맞지만 학생이 재현하기 어려운 풀이
- 그림이 있으면 이해가 쉬워지는 문항
- 식만으로 충분하여 SVG 예외가 가능한 문항
- 퇴화·공집합·실수해 부재에 해당하는 문항

해설은 고1 학생이 풀이를 그대로 재현할 수 있도록 작성하며, 내부 검수 메모나 에이전트용 표현을 학생용 해설에 남기지 않는다.

### 2단계. 전수 SVG 제작 및 해설 연결

1단계의 시각화 요구사항을 기준으로 SVG를 제작한다.

- 좌표축, 점, 직선, 원의 위치가 실제 계산과 일치해야 한다.
- 해설에 등장하는 점·직선·원·접점·교점의 이름이 SVG 라벨과 일치해야 한다.
- 문제 조건과 그림의 위치관계가 일치해야 한다.
- 점선, 화살표, 접선, 교점 등 의미 있는 요소를 구분한다.
- SVG 내부에 LaTeX, `<br>`, 외부 리소스, 불필요한 HTML을 넣지 않는다.
- clipping, overflow, 라벨 겹침을 방지한다.
- 그림이 없는 경우에는 단순 누락이 아니라 명시적인 예외 사유를 기록한다.

### 3단계. 독립 에이전트 A — 수학·해설·교육성 검수

제작자와 다른 컨텍스트의 독립 에이전트가 전체 manifest를 검수한다. 이 에이전트는 수정하지 않고 FAIL과 근거만 기록한다.

검수 항목:

- 문제·보기·정답·해설의 일치
- 계산과 공식의 정확성
- 논리 점프와 근거 없는 결론
- 조건·범위·경우 나누기 누락
- 교육과정 적합성
- 학생이 해설을 보고 풀이를 재현할 수 있는지
- 시각화가 필요한데 `solutionImage`가 빠졌는지

권장 실패 코드:

- `FAIL_SOLUTION_LOGIC`
- `FAIL_SOLUTION_CALCULATION`
- `FAIL_CONDITION_CASE`
- `FAIL_ANSWER`
- `CURRICULUM_FAIL`
- `SOLUTION_VISUAL_MISSING`

### 4단계. 수정 프로토콜 1차

- A 검수의 FAIL 문항만 수정한다.
- 문제·보기·정답은 기본적으로 수정하지 않는다.
- 해설을 수정하면 관련 SVG의 좌표·라벨·설명도 함께 재생성한다.
- 문항별 수정 전후 diff와 수정 사유를 기록한다.
- 수정된 산출물에 새 SHA를 부여한다.
- 수정 이전의 PASS는 모두 무효화한다.
- 수정 문항만 고치는 데 그치지 않고 전체 solution 렌더를 다시 생성한다.

### 5단계. 독립 에이전트 B — SVG·도형 대응성 검수

A와 다른 독립 에이전트가 SVG와 해설의 대응성을 검수한다.

핵심 검수 관계:

- 문제 ↔ 해설
- 문제 ↔ SVG
- 해설 ↔ SVG

세부 항목:

- 점·직선·원·접점·교점의 위치와 계산 일치
- 접선, 교점, 교차 여부, 내부·외부 위치관계의 정확성
- 좌표축과 눈금의 방향 및 라벨 일치
- 선분·점선·화살표의 의미 일치
- 라벨 겹침, 잘림, 화면 밖 요소, 빈 패널
- 학생이 그림을 보고 잘못 해석할 가능성

### 6단계. 수정 프로토콜 2차

- B 검수의 FAIL 문항만 수정한다.
- SVG를 고칠 때 해설의 수치·라벨과 함께 재확인한다.
- 수정된 SVG의 정적 유효성 검사를 다시 수행한다.
- 전체 단원의 SVG 존재·동기화 검사를 다시 수행한다.
- `solution`, `exam`, `answer` 렌더를 다시 생성한다.
- 새 artifact SHA와 수정 ledger를 기록한다.

### 7단계. 독립 에이전트 C — 파일·엔진·릴리스 무결성 검수

세 번째 독립 에이전트는 수학 내용과 별도로 실제 릴리스 산출물을 검수한다.

- SVG XML과 path 구조의 유효성
- 파일 존재성과 경로 일치
- JS·DB·question-index의 문항 수와 ID 일치
- `solution`, `exam`, `answer` 실제 렌더 여부
- 브라우저 console 오류
- 페이지 overflow와 clipping
- 보호 문항의 변경 여부
- `NOT_TESTED` 항목 존재 여부
- 현재 artifact SHA와 검수 완료 SHA 일치 여부

C에서 FAIL이 발생하면 수정 프로토콜을 다시 수행한 뒤 C 검수를 반복한다. C가 확인하지 못한 항목은 PASS로 처리하지 않는다.

### 8단계. 최종 마더 에이전트 — 전체 단원 봉인

마더 에이전트는 제작자가 아닌 최종 검수자로서 모든 결과를 종합한다.

최종 PASS 조건:

- 독립 A·B·C 검수 모두 PASS
- 미해결 FAIL 없음
- `NOT_TESTED` 없음
- 보호 필드 변경 없음
- 모든 수정 이력과 SHA가 연결됨
- 전체 solution/exam/answer 렌더 완료
- SVG 필수 문항에 시각화가 존재함
- SVG 예외 문항은 예외 사유가 기록됨
- 최종 산출물 SHA와 검수 대상 SHA가 일치함

조건을 하나라도 만족하지 못하면 전체 단원은 `SEALED`가 아니라 `REPAIR_REQUIRED`로 남긴다.

## 7. 검수 상태 모델

문항과 전체 단원에 다음 상태를 사용한다.

`BUILDING → SELF_CHECKED → FROZEN → VERIFYING_A → REPAIRING → VERIFYING_B → REPAIRING → VERIFYING_C → FINAL_REVIEW → SEALED`

실패 시 해당 단계로 되돌아가며, 산출물이 변경되면 이전 PASS는 자동으로 무효화한다.

## 8. 산출물

최종적으로 다음 기록을 남긴다.

- 전수 대상 manifest
- 문항별 해설 개선 ledger
- 문항별 SVG 요구사항 matrix
- 독립 A 수학·해설 검수 보고서
- 1차 수정 protocol 및 diff 기록
- 독립 B SVG 검수 보고서
- 2차 수정 protocol 및 diff 기록
- 독립 C 릴리스 무결성 보고서
- 최종 마더 검수 보고서
- 최종 artifact SHA와 검수 SHA
- 예외 문항 목록
- 전체 렌더 결과와 오류 목록

## 9. 완료 기준

다음 조건을 모두 만족할 때만 “도형의 방정식 단원 업그레이드 완료”로 표시한다.

1. 전체 425문항이 manifest에 포함되어 있다.
2. 신규·보강 대상 해설이 모두 작성되어 있다.
3. SVG 필수 문항에 SVG가 연결되어 있다.
4. 해설 논리 점프와 계산 오류가 해결되어 있다.
5. 문제·해설·SVG의 수학적 관계가 일치한다.
6. 독립 에이전트 A·B·C가 각각 PASS했다.
7. 수정 후 전체 렌더가 다시 통과했다.
8. 보호 필드가 무단 변경되지 않았다.
9. 최종 마더 에이전트가 SHA와 전체 보고서를 확인하고 봉인했다.

## 10. 이번 계획의 핵심 결정

이번 작업은 시험지 하나를 골라 완결하는 방식으로 시작하지 않는다. 도형의 방정식 전체 범위를 먼저 전수 제작·정리한 뒤, 독립 검수 세 차례와 수정 프로토콜을 반복하고, 마지막에 마더 에이전트가 전체 단원을 봉인한다.

단, 안정성을 위해 내부적으로는 문항 ID와 5문항 배치 루프를 사용하고, 수정은 반드시 문항 단위로 추적한다. 이렇게 하면 전수 작업의 누락을 막으면서도 최종 품질 판단은 전체 단원 기준으로 수행할 수 있다.
