# APMS 내비게이션 정리 계획 v0.1 (impeccable `shape` 브리프)

- 날짜: 2026-11-02 · 상태: **사용자 확인 대기** (코드 작업 없음)
- 범위: APMS(`apmath/`)의 사이드바(서랍·레일), 검색, 뒤로 가기, 화면 이름. 학생 포털은 범위 밖.
- 선행: 모달 통합 4묶음(M8 진도·교재, M7 클리닉, M4+M6 반·학생, M3 원내평가·OMR — `2026-11-02-apms-ui-upgrade-plan-v0.1.md`)이 병합된 뒤 시작한다. 사이드바·뒤로 가기 코드가 공통 파일 `ui.js`에 있어 묶음 작업과 동시에 고치면 충돌한다.
- 근거: 2026-11-02 읽기 전용 조사(아래 "현재 사실"의 `파일:행`). 실기기 확인 전인 항목은 `EVIDENCE_DEBT`로 적었다.

## 1. 일과 사용자 (Job and audience)

- 선생님: 휴대폰·태블릿(갤럭시 탭)으로 수업 사이에 진도·출결·클리닉·성적을 처리한다. 한 손, 짧은 시간, 반을 자주 바꾼다.
- 원장: PC로 전체 반·학생·선생님을 관리하고 검색으로 바로 찾아간다.
- 모드: Operate(작업 완료형). 익숙한 내비게이션 패턴이 표현보다 앞선다.

## 2. 성공 기준 (Outcome)

- 자주 쓰는 일(진도·교재, 클리닉, 반·학생, 원내평가·OMR)에 **어디서 시작하든 같은 작업 화면**이 열리고, 대시보드에서 2번 안에 닿는다.
- 휴대폰 **뒤로 가기 버튼이 모달을 닫는다**(앱이 꺼지지 않는다). 입력 중이면 먼저 확인한다.
- 이름 하나에 화면 하나: 사이드바 라벨 = 작업 화면 제목.

## 4. 방향 (Selected direction)

**"입구는 여럿, 작업 화면은 하나."** 사이드바·대시보드·반 화면·검색 어디서 눌러도 같은 W 작업 화면을 열고, 시작점에 따라 미리 고른 반·학생만 다르게 넘긴다(예: 반 화면에서 열면 그 반 탭, 서랍에서 열면 마지막으로 본 반). 반 고르기 모달은 두지 않는다(작업 화면의 반 전환 탭이 대신한다).

### 4.1 사이드바 재배치 (N1)
- 묶음을 "자주 쓰는 순서"로: **수업**(시간표·출석부·진도·교재, 클리닉, 원내평가·OMR) / **반·학생**(반 관리, 학생 관리, 퇴원생) / **기록**(일지·메모·상담) / **자료**(아카이브, 시험지 보관함, 도형실험실) / **지원**.
- 서랍 "원내평가"와 "OMR 입력"을 **"원내평가·OMR" 하나**로(M3 작업 화면). 옛 `openOmrInput` 화면은 얇은 진입으로.
- "교재관리" → 진도 작업 화면의 교재 관리 모드. "클리닉" → 클리닉 작업 화면(마지막 반).
- 이름 통일: "학급"→"반"(반 관리·반 추가·반 수정), 퇴원생은 "퇴원생" 하나, 버튼 "진도" = 화면 "진도·교재".
- 현재 위치 표시(`aria-current="page"`).
- 원장 서랍: 아래 결정 D1에 따름.

### 4.2 레일 아이콘 (N1에 포함)
- ≥901px에서 레일에 항목 아이콘을 보이고 이름은 툴팁·`aria-label`로. 펼침(260px)은 그대로 둔다. 태블릿 가로(1280×800)에서 한 번에 닿게.

### 4.3 뒤로 가기·닫기 (N2, 공통 `ui.js`)
- 모달·작업 화면을 열 때 `history.pushState`, `popstate`에서 맨 위 모달을 닫는다(단계 모달은 한 단계 뒤로). 화면 전환(대시보드→반)도 같은 스택에 넣어 휴대폰 뒤로 가기 = 앱 ← 버튼.
- 변경 있음(dirty)일 때 뒤로 가기·헤더 "취소"·앱 ←도 Esc처럼 확인한다. 저장 성공 뒤 닫기(`closeModal(true)`)는 그대로.
- 모달이 열려 있을 때 토스트가 제목을 덮는 문제(M3 스크린샷)도 이 묶음에서 공통으로 고친다.

### 4.4 검색 (N3)
- 원장 검색을 공통 **빠른 찾기**로: 선생님에게도, 헤더(휴대폰)·상단 막대(PC)에 돋보기 버튼 하나, PC는 `Ctrl+K`·`/`.
- 찾는 대상: 학생 → 학생 상세, 반 → 반 화면, **기능 이름**(진도, 클리닉, OMR…) → 해당 작업 화면, 시험 → 원내평가 작업 화면. 권한에 없는 대상은 보이지 않음.
- 휴대폰에서는 화면 전체 검색 시트, 입력 16px 이상.

### 4.5 위치 복원 (N4, 선택)
- 주소에 `#class=<id>` 정도만 남겨 새로고침 시 반 화면 복원. 모달 상태는 복원하지 않는다. 결정 D3.

## 5. 범위와 경계

- 바꾸지 않는 것: 서버·인증·API·저장 payload, 학생 포털, 대시보드 카드 구성, 작업 화면 내부(각 묶음 소관).
- 하지 않는 것: 하단 탭바 신설(조사상 없음. 서랍+레일 체계를 유지), 새 아이콘 체계(기존 `DRAWER_ICON_SVG` 재사용), 장식.
- 죽은 입구 삭제는 별도 정리 PR(모달 통합 부록의 17개 후보와 합친다).

## 6. 상태와 범위

- 권한 3종: 원장 / 선생님 / `eieteacher`(서랍 없음 — 그대로).
- 기기: 390×844, 800×1280, 1280×800, 1440×900. 서랍(<901px)과 레일(≥901px) 둘 다.
- 검색 결과: 0건 / 몇 건 / 18건 넘음. 학생 동명이인(반·학년 함께 표시).

## 7. 순서와 묶음

| 단계 | 내용 | 파일 | 위험 |
| --- | --- | --- | --- |
| N1 | 사이드바 재배치·이름 통일·현재 위치·레일 아이콘 | `ui.js` 서랍 구간, `sidebar-foundation.css` | 낮음 |

## 8. 결정이 필요한 것

- **D1. 원장 서랍에도 교재·클리닉·원내평가·OMR·리포트 센터를 넣을까?** 추천: 넣는다(원장은 PC로 직접 확인하는 일이 많고 지금은 반 화면을 거쳐야 함). 원장 OMR 입력은 현재 코드가 거부한다 — 막을지 열지도 함께 정한다.
- **D2. 빠른 찾기를 선생님에게도 열까?** 추천: 연다(선생님은 학생을 찾으려면 지금 3번 + 스크롤).
- **D3. 새로고침 위치 복원(N4)을 할까?** 추천: N1~N3 뒤에 반 화면만.
- 반 화면 도구 줄의 "QR"(QR 생성기) 버튼은 그대로 둔다(M3에서 "QR/OMR"→"QR", "원내평가"→"원내평가/OMR"로 이름만 바꿈).
