## A. SVG 안의 `#` 참조를 파일로 오인하는 검사 (수리)

- 현상: `25 금당중 중간 기출`, `25 왕운중 중간 기출`(중3 1학기)의 인라인 SVG에 `marker-end="url(#arrow_r)"`가 있고, `verify-archive-content-scope`(와 그것이 쓰는 `archive/tools/archive-content-inputs.mjs`의 `questionAssetReferences`)가 이것을 로컬 파일 참조로 보아 `unsupported local image reference: #arrow_r`로 실패한다.
- 할 일: `#`으로 시작하는 참조(문서 내부 조각 참조)는 파일 참조에서 제외한다. 단 그 `#id`가 같은 SVG 안에 실제로 정의돼 있는지는 확인하고, 정의가 없으면 별도 오류(깨진 내부 참조)로 보고한다 — 검사를 없애는 것이 아니라 오인을 고치고 더 정확한 검사로 바꾸는 것이다.
- 테스트: `url(#id)` 정의 있음 = 통과, 정의 없음 = 실패, 실제 파일 참조는 지금과 같음.

## B. XML로 읽히지 않는 해설 SVG 2개 (수리)

- 대상: `21 왕운중 중3 1학기 기말`의 `q17-problem-v2.svg`, `21 팔마중 중3 1학기 기말`의 `q23-problem-v2.svg`(정확한 경로는 `archive/assets/images/`에서 찾는다). `verify-archive-content-scope`가 "SVG XML parse failed"로 실패한다.
- 할 일: 무엇이 깨졌는지(닫히지 않은 태그, 이스케이프 안 된 `&`·`<`, 잘린 파일 등) 확인하고, **그림 내용은 바꾸지 않고** XML만 올바르게 고친다. 고친 뒤 실제로 렌더되는지(Chrome 헤드리스나 저장소의 렌더 도구) 확인하고 전후 PNG를 저장소 밖에 만들어 보고서에 경로를 적는다. 내용이 손상돼 복구할 수 없으면 고치지 말고 상태만 보고한다.
- 이 두 파일이 다른 고정값(해시 고정 테스트, 그림 장부)에 묶여 있는지 확인하고, 묶여 있으면 `docs/agents/common.md` "공유 데이터 고정값" 절차를 따른다.

## C. Chrome 출력이 60초 안에 준비되지 않는 시험지 4개 (조사)

- 대상: `16 장흥중 기말`, `16 창포중 기말`, `17 서울가산중 중간`, `23 풍덕중 중간 기출`(모두 중3 1학기). 내용을 바꾸지 않은 PR에서도 Chrome 확인 단계가 60초를 넘기는 일이 있었다(실행마다 통과하기도 함).
- 할 일: 왜 느린지 찾는다(그림 수·크기, 수식 수, 특정 문항의 렌더 지연 등). 고치지 않고 원인과 선택지만 보고한다.

## D. 등록기 소요 시간 (조사와 제안)

- 워크플로 `archive-main-auto-meta.yml`("Archive Main Auto Metadata")의 최근 성공 실행 5개에서 단계별 소요 시간을 뽑는다(`gh run view <id> --json jobs`).
- 어느 단계가 시간을 쓰는지, 그 단계가 바뀐 시험지 수와 무관하게 전체를 다시 계산하는지를 코드(`tools/ci/archive-registration-writer.mjs`와 그것이 부르는 빌더들)에서 확인한다.
- PR CI의 `test` 잡에서 `Prepare and verify PR registration data once` 단계가 요청 수에 비례해 느려지는 이유도 같은 방식으로 확인한다(요청 35개 = 42.5분).
- 제안: 바뀐 시험지만 계산하게 하는 방법, 캐시할 수 있는 것, 병렬로 돌릴 수 있는 것. 각각 예상 절감과 위험(결과가 전체 재계산과 달라질 수 있는 지점). 구현은 하지 않는다.
