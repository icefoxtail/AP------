# 작업 8 — 운영 문서 한 장과 진입 스킬 초벌 (계획서 5장·8장)

## 왜

사용자가 원하는 것은 "이 기출 완성해", "이 기출의 유사문항 만들어", "빈 곳 채워" 한 줄 지시로 작업자가 정해진 길을 따라 끝까지 가는 것이다. 규칙의 본체는 저장소 문서 한 장과 도구에 두고, 실행기별 진입점(Claude 스킬 등)은 그 문서를 읽고 도구를 부르는 얇은 껍데기로 둔다. 그래야 어느 모델·어느 구독으로도 같은 길을 쓴다. 이 작업은 그 문서와 껍데기의 초벌이다.

## 어디에 쓰나

브랜치 `docs/one-route-20261116`(최신 `main`에서), 보고 `TASK-08-REPORT.md`. 문서 작업이라 코드는 없다.

## 먼저 읽을 것

`PLAN.md` 전체, `AGENTS.md`, `docs/agents/outcome-method-review.md`, `docs/agents/exam-pipeline.md`, `docs/agents/metadata.md`, `docs/agents/visual-svg.md`, `docs/agents/alive-generated.md`, `docs/agents/token-efficiency.md`, 4칸 계약, 메타 OS 문서, 그리고 저장소의 기존 스킬 폴더(`.claude/skills/`)의 형식.

## 만들 것

1. `docs/agents/one-route.md` — 한 장(3쪽 이내). 세 길("기출 완성", "유사문항 생성", "빈 곳 채우기") 각각의 단계표: 단계, 담당(저렴한 모델 / 다른 저렴한 모델 / 상위 모델 / 도구), 입력, 산출물, 합격 검사 명령, 실패 시 돌아갈 단계. `PLAN.md` 5장의 표를 뼈대로 하되, **각 단계에서 실제로 부를 명령과 읽을 기존 문서의 절**을 채운다. 아직 없는 도구는 "작업 N에서 만드는 중"으로 표시한다(작업 1·2·6·7의 지시 파일에서 명령 형태를 확인).
   - 기존 문서의 규칙을 다시 쓰지 않는다. 해당 문서의 절로 링크만 건다(그림 규칙, 4칸 판정 규칙, 난이도 판정 규칙 등). 규칙이 서로 충돌하는 곳을 발견하면 고치지 말고 보고서에 목록으로 적는다.
   - 모든 길에 공통인 것은 한 번만 쓴다: 독립 풀이(정답·해설을 가리고 품)와 메타 판정(해설을 읽고 판정하되 서로의 판정은 보지 않음)의 구분, 같은 모델로 두 판정을 다 받지 않는다, 근거 없이 채우지 않는다, 실행하지 않은 검사는 NOT_RUN, 완성도 검사 통과가 종료 조건.
   - 기존 예약 4단계 라인(제작 → 1·2·3차 검수)과의 관계는 사용자 결정 전이다(`PLAN.md` 9장 결정 1). 문서에는 "새 시험지는 이 길로 받는다(추천안)"로 쓰고 미정임을 표시한다.
2. `.claude/skills/exam-complete/SKILL.md`, `similar-create/SKILL.md`, `gap-fill/SKILL.md` — 각 20줄 안팎의 껍데기. 기존 스킬의 머리말 형식을 따르고, 본문은 "`docs/agents/one-route.md`의 해당 절을 읽고 단계대로 수행한다"와 입력으로 받을 것(시험지 경로 / 원본 시험지와 만들 문항 수 / 지도의 칸), 끝났다고 말하기 전에 돌릴 검사 명령만 적는다. 규칙을 스킬 안에 복사하지 않는다.
3. `AGENTS.md`의 "작업별 안내" 표에 한 줄 추가(문서 크기 상한 테스트 `tests/agents-md-budget.test.js`를 통과해야 한다).

## 판단 기준

- 읽는 사람은 이 저장소를 처음 보는 작업자(사람 또는 모델)다. 문서 한 장만 읽고 첫 단계를 시작할 수 있어야 한다.
- 쉬운 말로, 내부 약어는 처음 나올 때 풀어 쓴다. 날짜별 진행 현황이나 캠페인 숫자를 넣지 않는다.
- 스킬 형식이 저장소의 기존 스킬 검사(`tools/skills/verify-skills.mjs`)를 통과하는지 실행해 확인한다.

## 완료 기준

`node --test tests/agents-md-budget.test.js`와 `node tools/skills/verify-skills.mjs --json` 통과. 보고서에: 문서가 링크한 기존 문서·절 목록, 발견한 규칙 충돌, 아직 없는 도구에 기대는 단계 목록, 사용자 결정이 필요한 곳.
