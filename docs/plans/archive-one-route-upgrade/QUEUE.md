# 작업 대기열 (초벌 작업자용)

이 폴더는 "한 길 완성 체계" 계획(`PLAN.md`)의 작업 지시와 보고를 주고받는 자리다. 초벌 작업자는 이 파일을 읽고 **위에서부터 아직 보고서가 없는 작업을 하나씩** 수행한다. 관제(계획을 관리하는 Claude 세션)가 수시로 이 브랜치를 확인해 새 지시를 넣고, 올라온 초벌은 관제 쪽에서 검수·수정해 PR로 올린다.

## 도는 방법

1. 이 브랜치(`plan/archive-one-route-upgrade-20261116`)를 최신으로 받아 이 파일을 읽는다.
2. 아래 표에서 `TASK-NN-REPORT.md`가 아직 없는 가장 위 작업의 지시 파일을 읽고 수행한다. 지시 파일에 적힌 브랜치에만 코드를 커밋한다(없으면 최신 `main`에서 만든다).
3. 끝나면 이 브랜치에 `TASK-NN-REPORT.md`를 커밋한다. 이 파일(`QUEUE.md`)과 지시 파일은 고치지 않는다.
4. 다시 1로. 새 작업이 없으면 `FEEDBACK-*.md`(관제가 올린 수정 요청)가 있는지 보고, 있으면 그것을 처리한 뒤 해당 보고서 끝에 "수정 반영" 절을 덧붙인다. 둘 다 없으면 멈춘다.

## 공통 규칙 (모든 작업)

- `main` 병합, PR 생성, 강제 push, 이력 재작성, 다른 브랜치(다른 작업자의 것) 수정 금지.
- 운영 데이터(정본 메타, 레지스트리, 크로스워크, 4칸 사전, 영수증, 봉인 문서)는 고치지 않는다. 지시 파일이 명시한 파일만 바꾼다.
- 검사를 약하게 만들지 않는다. 테스트를 지우거나 건너뛰게 하지 않는다. 실행하지 않은 검사는 보고서에 NOT_RUN.
- 기존 함수를 재사용하고 새 판정 기준을 지어내지 않는다. 모호하면 보수적으로 정하고 "임의로 정한 것"에 적는다.
- 위험하거나 지시가 실제 코드와 맞지 않으면 구현하지 말고 조사 결과와 선택지를 보고한다. 초벌의 목표는 "검수자가 바로 판단할 수 있는 상태"다.
- 커밋·코드·보고서에 모델 이름을 적지 않는다. 줄바꿈 LF. 저장소 밖 경로에만 임시 출력을 쓴다.
- 작업 사이에 파일이 겹치면(앞 작업의 브랜치가 아직 main에 없음) 앞 브랜치를 기반으로 하지 말고 `main` 기준으로 하되, 보고서에 "앞 작업 병합 뒤 합칠 곳"을 적는다.
