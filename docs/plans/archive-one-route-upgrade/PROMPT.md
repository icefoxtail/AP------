# Archive 2.0 "한 길 완성 체계" 업그레이드 계획서 — 초안 작성 지시 (2026-11-16)

이 폴더는 계획서 초안을 받기 위한 작업 브랜치 전용 자리다. **초안은 같은 폴더의 `DRAFT.md`에 쓴다**(이 브랜치에 커밋). `main`에는 병합하지 않는다. 다른 파일은 고치지 않는다.

역할: 당신은 수학 문제 아카이브 "Archive 2.0"의 운영 체계를 설계하는 설계자다. 아래 배경과 결정 사항을 바탕으로 계획서 초안을 한국어로 작성한다. 구현은 하지 않는다.

## 배경

- 중1~고3 수학 기출·유사문항·교과서 문항 약 28,000문항. 시험지 1개 = JS 파일 1개, 문항마다 발문·보기·정답·해설·그림과 메타가 붙는다.
- 메타 종류: 단원·소단원, 난이도(1~5 정수 + 확신도·경계 표시·옛 난이도 호환), 유형(PT/TPL), 연결 개념·조건·통합 방식, 4칸(주어진 것/조건/목표/풀이 방법을 사전 용어로 적은 조각).
- 지금의 문제: 발문·해설 수정, 그림 교체, 단원·난이도 등록, 4칸 등록이 각각 다른 PR·다른 요청 형식·다른 등록기로 들어가고, 서로를 내용 해시(지문)로 묶는다. 그래서 그림 하나만 바꿔도 메타 등록이 막힌다.
- 중등 9,139문항 실측(2026-11-16): 난이도 숫자는 99.5% 있지만 형식까지 갖춘 것은 61%, 유효한 유형은 1,857문항, 4칸 등록은 6,729문항, "원본이 바뀜" 때문에 4칸이 대기 중인 문항이 1,363개.
- 확인된 사실: 문항 번호표(UID)는 파일 경로와 순번으로 정해져 내용과 무관하다. 어긋난 문항의 약 90%는 그림·해설만 바뀐 것이고 문제 자체는 같다.

## 사용자가 원하는 모습

1. 짧은 지시 한 줄로 끝까지 가는 공식 길:
   - "이 기출 완성해" → 발문·정답·해설·그림·모든 메타까지 한 번에.
   - "이 기출의 유사문항 만들어" → 유사문항의 발문·해설·그림(SVG)·메타까지 한 번에.
   - "빈 곳 채워" → 유형·4칸 분석으로 찾은 빠진 문항을 생성.
2. 새 기출·유사문항이 들어올 때 한꺼번에 정리되는 가장 효율적인 관리 방법.
3. 유형·4칸 분석으로 "이 유형인데 4칸 풀이 방법이 다른 문항이 하나 더 있으면 좋겠다" 같은 빈 곳을 찾아 채우는 로드맵.

## 이미 정한 결정 (바꾸지 말고 전제로 삼는다)

- **시험지 1개 = 꾸러미 1개.** 발문·정답·해설·그림·단원·난이도·유형·4칸을 한 PR에 담고 등록기가 한 번에 받는다.
- **"완성"은 기계가 판정한다.** 문항별로 발문·정답·해설·그림·단원·난이도·유형·4칸·등록 상태를 보여 주는 완성도 검사 도구가 작업 종료 조건이자 밀린 일 목록이다. 계획의 첫 구현 단계는 이 도구다.
- **규칙 본체는 저장소의 문서 한 장과 도구에 둔다.** Claude 스킬 등 실행기별 진입점은 그것을 부르는 얇은 껍데기다(GPT·Gemini·Codex·opencode 어느 것으로도 같은 길).
- **판단은 모델, 형식과 합격은 도구.** 대량 판정은 저렴한 모델 2회 독립 판정 + 기계 대조, 어긋난 것만 상위 모델이 본다. 실측: 딥시크 4.1 플래시가 그림(PNG)까지 읽고 난이도 일치율 70%(전부 1단계 이내), 소단원 87%로 codex 테라와 비슷했다.
- **유형(PT/TPL)은 공식 판정기 전용이 아니다(2026-11-16 해제).** 값은 판정기 조회, 풀이의 결정 단계를 근거로 한 직접 판정, 새 유형 키 신설 가운데 어느 길로든 낼 수 있다. 유지하는 원칙은 "근거 없이 채우지 않는다"뿐이다. 유형은 계속 늘어나는 분류로 다룬다.
- **이미 등록된 문항을 고칠 때는 재결속.** 번호표로 문항을 찾아 옛 판본과 비교해 무엇이 바뀌었는지(그림/표기/해설/발문 수정/정답 변경/문항 교체) 판정하고, 메타는 유지하되 꼬리표를 단다. 문항이 통째로 교체된 경우만 옛 값을 막는다.
- **학생 화면 기준.** 완성 기준은 "학생이 풀고 해설을 이해할 수 있는가"이며 수치상 완벽이 아니다. 검사를 약하게 만들어 통과시키지 않는다. 실행하지 않은 검사는 NOT_RUN으로 적는다.

## 제안된 단계 순서 (더 나은 순서가 있으면 근거와 함께 바꿔 제안)

1. 지금 진행 중인 메타 채우기와 재결속 마무리
2. 완성도 검사 도구와 상태표
3. 꾸러미 형식과 "기출 완성" 길 (새 시험지 1개로 시험 운영)
4. "유사문항 생성" 길을 같은 꾸러미로
5. 단원 × 유형 × 4칸 풀이 방법 × 난이도 지도 → 빈 곳 찾기 → 생성

## 계획서에 꼭 담을 것

- **A. 목표 모습 한 쪽 요약** (지금 대 이후, 표 하나).
- **B. 꾸러미 설계:** 폴더·파일 구성, 필수 칸과 선택 칸, 꾸러미 목록 파일(manifest)에 적을 것, 부분 완성 상태의 표현(예: 유형 보류, 그림 없음), 기존 요청 형식들을 어떻게 흡수하거나 남길지.
- **C. 완성도 검사 도구:** 입력·출력, 문항별 상태 값 목록, 시험지·학년·전체 단위 집계, CI와 사람이 각각 어떻게 쓰는지.
- **D. 세 가지 길의 단계별 흐름** ("기출 완성", "유사문항 생성", "빈 곳 채우기"): 각 단계의 담당(저렴한 모델/상위 모델/도구/사람), 입력과 산출물, 합격 검사, 실패했을 때 되돌아가는 길. 그림은 SVG 제작과 실제 화면(PC·휴대폰) 확인을 포함.
- **E. 유형 확장 운영:** 새 유형 키를 만드는 기준과 이름 규칙, 같은 뜻의 키가 늘어나는 것을 막는 상위 묶음 방식, 판정기와 직접 판정이 다를 때의 처리.
- **F. 빈 곳 지도:** 칸을 어떻게 정의하는지, "실제 공백"과 "아직 메타가 안 채워진 것"을 구분하는 법, 생성 우선순위 기준(교과서·문제집에는 있는데 기출에 없는 유형, 특정 난이도 공백, 4칸 풀이 방법 변형 공백), 생성 문항의 품질 검수.
- **G. 기존 28,000문항의 이행:** 무엇을 그대로 두고 무엇을 꾸러미로 옮길지, 순서와 되돌리기 방법.
- **H. 단계별 완료 기준, 예상 위험과 대응, 사용자가 정해야 하는 결정 목록** (선택지와 추천안을 함께).
- **I. 비용 관점:** 단계마다 어느 모델을 얼마나 쓰는지의 대략적 배분과 토큰을 아끼는 지점.
