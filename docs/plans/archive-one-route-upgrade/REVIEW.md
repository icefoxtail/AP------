## 고칠 것

1. **E-2 "직접 판정은 아직 등록기가 받지 못한다"는 부정확하다.** `archive/tools/meta-foundation/reviewed-exam-registration-v2.mjs`의 REVIEW2 경로는 요청의 PT/TPL을 직접 받고 `resolve()`(1690행 부근)에서 ACTIVE 키·TPL 부모·교육과정 바인딩만 검사한다(코드 읽기로 확인, 실제 등록 실행은 NOT_RUN). 실제로 막힌 곳은 셋이다: ① 바인딩 행이 없으면 거부(요청 생성기가 add-only로 자동 추가하지 않음) ② 유형 보류(`typeHold`)로 등록된 문항에 나중에 유형을 채우는 경로 ③ 기출 생산 게이트(`archive/tools/past-exam-pipeline/lib/completion-evidence.mjs`)의 판정기 일치 강제. E장과 다음 2주 할 일을 이 셋 기준으로 다시 쓴다.
2. **CI 미리보기가 유형 보류 문항을 막는다(오늘 실측).** `tools/ci/archive-pr-native-preview.mjs`의 `difficultyAssignmentInformation`(943행 부근)이 `assignment_missing` 행을 난이도 요청일 때만 허용해서, 유형이 없는 문항이 든 단원 등록 PR은 `PR_NATIVE_PREVIEW:CONSUMER_NOT_PASS`로 실패한다. B-3의 "유형 근거가 부족하면 `type=HOLD`"가 지금 CI에서는 통과하지 못한다는 뜻이다. 부분 완성 상태를 설계할 때 이 조건을 어떻게 바꿀지 포함한다.
3. **처리량 병목이 계획에 없다(가장 큰 누락, 오늘 실측).** "시험지 1개 = PR 1개"로 가면 main push가 잦아진다. 지금은 ① main 병합마다 등록기(Archive Main Auto Metadata)가 20~60분 돌고, 그 사이 다른 push가 오면 취소·재시도 소진이 난다 ② PR CI의 `test` 잡이 45분 제한이라 요청 306개짜리 PR이 취소됐다 ③ Chrome 확인 단계가 8분 제한이라 시험지 74개 PR을 5개로 쪼개야 했다. 꾸러미 길의 병합 순서(대기열·묶음 병합·등록기 직렬화)와 PR 크기 기준을 B장 또는 G-3에 넣는다. 이것이 없으면 한 길이 CI 대기에서 멈춘다.
4. **부분 제출 경로가 생각보다 좁다(오늘 실측).** 4칸 부분 제출(`PARTIAL_UIDS`)은 서로 다른 작성자·검토자의 영수증을 요구하고, 원장 변환물을 받는 어댑터가 없다. 이미 영수증에 묶인 기존 4칸이 있는 시험지에 나머지 문항을 더하는 길도 없다(금당중 중1 두 시험지가 여기서 멈췄다). B-3-2는 이 경로를 새로 만들어야 하는 일로 적는다.
5. **기존 4단계 라인과의 관계가 정해지지 않았다.** D-1은 R1·R2·R3 전 문항 블라인드 검수를 그대로 두고 그 위에 메타 독립 판정 2회를 더한다. 사용자가 원하는 것은 "한 줄 지시로 끝까지"다. 꾸러미 길이 예약 CREATE/R1/R2/R3 라인을 **감싸는지, 대체하는지, 신규 시험지에만 쓰는지**를 H-3 사용자 결정에 올리고, 각 선택의 단계 수와 모델 호출 수를 나란히 적는다.
6. **화면 확인 범위가 과하다.** D-1의 "전 문항을 PC와 휴대폰 실제 Chrome에서 시험지·정답·해설 모드로"는 사용자 기준("학생이 쓰기에 적당한가", 추가 전수 측정은 요청이 있을 때만)과 맞지 않는다. 제안: 렌더 오류·잘림·넘침은 도구가 전 문항 자동 검사, 사람·모델의 눈 확인은 그림 문항과 도구가 표시한 문항. 역할 문서가 전수를 요구하는 단계는 그대로 두되 어느 문서의 요구인지 적는다.
7. **재결속 표(D-2) 보강.** 오늘 검수에서 나온 것: `ANSWER`는 "빈 정답이 채워짐"과 "값이 바뀜"으로 나눈다(중2 121건 중 71건이 채움). 등급만 보지 말고 `changed.*`와 `otherChangedKeys`(예: `sharedMaterial`)를 재결속 조건에 넣는다. `REPLACED`는 짧은 수식 발문에서 과대 판정되므로 확정 전 확인이 필요하다는 초안의 서술은 맞다.
8. **모델 배분(I장)을 현재 사정으로.** codex 구독은 2026-11-16에 끝났다. 대량 판정은 `opencode-go/deepseek-v4.1-flash`(그림 포함)가 기본이고, 같은 모델로 1차·2차를 둘 다 받으면 독립성이 약하므로 한쪽은 다른 모델로 받는다. opencode는 동시 실행 6줄 안팎, 내부 DB 용량 관리가 필요하다.
9. **2주 일정은 낙관적이다.** 6일차 하루에 "운영 문서·manifest·등록 어댑터·계약 전환"을 다 넣었다. 등록기는 3,000줄이 넘고 봉인·영수증 검증이 얽혀 있다. 일정은 "검사 도구 → 기준선 → 재결속 연결"까지를 2주 목표로 줄이고, 꾸러미 시험 운영은 그다음으로 둔다.
