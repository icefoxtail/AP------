# Archive 2.0 “한 길 완성 체계” 업그레이드 계획서 — 초안

## A. 목표 모습 한 쪽 요약

**결론: 시험지 하나를 한 꾸러미로 받아, 학생용 내용·메타·등록을 함께 마치고 완성도 검사로 종료한다. 첫 구현물은 검사 도구다.**

- 기준: 2026-11-16, 브랜치 `plan/archive-one-route-upgrade-20261116`, 조사 기준 커밋 `89899583932c4ca4c89d2ea70df3648ac46ad50a`.
- 이번 산출물은 계획서뿐이다. 구현·데이터 변경·기존 규칙 개정·운영 적용은 하지 않는다. 이 문서에서 새 경로·필드·명령·목표 수치는 별도 표시가 없어도 **구현 제안**이며, 현행 사실에는 근거 경로를 붙였다.
- 고정 결정은 같은 폴더 `PROMPT.md`를 따른다. 이전 문서의 유형 판정기 전용 제한보다 이번 결정이 우선한다. 검수·블라인드·증거·쓰기 권한은 유지한다.

| 항목 | 지금 | 이후 |
| --- | --- | --- |
| 사용자 요청 | 발문·그림·난이도·유형·4칸을 따로 의뢰 | “이 기출 완성해”, “유사문항 만들어”, “빈 곳 채워”가 같은 절차로 진입 |

| 실행기 | 실행기별 지시가 달라질 수 있음 | 저장소의 운영 문서 한 장과 도구를 공통 본체로 사용. 실행기 진입점에는 호출 방법만 둠 |

**현황의 해석.** `PROMPT.md`가 제공한 중등 9,139문항 실측은 난이도 숫자 99.5%, 형식 완비 61%, 유효 유형 1,857문항, 4칸 등록 6,729문항, 원본 변경에 따른 4칸 대기 1,363문항이다. 어긋난 문항 약 90%가 그림·해설 변경이라는 수치도 제공 자료다. 이번 작성에서 재측정하지 않았으며, 서로 겹치는 수를 합산하거나 전체 약 28,000문항으로 외삽하지 않는다.

**순서 제안.** 완성도 검사 → 재결속 연결과 기존 채우기 마감 → 새 기출 한 꾸러미 → 유사문항 → 빈 곳 생성 순으로 간다. 기존 채우기를 모두 끝내야 검사를 만드는 순서는 바꾼다. 무엇이 남았는지 같은 기준으로 알아야 중복 판정과 거짓 완료를 줄일 수 있기 때문이다. 진행 중 작업은 중단하지 않고 검사 결과에 합류시킨다.

**완성과 이용 가능은 다르다.** 새 작업은 필수 메타가 남으면 미완료다. 기존 문항은 4칸 누락·보류 때문에 검색·선택·출력에서 빼지 않는다. 학생이 풀고 해설을 이해할 수 있는지와 메타 작업이 끝났는지를 상태표에서 나란히 보여 준다. 근거: `docs/architecture/JS_Archive_Item_4Slot_Term_Contract_CURRENT_v1.md` §11-6·14, `docs/architecture/JS_Archive_Meta_OS_CURRENT.md` §0·3.

## B. 꾸러미 설계

**결론: 기존 정본 파일은 제자리에 두고 목록 파일(manifest)로 묶는다. 파일 이동과 공용 메타 복제는 하지 않는다.**

### B-1. 폴더와 파일

| 위치 | 내용·역할 | 구분 |
| --- | --- | --- |
| `archive/data/exam-bundles/<bundleId>/manifest.json` | 시험지·문항·파일·검사·등록 요청을 잇는 목록 | 신설 제안 |
| `archive/exams/**/<시험지>.js` | 최종 발문·보기·정답·해설, 인라인 메타 | 기존 위치 유지 |
| 기존 자산 위치 / 생성 SVG의 승인된 자산 위치 | 실제 학생용 그림, 문항별 참조와 바이트 해시 | 기존 자산·시각 계약 준수 |
| `.archive-meta-register/inbox/*.json` | 꾸러미 도구가 만든 시험지별 소형 등록 요청 | 기존 입력 재사용 |
| `archive/data/item-4slot/**/*.4slot.json` | 용어 번호만 담은 4칸 운영 파일(compact) | 기존 importer로 제작 |
| 기존 등록·4칸 수납 영수증 위치 | 실제 수납 결과와 판본·범위 | 기존 영수증 불변, 새 결과는 추가 |
| 작업 워크트리의 `.tmp/` 및 허용된 외부 증거 보관소 | 독립 판정 원장, 상세 인용·검토 기록, 화면 캡처 | 원시 증거는 꾸러미 커밋에서 제외 |

생성문항의 기존 shard 저장소는 그대로 두고 `{store, uid}`로 참조한다. 시험지 형태의 유사문항은 JS 하나를 기준으로 묶는다. 실제 저장 경로·등록 경로가 다른 생성 저장소에 기출용 UID나 스키마를 억지로 적용하지 않는다.

### B-2. 필수 칸과 선택 칸

| 묶음 | 필수 정보 | 선택·조건부 정보 |
| --- | --- | --- |
| 꾸러미 식별 | `schemaVersion`, `bundleId`, `revision`, 요청 종류, 시험지 경로, 기준 커밋·소스 blob, 교육과정·학년·과목, 기대 문항 수 | 원본 시험지·생성 과제·빈 곳 지도 참조 |
| 문항 식별 | 기존 UID, 저장소, 배열 위치 `sourceOrdinal`, 원표기 번호 `sourceQuestionNo` | 출처 UID·생성 당시 원본 판본 |
| 학생용 내용 | 발문·정답·해설 및 검사 근거 | 보기·문제 그림·해설 그림은 해당할 때 필수. 불필요함도 이유를 기록 |
| 메타 | 단원·소단원, 1~5 정수 난이도와 확신도·경계·옛 난이도 호환, 유형 PT(문제 유형)·TPL(풀이 틀), 교육과정 내 사고 경로, 연결 개념·조건·통합 방식 | 기존 `level`은 독립 값으로 보존. 없다고 숫자 난이도에서 환산하지 않음 |
| 4칸 | `given`, `condition`, `goal`, `method`, `format`, 실제 사전 버전·해시 | goal·method는 필수. given·condition은 실제 해당할 때 작성. 순서가 핵심이면 `steps` |
| 판정·검사·등록 | 필드별 상태·근거 참조, 판정·검토 역할과 시각, 검사기 버전·입력 해시·실행 결과, 등록 요청 ID | 보류 이유·담당·재개 조건, 유형·용어 신설 제안 |
| 원문 변경 | 이전·현재 판본 참조, 기존 지문, 자산 해시, 변경 종류·세부 플래그 | 신규 문항이면 이전 판본 없음이 정상. 기존 문항의 이전 판본 유실과 구별 |

manifest의 메타 **값**은 소형 요청·4칸 파일을 참조한다. 상태표와 집계는 이 자료에서 계산하며, 저장된 `complete:true` 선언을 믿지 않는다. 문항·자산 파일의 실제 바이트와 목록이 다른 경우 실패한다. 정식 등록 요청의 `before`·해시·문항 수는 도구가 만들고 모델은 의미 판정만 낸다.

### B-3. 부분 완성과 기존 요청 수용

1. 유형 근거가 부족하면 `type=HOLD`, 이유·담당·다음 행동을 적는다. 맞는 기존 키가 없을 뿐이라면 E장의 신설 경로로 간다. 그림이 필요 없으면 `NOT_APPLICABLE`, 필요한 그림이 없으면 `MISSING`이다.
2. 부분제출은 전체 문항 수와 `selected`·`unsubmitted`를 유지한다. 두 집합은 겹침 없이 전체를 덮고, 미제출은 `NOT_SUBMITTED`, 시험지는 `SUPPLEMENT_PENDING`이다. 일반 전체제출의 누락을 부분제출로 숨기지 않는다.
3. v2·REVIEW2·난이도·기본범위 재결속·최종 검수 요청은 어댑터로 수용한다. 원래 승인 범위·보호 필드는 유지하고, 제한된 최종 검수를 새 유형 판정 권한으로 바꾸지 않는다. 지원하지 않는 새 필드는 `TOOLING_GAP`으로 남긴다.
4. 현 단일 등록 writer에 manifest 입력을 추가한다. 소스·그림·compact는 PR에 먼저 싣고, 등록기는 허용된 출력만 만든다. 같은 요청의 같은 내용 재실행은 중복 없이 끝내고, 내용 변경은 새 revision·요청 ID로 보낸다. 동시 수정은 `before` 대조로 검출한다.

현행 근거: `docs/architecture/JS_Archive_Meta_OS_CURRENT.md` §2·4·7, 4칸 계약 §11·17, `docs/agents/git-evidence.md`, `tools/ci/archive-registration-writer.mjs`.

## C. 완성도 검사 도구와 상태표

**결론: 읽기 전용 검사기를 먼저 만들어 같은 문항 목록으로 누락·품질·등록을 따로 보여 준다.**

### C-1. 입력과 출력

- 제안 명령: `node archive/tools/completion/check.mjs --exam <경로> --format json|tsv`와 `--bundle <manifest>`, `--grade <학년>`, `--all`. 아직 존재·실행 여부를 확인한 명령이 아니라 신설 명세다.
- 입력: 현재 소스·자산, 기존 identity map, 운영 메타·4칸·사전, 실제 검사와 수납 영수증, 등록 대기·거절 목록. manifest 없는 옛 시험지도 가상 목록으로 읽는다.
- 출력: 문항별 발문·정답·해설·그림·단원·난이도·유형·4칸·등록 상태, 실제 검사 범위, 남은 이유·담당·다음 명령. 상세 표에는 소단원·사고 경로·연결 개념·조건·통합 방식도 빠짐없이 포함한다.
- 모든 결과는 기준 커밋·소스/자산/사전/검사기 버전에 결속한다. 캐시는 그 의존성이 같을 때만 재사용하며, 바뀐 문항과 직접 영향 검사만 다시 실행한다.

### C-2. 상태 값과 완성 판정

| 축 | 값 | 뜻 |
| --- | --- | --- |
| 필드 상태 | `MISSING`, `RECORDED`, `PASS`, `NOT_APPLICABLE` | 없음 / 값은 있음 / 필요한 근거와 검사 충족 / 실제 해당 없음 |
| 미완료 이유 | `HOLD`, `EVIDENCE_DEBT`, `INVALID`, `NEEDS_RECHECK`, `NOT_SUBMITTED` | 판단 보류 / 근거 부족 / 형식·참조 결함 / 변경 영향 재확인 / 명시적 미제출 |
| 검사 실행 | `PASS`, `FAIL`, `NOT_RUN` | 실제 실행 결과. 파일 존재·작성자의 선언으로 PASS를 만들지 않음 |
| 등록 | `NOT_SUBMITTED`, `PENDING`, `PARTIAL`, `REGISTERED`, `REJECTED` | 제출 전부터 실제 수납까지의 별도 상태 |
| 문항 종합 | `IN_PROGRESS`, `READY_TO_REGISTER`, `COMPLETE`, `BLOCKED` | 작업 중 / 등록 전 필수 검사 완료 / 등록 후 읽기 확인까지 완료 / 실제 결함·필수 의존성 때문에 중단 |
| 변경 표시 | source-delta의 8개 class + 세부 플래그 | 값의 검토 상태와 별개. 변경 표시 자체를 결함으로 간주하지 않음 |

`RECORDED`는 등록 전 필수 품질을 충족했다는 뜻이 아니다. `HOLD`도 문항 전체의 기존 이용 차단을 뜻하지 않는다. `NOT_APPLICABLE`은 모델의 근거 있는 판단을 검사기가 확인한 경우만 허용하며, 필수 유형·goal·method 누락에는 쓸 수 없다.

1. `READY_TO_REGISTER`: 기대 문항 전체가 정확히 식별되고, 필수 내용·메타·4칸과 역할별 검수·PC/휴대폰 확인이 끝났으며, 등록 사전 검사가 통과했다. 필요한 그림만 존재 여부·의미·렌더를 검사한다.
2. `COMPLETE`: 위 조건에 더해 해당 판본의 필요한 등록 단계가 성공하고, 운영 메타·색인에서 대상 UID와 값을 다시 읽어 일치를 확인했다. 독립 검수·기계 형식 검사의 증거를 구별한다.
3. `studentReady`, `registrationStatus`, `deploymentStatus`는 별도 출력한다. 등록 완료가 배포 완료를 뜻하지 않는다. 배포까지 맡긴 실행의 종료 조건에는 실제 배포·학생 화면 확인도 추가한다.
4. 숫자 난이도는 활용 가능하지만 보조값이 없으면 새 꾸러미의 난이도 완성은 아니다. 기존 이용 가능 여부를 보조값 때문에 낮추지 않는다. 4칸도 같은 원칙이다.

### C-3. 집계와 사용 방식

| 사용자 | 보는 것 | 행동 |
| --- | --- | --- |
| 작업자 | 시험지 N문항 중 완성/대기/결함, 필드별 부족 목록 | 부족한 문항·필드만 다시 처리 |
| 운영자 | 학년·과목·전체의 동일 분모, 등록 전후 차이, 보류 기간·사유 | 겹치는 대기는 중복 표시하고 작업 순서 배정 |
| 자동 검사(CI) | 변경 꾸러미 전체 분모·근거·사전 검사·기존 이용 회귀 | 완료 주장과 실제 상태 불일치, 실제 결함은 실패 처리 |

전체 집계는 UID 중복을 제거하고 원본·유사·생성·교과서를 구분한다. 필드별 부족 수는 겹칠 수 있으며 문항 종합 상태 수의 합만 전체 N과 같아야 한다. 필수·해당 없음·미판정 수를 함께 보여 분모를 숨기지 않는다.

조회 모드는 보고서를 만들었다는 사실과 완성 여부를 구분한다. CI의 `--require ready` 또는 등록 후 `--require complete`는 해당 조건 미달 시 실패한다. 부분 저장을 허용하는 PR에는 부분 상태를 명시하며 완료라고 표시할 수 없다. 현행 `audit.mjs`와 backlog 도구는 입력으로 재사용하되, 원문·그림·독립 검수까지 보지 못하는 기존 메타 집계를 완성 검사라고 부르지 않는다. 근거: 메타 OS §0·6, `docs/agents/outcome-method-review.md` §4.

## D. 세 가지 길 — 공통 절차와 기출 완성

**결론: 세 길 모두 내용 작성 → 독립 검수 → 메타 판정 → 화면 확인 → 한 번 제출 → 수납 확인으로 닫힌다. 실패는 담당 단계로만 되돌린다.**

### D-1. “이 기출 완성해”

| 단계·담당 | 입력 → 산출물 | 합격 검사 / 실패 시 복귀 |
| --- | --- | --- |
| 1. 범위 확정 — 도구, 범위 모호할 때 사람 | 시험지·원본 자료 → 전체 UID/번호 목록, 기존 완성도·결함 목록 | 누락·중복 0, 출처 확인 / 자료·번호 확인으로 복귀 |
| 2. 내용 완성 — 저렴한 모델, 어려운 결함은 상위 모델 | 원문·실제 그림·기존 결함 → 교정된 발문·보기·정답·학생용 해설·그림 설계 | 교육과정 내 풀이, 답의 존재·유일성, 조건 충족 / 작성 단계 수리 |
| 3. 수학 독립 검수 — 독립 검토 역할 | 정답·해설을 가린 발문·그림 → 독립 풀이 동결, 이후 원안 대조 | 기존 R1·R2·R3의 전 문항 의무 유지 / 틀린 문항 수리 후 영향 검수 |
| 4. 메타 판정 — 저렴한 모델 2회, 도구, 상위 모델 | 확정 문항·해설·실제 그림 → 독립 원장 2개·불일치 해결 기록 | 서로 원장 비노출, 정확한 인용·문항 매칭·키/부모·4칸 검사 / 형식은 도구 수리, 의미 불일치는 상위 검토 |
| 5. 그림·실제 화면 — 작성 모델, 도구, 검토자 | 필요 그림 명세 → SVG 또는 적합한 기존 자산, 실제 렌더 근거 | 수학 조건·눈금·라벨·정답 누설·가독성·잘림 확인 / SVG·본문·레이아웃 수리 |
| 6. 꾸러미 사전 검사 — 도구, 제출자 | 최종 소스·메타·4칸·근거 → manifest·소형 요청·한 PR | 전체 문항 분모, READY_TO_REGISTER, 변경 범위·보호 필드 / 실패 단계로 복귀 |
| 7. 수납·마감 — 기존 등록 writer, 도구, 운영 담당 | 승인된 PR의 입력 → 등록 영수증·소비자 읽기 결과·최종 상태표 | 대상 UID·값·판본 일치, 필수 단계 실제 성공 / 같은 꾸러미의 대기만 재시도 |

수학 블라인드 검수에는 정답·해설·method·4칸을 미리 주지 않는다. 메타 독립 판정 2회는 확정 해설을 읽지만 서로의 판정은 보지 않는다. 두 절차를 혼동해 기존 블라인드 검수를 생략하지 않는다. 판정기와 직접 판정이 다르면 E장의 절차로 해결한다.

그림이 필요한 신규·유사 문항은 승인된 SVG 제작 경로로 만든다. 기존 그림은 품질이 충분하면 보존한다. 도구의 SVG 문법 검사는 수학적 정확성을 대신하지 않는다. 전 문항을 PC와 휴대폰 실제 Chrome에서 시험지·정답·해설 모드로 확인하고, 좁은 폭·긴 수식·큰 그림·가로세로 전환을 포함한다. 캡처에는 UID·소스/자산 판본·뷰포트를 연결한다. 기존 흐름의 필수 전수 검사 범위는 줄이지 않는다.

### D-2. 기존 문항 수정의 재결속

| 변경 종류 | 값 처리·필요한 확인 |
| --- | --- |
| `UNCHANGED` | 기존 값·유효 검수 재사용. 별도 레이아웃 변경이 있으면 화면 검사는 수행 |
| `FIGURE` | 값 유지, 자산 바이트·실제 도형 조건 확인. 의미 영향에 따라 given·condition·method 재확인 |
| `NOTATION` | 값 유지, 명시적 표기 동치 규칙과 실제 수식 렌더 확인 |
| `SOLUTION` | 값 유지, 해설 수학과 method·steps·난이도 영향 확인 |
| `STEM_EDIT` | 값 유지, 바뀐 발문·보기의 조건·목표·답·메타 적합성 재확인 |
| `ANSWER` | 값 유지, 독립 풀이로 새 정답과 해설·난이도·풀이 방법 확인 |
| `REPLACED` | 교체 **후보**. 독립 의미 확인으로 통째 교체가 확정된 경우만 옛 값을 새 문항에 적용하지 않음 |
| `NUMBER_MISMATCH` | 동일성 미확인. UID·파일·배열 위치·원표기 번호 재대조 전 재결속하지 않음. 교체로 단정하지 않음 |

같은 문항의 수정은 값을 버리지 않고 변경 표시와 재확인 대상을 남긴다. 확인된 오분류는 근거 있는 정정으로 고치며, 실제 수학·자산 결함은 별도로 수리한다. 교체 확정 시에도 옛 값은 옛 판본 이력에 보존한다. 과거 판본이 없으면 `EVIDENCE_DEBT`이며 현재 해시로 덮어 통과시키지 않는다.

현행 `archive/tools/meta-foundation/source-delta.mjs`는 객체 비교만 한다. 3글자 묶음 유사도에 따른 교체 후보는 확정 판정이 아니며, 같은 경로의 그림 바이트 변경은 잡지 못한다. 대표 class 외 `changed`·`otherChangedKeys`와 자산 해시도 함께 검사한다. 기존 지문 계산식은 바꾸지 않는다. 이 결과를 등록기·4칸에 연결하는 일은 후속 구현이다.

## D. 세 가지 길 — 유사문항 생성과 빈 곳 채우기

**결론: 생성의 목표 유형은 출제 의도일 뿐이다. 완성된 문항을 다시 독립 판정한 결과로 등록한다.**

### D-3. “이 기출의 유사문항 만들어”

| 단계·담당 | 입력 → 산출물 | 합격 검사 / 실패 시 복귀 |
| --- | --- | --- |
| 1. 원본 이해 — 저렴한 모델, 도구 | 원본 시험지·실제 풀이·그림 → 핵심 사고, 보존할 구조, 바꿀 조건·수치, 출처 UID | 원본 자체의 결함·교육과정 확인 / 원본 확인 또는 결함 수리 |

| 3. 독립 풀이·유사성 검토 — 독립 검토 역할 | 새 발문·그림 → 블라인드 풀이 동결 후 해설 대조·구조 비교 | 수학·난이도·목표 사고·원본과의 관계 충족 / 제작 단계 복귀 |
| 4. 독립 메타 판정 — 저렴한 모델 2회, 상위 모델 | 새 문항의 확정 발문·해설·그림 → 모든 메타·4칸·불일치 해결 | 원본 4칸·정답 메타를 베끼지 않음. 새 풀이의 결정 단계 인용 / 판정 단계 복귀 |

생성 문항은 원본과 별개의 UID를 **기존 식별 도구로** 부여받는다. 원본 UID·생성 당시 판본을 출처 관계로 기록하고, “원본에서 만들었다”와 “같은 풀이 구조다”를 구별한다. 검색 유사도만으로 쌍둥이 판정을 부여하지 않는다. 근거: 4칸 계약 §7·11-3·11-4·13.

### D-4. “빈 곳 채워”

| 단계·담당 | 입력 → 산출물 | 합격 검사 / 실패 시 복귀 |
| --- | --- | --- |
| 1. 지도 갱신 — 도구 | 현재 문항·메타·그룹·사전 → F장의 칸별 수량·미판정 수 | 중복 제거, 전체 분모·버전·출처 일치 / 입력·분류 수리 |
| 2. 공백 확인 — 도구, 저렴한 모델 2회, 상위 모델 | 0개·부족 칸과 관련 미판정 문항 → 실제 공백 또는 판정 대기 | 미등록·후보·재결속 대기가 만든 가짜 공백 배제 / 먼저 메타·재결속 작업으로 복귀 |
| 3. 생성 명세 — 저렴한 모델, 우선순위 예외는 사람 | 검증된 공백 → 교육과정·유형·method·목표 난이도·생성 수·금지 중복 | 교육적 필요와 교과서·문제집 사례 근거 / 명세 수정 |
| 4. 제작·독립 검수 — D-3의 담당 | 생성 명세 → 문항·해설·SVG·독립 풀이 | D-3 2~3단계의 동일 품질 / 제작으로 복귀 |
| 5. 메타·화면·수납 — D-3의 담당 | 완성 문항 → 독립 메타·4칸·실제 화면·꾸러미 | D-3 4~6단계, 실측 유형·방법·난이도가 목표 칸과 맞음 / 판정 또는 제작으로 복귀 |
| 6. 효과 확인 — 도구 | 등록 후 지도 → 실제 늘어난 고유 문항·방법 수 | 새 칸 점유와 중복 여부 확인 / 목표 미달은 대기, 생성 수만으로 완료 처리 금지 |

목표 칸과 실제 판정이 다르면 메타를 목표에 맞춰 덮어쓰지 않는다. 문항이 유용하면 실제 칸에 보존하고 원래 공백은 미해결로 남기거나, 명세에 맞는 새 문항을 다시 만든다. 같은 원본의 수치만 바꾼 여러 문항을 새로운 풀이 방법 확보로 세지 않는다.

### D-5. 공통 실패 복구와 담당

1. 형식·해시·등록 요청 생성 오류는 도구 담당이 고친다. 의미 값·판정 숫자는 형식 정규화로 바꾸지 않는다.
2. 독립 판정 불일치는 상위 모델이 두 근거와 실제 문항을 보고 해결한다. 근거가 여전히 부족하면 이유·필요 자료·담당을 남긴다. 동의만으로 수학적 정답을 보장하지 않는다.
3. 소스가 검수 뒤 바뀌면 해당 변경의 직접 영향 검사만 무효화한다. 검토 이력은 지우지 않는다. 기존 필수 전수 절차가 적용되는 신규 제작은 그대로 수행한다.
4. 등록 중 실패하면 허용된 출력의 적용을 되돌리거나 기존 정상 출력을 유지하고, 단계별 영수증을 남긴다. 4칸 대기는 새 꾸러미 완성을 막지만 기존 학생 이용을 막지 않는다. 운영 담당이 자동 재시도와 최종 상태표를 책임지며 작업자에게 새 요청을 반복해서 손으로 만들게 하지 않는다.

## E. 유형 확장 운영

**결론: 근거 있는 유형은 조회·직접 판정·신설 어느 경로로든 받는다. 기존 키는 보존하고 같은 뜻은 상위 묶음으로 정리한다.**

### E-1. 세 경로의 같은 제출 계약

| 경로 | 필수 근거 | 도구가 확인할 것 |
| --- | --- | --- |
| 판정기 조회 | 현재 문항의 핵심 풀이·결정 단계, 조회 입력과 결과 | 현재 교육과정 바인딩, PT·TPL 부모 관계, 판본 |
| 직접 판정 | 실제 해설 인용, 선택한 키 정의와의 대응, 다른 후보를 배제한 이유 | 키 존재·의미 참조·부모·범위, 독립 판정 결과 |
| 새 키 신설 | 기존 키로 표현 못 하는 차이, 일반화한 풀이 구조, 지원 UID·반례 | 이름 충돌·중복 후보, 정의·부모·근거, 등록 경로 지원 여부 |

판정 방법은 `RESOLVER`, `DIRECT`, `NEW_KEY`로 기록하되 신뢰 등급의 우열로 쓰지 않는다. `primaryMethod`는 핵심 풀이, `decisiveStep`은 답을 결정하는 단계다. 기존 RPM(사고 경로 분류)의 L1~L4와 유형 키를 기계적으로 1:1 치환하지 않는다. 수학적 의미가 같으면 교육과정 바인딩을 달리해 기존 키를 재사용한다.

### E-2. 신설 기준·이름·묶음

1. **신설 기준:** 같은 부모 아래 기존 정의·별칭·대표 문항을 읽어도 결정적 풀이 구조를 담을 키가 없을 때 만든다. 숫자·학교·문항 번호·표기만 다르면 재사용한다. 기존 정의를 넓히면 다른 문항이 섞이는 경우도 새 키 대상이다.
2. **이름 규칙:** 기존 키는 개명하지 않는다. 새 키는 기존의 `PT_<범위>_<핵심 전략>`, `TPL_<범위>_<풀이 구조>` 형태를 따르고 영문 대문자·밑줄로 일관되게 만든다. 실제 허용 문법은 등록기에서 확인한다. 범위 표기는 기존 관례를 따르되 연도·학년만 달라졌다고 동일 의미 키를 다시 만들지 않는다.
3. **정의 묶음:** 한국어 이름, 한 줄 정의, 부모 PT, `internalSkeleton`(일반 풀이 순서), 포함·제외 예, 근거 UID·판본을 함께 둔다. 특정 수치·시험 이름을 정의에 넣지 않는다.
4. **받고 나중에 묶기:** 새 값 등록부를 확장해 의미와 근거가 있는 키는 `UNGROUPED`로 수용한다. 상위 그룹이 아직 없다는 이유로 값을 지우지 않는다. 정본 승격·잠긴 마스터 변경은 별개다.
5. **상위 묶음:** 키→대표 유형 그룹의 별도 표를 둔다. 이름의 유사성이 아니라 정의·결정 단계·대표 문항으로 동의 관계를 판단한다. 상하위 관계와 같은 뜻의 별칭을 구분한다. 원키·원판정·옛 영수증을 유지하고 그룹 버전을 지도에 기록한다.
6. **충돌 방지:** 새 키 신청 때 기존 키·별칭·미분류 등록부를 함께 검색한다. 동시 신청은 한 등록 writer가 병합하고 같은 키의 다른 정의는 거부한다. 기존 크로스워크 행은 추가만 하며 봉인과 참조 행 검증을 유지한다.

기존 근거: `docs/agents/metadata.md` “확장 원칙”, 메타 OS §5·부록의 `archive/data/meta-os/received-values.json`. 현재 등록부는 새 PT/TPL을 문항의 본칸에 쓰는 경로까지 열려 있지 않다. **직접 판정·새 키 수용은 이번 결정에 따른 후속 계약·등록기 변경이며, 이미 지원된 기능으로 취급하지 않는다.**

### E-3. 조회와 직접 판정이 다를 때

| 원인 | 처리 |
| --- | --- |
| 의미는 같고 표기·키만 다름 | 상위 묶음·별칭 후보로 정리. 원키 보존 |
| 의미는 맞지만 과정 바인딩·대응표가 없음 | 값·근거를 수용하고 연결 정보를 보완. 문항의 풀이를 다른 유형으로 억지 재분류하지 않음 |
| 풀이의 결정 단계가 서로 다름 | 상위 모델이 실제 학생용 해설·두 근거를 비교. 판정기 결과를 자동 승자로 삼지 않음 |
| 여러 풀이가 가능함 | 학생에게 제공할 주 풀이를 기준으로 유형·method를 판정하고 대안 풀이는 선택 기록. 주 풀이가 불명확하면 먼저 해설 정리 |
| 어느 쪽도 근거가 부족함 | 값 후보·차이를 보존하고 `EVIDENCE_DEBT`. 거짓 키나 가짜 `NONE`으로 채우지 않음 |

4칸은 유형에서 복사하지 않는다. 새 용어는 사전 후보로 선언하고 중앙에서 번호를 발급한다. 같은 뜻이면 별칭, 다른 개념이면 새 번호다. `goal`·`method` 필수와 인용·방법 근거 규칙은 유지한다. 읽은 현행 계약의 사전은 v1.6이며, 실제 실행에서는 파일의 버전·해시를 조회해 고정한다. 근거: 4칸 계약 §7~11.

## F. 빈 곳 지도

**결론: “0개”를 바로 생성 지시로 바꾸지 않는다. 분류가 끝난 범위의 실제 공백과 메타가 비어 보이지 않는 문항을 먼저 구분한다.**

### F-1. 칸의 정의

`교육과정·과목·단원/소단원 × 유형 그룹(PT/TPL) × 풀이 방법 묶음 × 난이도 1~5`를 기본 칸으로 한다. 학년·출처·기출 연도·원본/유사/교과서/문제집은 별도 필터다. 모든 조합을 무작정 만들지 않고 실제 문항, 교과 자료 또는 교사의 출제 목표로 가능한 조합만 연다.

- 풀이 방법 묶음은 검토된 4칸 `method` 용어 번호 집합과, 순서가 핵심인 경우의 `steps`로 만든다. given·goal·condition은 변형과 중복 판단의 보조 축이다.
- 같은 method 집합이라도 같은 풀이 구조라는 보장은 없다. 대표 문항의 결정 단계로 확인하며, 용어 순서 차이만으로 새 방법 수를 늘리지 않는다.
- 키 그룹·사전·점수 규칙 버전, 대상 UID 목록의 판본을 고정한다. 서로 다른 버전 지도의 증감을 새 문항 효과로 섞지 않는다.

### F-2. 칸별 수량과 상태

| 항목 | 기록할 내용 |
| --- | --- |
| 관측 수 | 현재 칸에 판정된 고유 문항 수, 기출 수, 교과서·문제집 수, 생성 수 |
| 준비 수 | 실제 내용·메타 확인이 끝난 문항 수와 등록 대기 수 |
| 불확실 수 | 관련 범위의 유형/4칸/난이도 미판정, 후보 용어, 재결속 대기, 자료 미열람 수 |
| 상태 | `COVERED` 충족 / `THIN` 부족 / `CONFIRMED_GAP` 검증된 공백 / `UNKNOWN_COVERAGE` 조사 부족 / `NOT_APPLICABLE` 교육적으로 성립하지 않는 칸 |
| 필요 근거 | 교과 자료의 해당 유형·풀이 사례, 교사 요청, 목표 문항 수와 선정 이유 |

**실제 공백 판정 절차:** ① 해당 칸이 교육과정에서 의미 있는지 확인 → ② 유형 별칭·방법 묶음·교과 자료까지 찾아 중복을 해소 → ③ 관련 단원·과목의 미판정과 등록 대기를 조사 → ④ 해당 칸에 들어갈 가능성이 있는 미해결 문항이 없을 때만 범위를 명시해 `CONFIRMED_GAP`으로 확정한다. 단원 자체가 미상인 자료는 상위 과목 범위의 불확실 분모에 남긴다.

예를 들어 기출 0개·교과서 4개인 칸이라도 같은 단원 미판정 30문항이 남았다면 “기출 공백 후보”다. 이 30문항을 확인해 해당 유형이 없음을 확인한 뒤에만 “조사 범위 내 기출 공백”이라 한다. 4칸 사전 후보가 검색에서 제외되어 생긴 0도 실제 공백이 아니다. 실제 조사는 아직 하지 않았으므로 이 숫자는 설명용 예시다.

### F-3. 생성 우선순위

| 순서 | 대상 | 이유·종료 기준 |
| --- | --- | --- |
| 선행 | 메타 누락·재결속·등록 대기가 만든 공백 | 이미 있는 문항을 먼저 되살린다. 불확실 수 해소가 목표 |
| 1 | 교과서·문제집에는 확인되나 기출에 없는 필요한 유형 | 교육과정 학습 범위를 보충. “기출”로 출처를 바꾸지 않고 생성으로 표시 |
| 2 | 같은 유형의 특정 난이도 공백 | 쉬운 입문·중간 연결·어려운 심화의 연속성을 확보. 모든 유형에 1~5를 강제하지 않음 |
| 3 | 같은 유형인데 4칸 풀이 방법이 다른 변형 공백 | 다른 결정 단계·표현·조건을 경험하게 함. 숫자만 다른 문항은 우선순위를 낮춤 |

동순위에서는 수업 수요 → 대표성 → 기존 문항과의 차이 → 제작·검수 비용 순으로 고른다. 첫 시범은 칸마다 1문항부터 만들고, 한 칸의 동형 문항을 대량으로 늘리기 전에 실제 사용성을 확인한다. 가중치 점수·목표 재고는 사용자 선택 사항으로 남긴다.

### F-4. 생성 품질 수납

1. D-3의 독립 풀이, 교육과정, 조건·정답·해설·SVG·실제 화면 검사를 전부 적용한다.
2. 생성 의도를 가린 메타 판정으로 실제 유형·method·난이도를 확인한다. 기존 문항 검색과 실제 해설 비교로 중복을 검토한다.
3. 등록 후 지도를 다시 계산해 새 고유 문항과 방법 수가 늘었는지 확인한다. “5개 생성”과 “부족한 방법 1개 확보”를 따로 보고한다.
4. 신규 유형·용어가 미분류인 문항은 보존하되, 묶음 확정 전의 지도 수치에는 불확실 표시를 붙인다. 키 정리로 이동한 수와 새로 생성한 수를 분리한다.

## G. 기존 약 28,000문항의 이행

**결론: 파일을 대이동하지 않고 기존 정본 위에 꾸러미 목록을 얹는다. 값은 재사용하고 미확인·변경 영향만 처리한다.**

### G-1. 그대로 둘 것과 옮길 것

| 그대로 유지 | 꾸러미 체계로 옮길 운영 책임 |

UID는 내용과 독립이지만 경로·순번과 식별 이력이 중요하다. `archive/tools/intelligence/sync-question-identity-map-v1.mjs`와 4칸 계약 §11-3이 다루는 연속성을 보존한다. 경로 변경·문항 삽입을 단순 파일 정리로 처리하지 않고 기존 식별 도구의 매핑 검증 대상으로 삼는다.

### G-2. 이행 순서와 완료 기준

| 단계 | 수행 범위 | 완료 증거 |

전체 전수 측정은 구현 첫 기준선과 단계 완료 집계에 수행한다. 작은 수정을 할 때마다 약 28,000문항을 다시 판정하지 않는다. 역사적 집계 28,615·28,623과 요청의 약 28,000을 하나의 정확한 분모로 간주하지 않는다. 새 검사기가 같은 기준에서 산출한 실제 분모를 사용한다.

### G-3. 등록·실패·되돌리기

1. **단일 쓰기 유지:** 기존 writer의 reviewed→semantic→shared→generated→studentIndexes→fourSlot 순서를 재사용한다. 단계 이름은 기존 구현 사실이며, 새 꾸러미가 이 순서를 바꿔야 한다면 의존성 근거부터 확인한다.
2. **안전한 적용:** 꾸러미 사전 검증 → 임시 출력 생성 → 대상 UID·영수증·소비자 일치 확인 → 허용 출력 적용 순으로 한다. 기존 writer의 불변 입력 보호와 실패 복구를 재사용한다. 소스·그림·compact를 등록기가 임의 교정하지 않는다.
3. **부분 실패:** 현재 fourSlot 단계는 필수가 아닌 설정이다. 이를 전체 기존 출고 차단으로 바꾸지 않고 꾸러미의 완성 판정에서 필수 수납 여부를 따로 확인한다. 실패한 단계의 입력이 바뀌었거나 도구가 수리되면 해당 단계만 재시도한다.
4. **되돌리기:** 기능 스위치로 새 어댑터·재결속·지도 사용을 각각 중지한다. 정상 기존 색인을 유지하고 코드·설정은 일반 되돌림 커밋으로 복구한다. 이미 등록된 값의 정정은 정확한 이전 값·판본을 가진 공식 정정 요청으로 처리한다. 원시 증거·영수증·기존 키를 삭제하지 않는다.
5. **중단 조건:** UID 오결속, 실제 교체에 옛 메타 적용, 승인 값 무단 변경, 기존 학생 이용 감소가 하나라도 나오면 해당 배치 확대를 멈추고 원인을 고친다. 같은 입력 재시도로 중복 등록·다른 UID 변경이 없어야 한다.

## I. 비용 관점과 검증 범위

**결론: 이미 있는 값을 재판정하지 않는 것이 가장 큰 절감이다. 모델은 의미를 읽고 도구는 형식·지문·대조·등록을 맡는다.**

### I-1. 단계별 배분과 추정식

| 단계 | 모델 배분(문항당 작업 단위) | 토큰을 아끼는 곳 |
| --- | --- | --- |
| 완성도 검사·꾸러미 변환 | 대량 모델 호출 0, 설계·예외 표본만 | 기존 파일·영수증 조회, 해시·스키마·집계는 도구 |
| 재결속 | 기계 분류 후 의미 확인 필요한 M문항에 저렴한 판정 2M회, 불일치 pM회 상위 검토 | 기존 유효 근거 재사용, 바뀐 문항·필드만 전달 |
| 부족 메타 채우기 | N문항에 저렴한 판정 2N회, 불일치 pN회 상위 검토 | 한 번 읽을 때 필요한 모든 메타와 4칸 수집, 전체 사전 대신 관련 선택지 제공 |
| 기출 내용 수리·유사 생성 | 문항당 초안 1회, 실패 시 필요한 수정. 메타는 독립 2회 | 기존 출제·검수 절차 재사용. 수학·SVG 필수 검수 비용 별도 |
| 빈 곳 지도·생성 | 집계는 호출 0, 공백 후보 확인 후 선정 G문항만 제작 | 기존 문항 회수·중복 검색을 먼저 수행 |

N은 전체 문항 수가 아니라 실제 추가 판정 대상이다. 극단적으로 약 28,000문항 전부를 새로 판정하면 저렴한 판정은 약 56,000문항회다. 실제 네트워크 요청 수는 시험지 묶음 처리에 따라 다르다. 불일치율 p를 **예산 가정** 10~40%로 놓으면 상위 검토는 약 2,800~11,200문항회이며, 실측 비용이나 목표 일치율이 아니다. 제공된 난이도·소단원 비교 일치율을 전체 필드의 p로 그대로 쓰지 않는다.

`예상비용 = 2N × 저렴한 판정의 평균 입출력 비용 + pN × 상위 검토 평균 비용 + 제작·수학/시각 검수·도구 실행 비용`으로 산정한다. 그림 입력 비용도 포함한다. 첫 시험지에서 입력/출력 토큰·그림 수·불일치율·수리 횟수를 측정하고 다음 배치 예산을 갱신한다. 가격·평균 토큰·처리 시간은 **확인 필요**이며 실제 실행 영수증과 당시 단가표로 확인한다.

자료 추출·공통 지침은 캐시하되, 2차에게 1차 판단을 전달하지 않는다. 블라인드 풀이 패킷과 해설 포함 메타 패킷도 분리한다. 세부 키 목록은 관련 범위만 주되 맞는 키가 없을 때 전체 검색·신설 경로로 나갈 수 있게 한다. 검사 생략·분모 축소를 절감으로 계산하지 않는다.
