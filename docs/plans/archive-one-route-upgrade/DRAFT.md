**현황의 해석.** `PROMPT.md`가 제공한 중등 9,139문항 실측은 난이도 숫자 99.5%, 형식 완비 61%, 유효 유형 1,857문항, 4칸 등록 6,729문항, 원본 변경에 따른 4칸 대기 1,363문항이다. 어긋난 문항 약 90%가 그림·해설 변경이라는 수치도 제공 자료다. 이번 작성에서 재측정하지 않았으며, 서로 겹치는 수를 합산하거나 전체 약 28,000문항으로 외삽하지 않는다.

**합의된 순서.** 완성도 검사 → 기준선 → 재결속 연결 → 꾸러미 시범 → 유사문항 → 빈 곳 생성 순으로 간다. 진행 중 채우기는 검사 결과에 합류시킨다. 첫 2주는 검사·기준선·재결속 연결까지이며, 등록 어댑터와 새 시험지 시범은 그다음이다.

**완성과 이용 가능은 다르다.** 새 작업은 필수 메타가 남으면 미완료다. 기존 문항은 4칸 누락·보류 때문에 검색·선택·출력에서 빼지 않는다. 학생이 풀고 해설을 이해할 수 있는지와 메타 작업이 끝났는지를 상태표에서 나란히 보여 준다. 근거: `docs/architecture/JS_Archive_Item_4Slot_Term_Contract_CURRENT_v1.md` §11-6·14, `docs/architecture/JS_Archive_Meta_OS_CURRENT.md` §0·3.

## B. 꾸러미 설계

**결론: 기존 정본 파일은 제자리에 두고 목록 파일(manifest)로 묶는다. 파일 이동과 공용 메타 복제는 하지 않는다.**

### B-1. 폴더와 파일

1. 신설 목록: `archive/data/exam-bundles/<bundleId>/manifest.json`이 시험지·문항·파일·검사·요청을 잇는다.
2. 학생 내용: `archive/exams/**/<시험지>.js`와 기존 자산 위치를 유지한다. 새 SVG(벡터 그림)도 승인된 자산 경로에 둔다.
3. 메타 요청: `.archive-meta-register/inbox/*.json`을 기존 등록기가 읽는다.
4. 4칸: `archive/data/item-4slot/**/*.4slot.json`은 용어 번호만 담는 운영 파일(compact)로, 기존 importer로 만든다.
5. 결과·근거: 기존 영수증은 불변으로 두고 새 결과만 추가한다. 상세 판정 원장·인용·캡처는 작업 `.tmp/`와 허용 외부 증거 보관소에 두며 커밋하지 않는다.
6. 생성 저장소: 기존 shard(분할 저장 파일)는 `{store, uid}`로 참조한다. 시험지형 유사는 JS 하나로 묶되 다른 저장소에 기출 UID·스키마를 억지 적용하지 않는다.

### B-2. 필수 칸과 선택 칸

| 묶음 | 필수 정보 | 선택·조건부 정보 |
| --- | --- | --- |
| 꾸러미 식별 | `schemaVersion`, `bundleId`, `revision`, 요청 종류, 시험지 경로, 기준 커밋·소스 blob(파일 판본), 교육과정·학년·과목, 기대 문항 수 | 원본 시험지·생성 과제·빈 곳 지도 참조 |
| 문항 식별 | 기존 UID, 저장소, 배열 위치 `sourceOrdinal`, 원표기 번호 `sourceQuestionNo` | 출처 UID·생성 당시 원본 판본 |
| 학생용 내용 | 발문·정답·해설 및 검사 근거 | 보기·문제 그림·해설 그림은 해당할 때 필수. 불필요함도 이유를 기록 |
| 메타 | 단원·소단원, 1~5 정수 난이도와 확신도·경계·옛 난이도 호환, 유형 PT(문제 유형)·TPL(풀이 틀), 교육과정 내 사고 경로, 연결 개념·조건·통합 방식 | 기존 `level`은 독립 값으로 보존. 없다고 숫자 난이도에서 환산하지 않음 |
| 4칸 | `given`(주어진 것), `condition`(조건), `goal`(목표), `method`(풀이 방법), `format`(문항 형식), 사전 버전·해시 | goal·method는 필수. given·condition은 실제 해당할 때 작성. 순서가 핵심이면 `steps` |
| 판정·검사·등록 | 필드별 상태·근거 참조, 판정·검토 역할과 시각, 검사기 버전·입력 해시·실행 결과, 등록 요청 ID | 보류 이유·담당·재개 조건, 유형·용어 신설 제안 |
| 원문 변경 | 이전·현재 판본 참조, 기존 지문, 자산 해시, 변경 종류·세부 플래그 | 신규 문항이면 이전 판본 없음이 정상. 기존 문항의 이전 판본 유실과 구별 |

manifest는 메타 값의 정본을 복제하지 않고 참조한다. 완성 상태는 실제 자료로 계산하며 `complete:true` 선언을 믿지 않는다. `before`·해시·문항 수는 도구가 만들고 모델은 의미만 판정한다.

### B-3. 부분 완성과 기존 요청 수용

1. 유형 근거가 부족하면 `type=HOLD`와 이유·담당을 표시한다. 단, **현재 CI 통과를 뜻하지 않는다.** `tools/ci/archive-pr-native-preview.mjs`의 `difficultyAssignmentInformation()`은 `assignment_missing`을 난이도 요청에만 허용한다. 단원 등록의 유형 보류가 `PR_NATIVE_PREVIEW:CONSUMER_NOT_PASS`로 막힌 사실은 `REVIEW.md` #2의 실측이다. 그림 불필요는 `NOT_APPLICABLE`, 필요한 그림 누락은 `MISSING`이다.
2. **CI 보완 제안:** REVIEW2(독립 2회 검토)의 명시적 `typeHold` 요청에 한해 요청 ID·UID·배열 위치·현재 소스·보류 이유를 결속해 기대된 유형 미배정만 정보로 수납한다. 단원 등 실제 등록 필드의 소비자 일치, 무결성·보호 필드 검사는 유지한다. 다른 UID, 유형이 있어야 하는 행, 다른 실패는 계속 거부한다. 유형 승인 수는 0, 상태는 부분완성으로 남긴다. 허용/거부 반례를 함께 검증한 뒤 적용한다.
3. **4칸 부분제출(`PARTIAL_UIDS`)은 일반화 작업이 필요하다.** 전체 분모와 `selected`·`unsubmitted`를 겹침 없이 유지하고, 미제출은 `NOT_SUBMITTED`, 시험지는 `SUPPLEMENT_PENDING`으로 둔다. 현 기본 importer는 서로 다른 작성자·검토자의 실제 원문과 영수증을 요구하며 단순 원장 변환물을 받지 않는다. `mid`·`mid2`·`mx4`용 일반 어댑터를 만들되 독립 검토 증거를 포맷 변환으로 꾸미지 않는다.
4. **기존 compact의 나머지 문항 추가도 보완 대상이다.** 기본 부분 importer는 새 파일 또는 동일 바이트 재실행만 허용한다. `tools/4slot/private-source-structure-append.cjs`에 그림 없는 객관식의 발문·보기만 보는 구조 검토를 위한 전용 추가 경로는 있다. 이를 일반 해설·그림 문항 수납으로 확대할 때 기존 compact·영수증 해시 대조, 기존 행 불변, 미제출 UID만 추가, 새 영수증 연결을 유지한다. 마지막 미제출까지 채우면 빈 `unsubmitted`를 억지 허용하지 않고 전체 제출로 전환하는 계약을 마련한다. 검토문 #4의 금당중 두 시험지 중단은 일반 경로의 운영 막힘으로 기록한다.
5. 기존 v2·난이도·재결속·최종 검수 요청은 권한·보호 필드를 유지해 어댑터로 받는다. 현 단일 자동 등록 실행기(writer)에 목록 입력을 추가하고 소스·그림·compact는 PR에 먼저 싣는다. 같은 내용의 재실행은 중복 없이 끝내며 변경은 새 revision·요청 ID로 보낸다. 병합 대기열과 PR 크기 기준은 G-3을 따른다.

## C. 완성도 검사 도구와 상태표

**결론: 읽기 전용 검사기를 먼저 만들어 같은 문항 목록으로 누락·품질·등록을 따로 보여 준다.**

### C-1. 입력과 출력

- 제안 명령: `node archive/tools/completion/check.mjs --exam <경로> --format json|tsv`와 `--bundle <manifest>`, `--grade <학년>`, `--all`. 아직 존재·실행 여부를 확인한 명령이 아니라 신설 명세다.
- 입력: 현재 소스·자산, 기존 identity map, 운영 메타·4칸·사전, 실제 검사와 수납 영수증, 등록 대기·거절 목록. manifest 없는 옛 시험지도 가상 목록으로 읽는다.
- 출력: 문항별 발문·정답·해설·그림·단원·난이도·유형·4칸·등록 상태, 실제 검사 범위, 남은 이유·담당·다음 명령. 상세 표에는 소단원·사고 경로·연결 개념·조건·통합 방식도 빠짐없이 포함한다.
- 모든 결과는 기준 커밋·소스/자산/사전/검사기 버전에 결속한다. 캐시는 그 의존성이 같을 때만 재사용하며, 바뀐 문항과 직접 영향 검사만 다시 실행한다.

**첫 입력은 이미 있는 재료다.** 중등 원장 `mid`·`mid2`·`mx4`(검토문 제공), `archive/tools/meta-foundation/source-delta-report.mjs` 보고, `archive/data/item-4slot-index.json`의 대기 사유를 UID로 연결한다. 원장 위치·스키마·판본은 실제 파일 목록·해시로 확인해야 한다. 원장 존재를 등록 완료로 세지 않으며, 재사용 시 모델·입력·시각·상호 비노출을 확인한다. 같은 모델의 두 원장은 서로 다른 모델 판정으로 표시하지 않는다.

### C-2. 상태 값과 완성 판정

| 축 | 값 | 뜻 |
| --- | --- | --- |
| 필드 상태 | `MISSING`, `RECORDED`, `PASS`, `NOT_APPLICABLE` | 없음 / 값은 있음 / 필요한 근거와 검사 충족 / 실제 해당 없음 |
| 미완료 이유 | `HOLD`, `EVIDENCE_DEBT`, `INVALID`, `NEEDS_RECHECK`, `NOT_SUBMITTED` | 판단 보류 / 근거 부족 / 형식·참조 결함 / 변경 영향 재확인 / 명시적 미제출 |
| 검사 실행 | `PASS`, `FAIL`, `NOT_RUN` | 실제 실행 결과. 파일 존재·작성자의 선언으로 PASS를 만들지 않음 |
| 등록 | `NOT_SUBMITTED`, `PENDING`, `PARTIAL`, `REGISTERED`, `REJECTED` | 제출 전부터 실제 수납까지의 별도 상태 |
| 문항 종합 | `IN_PROGRESS`, `READY_TO_REGISTER`, `COMPLETE`, `BLOCKED` | 작업 중 / 등록 전 필수 검사 완료 / 등록 후 읽기 확인까지 완료 / 실제 결함·필수 의존성 때문에 중단 |
| 변경 표시 | source-delta의 8개 class + 세부 플래그 | 값의 검토 상태와 별개. 변경 표시 자체를 결함으로 간주하지 않음 |

값 기록·보류와 완성·이용 자격을 혼동하지 않는다. `NOT_APPLICABLE`에는 근거가 필요하며 필수 유형·goal·method 누락에 쓸 수 없다.

1. `READY_TO_REGISTER`: 기대 문항 전체가 정확히 식별되고 필수 내용·메타·4칸·역할별 검수, D-1에 정한 자동 렌더 검사와 필요한 눈 확인, 등록 사전 검사가 통과했다.
2. `COMPLETE`: 위 조건에 더해 해당 판본의 필요한 등록 단계가 성공하고, 운영 메타·색인에서 대상 UID와 값을 다시 읽어 일치를 확인했다. 독립 검수·기계 형식 검사의 증거를 구별한다.
3. `studentReady`, `registrationStatus`, `deploymentStatus`는 별도 출력한다. 등록 완료가 배포 완료를 뜻하지 않는다. 배포까지 맡긴 실행의 종료 조건에는 실제 배포·학생 화면 확인도 추가한다.
4. 숫자 난이도·기존 문항은 활용하되 보조값·4칸 부족은 새 작업의 미완료로 표시한다.

### C-3. 집계와 사용 방식

| 사용자 | 용도 |
| --- | --- |
| 작업자 | 시험지 N문항의 완성/대기/결함과 부족 필드를 보고 해당 부분만 처리 |
| 운영자 | 학년·과목·전체의 동일 분모, 등록 전후 차이·보류 기간으로 순서 배정 |
| CI | 변경 꾸러미의 전체 분모·근거·보호 필드·이용 회귀 검사. 거짓 완료와 실제 결함은 실패 |

UID 중복을 제거하고 자료 종류를 구분한다. 필드별 부족 수는 겹칠 수 있으며 문항 종합 상태의 합만 전체 N과 같아야 한다. 필수·해당 없음·미판정 수를 함께 표시한다. 조회 성공과 완성은 별개다. CI의 `--require ready|complete`는 해당 조건 미달 시 실패하고 부분제출은 부분 상태로 남긴다. 현행 `audit.mjs`·backlog 도구는 입력으로 재사용하되 이를 내용·그림 검수까지 포함한 완성 검사로 부르지 않는다(메타 OS §0·6).

## D. 세 가지 길 — 공통 절차와 기출 완성

**결론: 세 길 모두 내용 작성 → 독립 검수 → 메타 판정 → 화면 확인 → 한 번 제출 → 수납 확인으로 닫힌다. 실패는 담당 단계로만 되돌린다.**

### D-1. “이 기출 완성해”

| 단계·담당 | 입력 → 산출물 | 합격 검사 / 실패 시 복귀 |
| --- | --- | --- |
| 1. 범위 확정 — 도구, 범위 모호할 때 사람 | 시험지·원본 자료 → 전체 UID/번호 목록, 기존 완성도·결함 목록 | 누락·중복 0, 출처 확인 / 자료·번호 확인으로 복귀 |
| 2. 내용 완성 — 저렴한 모델, 어려운 결함은 상위 모델 | 원문·실제 그림·기존 결함 → 교정된 발문·보기·정답·학생용 해설·그림 설계 | 교육과정 내 풀이, 답의 존재·유일성, 조건 충족 / 작성 단계 수리 |
| 3. 수학 검수 — 기존 독립 검토 역할 | R1 독립 풀이 동결 → R2 내용·계산 검토 → R3 최종 결과물 감사 | 역할별 범위 유지. R2·R3 전체를 새 블라인드 풀이로 반복하지 않음 / 영향 문항 수리 |
| 4. 메타 판정 — 서로 다른 모델 A·B, 도구, 상위 모델 | 확정 문항·해설·실제 그림 → 독립 원장 2개·불일치 해결 기록 | 서로 원장 비노출, 정확한 인용·문항 매칭·키/부모·4칸 검사 / 형식은 도구 수리, 의미 불일치는 상위 검토 |
| 5. 그림·실제 화면 — 작성 모델, 도구, 검토자 | 필요 그림 명세 → SVG 또는 적합한 기존 자산, 실제 렌더 근거 | 수학 조건·눈금·라벨·정답 누설·가독성·잘림 확인 / SVG·본문·레이아웃 수리 |
| 6. 꾸러미 사전 검사 — 도구, 제출자 | 최종 소스·메타·4칸·근거 → manifest·소형 요청·한 PR | 전체 문항 분모, READY_TO_REGISTER, 변경 범위·보호 필드 / 실패 단계로 복귀 |
| 7. 수납·마감 — 기존 등록 writer, 도구, 운영 담당 | 승인된 PR의 입력 → 등록 영수증·소비자 읽기 결과·최종 상태표 | 대상 UID·값·판본 일치, 필수 단계 실제 성공 / 같은 꾸러미의 대기만 재시도 |

**기존 라인은 우선 감싸는 안을 추천하며 최종 선택은 H-3에 둔다.** 사용자는 한 번 요청하고 도구가 단계 인계·재시도를 이어 간다. 블라인드 풀이에는 정답·해설·method·4칸을 미리 주지 않는다. 메타 A·B는 확정 해설을 읽되 서로의 판정은 보지 않는다.

**화면 확인은 자동 전수와 필요한 눈 확인을 나눈다.** SVG(벡터 그림)를 만들고 전 문항의 렌더 오류·잘림·넘침을 PC/휴대폰 폭에서 도구로 검사한다. 사람·모델의 실제 Chrome 눈 확인은 그림 문항과 도구가 표시한 문항에 집중한다. 시험지·정답·해설 모드 전환은 대표 시험지에서 확인하며, SVG 문법 PASS로 수학 조건·라벨·가독성을 대신하지 않는다.

전수 의무 근거: `docs/rules/02_PIPELINES/gpt-reservation/` 아래 `CREATE_CURRENT.md` §2·4는 전체 제작·필요 그림, `R1_CURRENT.md` §2·3·5는 전 대상 독립 풀이 동결 후 답·해설·그림 대조, `R2_CURRENT.md` §2는 전체 내용·계산 검토와 의심 항목 독립 재계산, `R3_CURRENT.md` §2·3은 전체 결과물 감사·동일 판본 증거 재사용이다. 이를 유지하되 전 문항×두 기기×세 모드 눈 확인을 새로 강제하지 않는다.

### D-2. 기존 문항 수정의 재결속

| 변경 종류 | 값 처리·필요한 확인 |
| --- | --- |
| `UNCHANGED` | 기존 값·유효 검수 재사용. 별도 레이아웃 변경이 있으면 화면 검사는 수행 |
| `FIGURE` | 값 유지, 자산 바이트·실제 도형 조건 확인. 의미 영향에 따라 given·condition·method 재확인 |
| `NOTATION` | 값 유지, 명시적 표기 동치 규칙과 실제 수식 렌더 확인 |
| `SOLUTION` | 값 유지, 해설 수학과 method·steps·난이도 영향 확인 |
| `STEM_EDIT` | 값 유지, 바뀐 발문·보기의 조건·목표·답·메타 적합성 재확인 |
| `ANSWER` — 빈 정답 채움 | 메타 유지. 이전 값이 실제 미기재였는지, 새 답이 기존 발문·풀이로 도출되는지 확인. 0·false를 빈 값으로 취급하지 않음 |
| `ANSWER` — 기존 값 변경·삭제 | 메타 유지, 독립 풀이로 새 답·해설·난이도·방법 영향 확인. 유효 답 삭제는 실제 결함으로 수리 |
| `REPLACED` | 교체 **후보**. 독립 의미 확인으로 통째 교체가 확정된 경우만 옛 값을 새 문항에 적용하지 않음 |
| `NUMBER_MISMATCH` | 동일성 미확인. UID·파일·배열 위치·원표기 번호 재대조 전 재결속하지 않음. 교체로 단정하지 않음 |

같은 문항의 수정은 값을 버리지 않고 변경 표시와 재확인 대상을 남긴다. 확인된 오분류는 근거 있는 정정으로 고치며, 실제 수학·자산 결함은 별도로 수리한다. 교체 확정 시에도 옛 값은 옛 판본 이력에 보존한다. 과거 판본이 없으면 `EVIDENCE_DEBT`이며 현재 해시로 덮어 통과시키지 않는다.

현행 `archive/tools/meta-foundation/source-delta.mjs`의 class 8개는 유지하고 정답 채움/변경은 보고·재결속의 하위 표시로 추가한다. `REVIEW.md` #7의 중2 ANSWER 121건 중 71건 채움은 제공 실측이며 이번에 재측정하지 않았다. **재결속 조건은 UID·이전 판본 + class + `changed.*` + `otherChangedKeys` + 실제 자산 해시의 결합**이다. `sharedMaterial` 같은 공통 지문 변경은 UNCHANGED여도 내용 검토가 필요하고, 모르는 필드는 안전하다고 자동 통과시키지 않는다. 문항 객체 밖 공유 지문도 목록의 참조를 따라 영향 문항을 펼친다. 짧은 수식의 교체 과대 판정과 같은 경로 자산 교체를 확인하며 기존 지문 식은 유지한다.

## D. 세 가지 길 — 유사문항 생성과 빈 곳 채우기

**결론: 생성의 목표 유형은 출제 의도일 뿐이다. 완성된 문항을 다시 독립 판정한 결과로 등록한다.**

### D-3. “이 기출의 유사문항 만들어”

| 단계·담당 | 입력 → 산출물 | 합격 / 실패 복귀 |
| --- | --- | --- |
| 1. 원본 이해 — 모델 A·도구 | 원본·풀이·그림 → 핵심 사고·변형 명세·출처 UID | 원본 정확성·교육과정 / 자료·명세 확인 |
| 2. 제작 — 모델 A, 어려운 구조는 상위 모델 | 명세 → 발문·보기·정답·해설·SVG | 조건 성립·답 존재/유일성 / 해당 문항 재작성 |
| 3. 독립 검수 — 기존 검토 역할 | 새 발문·그림 → 풀이 동결 후 원안·구조 비교 | 수학·유사성·목표 사고 / 제작으로 복귀 |
| 4. 메타 — 모델 A·B, 불일치 상위 검토 | 새 확정 문항 → 모든 메타·4칸·근거 | 원본 메타 복사 금지·독립 근거 / 재판정 |
| 5. 화면 — 도구·검토자 | 실제 자산·문항 → 자동 렌더·필요한 눈 확인 | D-1 범위, 조건·라벨·답 누설 / 내용·시각 수리 |
| 6. 수납 — 도구·제출자·writer | 한 꾸러미 → 한 PR·영수증·상태표 | D-1 6~7단계 / 실패 단계만 재진입 |

새 UID는 기존 식별 도구로 받고 원본 UID·생성 당시 판본을 연결한다. 출처 관계와 수학적 쌍둥이 판정은 다르며 검색 점수만으로 후자를 부여하지 않는다(4칸 계약 §7·11-3·11-4·13).

### D-4. “빈 곳 채워”

| 단계·담당 | 입력 → 산출물 | 합격 / 실패 복귀 |
| --- | --- | --- |
| 1. 지도 — 도구 | 현재 문항·메타·그룹 → F장의 수량·불확실 수 | 분모·판본·중복 검사 / 입력 수리 |
| 2. 공백 — A·B·도구, 불일치 상위 검토 | 부족 칸·미판정 → 실제 공백 또는 대기 | 미등록·재결속·후보 때문에 생긴 0 배제 / 메타 작업 |
| 3. 명세 — 모델 A, 우선순위 예외는 사람 | 검증 공백 → 과정·유형·method·난이도·생성 수 | 교과 근거·교육적 필요 / 명세 수정 |
| 4. 제작·검수 — D-3 담당 | 명세 → 문항·SVG·독립 풀이·메타·화면·꾸러미 | D-3 2~6단계 / 해당 실패 단계 |
| 5. 효과 — 도구 | 등록 후 지도 → 고유 문항·방법 증가 | 실제 목표 칸 충족·중복 없음 / 미달 칸은 대기 |

목표 칸과 실제 판정이 다르면 메타를 억지로 맞추지 않는다. 문항은 실제 칸에 보존하거나 다시 제작하고 원래 공백은 미해결로 남긴다. 수치 변형 여러 개를 새 풀이 방법 여러 개로 세지 않는다.

### D-5. 공통 실패 복구

1. 형식·해시 오류는 도구가 수리하고 의미 값·난이도는 추정 변경하지 않는다. A·B 불일치는 상위 모델이 실제 문항과 두 근거로 검토하며 근거 부족은 이유·담당을 남긴다.
2. 검수 뒤 소스 변경은 직접 영향 검사만 무효화한다. 신규 제작의 역할별 전수 의무는 유지한다.
3. 등록 실패는 기존 정상 출력을 보존하고 해당 단계만 재시도한다. 운영 담당이 인계·재개를 책임진다. 4칸 대기는 새 완성을 막되 기존 학생 이용을 막지 않는다.

## E. 유형 확장 운영

**결론: 근거 있는 유형은 조회·직접 판정·신설 어느 경로로든 받는다. 기존 키는 보존하고 같은 뜻은 상위 묶음으로 정리한다.**

### E-1. 세 경로의 같은 제출 계약

| 경로 | 필수 근거 | 도구가 확인할 것 |
| --- | --- | --- |
| 판정기 조회 | 현재 문항의 핵심 풀이·결정 단계, 조회 입력과 결과 | 현재 교육과정 바인딩, PT·TPL 부모 관계, 판본 |
| 직접 판정 | 실제 해설 인용, 선택한 키 정의와의 대응, 다른 후보를 배제한 이유 | 키 존재·의미 참조·부모·범위, 독립 판정 결과 |
| 새 키 신설 | 기존 키로 표현 못 하는 차이, 일반화한 풀이 구조, 지원 UID·반례 | 이름 충돌·중복 후보, 정의·부모·근거, 등록 경로 지원 여부 |

판정 방법은 `RESOLVER`, `DIRECT`, `NEW_KEY`로 기록하되 신뢰 등급의 우열로 쓰지 않는다. `primaryMethod`는 핵심 풀이, `decisiveStep`은 답을 결정하는 단계다. 기존 RPM(사고 경로 분류)의 L1~L4와 유형 키를 기계적으로 1:1 치환하지 않는다. 수학적 의미가 같으면 교육과정 바인딩을 달리해 기존 키를 재사용한다.

### E-2. 신설 기준·이름·묶음

1. 기존 정의·별칭·대표 문항으로 결정적 풀이를 담을 수 없을 때 신설한다. 숫자·시험명·표기만 다르면 재사용하고, 기존 정의를 넓혀 다른 문항을 섞지 않는다.
2. 새 이름은 기존 `PT_<범위>_<핵심 전략>`, `TPL_<범위>_<풀이 구조>` 관례를 따른다. 실제 허용 문법은 등록기에서 확인한다. 연도·학년만 다르다고 동일 의미 키를 재발급하지 않는다.
3. 한국어 이름·정의·부모 PT·일반 풀이 순서(`internalSkeleton`)·포함/제외 예·지원 UID·판본을 동봉한다. 특정 수치·시험명을 정의에 넣지 않는다.
4. 새 값은 근거와 함께 `UNGROUPED`로 받아 두고 정본 승격과 구분한다. 별도 키→대표 그룹 표에서 동의어와 상하위를 구별하며 원키·판정·영수증을 보존한다.
5. 신설 전 기존 키·별칭·미분류 등록부를 함께 검색한다. 동시 신청은 단일 writer가 처리하고 같은 키의 다른 정의는 거부한다. 크로스워크는 추가만 하고 봉인·참조 행 검증을 유지한다.

근거: `docs/agents/metadata.md` 확장 원칙, 메타 OS §5·부록의 `archive/data/meta-os/received-values.json`. 미분류 등록부 수록과 ACTIVE 키로 실제 수납되는 것은 다르다.

### E-3. 이미 되는 것과 실제로 보완할 세 곳

**1판 정정: REVIEW2는 직접 판정한 PT/TPL을 이미 받는다.** `archive/tools/meta-foundation/reviewed-exam-registration-v2.mjs`는 `patch.after`를 적용한 뒤 `resolve()`에서 ACTIVE 키·TPL 부모·정확한 과정 바인딩 등을 검사한다. 별도 판정기 결과와의 의미 일치를 여기서 강제하지 않는다. 코드 열람으로 확인했으며 실제 등록 실행은 `NOT_RUN`이다.

| 보완 지점 | 현재 경계 | 후속 구현·합격 조건 |
| --- | --- | --- |
| ① 바인딩 생성 | 키가 있어도 정확한 과정·과목·단원·소단원·PT 바인딩이 없으면 거부 | 요청 생성기가 근거 있는 바인딩 추가를 add-only로 제안·동봉. 기존 행 불변·정확 부모·범위 검증 유지 |
| ② 유형 보류 후 채움 | `typeHold:true`로 PT/TPL을 쓰는 것은 금지. 플래그 없는 새 일반 요청 경로는 있으나 유형 키만 넣으면 끝나는 운영 절차가 아님 | 새 요청 ID·정확 before·현재 소스·단원 정본화·부모 연결·런타임·소비자 전환까지 연결해 검증. 기존 단원·다른 필드 보호, 성공 후 해당 유형 보류만 해제 |

### E-4. 조회와 직접 판정이 다를 때

1. 같은 의미·다른 키는 별칭/그룹으로 연결하고 원키를 보존한다. 바인딩만 없으면 연결을 보완하며 풀이를 다른 유형으로 바꾸지 않는다.
2. 결정 단계가 다르면 상위 모델이 실제 해설·두 근거를 본다. 여러 풀이가 있으면 학생에게 제공할 주 풀이를 기준으로 하고 판정기를 자동 승자로 삼지 않는다.
3. 근거 부족은 후보·차이를 보존해 `EVIDENCE_DEBT`로 둔다. 4칸은 유형에서 복사하지 않으며 새 용어는 후보→중앙 번호 발급으로 처리한다. goal·method·인용 규칙을 유지하고 실제 사전 버전·해시를 고정한다(4칸 계약 §7~11, 현행 v1.6).

## F. 빈 곳 지도

**결론: 0개를 곧바로 생성 지시로 바꾸지 않는다. 실제 공백과 아직 메타가 없어 보이지 않는 문항을 구분한다.**

### F-1. 칸과 분모

`교육과정·과목·단원/소단원 × 유형 그룹(PT/TPL) × 풀이 방법 묶음 × 난이도 1~5`가 기본 칸이다. 출처·학년·기출 연도는 필터다. 실제 문항·교과 자료·수업 목표로 가능한 조합만 열고 모든 조합을 강제하지 않는다.

방법 묶음은 검토된 `method` 용어 번호 집합과 필요한 `steps`로 만든다. given·goal·condition은 변형·중복 판단에 쓴다. 같은 method 집합도 결정 단계가 다를 수 있으므로 대표 풀이로 확인한다. 키 그룹·사전·점수 규칙·대상 UID 판본을 고정한다.

| 칸별 정보 | 내용 |
| --- | --- |
| 관측·준비 수 | 고유 문항 수, 기출/교과서/문제집/생성 수, 확인 완료·등록 대기 수 |
| 불확실 수 | 관련 범위의 유형·4칸·난이도 미판정, 후보 용어, 재결속·자료 대기 |
| 상태 | `COVERED` 충족, `THIN` 부족, `CONFIRMED_GAP` 실제 공백, `UNKNOWN_COVERAGE` 조사 부족, `NOT_APPLICABLE` 성립하지 않는 칸 |
| 필요 근거 | 교과 사례·교사 요청·목표 수량과 선정 이유 |

실제 공백은 ① 교육과정상 의미 확인 → ② 별칭·방법 묶음·교과 자료 검색 → ③ 관련 미판정·등록 대기 조사 → ④ 그 칸에 들어갈 미해결 문항이 없음을 확인한 범위에서만 확정한다. 단원 미상은 상위 과목의 불확실 분모에 남긴다. 예를 들어 기출 0·교과서 4개라도 관련 미판정 30개가 있으면 공백 후보일 뿐이다(설명용 수치). 사전 후보가 검색에서 제외되어 생긴 0도 공백이 아니다.

### F-2. 우선순위와 품질 수납

| 순서 | 대상·종료 기준 |
| --- | --- |
| 선행 | 메타 누락·재결속·등록 대기로 가려진 기존 문항 회수 |
| 1 | 교과서·문제집에는 있으나 기출에 없는 필요한 유형. 생성 출처를 기출로 바꾸지 않음 |
| 2 | 특정 난이도 공백. 학습 연결을 보완하되 모든 유형에 1~5를 강제하지 않음 |
| 3 | 같은 유형의 다른 4칸 풀이 방법. 숫자 변형보다 결정 단계·조건의 다양성 우선 |

동순위는 수업 수요→대표성→차별성→제작·검수 비용으로 고른다. 첫 시범은 칸당 1문항이다. D-3의 수학·교육과정·SVG·화면·등록 검사를 모두 적용하고 생성 의도를 가린 재판정과 실제 풀이 비교로 중복을 걸러낸다. 등록 후 지도에서 실제 칸 점유·방법 증가를 확인한다. 미분류 키·용어는 보존하되 불확실 표시를 유지하고 그룹 변경으로 이동한 수와 새 생성 수를 구분한다.

## G. 기존 약 28,000문항의 이행

**결론: 파일을 대이동하지 않고 기존 정본 위에 꾸러미 목록을 얹는다. 값은 재사용하고 미확인·변경 영향만 처리한다.**

### G-1. 보존과 전환

JS·생성 shard(분할 저장 파일) 경로, UID·출처, 공용 메타·4칸 정본, 키·용어 번호·영수증·봉인·학생 엔진 주소·기존 이용 자격은 보존한다. 꾸러미로 옮길 것은 작업 목록·전체 분모·진행 상태, 소형 요청 생성·재시도, 변경별 재결속과 새 유형 묶음 운영이다.

UID는 내용과 독립이지만 경로·순번·식별 이력은 중요하다. 이동·삽입은 기존 식별 도구로 매핑을 검증한다. 근거: `archive/tools/intelligence/sync-question-identity-map-v1.mjs`, 4칸 계약 §11-3.

### G-2. 이행 순서

| 단계 | 범위·완료 증거 |
| --- | --- |
| 1. 기준선 | 전 범위 읽기·판본 고정. 중복/누락과 기존 집계의 정의 차이를 설명 |
| 2. 진행 작업 합류 | 원장·부분제출·거절을 시험지 목록에 연결. 중복 판정 방지·대기 담당 확정 |

전수 집계는 첫 기준선과 단계 마감에 한다. 작은 수정마다 전량 재판정하지 않는다. 과거 28,615·28,623과 약 28,000을 같은 정확한 분모로 취급하지 않는다.

### G-3. 처리량·병합 대기열·PR 크기

**시험지별 PR은 유지하고 병합 속도를 등록 처리량에 맞춘다.** 검토문 #3의 실측은 등록 20~60분, 306요청 PR의 45분 초과, 74시험지의 5개 PR 분할이다. 현재 `.github/workflows/archive-main-auto-meta.yml`은 이미 직렬·`cancel-in-progress:false`, `ci.yml` test는 45분, `archive2-runtime-guard.yml`은 8분 단계·12분 잡을 둔다. 개별 취소 원인은 실행 로그 확인 필요이며 이번에 재현하지 않았다.

| 항목 | 운영 제안 |
| --- | --- |
| 대기열 | bundleId·revision·입력 SHA·PR·검사 범위·요청 수·실제 등록 SHA·재시도 사유를 영속 기록. Actions의 대기 실행 하나를 전체 원장으로 삼지 않음 |
| 최초 병합 | 제작·PR 검사는 병렬, 병합은 담당 한 곳에서 1개씩. 해당 등록 영수증과 결과를 받은 뒤 다음 PR 반영. 실행 중 writer를 새 push 때문에 취소하지 않음 |
| 묶음 병합 | 안정화 후 별도 선택. 개별 시험지 PR을 소규모 병합 창에서 연속 반영하되 마지막 SHA까지의 모든 입력을 한 등록 배치로 합치는 접수·재개 기능부터 구현. 현행 push별 실행만으로 등록 1회를 보장하지 않음 |
| 등록 직렬화 | 기존 writer 잠금 재사용. 처리 중 새 입력은 다음 배치로 넘기고 완료된 요청은 재적용하지 않음. main 이동 재생성·검증과 비강제 push 유지, 재시도 소진은 운영 담당이 입력을 보존해 재개 |
| PR 크기 | 새 작업은 시험지 1개·꾸러미 1개. 요청 수·문항 수·자산량·예상 test/Chrome 시간을 함께 측정. 초기 시간 예산은 해당 단계 제한의 70% 이내(test 31.5분, 8분 단계 5.6분 등)라는 제안값으로 시작 |
| 초과 처리 | 여러 시험지의 기존 대량 작업은 시험지별 PR로 분할. 한 시험지 자체가 초과하면 같은 PR 안에서 검사 분할 실행·결과 합산을 설계. 전 문항 분모·필수 검사를 줄이거나 완료 주장부터 하지 않음 |

306요청·74시험지를 안전 상한으로 삼지 않는다. 실제 시간으로 배치 크기를 조정하고 묶음 창은 예상 등록 60분 이내부터 시험한다. 담당·권한·도입은 H-3에서 결정한다.

### G-4. 등록·실패·되돌리기

1. 기존 writer의 reviewed→semantic→shared→generated→studentIndexes→fourSlot을 재사용한다. 사전 검증→임시 출력→대상 UID·소비자 일치→허용 출력 적용 순으로 처리하며 소스·그림·compact를 임의 수정하지 않는다.
2. 현 fourSlot은 필수가 아닌 설정이다. 신규 완성에는 수납을 요구하되 기존 출고를 일괄 차단하지 않는다. 실패 단계만 재시도하고 정상 색인은 유지한다.
3. 새 어댑터·재결속·지도는 각각 중지할 수 있게 한다. 코드·설정은 일반 되돌림 커밋, 데이터는 이전 값·판본을 결속한 공식 정정 요청으로 복구한다. 영수증·기존 키는 삭제하지 않는다.
4. 오결속·교체 문항에 옛 값 적용·무단 값 변경·기존 이용 감소가 나오면 확대를 중단한다. 같은 입력 재실행은 중복 등록·다른 UID 변경이 없어야 한다.

근거: 메타 OS §4·7, `tools/ci/archive-registration-writer.mjs`, `docs/architecture/Archive_4Slot_Auto_Registration_CURRENT.md`. 현 `STALE_STUDENT_PAYLOAD` 제외는 변경 종류별 재결속으로 전환할 계약·코드 대상이다.

### H-3. 사용자에게 남길 선택

아래는 후속 실행 범위의 결정 목록이며 이번 문서 커밋을 멈추는 승인 요청이 아니다. 한 꾸러미·기계 완성·유형 개방·재결속은 재논의하지 않는다.

**기존 CREATE(작성)·R1(독립 풀이)·R2(재검)·R3(최종 감사)와의 관계:** `C4`는 기존 4역할의 실제 모델 호출 수, `B`는 메타 1회에 필요한 배치 수, `E`는 추가 불일치·시각 수리·재시도 호출이다. 단계 하나가 API 호출 하나라는 뜻이 아니다.

| 선택 | 역할·판정 단계 수 | 모델 호출 비교·조건 |
| --- | --- | --- |
| 감싸기 — 추천 | 기존 4역할 + 메타 2회 = 6 | `C4 + 2B + E`. 한 줄 요청 뒤 기존 예약·검수는 도구가 인계. 초기 변경 위험이 작음 |
| 대체 | 통합 4단계 안에 기존 품질 역할과 메타 2회를 배치 | 메타를 기존 검토에서 재사용할 조건을 충족하면 `C4 + E`, 아니면 `C4 + 2B + E`. 기존 예약 종료·대체 품질 동등성 확인 후 선택 |
| 신규 시험지만 적용 | 신규는 4+2, 기존은 현 라인 유지 | 신규 `C4 + 2B + E`, 기존 호출은 별도. 초기 영향은 작지만 두 진입 경로를 운영 |

재사용 조건은 **같은 최종 판본·서로 다른 모델·상대 메타 비노출·각자 고정한 원장**이다. R2 결과를 이미 본 R3를 독립 메타로 소급 계산하지 않는다. 어느 선택이든 필수 수학·블라인드·시각 검수는 보존하며, 호출 절감은 실제 배치 측정 후 확정한다.

| 결정 | 선택지 | 추천안 |
| --- | --- | --- |
| 새 기출 시범 | 새 중등 시험지 / 새 고등 시험지 | 실제 다음 입고분 중 그림·보기가 섞인 중등 1개. 이어 고등 1개로 확장 |
| 운영 문서 한 장 | 새 공통 문서 / 메타 OS를 내용·생성까지 확대 | 새 공통 운영 문서를 진입점으로 두고 메타 OS·4칸 계약은 참조. 규칙 본문 복제 금지 |
| 병합·등록 대기열 운영 주체 | 지정 운영자 / 자동 대기열 봇+예외 담당자 | 초기에는 지정 운영자, 안정화 후 봇. 기존 writer 쓰기 권한은 유지하고 예외 담당을 지정 |
| 유형 보류 CI 조건 | 유형 완료까지 대기 / 명시적 보류만 부분 수납 | B-3의 정확한 요청·UID에 결속된 `assignment_missing`만 정보 처리. 다른 결함은 계속 실패 |
| 부분 수납 운영 | 완성 전 제출 금지 / 부분 상태를 명시해 수납 | B-3 어댑터·추가/전체 전환을 만든 뒤 부분 수납. 전체 완료 주장은 금지 |
| 빈 곳 첫 범위·수량 | 여러 단원 동시 / 한 단원·칸당 1개 | 한 단원 1~3칸부터. 검수·실사용 뒤 목표 재고 확대 |
| 2차 모델·예산 | 별도 계열의 그림 판독 모델 후보 / 비용·접근 가능성 비교 | I장의 A와 다른 모델 B를 소표본 비교로 선정. 시험지별 예산·동시 실행 상한 설정 |

새 4칸 검색·선택의 운영 전환은 기존 통합 계약의 승인 범위에 맞춘다.

## I. 비용 관점과 검증 범위

**결론: 이미 있는 값을 재판정하지 않는 것이 가장 큰 절감이다. 모델은 의미를 읽고 도구는 형식·지문·대조·등록을 맡는다.**

### I-1. 단계별 배분과 추정식

운영 전제는 `REVIEW.md` #8을 따른다. 기존 구독은 2026-11-16 종료되었으며, 기본 A는 그림을 읽는 `opencode-go/deepseek-v4.1-flash`다. **2차 B는 다른 모델**로 선정한다. 같은 모델의 새 대화만으로 A·B를 대체하지 않는다. B의 그림 판독·접근·단가는 확인 필요이며 같은 소표본의 독립 결과와 실행 영수증으로 선택한다. 불일치만 상위 모델이 본다.

| 단계 | 모델 배분(문항당 작업 단위) | 토큰을 아끼는 곳 |
| --- | --- | --- |
| 완성도 검사·꾸러미 변환 | 대량 모델 호출 0, 설계·예외 표본만 | 기존 파일·영수증 조회, 해시·스키마·집계는 도구 |
| 재결속 | 의미 확인 필요한 M문항에 A M회·B M회, 불일치 pM회 상위 검토 | 기존 유효 근거 재사용, 바뀐 문항·필드만 전달 |
| 부족 메타 채우기 | N문항에 A N회·B N회, 불일치 pN회 상위 검토 | 한 번 읽을 때 모든 필요한 메타·4칸 수집 |
| 기출 내용 수리·유사 생성 | 문항당 초안 1회, 실패 시 필요한 수정. 메타는 독립 2회 | 기존 출제·검수 절차 재사용. 수학·SVG 필수 검수 비용 별도 |
| 빈 곳 지도·생성 | 집계는 호출 0, 공백 후보 확인 후 선정 G문항만 제작 | 기존 문항 회수·중복 검색을 먼저 수행 |

N은 추가 판정 대상이다. 전량 28,000문항이면 A·B 합계 약 56,000문항회이며 API 호출 수는 배치에 따라 다르다. p=10~40%는 실측이 아닌 예산 가정이다. 기존 원장은 판본·독립성·모델 차이가 확인된 범위만 재사용한다.

`예상비용 = N×A 평균 비용 + N×B 평균 비용 + pN×상위 검토 평균 비용 + 제작·수학/시각 검수·도구 실행 비용`. 그림 입력을 포함하고 첫 시험지의 토큰·그림 수·불일치·수리 횟수로 보정한다. 가격·평균 토큰·시간은 확인 필요하며 당시 단가와 실제 영수증을 사용한다. H-3의 기존 검토 재사용분은 중복 청구하지 않는다.

실행은 동시 약 6줄이라는 제공 조건 안에서 **A·B 두 쌍 4줄 + 불일치 검토 1줄 + 재시도 여유 1줄**부터 운영한다. 대기열이 밀리면 신규 배치를 줄인다. 실행 전후 내부 DB 크기·디스크 여유·진행 중 작업을 확인하고, 검증된 완료 원장은 외부 증거 보관소로 인계한다. 실제 DB 위치·보존/정리 기능은 설정과 도구 문서로 확인하며 활성 작업 DB를 임의 삭제하지 않는다. 용량 경계에 닿으면 신규 시작만 멈추고 보존·재개한다.

공통 지침·추출 자료는 캐시하되 A의 판단을 B에 주지 않는다. 블라인드 패킷은 해설 포함 패킷과 분리한다. 관련 키를 먼저 주고 부족하면 전체 검색·신설로 연결한다. 검사 생략은 절감으로 세지 않는다.
