# 작업 15 시범(PILOT) 확인 — 굵기 승인, 나머지 진행 (2026-11-17, 관제)

`type-bundles/PILOT-m2-number-expr.md`(25d8ea3)를 읽었다. **굵기는 맞다. 이 굵기로 나머지 A·B를 진행한다.** 688줄이 수십 개 이름에서 5개 개념으로 모였고, 이름만 보고 합치지 않고 결정 단계를 읽어 12줄을 옮긴 것, 기존 키의 정의를 읽고 억지로 흡수하지 않은 것이 좋았다. 요청한 결정 세 가지와 고칠 점은 아래와 같다.

## 결정 ① 다섯 개념의 굵기 — 승인, 이름 둘만 다듬는다
- `NPT_M2_POWERS` "거듭제곱" → **"지수법칙"**. 중2 교과서 소단원 이름이고, 교사가 한 단어로 떠올리는 말이다. id도 `NPT_M2_EXPONENT_LAWS`.
- `NPT_M2_RATIONAL` "유리수와 소수" → **"유한소수"**. 묶음의 중심(212줄 중 유한소수 판별·조건·변환이 대부분)이 유한소수다. "유리수와 소수의 관계·수의 분류"(43줄)는 이 PT의 TPL "수의 분류"로 둔다. id는 `NPT_M2_FINITE_DECIMAL`.
- 순환소수·단항식·다항식은 그대로.
- TPL 후보는 PT당 4~6개로 적당하다. TPL 이름도 지금처럼 짧게 유지한다. "오독 복원", "계산 판별"처럼 묻는 방식이 드러나는 한 단어가 좋다.

## 결정 ② 다른 학년·과목 키의 재사용 — 하지 않는다. 학년 팩 안에서 만들고 묶음표로 잇는다
- 고등 키(`PT_H22A_01_EXPONENT_LAWS`, `PT_H1_POLY_OPERATION_EXPANSION`, `PT_H1_POLY_DIVISION`)를 중2 문항에 붙이지 않는다. 중2 문항은 중2 팩의 PT를 갖는다. 이유: 단원·난이도 필터와 "같은 학년 유형 연습"이 학년 팩 기준으로 돈다. 사용자 결정도 "키는 그대로 두고 비슷한 것끼리 묶음표를 얹는다"이다.
- 대신 묶음 목록의 각 항목에 `relatedKeys` 칸을 둔다: 뜻이 이어지는 다른 학년·과목의 기존 PT 키를 적는다(예: 지수법칙 → `PT_H22A_01_EXPONENT_LAWS`, 다항식 → `PT_H1_POLY_OPERATION_EXPANSION`). 관제가 학년을 가로지르는 묶음표를 만들 때 쓴다.
- `absorbInto`는 **같은 학년 팩의 기존 PT**이고 정의가 실제로 그 문항을 덮을 때만 쓴다.
- 같은 학년 팩의 기존 PT가 좁게 정의돼 있어 흡수할 수 없는 경우(예: `PT_M2_MONOMIAL_MULTIPLICATION_DIVISION`은 "옳지 않은 계산식 고르기", `PT_M2_POLYNOMIAL_ADDITION_SUBTRACTION_CORRECTION`은 "잘못 더한 식 복원", `PT_M2_POLYNOMIAL_DIVISION_GEOMETRIC_AREA`는 "삼각형 넓이에서 높이"): 흡수하지 않는 판단이 맞다. 이런 기존 키는 사실 새 개념 PT 아래의 TPL 굵기다. 묶음 목록에 `narrowExisting` 칸을 두고 그 키를 적는다(예: 단항식 → `PT_M2_MONOMIAL_MULTIPLICATION_DIVISION`). 기존 키와 그 키가 붙은 문항은 건드리지 않는다. 관제가 묶음표에서 새 PT 밑으로 잇는다.

## 결정 ③ 거듭제곱의 일의 자리 주기 — TPL로 둔다
별도 개념으로 세우지 않는다. 지수법칙의 TPL "일의 자리"로 두고, 주기성은 `crossConceptHints`에 "규칙성"으로 적는다. 단순 반복 곱셈 맥락 1줄도 지수법칙에 두되 TPL은 비워도 된다.

## 고칠 점
1. **수치 차이 설명:** 시범은 NEW_KEY를 3,102줄(교과서·유형 702)로 셌고 관제 점검은 3,196줄(796)이었다. 차이 94줄이 어디서 났는지(결과 브랜치 커밋 차이, `비상_미적분1` 중복 제외 여부 등) `TASK-15-REPORT.md`에 적는다. 대응표의 완료 조건은 "작업 시점 결과표의 NEW_KEY 줄 전부"이고 그 시점 세 브랜치 커밋을 적는다.
2. **도형 경계 1줄**(숫자 부피비)처럼 어느 묶음에도 억지로 넣지 않은 줄은 대응표에 `"bundle": null, "note": "<이유>"`로 남긴다. 빠뜨리지 않는다.
3. **꼬리표 키를 지어내지 않는다는 원칙 유지.** 시범 3절의 `COND_*`, `CC_*`는 실제 레지스트리에 있는 키일 때만 쓰고, 없으면 한글 단어("자연수 조건", "최소공배수")로 적는다. 관제가 키로 만든다.
4. 이제 `new-pt-bundles.json`과 `new-pt-assign.jsonl`을 실제 파일로 쓴다(시범 688줄 포함). 묶음 항목 형식은 `TASK-15`의 것에 `relatedKeys`, `narrowExisting` 두 칸(배열, 없으면 빈 배열)을 더한다.
