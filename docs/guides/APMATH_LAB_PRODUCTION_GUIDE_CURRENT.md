> **기준일:** 2026-10-28 (KST)  
> **적용:** 공통수학·대수·기하 등 새 실험실 제작과 사용자가 지정한 기존 실험실 개선  
> **문서 역할:** 무엇을 만들고 어떻게 수학적으로 검증할지 결정한다. **레이아웃/상태 전환 상세는 UI 계약서**, 디자인 인상은 참고 기준서에 따른다.  
> **선행 문서:** [UI·동작 계약](APMATH_LAB_UI_CONTRACT_CURRENT.md) · [디자인 참고 기준](APMATH_LAB_DESIGN_REFERENCE_CURRENT.md)

## 1. 목표와 적용 범위

학생이 **문제 읽기 → 조건·도형 관찰 → 필요할 때 보조선·풀이 확인 → 스스로 다시 풀기**까지 진행하는 단일 HTML 학습 도구를 만든다. 화려한 움직임 자체보다 수학적 이해·재현 가능성을 우선한다.

- 대상 단원, 교육과정 연도·학년, 문항 개수와 원본·수정 범위를 작업 시작 전에 고정한다. 기존 실험실 수정은 **최신 Git `main`의 해당 파일을 직접 읽고** 그 파일을 수정한다. 새 파일을 만들어 중복 등록하지 않는다.
- 예제·창작 문항을 검증된 학교/평가원 기출로 소개하지 않는다. 기존 정상 문항·도형·이벤트·연동 스크립트는 보존하고 요청된 결함을 표적 수리한다.
- 작업 도중 코드를 여러 조각으로 나누어 개발해도 전달 결과는 명시된 문항이 모두 포함된 **실행 가능한 단일 HTML**이어야 한다. 사용자가 요청하지 않은 다른 단원·운영센터·Archive·Worker는 변경하지 않는다.

## 2. 제작 순서 — 수학부터

1. **문항 설계:** 기본/심화의 개념·발문·주어진 조건·구할 값·정답·해설·시각화를 정한다. 조건 불충분, 복수 정답, 경계·퇴화·예외를 먼저 확인한다.
2. **독립 풀이:** 각 문항을 직접 풀고 핵심 정리를 왜 쓸 수 있는지 증명한다. 사인법칙, 접선·대칭·등적변형 등의 적용 조건을 확인한다. 근호·호도법·분모 0·경계·무연근을 점검한다.
3. **시각화 계약:** 문항마다 `주어진 조건 → 계산 좌표/길이/각 → 조작 매개변수 → 핵심 프리셋 → 보조선 1·2·3 → 풀이·정답` 대응표를 마련한다. 실제 식에서 좌표를 계산하며, 정답을 알지 못하는 초기화면에서 결과를 미리 노출하지 않는다.
4. **구현:** [UI 계약서](APMATH_LAB_UI_CONTRACT_CURRENT.md)의 화면 요소·상태 전환을 사용하고, 단원별 도형 렌더러만 독립적으로 작성한다. 별도 기능이 필요하면 수학적 목적이 분명할 때만 넣는다.
5. **검수·출고:** 수학 검산과 실제 상호작용·PC/태블릿/모바일 표적 검증 후 전체 HTML을 전달한다. 미검증 항목은 PASS로 쓰지 않는다.

## 3. 학생 화면과 정답 노출

- 시작 화면은 **문제 본문, 문제 이해에 필요한 기본 도형, 보조선 꺼짐/1/2/3/전체보기, 필요한 슬라이더·프리셋, 칠판 열기**만 간결하게 배치한다. 중복 안내 카드·상세 풀이·장식형 HUD를 늘리지 않는다.
- 문제 제목은 `기본 01 · 무엇을 구하는가` 형식으로 간명하게 쓰고 기본/심화 및 전체 문항 제목 목록을 제공한다.
- **초기 상태에서 미지수의 답, 결정적 좌표·길이·넓이·최적 위치·정답을 직접 알려주는 프리셋 이름을 노출하지 않는다.** 이미 발문에 주어진 조건은 표시 가능하다.
- 예시 파라미터가 발문의 모든 조건을 만족하지 않으면 `탐구용 예시`로 구별한다. 아직 구하지 않은 정답 그래프를 확정 사실처럼 그리지 않는다.
- **소형 칠판을 처음 열면 Step 1의 첫 보조선·첫 풀이가 자동 공개**된다. 이미 Step 2·3·전체보기까지 진행한 상태에서 닫았다 다시 열면 기존 단계를 유지한다. Step 1/2/3는 각 단계에 필요한 그림·수식만 연결하고, **최종 정답·풀이 비교는 Step 3/전체보기 또는 명시적인 최종 공개 동작 이후** 보이게 한다. **칠판 열기만으로 Step 2·3이나 정답을 자동 공개하지 않는다.**

## 4. 소형 칠판: 실제 수학 강사의 풀이 기준

각 문항을 학생이 처음 읽어도 논리적 흐름을 따라갈 수 있도록 작성한다. 기본 3단계 구조를 무리하게 늘리지 말고 단계 안의 설명을 보강한다.

1. **왜:** 발문 조건에서 왜 해당 공식·보조선·치환을 떠올렸는지.
2. **어떻게:** 공식 적용 조건, 중간 식의 변형, 계산과 경우 분기, 필요한 예외 처리.
3. **무엇을 얻었나:** 결과가 다음 단계와 답으로 어떻게 연결되는지.

- 기본 문항은 개념·표준 풀이를 충분히 연결하고, 심화 문항은 핵심 발상·보조선을 그은 목적·숨은 조건의 발견 과정을 설명한다.
- `⚡ 실전 10초 컷`, `🎯 실전 최적 풀이`, `🔍 핵심 정석 풀이`는 실제 풀이 속도와 성격이 맞을 때만 사용한다. 과장이나 논리 생략 금지.
- 풀이 비교는 빠른 풀이의 타당성과 정석 풀이의 재현 가능성을 함께 보여준다. 증명이 필요한 결론을 애니메이션만으로 정당화하지 않는다.
- 예: `S=25-(r-5)^2` 뒤에는 **제곱항이 0 이상이므로 `r=5`일 때 최대**라는 연결 논리가 필요하다.
- 잘못된 수식을 보존하려고 틀린 그림에 맞추지 않는다. 오류가 확인되면 발문·조건·계산·도형·해설의 관계를 함께 바로잡는다.

## 5. 교과서식 수학 표기

- 정확한 값은 **정수·세로 분수·근호·특수각·π**를 우선한다. HTML 풀이에는 KaTeX 등 수식 렌더링을 쓴다. Canvas 위 도형 라벨도 필요하다면 투명 수식 레이어·SVG 등의 방법으로 교과서식 분수를 구현한다.
- **각도 단위는 문제를 따른다.** 호도법/삼각함수 그래프에서는 `π/3`, `2 rad`; 일반 기하에서 도 단위를 사용하면 `30°`, `60°`를 우선한다. 무조건 rad를 붙이지 않는다.
- 드래그 값이 복잡한 실수면 `≈`를 쓰고 필요 정밀도로 표시한다. 실제 값 `3.32`를 단순히 `=3.3`이라 표시하거나 근삿값을 임의의 간단한 분수로 둔갑시키지 않는다.
- 수치 표시는 **단일 계산 결과**를 공유해 도형 좌표·슬라이더·치수선·측정 배너와 일치하게 한다.
- **근호·분수의 그래프 표시(2026-10-28):** 학생이 관찰할 변의 길이는 `4.31` 같은 근삿값만 표시하지 말고 기하적 성질을 드러내는 `4√2`, `(b−a)√2`, 필요 시 유리수 분수의 정확식으로 보여준다. 고정된 문제 조건·특수 위치에서는 정확한 수를 확정하고, 자유 이동 중 복잡한 좌표·길이는 정확식과 `≈` 근삿값을 분리한다. 단순히 근삿값을 등호 오른쪽에 쓰거나 억지 간단한 분수로 바꾸지 않는다.
- **학습 화면 문구(2026-10-28):** 그래프 점·핸들에 `[드래그]` 같은 개발자 문구를 붙이지 않는다. 조작은 실제로 가능하게 두되, 학생에게 필요한 경우 `점을 움직여 보세요`처럼 간결하게 안내한다. 기하 화면의 일상 문구에 제작 용어·임시 디버그 문자열을 노출하지 않는다.
- 학년 교육과정 용어를 우선하고 새 용어는 짧게 뜻을 밝힌다. `레이저·스캔·모핑·킬러·1초 공식` 등 과장형·제작자 중심 용어를 지양한다.

## 6. 프리셋·자유 드래그의 교육적 목적

- 문항에 필요한 의미 있는 정수·분수·특수각·경계 조건 프리셋을 제공한다. **정답 노출 이전에는 프리셋 라벨 자체가 답을 알려주지 않도록** 한다.
- 학생이 `무엇이 바뀌고 무엇이 보존되는지` 관찰할 수 있어야 한다. 프리셋 비교가 이해를 돕는 경우 먼저 비교하게 하고 자유 드래그로 검증하도록 연결하되, 특정 문항의 자유 탐구를 불필요하게 봉쇄하지 않는다.
- 드래그 핸들·슬라이더·좌표·칠판 단계가 같은 상태를 가리켜야 한다. 없는 버튼/렌즈/자동 재생/조각 카드를 새로 만들지 않는다.
- 가독성용 `visualScale`·클램핑은 허용한다. 다만 학생이 믿는 **기하 조건·수식·실제 계산**은 정확해야 하고, 비례 왜곡이 오개념을 유발하지 않아야 한다.

### 문항별 고정 조건·탐구 조건 계약 — 2026-10-28 보강

- **구현 전에 문항마다** `항상 고정되는 조건 / 슬라이더로 변화하는 조건 / 만족시킬 목표 조건`을 한 줄로 정한다. 학생은 조건을 만족하는 현재 그림인지, 조건을 일부 바꾼 **탐구용 변형**인지 알 수 있어야 한다.
- 발문이 `PQ=4√2`와 넓이 `16`을 요구하면, 화면에서 PQ를 자유로이 바꾸면서 둘 다 만족하는 것처럼 표시하면 안 된다. 예: `b−a=4`를 유지하며 넓이를 변화시켜 해를 찾거나, `PQ`도 바뀌는 실험이라면 **원래 조건과 다른 현재 예시**임을 별도로 명시한다. 이 선택은 문항의 수학 목적에 따라 결정한다. 한 수학적 조건을 고정하기 위해 다른 미지수·함수를 변경했다면 그것도 학생에게 설명한다.
- 자유 이동 중 소수 측정값 자체는 허용하되 **정확식·근삿값·목표값**을 혼동하지 않는다. 각 프리셋이 실제로 표시하는 유리수·무리수·기울기와 숫자가 맞아야 한다. 정답 위치와 현재 위치가 다르면 수학 풀이의 정답 그림을 현재 측정값처럼 붙여 놓지 않는다.
- **최소 표적 검수:** 첫 위치 + 각 프리셋 + 대표적인 사이값·구간 경계에서 실제 도형 조건·교점 수·표시 값·칠판의 전제 일치를 검산한다. 특히 **판별식의 부호별 교점 개수 / 정의역 경계 / 분모가 0인 경우**를 독립적으로 계산한다. 렌더링·문항 전환 PASS는 수학적 조건 PASS를 대신하지 않는다.


## 7. 구현 보호·검수·완료 기준

- 정본 파일의 기존 DOM ID, 화면·모드, 이벤트·드래그, KaTeX와 외부 연동을 보존한다. `ap-mobile-bridge`, `ap-mobile-adapter`, `ap-touch-adapter`가 실제 원본에 있다면 그대로 유지한다. 존재하지 않는 ID의 무조건적 신설은 금지한다.
- 실측 기준: PC `1440×900`, 태블릿 `820×1180`·`1024×768`, 모바일 `390×844`. 화면에서 문제·도형·칠판 비교, 수식 줄바꿈, 핵심 라벨·버튼 접근성을 검사한다.
- 문항별 최초화면에서 정답이 누출되지 않는지, **칠판 열기 → Step 1 자동 공개(최종 정답 비공개)**, Step 1/2/3/전체보기, 칠판 닫기·재열기, 프리셋, 드래그, 확대·초기화가 실제로 반응하는지 검사한다. 경계·중근·정의역·퇴화 등 관련 지점을 검산한다.
- **실사용 감사 등급:** P0=수학 오류/핵심 기능 먹통/백지화, P1=핵심 풀이 점프/학생을 오도하는 표기/심각한 상태·가독성 문제, P2=유익한 경미 개선. 사소한 픽셀 차이로 등급을 부풀리지 않는다.
- 완료 보고: 실제 수정 파일·문항 수·수학 검산·브라우저 확인 범위·남은 미검증을 짧게 분리한다. **Git 병합이나 Pages 배포는 사용자가 명시적으로 요청했을 때만** 진행한다.
