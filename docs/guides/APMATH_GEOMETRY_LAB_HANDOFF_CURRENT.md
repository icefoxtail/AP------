## 보존할 운영 결정

- 학생 기준은 “문제와 그림을 읽고, 조작·풀이·답이 서로 맞는가”다. 눈에 띄는 수학 오류, 잘린 그림·수식, 겹친 라벨, 멈춘 조작을 먼저 고친다.
- 도형과 관련 수치·단계 풀이·문제 답은 같은 상태에서 갱신돼야 한다. 시작 화면은 정답을 미리 노출하지 않는다. 가독성을 위해 그림은 크게, 치수와 각은 그림 안에 명료하게 둔다.
- 세로 이동은 금지하고 필요한 이동은 가로로 한다. 입체는 밑면이 아래에 오는 3D 겨냥도를 우선한다. 교과서와 교육과정 용어·정확한 분수/근호/π 표기를 쓴다.
- PC 폭 검사는 실기기 검사가 아니다. 검사하지 않은 뷰포트·상호작용·배포는 `NOT_RUN`으로 적는다. 기존 UI·엔진 계약과 저장소 지침은 [공통 제작 지침](APMATH_LAB_PRODUCTION_GUIDE_CURRENT.md), [UI 계약](APMATH_LAB_UI_CONTRACT_CURRENT.md), 루트 `AGENTS.md`를 따른다.

1. 위 Library 파일을 ID·버전 그대로 정식 materialization해서 현재 작업환경에 저장한다. 파일 크기와 Library ID/version 속성을 확인하고 patch/tar 경로를 기록한다. 파일이 없는 상태에서 검색 조각이나 점검표 텍스트를 코드 패치로 재구성하지 않는다.
2. 최신 `origin/main`과 각 patch의 base·변경 경로를 대조한다. `중1_겉넓이_부피_main_기준_통합안.patch`를 surface v92의 비교 기준으로 사용한다. 이미 main에 들어간 것, #1381/#1356 중복, 두 단원의 공유 키트 변경을 분리하고 다른 변경은 보존한다.
3. 단원별 수정 후 JS 문법, 독립 수학 재계산, 필요한 scene 계산을 실행한다. `node --test apmath/playground/next/tools/catalog.test.mjs`를 실행하고 카탈로그 수·manifest를 맞춘다.
4. 실제 브라우저로 수정 장면과 위험 표본을 PC·390×844 휴대폰에서 열어 픽셀, 콘솔, 잘림, 조작, 단계별 답 공개를 확인한다. scene-smoke의 외부 리소스 인증서 오류는 실제 환경 문제로 분리해 기록하며 검사 기준을 낮추지 않는다. 가능하면 CI와 Pages 학생 경로까지 확인한다.
5. 테스트가 통과하면 최신 main 기반 PR을 만들고 CI 결과를 확인한 뒤, 승인된 범위만 main에 병합한다. 학생 허브와 실험실 URL을 운영에서 실제 열어 확인하고 main SHA, PR, Pages 확인 여부를 이 문서에 갱신한다.
6. 원과 부채꼴은 남은 58장면을 그룹별로 점검하며 그림이 작다고 명시된 `z3-sectorProof`부터 개선한다. 겉넓이·부피는 30장면 1차 점검을 전체 전수 브라우저/모바일 검수로 확대하지 말고, 구현 후 수정 영향과 문제 위험에 맞는 회귀 표본을 고른다.
