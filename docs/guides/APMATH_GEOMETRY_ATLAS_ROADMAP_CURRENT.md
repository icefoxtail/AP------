## 2. 단계별 계획

### 1단계 · 출시 점검 (다음)

- **목표:** 중등과 고등을 한 번에 훑어 학생이 쓰기에 걸리는 것이 없으면 출시한다.
- **할 일:**
  1. `scene-smoke`에 태블릿 세로 768×1024, 가로 1024×768을 추가하고 전 실험실을 1회 돌린다. 이유: 설계 §5에서 주 화면을 태블릿·PC로 정했는데 아직 그 크기로 잰 적이 없다.
  2. 과목마다 대표 실험실 1~2개를 PC·태블릿·폰에서 사진으로 본다. 범위는 중1·중2·중3, 공통, 대수, 미적분, 기하, 확통이다. 문제 탭, 정리 탭 끝 단계, 「새 문제」를 함께 본다.
  3. 선생님이 원하면 `/impeccable critique`로 허브와 대표 장면의 화면을 비평한다. 이 스킬은 선생님이 직접 부를 때만 켜진다.
  4. 걸린 것은 핫픽스로 고친다. 새 기능은 넣지 않는다.
- **완료 기준:** 학생 화면에서 오류, 깨진 그림, 가려지는 문제 문장, 동작하지 않는 버튼이 없다. 전체 테스트 결과가 main과 같다.
- **결정(선생님, 2026-11-03):** 학부모 안내는 하지 않는다. 선생님이 학생들에게 열어 주고 써 보게 한 뒤, 학생과 주변 선생님에게 피드백을 받는다. 그래서 출시는 「공개 + 피드백 수집」이다.
- **피드백 처리:** 선생님이 받은 피드백을 대화로 전달하면 메인이 「학생 화면 결함(바로 고침)」과 「개선 제안(로드맵 단계에 배치)」으로 나눠 이 문서 §4·해당 단계에 적는다.

### V · 중1 영상 목차 (우선)

- **목표:** 학생이 단원(실험실)을 열면 오른쪽에서 목차 패널을 끌어 연다. 장면을 누르면 그 장면의 짧은 영상(15~30초)이 먼저 재생되고, 끝나면 같은 그림을 바로 손으로 움직여 볼 수 있다.
- **이유(선생님):** 중1이 도형을 가장 약해한다. 클릭 한 번으로 보고 원하는 것을 찾아볼 수 있으면 공부가 재미있어진다. 멈추고 천천히 볼 수 있으면 「왜 그런지」 알게 된다.
- **방식:**
  - 영상을 따로 그리지 않는다. 실험실 그림을 「대본」대로 움직인다. 대본은 장면마다 몇 초에 무엇을 바꾸고 무슨 자막을 띄울지 적은 짧은 데이터다.
  - 근거: 실험실 그림 품질이 충분하다. 메인이 g7-polyhedra 화면을 직접 확인했다. 이미 「빙글 돌려 보기」 같은 자동 움직임과 값 보간 기능이 있다.
  - 공용 키트에 한 번 만든다.
    - 영상 화면: 그림 크게, 자막 막대, 멈춤·느리게·다시 보기
    - 재생기
    - 목차 패널: 기존 장면 목록을 끌어 여는 패널
  - 영상 끝에는 「이제 직접 해 보세요」 한 가지 할 일과 한 줄 요약 카드를 둔다. 이유: 보기만 하는 공부를 막는다.
- **결정(선생님, 2026-11-03):**
  - 순서는 원과 부채꼴(g7-circle-sector) → 다면체(g7-polyhedra) → 회전체(g7-solids) → 입체도형의 겉넓이·부피(g7-surface-volume)다. 중1만 하고 하나씩 넓힌다.
  - 목차에 진도 표시(✓)는 넣지 않는다. 학생마다 필요한 것을 골라 보는 곳이지, 숙제처럼 만들면 안 된다. 같은 이유로 「내 기차」 진도 표시도 다시 묻는다.
  - 대본·영상의 초안은 DeepSeek(OpenCode)가 만들고, 마감은 Claude가 한다(선생님 결정, 2026-11-03). 마감 순서: Sonnet 검수자가 스크린샷을 보고 대본을 기존 정리 단계 글·정답과 대조해 고칠 목록을 만들고, Sonnet 작업자가 고치고, 검수자가 다시 확인한다. 메인은 실험실마다 끝 화면과 장면 1~2개 PNG만 표본으로 보고 게시 여부를 정한다(선생님 결정, 2026-11-03). 이유: DeepSeek은 이미지를 못 보므로 그림 판단은 Claude가 하되, 메인의 확인이 병렬 작업의 병목이 되지 않게 한다. 표본 확인을 남기는 이유는 보고만 믿고 값이 빠진 그림을 게시한 일이 있었기 때문이다. 샘플이 좋으면 실험실 하나당 DeepSeek 1개씩 병렬로 돌리고, 장면 점검·스크린샷 같은 무거운 검사는 하나씩 돌린다.
  - 영상은 쇼츠처럼 짧게 한다(선생님 피드백, 2026-11-03): 8~15초, 자막 2~3줄, 영상 하나에 핵심 하나, 소개 줄 없이 첫 프레임부터 그림이 움직이고 공식·결론은 마지막 한 줄. 개념이 크면 짧은 영상 2개로 나눈다. 이유: 24초 샘플이 늘어졌다.
  - DeepSeek 첫 샘플 초안은 그대로 못 쓰는 수준이었다(범위 끝 값으로 라벨 겹침, 정의 전 공식, 화면 확인 못 함). 견본 대본·장면별 상태값 표를 넣은 지시서로 2장면을 한 번 더 시험하고, Sonnet 마감자가 초안에서 고친 양을 기록한다. 그래도 못 쓰는 수준이면 대본은 Sonnet이 쓰고, DeepSeek는 그림 판단이 필요 없는 코드 작업(테스트·검사 도구·데이터 정리 등)에 쓴다(선생님 결정).
  - DeepSeek 재시험 결과(2026-11-03, 장면 1210·f1-ss2): 「쓸 만하나 마감 필요」. 자막 6줄 중 5줄을 그대로 쓰고 1줄을 새로 썼으며, 타이밍 2곳을 고쳤다. 고친 이유는 그림을 못 봐서 생긴 것뿐이다(결론 자막이 그림보다 2초 앞섬, 화면에 안 보이는 값 4.5를 말함). 견본 대본과 상태값 표를 넣은 지시서가 효과가 있었다. 그래서 대본은 DeepSeek 초안 → Sonnet 마감으로 간다. 비용은 지시서용 상태값 표(라벨이 깨끗한 값 찾기)를 사람 눈으로 만드는 데 가장 많이 든다. 이 부분은 그림 판단 없이 코드(SVG 라벨 상자 겹침 계산)로 자동화한다.
  - 영상 작업자는 기존 장면 결함(라벨 겹침 등)을 고치지 않고 실험실별 `VIDEO_FINDINGS.md`에 적는다. 실험실 영상이 끝나면 목록을 한 번에 고친다. 이유: 영상 작업과 장면 수정이 섞이면 범위가 커지고 충돌한다. 영상 제작이 장면 재검수를 겸한다. 호출 경로(2026-11-03 확인): DeepSeek 계정이나 키를 따로 쓰지 않는다. 환경의 `opencode.ai` 시크릿(OpenCode Go)을 프록시가 요청에 넣어 주므로 별도 키가 필요 없다.
    - 모델: `opencode-go/deepseek-v4.1-flash`, `opencode-go/deepseek-v4-pro`
    - 실행: `OPENCODE_API_KEY=dummy npx opencode-ai run --model opencode-go/deepseek-v4.1-flash "<지시>"`. 저장소 밖 작업 폴더에서 실행하거나 범위를 `apmath/playground/`로 한정한다.
    - API를 직접 부를 때는 `x-opencode-session` 헤더가 필요하다.
- **최종 목표(선생님, 2026-11-03):** 중1 실험실에 짧은 영상을 최대한 많이 만든다. 원리 장면뿐 아니라 문제 탭의 문항 풀이도 영상으로 만든다. 순서는 원과 부채꼴 시범 8장면 → 라벨 겹침 정리 → 문항 영상 형식 정하기 → 나머지 중1 실험실이다.
- **문항 영상 형식(조사 2026-11-03, 메인 결정):** 대표 문항 1개의 값을 대본 `start`/`set`으로 고정한 「예시 풀이」 영상으로 만든다. 자막은 그 문항의 정리 단계 글·풀이(`steps`·`std`)에서 따와 2~3줄로 줄이고, 끝 카드의 할 일은 「새 문제를 눌러 직접 풀어 보세요」로 둔다. 이유: 「새 문제」마다 숫자가 바뀌어 자막을 변수로 채우는 방식(안 C)은 키트 변경과 검증 비용이 크다. 정리 단계 글을 자막으로 자동 생성하는 것(안 B)은 초안용으로만 쓴다(글이 쇼츠 길이를 넘음). 키트에는 대본이 재생할 탭(`tab: 'explore'|'review'|'problem'`)을 고르는 필드가 필요하다. 「새 문제」의 reroll 상태(`soPw` 등)와 `Math.random` 값은 반드시 고정한다.
  - 중1 영상 후보: 원리 장면 약 282개, 문항 약 190개(실험실 10곳, `g7-nets`는 무대가 없어 뺀다). 원과 부채꼴이 장면 92개로 3분의 1을 차지한다. 실험실마다 핵심 5~8개부터 만들고 넓힌다.
- **라벨 겹침 검사 도구:** `tools/label-sweep.mjs`(만드는 중)가 장면 상태값을 차례로 바꾸며 캔버스 글자 상자(`board._bbox.texts`)의 겹침·잘림을 계산해 「깨끗한 값」 구간을 낸다. 영상 지시서의 상태값 표를 이 도구로 뽑고, `--all`로 실험실 전체 라벨 결함도 찾는다. 이유: 사람이 화면을 보며 값을 찾는 비용이 영상 작업에서 가장 컸다.
- **원과 부채꼴 시범 범위(약 8장면):**
  1. 호의 길이와 넓이
  2. 넓이와 호의 관계(S=½rl)
  3. 반원 파내기(F01)
  4. S자 곡선 → 반원(F04)
  5. 트랙·끈의 길이(F05)
  6. 굴리기(F06)
  7. 묶인 동물의 영역(F06)
  8. 잎 모양(F03)
  - 나머지 장면은 목차에 보이고 탐구 화면으로 바로 열린다.
- **완료 기준:** 태블릿·PC에서 목차 → 영상 → 직접 조작이 끊기지 않는다. 자막·그림이 맞고(메인이 사진과 영상 프레임으로 확인), 멈춤·느리게·다시 보기가 동작한다. 학생 몇 명에게 써 보게 하고 반응을 본다.
- **나중에 같은 재생기를 쓸 곳:** 고등 정리 탭(이미 1·2·3단계로 나뉨)의 자동 넘김 해설. 아카이브 그림 해설도 여기에 든다(아래 「아카이브 해설」).

### 다면체 전개도 (선생님들 요청, 2026-11-03 반영)
- 전개도 점 이름은 교과서처럼 테두리를 따라 반시계 순서로 붙인다. 「이름 바꾸기」는 시작점·방향만 바꾼다(무작위 섞기 아님). 이유: 교과서·시험지 배치와 같아야 학생이 익숙하다.
- 처음 뜨는 전개도는 선생님이 보낸 교과서 그림과 같은 모양이다(정사면체 평행사변형 띠, 정육면체 1-4-1형, 정팔면체 가운데 띠+양 끝). 나머지는 단추(㉯·㉰)로 고른다. 11종 전부는 보여 주지 않는다(선생님 결정). 정팔면체 목록은 `geo.js`의 `OCTA_PICK` 한 줄로 바꾼다.
- 평행한 면은 같은 파스텔색으로 칠한다(정육면체 3쌍, 정팔면체 4쌍). 문제 탭은 정답이 드러나므로 칠하지 않는다.
- 이름 배치와 무관하게 「겹치는 점」 정답을 3차원 위치로 대조하는 `tools/polyhedra-names.test.mjs`가 있다.

### 원·부채꼴 값 표기 (선생님 결정, 2026-11-03)
- 원의 둘레·넓이, 부채꼴의 호의 길이·넓이 등 π가 들어가는 값은 화면 어디에도 소수로 쓰지 않는다. 반지름 5면 둘레 10π, 넓이 25π처럼 π 꼴(정수나 기약분수 계수)로만 쓴다. 「≈ 31.4」 같은 근삿값 보조 표기와 「π ≈ 3.14」 예외도 두지 않는다. 이유: 소수가 하나라도 섞이면 중1 학생이 헷갈린다.
- 각도도 소수로 쓰지 않는다(67.5° 금지). 중1 화면에는 √(제곱근)를 쓰지 않는다. 대각선처럼 √가 되는 길이는 교과서처럼 그 길이를 주어진 정수 값으로 보여 주고(예: 「대각선의 길이 8 cm」) 그 값으로 계산한다(선생님 결정). 이유: 제곱근은 중3 내용이다.
- 움직이는 도중 깨끗한 π 꼴이 안 나오는 값은 숨기거나 깨끗한 값만 지나가게 한다(영상은 cue `snap`).

## 3. 일하는 방식 (모든 단계 공통)

- 메인이 지시서를 쓰고, Sonnet 작업자가 만들고, 메인이 사진과 정답을 직접 대조해 병합한다. PR을 만든 뒤 바로 머지한다. 근거는 `CLAUDE.md`다.
- 완료 기준은 「학생이 쓰기에 적당한가」다. 전수 측정이 아니라 표본으로 보되, 정답 검산과 화면 노출 스캔은 도구로 전부 돌린다.
- 지시서에는 이 문서의 단계 번호와 「왜, 무엇이 학생에게 좋은가」를 적는다.
- 탐구 흐름이 먼저이고, 문제는 그 위에 얹는다. 숫자만 바꾸면 학습 포인트가 흐려지는 장면에는 「새 문제」를 넣지 않는다. 단위원 1~4장면은 그대로 둔다.
- **PC·태블릿 배치(2026-11-03 선생님 결정):** 그림 무대를 줄이고, 누르는 것(세부 장면 칩·고르기 칩)은 무대 위쪽 띠에, 끌어서 움직이는 막대는 무대 아래 받침에, 설명(질문·탭·안내·값·정리·문제)은 오른쪽 패널에 둔다. 휴대폰 배치는 그대로다. 이유: 조작부가 오른쪽 패널 아래로 밀려 패널을 내려야 막대를 움직일 수 있었고, 그동안 그림을 볼 수 없어 조작감이 나빴다. 셸 공통(`kit/apl-shell.js`·`kit/apl.css`)에서 한 번에 바꾼다.
- **길이 막대 범위(2026-11-03 선생님 의견):** 높이는 20까지, 반지름·변·가로·세로는 12까지 둔다(min·step·기본값은 유지). 모선·빗변이 자연수여야 하는 장면은 범위 안의 자연수 조합(3·4·5, 6·8·10, 5·12·13, 9·12·15, 8·15·17, 12·16·20)을 허용한다. 작도 실험실은 화면 작도라 대상에서 뺀다. 이유: 높이가 9까지라 교과서·시험 값(10, 12, 15, 20)을 넣어 볼 수 없었다.
- **겉넓이·부피 설명 원칙(2026-11-03 선생님 결정):** 겉넓이는 전개도로 설명하고(면마다 치수·넓이, 「겉넓이 = 면 넓이의 합」과 바로 연결), 부피는 겨냥도로 설명한다(예: 원뿔대 = 큰 뿔 − 작은 뿔). 겉넓이 식을 입체 위에 떠 있는 글자로 두지 않는다. 이유: 원뿔대 장면에 전개도가 없고 식만 입체 위에 떠 있어 학생이 어느 면의 넓이인지 알 수 없었다.
