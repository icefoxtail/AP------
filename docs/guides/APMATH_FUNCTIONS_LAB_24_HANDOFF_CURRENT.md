### 0-2. 작업 범위와 변경 원칙

- 정본은 **`main`의 현재 파일**. 업로드 과거 HTML, 이전 대화의 캡처, PR 설명만으로 최신 상태를 단정하지 않는다. **실제 경로 조회 → Git blob/commit 확인 → 필요한 구간 읽기** 순으로 작업한다. 파일명 검색 실패를 파일 부재라고 단정하지 않는다.
- **기본 `bas-1~16` 16종 + 심화 `adv-1~8` 8종, 총 24종**의 발문·의도·핵심 도형·상호작용을 보존한다. 확인된 오류는 정확하게 고친다. 무관한 재구현·기능 축소·전면 리팩터링은 하지 않는다.
- 문항은 **창작 심화문항**이다. 실제 학교/평가원 **기출이라고 주장하지 않는다**. 기출의 실제 채택·출처 확인은 별개 작업이다.
- 사용자 요구가 바뀌지 않는 한 작업 파일은 위의 단일 HTML로 한정한다. 운영센터·아카이브·Worker/D1·다른 도형 실험실·타 예약 라인에는 손대지 않는다.
- 코드 변경 시 정본 충돌을 확인하고 작은 표적 변경 → 수학 검산 → 브라우저 검수 → 변경 파일만 Git 반영. **사용자가 Git 반영/배포를 명시하지 않은 후속 작업은 독자적으로 main 병합·배포하지 않는다.** 문서 생성 요청인 이번 인계는 예외적으로 사용자가 Git 저장을 허용했다.
- 종전 정상 기능, DOM ID, 24종 선택 UI, 풀이 칠판, 보조선, 슬라이더, 드래그를 보존하고 변경 영향 범위만 회귀검사한다. 불필요한 전체 레포 테스트 반복·장시간 CI 폴링은 피한다.

### 0-3. 화면 규칙 — **나열 금지 / 필요할 때 꺼내 보기**

**첫 화면의 핵심:** `[문제 본문] + [큰 메인 그래프] + [보조선 꺼짐/1·2·3/전체] + [슬라이더와 필요한 프리셋] + [풀이 칠판 열기]`.

- **상시 비노출:** 중복된 단계별 설명·체크포인트 카드·상세 피드백·긴 풀이. 같은 내용이 그래프 배지/하단 힌트/오른쪽 카드/칠판에 4중 노출되면 실패.
- **PC:** 그래프 중심의 좌우 비교, 문제 카드 우측, 풀이 칠판은 버튼으로 열어 우측에 도킹. 칠판을 열어도 그래프를 보며 풀이를 확인할 수 있어야 함.
- **태블릿:** PC를 기계적으로 축소하거나 모바일 구성 요소를 세로로 끝없이 쌓지 않음. 실제 화면 폭/방향에 따라 그래프와 필요 시 열린 칠판의 **실제 비교 가능성**을 확보. 58:42 같은 비율은 권장안이지 고정 규칙이 아님.
- **모바일:** 문제·수식·라벨 크게. 칠판의 `Step 1/2/3/풀이 비교`는 **한 번에 하나의 탭**만 표시하며 그래프를 참조할 수 있는 짧은 동선 유지. 프리셋 선택 자체가 사라지면 안 됨.
- **가독성 목표:** 문제/해설 약 16px 이상, 작은 좌표 라벨과 상태 안내도 눈으로 읽을 수 있게; 주요 터치 조작은 가능하면 **44px 이상**. 실측 검증이 우선이며 무조건적 픽셀값 강제보다 도형 시야·터치 정확성을 평가한다.
- **상호작용:** 슬라이더/프리셋/핸들 드래그가 실제 좌표와 일치, 도형 빈 공간 드래그는 화면 이동. 보조선 버튼·칠판 탭은 실제 대응 도형에 연동. 이전 단계 누적 표시가 학습상 필요한 경우 유지하고 각 단계의 차이를 실제 화면으로 확인한다.

### 0-4. 수학·해설 규칙

**문항마다 `[발문 조건] ↔ [독립 계산·정답] ↔ [그래프 실좌표·치수선] ↔ [모든 슬라이더 값·프리셋] ↔ [보조선 1·2·3] ↔ [칠판/정답 배지]`를 교차검산한다.** 기본 위치만 맞고 슬라이더 이동 때 틀어지는 구현은 FAIL이다.

- **⚡ 실전 10초 컷:** 실제로 매우 짧게 압축되는 문항만. `발문의 결정적 단서 → 핵심 대칭·보조선 발상 → 압축된 계산`을 보여야 하며 허위 시간표현·논리 생략 금지.
- **🎯 실전 최적 풀이:** 정석보다 명백히 효율적인 해법이 있고 10초 컷까지는 무리인 경우.
- **🔍/📖 핵심 정석 풀이:** 경계 조건, 정의역, 무연근·예외 판별 등이 핵심인 경우. 가짜 지름길을 만들지 않는다.
- 이전 기획의 **분류 후보:** `adv-1/5/8` 10초 컷, `adv-2/4/6/7` 최적 풀이, `adv-3` 정석·오답 함정. **후보는 판정이 아니다.** 실제 풀이 검수로 교정 가능.
- 고1 교육과정에서 납득할 수 있는 논증을 우선한다. 특정 넓이·교점 개수·불변량은 실제 식으로 증명해야 하고, 화면 애니메이션만으로 증명을 대체하지 않는다.
- 기존 수식 표기 선호: 불필요한 `\therefore`, `\because`·한국어 `\text{...}` 사용 지양; 집합·부등식·해설의 의미를 정확히 보존. 기존 텍스트는 확인된 문제만 표적 정리한다.

### 0-5. 향후 신규 변경이 있을 때만 적용할 검수 기준

| 레벨 | 실행 | PASS 조건 |

- 브라우저에서 CDN을 제거한 `page.set_content` 스모크는 **JS 실행 확인일 뿐 실제 KaTeX/Tailwind/FontAwesome 화면 검수 PASS가 아님**.
- 상태값은 기존 룰북대로 **완료 / 일부 완료 / 진행 중 / 보류 / 확인 필요 / 금지**. `미검증`을 `PASS`로 쓰지 않는다.
- 검수 결과마다 `문항 ID·근거 계산·재현 조작·기대값/실제값·영향 파일·판정(PASS/WARN/FAIL/NOT_RUN)`을 남기고, 변경 후 **영향받은 도형·해설·프리셋만 표적 회귀검사**한다.
