# AP Math Lab — 영상 목차 대본 작성 안내서 CURRENT

> **기준일:** 2026-11-03 (KST) · 쇼츠 규칙 개정 2026-11-03
> **적용:** 도형실험실 2.0 실험실에 짧은 「영상 목차」를 추가할 때 대본(`video.js`)을 쓰는 작업자.
> **원리:** 영상은 따로 그린 동영상이 아니라, **실험실 그림을 대본대로 움직이는 것**입니다. 계산은 `kit/apl-video-core.js`, 화면·재생은 `kit/apl-player.js`, 목차는 `kit/apl-toc.js`가 맡습니다.

## 1. 한 줄 요약

학생이 목차에서 ▶ 장면을 누르면, 그 장면의 그림이 대본대로 **8~15초** 동안 바로 움직이고(자막 포함), 끝나면 한 줄 요약 + 「이제 직접 해 보세요」가 나오며 같은 그림을 직접 조작하게 됩니다. 쇼츠처럼 필요한 부분만 보여 주는 영상입니다.

## 1-1. 쇼츠 규칙 (2026-11-03 선생님 지적: 24초·22초 샘플이 「너무 늘어진다」)

이유: 학생은 영상을 끝까지 보려고 여는 것이 아니라, 필요한 한 가지를 확인하려고 엽니다. 길면 중간에 닫고 그림을 직접 만지러 갑니다.

| 항목 | 규칙 |
| --- | --- |
| 길이 | **8~15초** (목표 12초) |
| 자막 | **2~3줄**, 한 줄 **40자 이하**(수식 하나는 4자, 휴대폰에서 2줄 안에 들어오는 길이), 한 줄 2.5초 이상 |
| 핵심 | 영상 하나에 **핵심 하나**. 개념이 크면 짧은 영상 2개로 나눕니다(장면을 둘로 나누거나 다른 장면에 나눠 담음) |
| 시작 | **소개 줄 없음.** 첫 칸(`at: 0`)부터 그림이 움직입니다(첫 1초 안에 `to` 시작. 검사가 막음). 「~를 구해 봐요」「오늘은~」 같은 도입 자막을 두지 않습니다 |
| 끝 | **공식·결론은 마지막 한 줄.** 그 전 줄들은 그림이 보여 주는 것을 짚는 말입니다 |
| 제목 | 대본 `title` 에 **질문형·핵심형 짧은 제목(20자 이내)**을 권장합니다(예: 「중심각이 2배면 호는?」, 「S자 곡선 → 반원」). 재생이 시작되면 그림 위쪽에 크게 떴다가 약 2초 뒤 무대 맨 위 머리글 줄로 줄어 영상이 끝날 때까지 남습니다. 생략하면 장면 제목을 씁니다. 별도 표지 화면은 없습니다(첫 1초부터 그림이 움직여야 하므로) |
| 재생기 | 시작 대기와 끝 카드 지연이 없습니다(▶ 누르면 바로 움직이고, 끝나면 바로 끝 카드). 자막·끝 카드 등장 효과도 0.18초입니다 |

**만드는 순서(권장):** ① 장면의 탐구 질문·정리 단계 글에서 학생이 꼭 알아야 할 **한 가지**를 고른다 → ② 그것을 보여 주는 **움직임 하나**(상태값 하나가 값 A에서 B로)를 정한다 → ③ 자막 2~3줄: (움직임을 말함) → (그림에 보이는 값을 읽음) → (공식·결론 한 줄) → ④ 끝 카드 `summary`는 공식, `task`는 학생이 직접 할 한 가지.

## 2. 파일을 만드는 법

실험실 폴더(예: `labs/g7-circle-sector/`)에 `video.js`를 만들고, 실험실 HTML이 이미 다음을 갖췄는지 확인합니다.

```html
<script defer src="../kit/apl-video-core.js"></script>
<script defer src="../kit/apl-player.js"></script>
<script defer src="../kit/apl-toc.js"></script>
<link rel="stylesheet" href="../kit/apl-video.css">
```

`createLab({ ... })`에 `videos: window.APL_VIDEOS['<실험실 id>']`가 있어야 하고, `video.js`는 모듈 목록(`MODULES`)에 포함돼야 합니다.

## 3. 대본 형식

```js
window.APL_VIDEOS = window.APL_VIDEOS || {};
window.APL_VIDEOS['<실험실 id>'] = {
  '<장면 id>': {
    length: 12,                                // 전체 길이(초), 8~15
    title:  '중심각이 2배면 호는?',              // (선택, 권장) 영상 제목. 질문형·핵심형 20자 이내, 글자만(수식·HTML 불가). 생략하면 장면 제목
    start:  { 상태값: 시작값 },                 // (선택) 시작할 때 맞출 숫자 상태값(움직이지 않는 값도 가능)
    summary: '$S=\\frac12 rl$',                 // 끝 화면 한 줄 요약(수식 $…$ 가능)
    task:    '중심각을 움직여 보세요',            // 끝 화면 「이제 직접 해 보세요」
    cues: [
      { at: 0, say: '자막', to: { 상태값: 목표값 }, dur: 6, ease: 'smooth', set: { ... }, step: 2, part: 'ref' }
      // ...
    ]
  }
};
```

### cue 한 칸의 필드(`at` 외에는 모두 선택)

| 필드 | 뜻 |
| --- | --- |
| `at` | 이 칸이 시작하는 시각(초). 첫 칸은 0, 칸마다 커져야 함 |
| `dur` | `to` 움직임이 걸리는 시간(초). 생략하면 다음 칸 시작까지(마지막 칸은 `length`까지) |
| `to` | **숫자** 상태값을 목표값까지 부드럽게 바꿈 `{ 이름: 목표값 }`. 같은 이름의 앞선 움직임이 끝난 뒤 시작해야 함 |
| `set` | (숫자가 아니어도 되는) 상태값을 이 시각에 바로 바꿈 `{ 이름: 값 }` |
| `ease` | `smooth`(기본) \| `linear` \| `in` \| `out` |
| `snap` | `to` 로 움직이는 동안 값을 (그 움직임의 시작값 기준) `snap` 의 배수로 반올림해 **계단식**으로 넘김. 예: `snap: 15` → θ가 90, 105, 120 … 180. 끝 값은 정확히 `to`. 규칙 9 참고 |
| `say` | 자막. `**굵게**`, `$수식$` 가능 (HTML 태그 금지) |
| `step` | 정리 탭 단계 번호(`s.step`)를 바꿈. 탐구 화면에서 단계를 읽는 장면에서만 의미 |
| `part` | 그림에서 강조할 부분 이름(`s.part`). 장면 `view().parts[].id`와 같은 값 |

## 4. 완성 견본 (중1 원과 부채꼴 · 부채꼴의 호의 길이와 넓이, 장면 `1209`) — 12초

이 대본 전문이 기준 견본입니다. 새 대본은 이 모양(움직임 하나 → 값 읽기 → 마지막 줄에 공식)을 따릅니다.

```js
'1209': {
  length: 12,
  title: '중심각이 2배면 호와 넓이는?',        // 질문형 제목(20자 이내). 시작 때 크게 → 2초 뒤 머리글
  start: { b1209_r: 12, b1209_th: 90 },     // 자막이 말하는 값은 start 에 적어 그림과 맞춥니다
  summary: '$l=2\\pi r\\times\\frac{\\theta}{360}$, $S=\\pi r^2\\times\\frac{\\theta}{360}$',
  task: '중심각 θ를 바꿔 호의 길이와 넓이가 같은 비율로 변하는지 보세요',
  cues: [
    { at: 0,   say: '중심각 $\\theta$를 **90° → 180°**, 2배로 키워요.', to: { b1209_th: 180 }, dur: 4, ease: 'smooth' },
    { at: 4.5, say: '호는 **6π → 12π**, 넓이는 **36π → 72π**. 둘 다 **2배**!' },
    { at: 8.5, say: '호 = 원주 × $\\frac{\\theta}{360}$, 넓이 = 원의 넓이 × $\\frac{\\theta}{360}$' }
  ]
}
```

왜 이렇게 만들었나(견본에서 배울 점):
- **첫 칸부터 움직임**: `at: 0`에서 θ가 90°→180°로 움직이기 시작합니다. 소개 줄이 없습니다.
- **자막이 말하는 순간 그림이 그 상태**: 둘째 줄(`at: 4.5`)은 움직임이 끝난(0~4초) 뒤에 나와서, 그림 라벨의 「호 12π cm」「넓이 72π cm²」를 그대로 읽습니다. 숫자는 장면 공식으로 다시 계산했습니다(r=12: θ=90° → 호 6π·넓이 36π, θ=180° → 12π·72π).
- **기호는 쓰기 전에 뜻을**: 첫 줄에서 `중심각 θ`로 먼저 말하고, 마지막 줄에서 θ를 씁니다. 정의 전에 공식이 나오지 않습니다.
- **마지막 한 줄이 결론**: 장면의 규칙(rule) 글 「호 = 원주 × θ/360, 넓이 = 원의 넓이 × θ/360」을 그대로 씁니다. 새 주장 없음.
- **값 고르기**: 처음엔 θ=120°→240°(호 8π→16π)였지만 240°에서 「240°」와 「넓이 96π cm²」 라벨이 맞닿아 90°→180°로 바꿨습니다(`labs/g7-circle-sector/VIDEO_FINDINGS.md` #1).

이 대본이 장면의 어느 글에서 왔는지(대조 근거)는 `labs/g7-circle-sector/video.js` 머리 주석에 적혀 있습니다. 새 대본도 같은 방식으로 적습니다.

## 5. 규칙

1. **상태값 이름은 장면에 실제로 있는 것만** 씁니다. 장면의 `params`·`state`·`view()`·`draw()`·`steps`에서 확인합니다. (예: `basic.js`의 장면은 `b<id>_<param>`, `f04.js`는 `f4_<id>_<var>` 형태로 `lab.s`에 붙습니다. 값 범위는 그 `params`의 min·max.)
2. **자막은 2~3줄**, 한 줄은 40자(수식 하나는 4자) 이하, 한 줄이 2.5초 이상 보여야 합니다. 새 수학 주장을 만들지 않고 **그 장면의 탐구 질문(question)·정리 단계 글(steps)·규칙(rule)·정답 계산에서** 출발합니다. 자막에 숫자를 쓰면 장면 공식으로 다시 계산해 같은지 확인합니다(테스트로 남기면 좋습니다).
3. **중1 학생이 아는 말만** 씁니다. 처음 나오는 기호(θ, R 등)는 한 번 뜻을 붙입니다(예: `$\\theta$는 중심각`).
4. **자막이 말하는 순간 그림이 그 상태여야** 합니다. 「이렇게 돼요」 자막은 `to` 가 끝나는 때와 같거나 그보다 조금 앞에서 시작하게 하고, 값을 말하는 자막은 그 값이 그림 라벨에 보이는 때 둡니다. 장면에 시간 구간(예: swirl 의 `t` 구간 0.12~0.30 조각 표시, 0.38~0.74 회전, 0.80~0.96 결과)이 있으면 그 구간에 맞춰 `at`·`dur`·목표값을 정합니다.
5. `to`는 숫자 상태값만, `set`은 숫자가 아니어도 됩니다. 같은 이름의 `to` 는 서로 겹치면 안 됩니다. 영상이 끝난 값이 학생이 이어서 만질 시작 상태가 되므로, 라벨이 서로 겹치는 극단값은 피합니다.
6. `title`은 **질문형·핵심형 짧은 제목(20자 이내)**을 권장하고, 장면 내용과 정리 글에서 벗어나지 않게 씁니다(제목이 영상이 보여 줄 한 가지를 말해 줌). 글자만 쓰고 수식·HTML·`**굵게**`는 쓰지 않습니다. `length`는 8~15초, `summary`(40자 이하)·`task`(90자 이하, 학생이 직접 할 한 가지)는 비어 있지 않아야 합니다. `summary` 안의 수식 앞뒤 구두점은 수식 밖에 붙입니다(`$a$, $b$`).
7. 키트 공용 파일(`apl-shell.js` 등)은 바꾸지 않습니다. 대본·`video.js`·이 안내서·테스트만 작업합니다. (영상 작업자가 쇼츠 한도 등 `apl-video-core.js` 기준을 바꾸지 않습니다. 기준 변경은 별도 작업입니다.)
8. 새 장면을 추가하면 `tools/video.test.mjs` 의 `SCENE_STATE` 표에 그 장면의 상태값과 범위를 적고, 그 값이 장면 소스와 같은지 확인하는 검사도 추가합니다.

9. **움직이는 동안 소수가 보이는 장면은 `snap` 으로 깨끗한 값만 지나가게 합니다.** 이유: 부드럽게 움직이면 중간에 「94.91°」「호 6.33π」「넓이 37.96π cm²」처럼 소수와 π 가 함께 보여, 중1 학생이 이 값이 무엇인지 헷갈립니다(선생님 지적 2026-11-03). `snap` 을 쓰면 그림이 한 계단씩 머물며 지나가서 값을 읽을 수 있고, 「6π → 7π → 8π…」처럼 같은 비율로 커지는 것이 보여 공부도 됩니다. 정하는 법: 장면 공식으로 `to` 값이 지나가는 모든 칸의 라벨·칩이 정수(또는 간단한 분수)가 되는 `snap` 을 고릅니다(예: r=12 부채꼴은 호 θ/15·π, 넓이 0.4θ·π 라 15° 배수면 모두 정수). 맞는 `snap` 이 없으면 값이 두 개뿐이어도 됩니다(r=9 의 1210 은 `snap: 40` 으로 120° → 160° 한 번에). 확인은 §6 의 「소수 수집」(재생을 0.1초 간격으로 멈춰 가며 그림 글자와 칩에서 `/\d+\.\d+/` 를 찾음)으로 하고, 장면 쪽 소수 표기는 장면 작업(`lab-cs-pi`)에서 고칩니다.

### 5-1. 금지 패턴 (DeepSeek 초안에서 실제로 나온 문제들)

| 금지 | 왜 | 대신 |
| --- | --- | --- |
| **소개 줄** (「~를 구해 봐요」「이 도형은…」로 시작) | 늘어짐. 첫 프레임부터 그림이 움직여야 함 | 첫 칸에서 바로 `to` 로 움직이며 그 움직임을 말함 |
| **정의 전에 공식** (θ, R, l 을 설명 없이 식에 씀) | 학생이 기호를 모름 | 앞 줄에서 말로 먼저 쓰고(예: 중심각 θ) 마지막 줄에서 식 |
| **새 수학 주장** (장면의 질문·정리 단계·규칙에 없는 말, 새 공식·비교) | 장면과 어긋나면 틀린 설명이 됨 | 장면 글을 줄이기만 함. 숫자는 장면 공식으로 다시 계산해 확인 |
| **범위 끝 값**(예: θ=350, 300°대) · **라벨이 겹치는 값** | 라벨이 서로 맞닿거나 가려져 학생이 값을 못 읽음 | 지시서의 상태값 표에서 「깨끗한 값」만 사용. 직접 화면에서 확인 |
| **장면에 없는 상태값** (이름 추측, 장면에 안 보이는 값) | 영상이 안 움직이거나 오류 | 장면의 `params`/`vars`·`lab.s` 에서 확인한 이름만 사용 |
| **소수가 보이는 채 지나가는 움직임** (94.91°, 6.33π 등) | 학생이 헷갈림 | `snap` 으로 정수 계단만 지나가게(규칙 9) |
| **화면에 안 보이는 값을 말함** (그림 라벨에 없는 숫자) | 학생이 확인할 수 없음 | 자막이 말하는 숫자는 그 순간 그림 라벨에 보이는 것 |
| **한 영상에 핵심 둘** | 쇼츠가 아님 | 영상을 둘로 나눔 |
| 화면을 직접 확인하지 않고 제출 | 겹침·잘림을 못 찾음 | 태블릿·휴대폰 화면을 찍어 직접 봄 (§6) |

### 5-2. 기존 장면의 결함은 고치지 말고 발견 목록에 적는다

영상 작업 중에 장면 자체의 결함(라벨 겹침, 잘못된 값 등)을 발견해도 **장면 코드(`basic.js`, `f01.js`, `f04.js` 등)는 고치지 않습니다.** 대신 그 값을 지나가지 않게 대본을 짜고, 실험실 폴더의 `VIDEO_FINDINGS.md` 에 한 건씩 적습니다(장면 id · 조건(상태값) · 화면 크기 · 증상 · 영상에서의 회피).

이유: 영상 작업과 장면 수정이 한 변경에 섞이면 범위가 커지고(검수할 것이 늘고), 같은 장면 파일을 고치는 다른 작업과 충돌하며, 장면을 고친 뒤 영상 대본의 값·타이밍을 다시 검수해야 합니다. 장면 수정은 목록을 보고 별도 작업으로 합니다.

## 6. 검수 방법

판단 기준은 「학생이 실제 화면에서 보고 이해할 수 있는가」입니다.

1. 정적 검사: `node --test apmath/playground/next/tools/catalog.test.mjs apmath/playground/next/tools/video.test.mjs` (형식·길이·상태값 이름과 범위·끝 값·자막 수치).
2. 장면 렌더: 저장소 루트에서 `python3 -m http.server 8811 &` 로 서버를 띄운 뒤 `node apmath/playground/next/tools/scene-smoke.mjs http://127.0.0.1:8811/apmath/playground/next/labs/ --only <실험실 id>`. 끝나면 그 PID 만 kill 합니다(`pkill -f` 금지).
3. 브라우저 확인(Playwright): 콘솔 오류 0 · 목차에서 ▶ 누르면 재생 · 재생 중 `lab.s` 값이 실제로 바뀜 · 자막이 나옴 · 멈춤/느리게/다시 보기/이전·다음 · 끝나면 요약 카드와 「이제 직접 해 보세요」 · 이후 슬라이더·손잡이 조작 가능.
4. 화면 확인(쇼츠는 한 영상이 12초라 장면당 중간 1장·끝 카드 1장이면 충분. 제목은 시작 0.5초의 큰 제목과 4초의 작은 머리글도 찍어, 그림 라벨·핵심 도형·칩을 가리지 않는지 봅니다): 1024×768(태블릿 가로)·390×844(휴대폰)·1440×900(PC)에서 재생 시작·중간·끝과 끝 카드를 찍어 **직접 봅니다.** 자막 막대·단추·카드가 그림의 핵심(호·부채꼴·곡선·라벨)을 가리지 않는지, 글자가 잘리지 않는지, 수식이 깨지지 않는지 봅니다. 그림 자체의 기존 라벨 겹침은 영상 문제가 아니므로 따로 보고만 합니다.
