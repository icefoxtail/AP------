## 3. 시각 표현의 세부 기준

### 면과 선

- **연한 면 채색 + 뚜렷한 경계선**이 기본. 겹치는 면 때문에 치수·보조선·형상이 가려지지 않게 한다.
- 조정 출발점(강제 임계값 아님): 일반 면의 `fillAlpha` 약 `0.05~0.18`, 선택 면 약 `0.14~0.30`. 테마와 겹침에 따라 실제 화면으로 보정한다.
- 기본 경계는 대체로 2~3px, 보조·숨은 선은 더 얇게, 조작 중 핵심 부분만 진하게 한다. 모든 선을 두껍게 하거나 면을 불투명하게 칠하지 않는다.
- 겉넓이의 **실제로 노출된 면**, 부피에서 **파낸 조각**, 접합된 **숨은 면**은 서로 혼동되지 않도록 한다. 회전·전개 애니메이션에서 색상의 의미가 바뀌지 않아야 한다.

### 도형 배치

- 핵심 도형은 무대에서 충분히 크게 그린다. 수식·라벨·조작부에 가려지거나, 오른쪽 패널을 열면 조각이 갑자기 작아지는 현상을 막는다.
- **PC**는 원래 도형과 분해/전개 결과를 나란히 보여주는 배치를 우선 검토하고, **휴대폰**에서는 필요 시 위아래로 비교한다. 이것은 *화면 배치* 규칙이지 조각 이동 방향을 바꾸라는 뜻이 아니다.
- 기존 중1 도형실험실 계약대로 조각의 위치 이동은 가로 방향으로 유지하며, 접거나 돌릴 때는 필요한 회전만 허용한다.
- 입체는 밑면이 아래로 향하는 겨냥도, 가려진 모서리는 점선, 보이는 선은 실선. 모바일에서 중복된 원래 도형을 줄여 전개도를 크게 보일 수 있지만 문제 이해에 필요한 기본 형상·조건은 숨기지 않는다.
- 라벨·수치·각도는 서로 겹치거나 화면 밖으로 잘리면 안 된다. **정확한 분수·근호·π**를 우선하며 임의 근삿값은 `≈`로 표기한다.

### 단원별 역할

- **원과 부채꼴**: 호/현/중심각과 넓이·둘레의 역할을 구분. 둘레에서는 경계선, 넓이에서는 면을 강조. 재배열 후 그림은 충분히 크게.
- **다각형과 작도**: 보조선·합동 대응선·내각/외각을 필수 정보만 보이게 단계별로 공개. 절단·이동 전후의 대응색 유지.
- **다면체·회전체·겉넓이/부피**: 밑면·옆면·절단면·접합면을 정확히 구분하고, 3D 겨냥도와 전개도·단면을 혼동시키지 않는다.

## 4. 작업자의 단원별 완료 조건

1. 최신 Git `main`의 실제 파일과 이 문서를 확인한다. 과거 PR/로컬 패치를 한꺼번에 덮어쓰지 않는다.
2. 핵심 문제의 **발문 ↔ 도형 ↔ 수치 ↔ 풀이 ↔ 정답**을 먼저 대조한다. 기능을 바꾸기 전 반드시 수학이 맞는지 확인한다.
3. 초기·탐구 조작·정리 단계·문제 화면에서 색상 역할, 채색 농도, 크기, 라벨, 보조선, 화면 잘림을 확인한다.
4. 적어도 대표 위험 장면을 `1440×900`, `820×1180`, `1024×768`, `390×844`에서 검증한다. 실제 휴대폰 실기기는 시행했을 때만 PASS한다.
5. 수정 장면에 대해 **전후 화면·장면 ID·조건값·검산·변경 파일·실행한 테스트**를 기록하고, 하지 않은 검사는 `NOT_RUN`으로 남긴다.
6. 공통 `apl.css`, `apl-shell.js`, `apl-catalog.js` 및 공통 3D 엔진은 **통합 담당 단일 소유**. 개별 단원 작업자는 자기 단원 파일만 수정하고 공통 변경 필요성을 보고한다.
7. 단원별 검증과 CI, PR, main 병합, Pages 배포, 학생 경로 확인은 서로 다른 완료 단계다. 하나가 PASS여도 다른 단계를 자동 완료 처리하지 않는다.

**우선순위:** P0=수학 오류·백지·조작 불가, P1=주요 도형 절단·오도하는 색/치수·핵심 그림이 너무 작음, P2=정상 기능을 해치지 않는 여백·색 농도·문구 개선. 취향 차이만으로 정상 장면을 전면 재작성하지 않는다.
