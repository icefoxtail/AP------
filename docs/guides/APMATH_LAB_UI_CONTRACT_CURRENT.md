## 1. 절대 원칙

1. 문제 선택/읽기, 그래프, 조작, 단계 공개, 소형 칠판이 모든 단원에서 일관되게 동작한다. **동일 CSS/이벤트 의미를 강제**하되 모든 원/곡선/도형의 기하 엔진을 동일하게 만들지 않는다.
2. 학생이 **공개 동작을 하기 전에는 정답·정답 위치·결정적 치수·해설이 노출되지 않는다.** **소형 칠판 열기 자체는 Step 1 공개 요청으로 간주**하되, 이때 최종 정답이나 Step 2·3의 결론을 노출하지 않는다. 문제에 제공된 사실은 예외.
3. 문제 선택/슬라이더/드래그/프리셋/보조선/풀이 칠판이 **하나의 현재 문제·현재 파라미터·현재 공개 단계**를 공유한다. UI 표시만 바뀌는 가짜 제어 금지.
4. 수학적 표기는 정확값을 우선하고 자유 드래그 근삿값은 `≈`로 구별한다. 길이·면적에 rad를 붙이거나 도 단위 문제를 임의로 호도법으로 바꾸지 않는다.
5. 단원별 추가 도구(조각 해부, 렌즈, 측정, 자동 재생 등)는 **실제로 필요한 경우에만** 등장한다. 없는 기능을 공통 UI라며 강제로 추가하지 않는다.

### `전체보기`의 모바일 예외

- **그래프/도형:** 모든 보조선을 표시한다.
- **PC/태블릿 칠판:** Step 1~3의 풀이 카드를 함께 볼 수 있다.
- **모바일 칠판:** 화면을 크게 점유하지 않도록 Step 1/2/3을 **탭 하나씩** 선택하되, 모든 보조선은 그래프에 표시된 상태를 유지한다. 마지막 단계만 보여주고 앞 단계에 접근하지 못하게 해서는 안 된다.

## 3. 상태 전환의 단일 계약

새 구현에서는 `problemId`, `auxStep ∈ {0,1,2,3,4}`, `sliderValue`, `chalkOpen`, `solutionMode`, `boardPage`, `scale`, `pan`을 동일한 현재 상태에서 파생하고, 렌더링 함수·라벨·접근성 속성(`aria-pressed`, `aria-expanded`)을 함께 갱신한다.

| 사용자 행동 | 문제/도형 | 풀이 칠판 | 프리셋/표시 |
| --- | --- | --- | --- |
| 첫 진입 또는 다른 문항 선택 | 탐구 기본값, `auxStep=0`, 화면 좌표/줌 초기화 | 닫힘, 답 미노출 | 답을 암시하지 않는 중립 표기 |
| `칠판 열기` | 단계 0이면 `auxStep=1`로 전환·첫 보조선 활성, 그 외 현재 단계 유지 | 열림; **Step 1 풀이 즉시 표시**(기존 진행 단계는 보존), 최종 답은 비공개 | 현재 조작값 유지; 정답 위치로 강제 이동 금지 |
| `Step 1` | 해당 첫 보조선 활성 | 첫 풀이 카드 | 풀이 정보에 맞는 표시 갱신 |
| `Step 2` | 해당 2단계 보조선 활성 | 두 번째 카드 | 앞 단계에서 얻은 조건을 활용 |
| `Step 3` | 정답 도출에 필요한 보조선 | 세 번째 카드 및 최종 답 공개 가능 | 값·정답 근거가 일치 |
| `전체보기` | 보조선 1·2·3 모두 활성 | 데스크톱 전체, 모바일 단계 탭 | 결과 수치에 대한 설명 접근 가능 |
| 드래그/슬라이더/프리셋 | 현재 조작 매개변수 변화 | **열린 단계는 보존** | 값·선택·라벨·측정 동기화 |
| `꺼짐` | 기본 도형으로 복귀 | 추가 풀이 비공개; **이 상태에서 다시 칠판 열면 Step 1 자동 공개** | 답 누출 프리셋 라벨 복귀 |
| `초기화` | 현재 문항 기본값·줌·이동으로 복귀 | 공개 단계 유지 여부는 고정된 UX 선택에 따르되 **답 누출 금지**; 신규 구현 기본은 `auxStep=0`, 칠판 닫힘 | 기본 중립 표기 |

**보조선 단계를 눌렀다고 답에 대응하는 슬라이더 위치로 몰래 강제 이동하지 않는다.** 증명을 위해 특정 값이 반드시 필요한 문항은 학생에게 명시적으로 프리셋을 선택하게 하거나, `조건 확인`의 의도를 분명히 안내하고 현재 매개변수 변화를 함께 표시한다.

### 필수 화면 상태

- 첫 진입은 `정답 미공개 + 풀리지 않은 도형 + 조작 가능` 상태여야 한다. 도형을 처음부터 숨겨 문제를 이해할 수 없게 하지 않는다.
- **칠판 버튼 클릭 시 `auxStep=0`이면 Step 1로 들어가는 동작을 포함해 검사한다.** Step 1에서 정답을 본문·배지·프리셋·상태 HUD로 누설하지 않는다. Step 2도 해당 단계의 결론까지만 공개한다.
- 자유 드래그를 하면 도형·수치·칠판의 상태가 달라지더라도 서로 모순되는 결론을 보여주지 않는다. 풀이에서 최종 조건만 사용하는 경우 `현재 탐구값`과 `풀이 조건`을 시각적으로 구분한다.
- 모바일 프리셋은 `display:none`으로 제거하지 않는다. 긴 목록은 **한 줄 가로 스크롤**을 사용하고 손가락으로 눌러도 작동해야 한다.

## 4. 화면·반응형·접근성 계약

| 뷰포트 | 기본 배치 | 필수 확인 |
| --- | --- | --- |
| PC `≥1200px` | 좌측 큰 칠판 + 우측 문제·칠판 | 문제 읽기, 도형 크기, 열렸을 때 풀이 비교 |
| 태블릿 `768~1199px` | 문제 상단, 도형·컨트롤·열린 칠판을 비교 가능한 2열 또는 적합한 대안 | `820×1180`, `1024×768`, 도형/풀이가 동시에 유용하게 보이는지 |
| 모바일 `≤767px` | 문제 → 도형 → 컨트롤·프리셋 → 소형 칠판 | `390×844`, 버튼/수식 가독성, 풀이 탭 한 개, 전체 가로 넘침 없음 |

- 문제·해설 본문은 **약 16px**, 주요 제어/목록은 **14px 이상**에서 출발. 버튼·프리셋·터치 타깃은 **최소 44px 높이를 기본 목표**로 삼고 실제 누르기 쉬운지 검사한다.
- 고정 HUD는 핵심 도형·수식·드래그 핸들을 가리지 않도록 배치한다. 수식이 길면 줄바꿈 또는 **수식 영역만 가로 스크롤**한다. 전체 페이지 수평 스크롤은 피한다.
- 키보드 포커스, 선택·비활성·펼침 상태를 시각적으로 제공하고 색상만으로 문제 성립 여부를 전달하지 않는다.
- 줌/팬은 스크린 좌표에만 적용하며 수학적 값이 바뀌지 않는다. 라벨이 보이는 점/선·해당 도형 요소를 따라 이동한다.

## 5. 수학 라벨·풀이의 표시 계약

- `drawLabel`·`drawDimension`·점·각 라벨·측정 HUD는 가능한 한 **하나의 숫자 모델**을 사용한다. 슬라이더 `r`와 도형 치수선 `r`가 서로 다른 반올림값을 등호로 표시하면 실패.
- 학생이 학습에서 쓰는 정확한 값은 KaTeX/MathML/SVG/적절한 오버레이로 **교과서식 분수**, 근호, π를 우선한다. Canvas의 일반 문자열 `3π/4`가 교육적 가독성을 해치면 수식 라벨로 교체한다.
- 실제 임의 드래그값은 `≈`로 근사임을 표시한다. **기호와 값의 의미를 우선**하며, 아무 실수나 단순한 분수나 근호로 위장해서는 안 된다.
- **Canvas 그래프의 정확한 수학 표기(2026-10-28 추가):** 무리수·유리수 구조를 소수 근삿값만으로 대체하지 않는다. 예: 대칭 직각이등변삼각형의 변 길이는 탐구 중 `PQ = (b−a)√2`, 조건 성립 위치는 `PQ = 4√2`처럼 **근호가 남은 정확식**으로 표시한다. 짧은 정수·분수는 정확값으로 표시하고, 임의 조작 중 복잡한 값은 **정확한 기호식 + `≈` 근삿값**으로 병기한다. `PQ = 4.31`, `b−a = 3.05`처럼 반올림한 수에 등호를 붙이지 않는다. 도형·치수선·측정 HUD가 같은 계산 결과를 공유한다.
- **학생용 그래프 라벨(2026-10-28 추가):** 점·핸들 옆의 `[드래그]`, `[핸들 드래그]` 같은 개발 문구를 표시하지 않는다. 점의 이름·좌표·길이에 집중하고, 필요한 안내만 `점을 움직여 보세요`처럼 자연어로 쓴다. 실제 조작 기능은 유지한다.
- 각도: 문제·교육과정에서 라디안을 요구하면 `rad` 또는 π형식, 일반 도 단위면 `°`. 길이/넓이/삼각비에 rad를 남용하지 않는다.
- 소형 칠판은 수식 변형의 핵심 중간 계산과 사용 정리의 이유를 제시한다. 최종 값만 달랑 제시하는 가짜 Step 1~3을 PASS하지 않는다.

## 6. DOM·아키텍처 범위

기존 `probTabBar`, `mobStatement`, `pcStatement`, `geoCanvas`, `aux-0~4`, `paramSlider`, `snapChipBox`, `miniChalkboard`, `boardTabs`, `chalkStepsContainer`, `chalkAlgContainer`, `chalkAnswerBadge`, `liveMetricBar` 등의 실제 DOM/역할을 가능한 한 유지한다. **ID만 동일하다고 기능 PASS가 되지 않으며** 이벤트가 실제 조작에 연동되어야 한다.

- 모바일 브리지/어댑터 `#ap-mobile-bridge`, `#ap-mobile-adapter`, `#ap-touch-adapter`와 외부 스크립트는 **원본에 실제 존재하는 경우 삭제하거나 비활성화하지 않는다**. 샘플에 없다는 이유로 기존 작업에서 제거하면 안 된다. 반대로 없는 아이디를 신설하기 위해 복잡한 시스템을 덧붙이지 않는다.
- KaTeX 등의 외부 CDN 의존성은 실패 시 수식의 깨짐을 조용히 방치하지 않고 대체 텍스트/오류 안내를 제공한다. 드래그 이벤트를 막는 오버레이는 `pointer-events: none`을 기본으로 검토한다.
- 별도 화면·다른 단원·학원 운영 코드에 대한 영향은 범위 밖. 3개의 `.md` 문서만 생성하는 계약 정립 작업이 기존 HTML 코드를 자동 수정하도록 허가하는 것은 아니다.

| 학습 품질 | 학생에게 결정적 풀이 점프가 없고 보조선 근거와 식이 연결 |
| 수학 표현 | 정수/분수/근호/각도 단위와 근삿값 부호 정확, Canvas 라벨 판독 가능 |
| 기기별 | 실제 브라우저 `1440×900`, `820×1180`, `1024×768`, `390×844`에서 핵심 화면 확인 |
| 결과 | 검증한 부분만 PASS; 미실시 브라우저·Pages 배포는 미확인으로 구분 |

### 우선순위

P0: 잘못된 수학 조건·정답·계산, 조작 먹통, 주요 도형 백지화/절단.  
P1: 풀이의 결정적 논리 점프, 오도하는 표기, 중대한 도형/수식/조작 동기화 오류, 심각한 가독성.  
P2: 개념 이해에 도움 되는 경미한 표현·프리셋·안내 개선.  
**사소한 픽셀 비율·마이크로 오차로 P0/P1을 억지 생성하지 않는다.**
