# Archive 2.0 — 사용자 응답성과 원본 기출 경로 필수 계약

status: CURRENT / MANDATORY

runtimeContractVersion: `ARCHIVE2_RUNTIME_CONTRACT_V1_20261006`

사용자 확정 원칙: **작업 속도와 안정적인 원본 열기는 기능 구현의 필수 조건이다. 눌렀는데 반응이 없거나, 열리는 듯하다 닫히거나, 브라우저 저장 공간 때문에 자료를 열지 못하는 업데이트를 허용하지 않는다.**

## 1. 적용 범위와 우선순위

Archive 2.0의 기출·자료, 단원별 기출, 문제지 만들기, 저장한 시험지, 출제 내역과 이들이 공유하는 검색·선택·렌더·출력·저장·출제 연결 코드에 적용한다. 신규 기능, UI 개편, 리팩터링, 엔진/의존성 업데이트도 예외가 아니다. 기존 시험지 품질·source fidelity·권한 계약을 함께 지킨다.

이 계약은 권고나 나중에 수행할 최적화가 아니다. 완료와 메인 반영의 필수 조건이다. 구현 편의, 통합 아키텍처, 코드 중복 제거를 이유로 위반하지 않는다. 계약 변경은 사용자의 명시적인 변경 지시와 검증 근거를 기록해야 하며, 구현자가 스스로 예외를 만들지 않는다.

## 2. 원본 기출은 Archive 1의 안정 경로 유지

- 시험·해설·정답은 `engine.html?data=exams/<sourceArchiveFile>&mode=exam|sol|ans`로 원본 파일을 직접 연다. 클릭 이벤트에서 완성된 URL로 새 창을 열며, 원본 전체를 복사·해시·저장하는 비동기 준비를 열기의 선행 조건으로 두지 않는다.
- 원본 열기에 `outputRequestId`, `archive2Context=archive2` 또는 브라우저 snapshot 저장소를 강제하지 않는다. 원본을 공통 envelope 구조로 통합한다는 이유로 이 경로를 폐지하지 않는다.
- 조합·저장·이미 출제한 시험지는 선택된 문항과 frozen snapshot을 정확히 유지한다. 이 자료를 원본 전체 파일로 대신 열어 문항·순서·출력 설정을 바꾸지 않는다.
- 팝업 실패, 원본 파일 로드 실패, 실제 렌더 실패는 사용자에게 보이는 상태로 처리한다. 빈 창이나 조용한 창 닫힘으로 숨기지 않는다.

## 3. 클릭 응답성과 성능

- 첫 시각적 반응은 100ms 이내를 목표로 한다. 실제 브라우저에서 선택 상태·진행 표시·출력 창 열기 중 어떤 반응이 언제 나타나는지 확인한다. 클릭 처리 시간, 첫 화면 반응, 데이터 준비 시간, 전체 수식 조판 완료 시간을 별도로 기록한다.
- 교육과정·과목·범위 선택, 전체 선택/초기화, 문항 수·배분 변경의 동기식 처리 상한은 실제 크기 회귀 검사에서 500ms다. 시간 상한을 넘기면 기능이 동작하더라도 해당 구현은 완료로 보지 않는다.
- 실제 catalog를 사용한다. 현재 성능 fixture는 최소 10,000개 문항을 포함해야 한다. 작은 모형 데이터만으로 PASS하지 않는다. Archive가 성장했을 때 분모를 축소하거나 기준을 느슨하게 하지 않는다.
- 클릭마다 전체 catalog를 여러 번 순회하거나 동일한 분류·품질·문항 수를 다시 계산하지 않는다. 검색 인덱스, 이미 계산한 결과, 한 렌더 안의 재사용을 활용하되, 다음 렌더 및 최종 선택·출제에서 현재 조건과 품질 상태를 재검증한다.
- 긴 준비 작업은 첫 반응을 막지 않는다. 준비 전에 진행 상태를 표시하고, 성공·오류·취소·화면 이동 시 종료한다. 로딩을 띄웠다는 이유로 실제 클릭 지연을 합격으로 처리하지 않는다.
- 수식·이미지 조판 시간을 줄이기 위해 문항이나 해설을 생략하거나, 품질·레이아웃 검사와 내용을 훼손하지 않는다. 남은 조판 지연은 숫자와 병목을 명시한다.

## 4. 저장소 상태는 자료 열기의 선행 조건이 아니다

- IndexedDB 내부 오류, primary quota 초과, 접근 차단/사용 불가와 fallback Storage quota 초과를 실패 주입으로 검증한다. 정상 새 프로필 한 번에서 열린다는 사실만으로 PASS하지 않는다.
- 원본 열기는 저장소에 의존하지 않는다. snapshot이 필요한 자료는 저장소가 막혀도 동일한 데이터를 현재 화면과 출력 창/iframe 사이에 전달할 수 있어야 한다.
- 큰 문항·이미지 데이터를 localStorage/sessionStorage에 중복 저장하지 않는다. Archive 2.0 흐름에 legacy `mixedQuestions_`/`mixedMeta_` 분리 저장을 다시 추가하지 않는다. 작은 fallback도 공간이 없으면 실패 없는 전달 경로를 사용한다.
- 전달 시 request/owner/mode, 문항 수·UID 순서, TTL와 내용 hash를 유지한다. 창 간 전달은 origin, 실제 sender와 nonce를 검증한다. 메모리와 정리는 제한·범위를 두고, 로그인·초안·사용자의 저장 자료를 임의 삭제하지 않는다.
- 구조화 복사/직렬화 실패, 변조, 권한·내용 불일치를 성공으로 위장하지 않는다. 사용자 자료 삭제나 전체 브라우저 초기화를 정상 사용의 필수 조치로 요구하지 않는다.

## 5. 구현과 업데이트의 완료 조건

1. 영향을 받는 화면·공통 모듈·원본/조합/frozen 경로를 확인한다.
2. `node tools/check-archive2-runtime.cjs`를 실행하고 exit code와 각 검사 결과를 확인한다. 이 검사는 CI의 `Archive2 Runtime Guard`에서도 실행한다.
3. 출력·저장소·렌더·선택 경로를 변경하면 `node tests/archive2-interaction-browser-audit.cjs` 또는 동등한 실제 Chrome 검증을 실행한다. Playwright/Chrome가 필요한 브라우저 검증을 실행하지 않았다면 NOT_RUN으로 명시하며 해당 흐름의 검증 완료를 주장하지 않는다.
4. 원본 시험/해설/정답, 큰 snapshot(최소 6MB), 저장소 실패, 단원 준비/미리보기/출제 연결, 선택 조건 변경과 품질 상태 갱신을 검증한다. 사용자 계정으로 실제 출제 데이터를 만드는 대신 로컬 fixture와 읽기 전용 검증을 사용한다.
5. 공통 JS와 해당 HTML/새 창/iframe의 캐시 버전을 함께 갱신한다. 코드와 실제 배포 응답의 반영 상태를 구분해서 보고한다.
6. 기존 실패는 수정 전 비교와 이름·원인을 기록한다. 런타임 계약 검사를 삭제·격리·skip하거나 시간/내용 검증을 약화하여 성공을 만들지 않는다.

## 6. 자동 회귀 검사

`tools/check-archive2-runtime.cjs`는 원본 직접 경로, 실제 크기 클릭 성능, 즉시 미리보기 피드백, storage/메모리 전달, 단원 snapshot 연결, 내용 계약, reader·출력 경로·용량·readiness 검사를 실행한다. 테스트를 통과하는 것이 모든 화면의 모든 상황을 보장하지는 않으므로, 변경된 흐름의 실제 브라우저 확인도 완료 조건이다.
