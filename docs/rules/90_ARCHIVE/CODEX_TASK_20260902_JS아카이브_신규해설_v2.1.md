# Codex 작업 지시서 — JS아카이브 신규 해설 v2.1 문서 규칙 동기화

## 0. 작업 목적

JS아카이브의 해설 생성·수정·검수 관련 문서들을 **신규 해설 v2.1 방향**으로 동기화한다.

이번 작업의 목적은 기존 JS 파일의 해설을 리모델링하는 것이 아니다.
이미 만들어진 기존 해설 자산은 보존한다.
앞으로 새로 제작되는 JS 파일, 신규 기출 변환 파일, 신규 solution 생성 작업부터 새 해설 규칙이 적용되도록 문서 규칙을 정리한다.

핵심 방향은 다음과 같다.

```text
기존 해설 전체 리모델링 금지
신규 파일부터 새 해설 v2.1 적용
[키포인트] 고정 라벨 폐기
부호표/구간표 중심 금지
수식 전개 + 실제 시각 이미지 중심
부등식은 수직선 이미지
함수는 그래프 개형 이미지
원의 방정식은 좌표평면 위 원 이미지
직선의 방정식은 좌표평면 위 직선 이미지
교육과정 외 풀이 강력 배제
정답 역산 금지
확정된 수학적 데이터만 SVG로 시각화
불확실하면 그림을 만들지 않고 review/오류 목록으로 분리
```

## 3. 최상위 원칙

모든 문서에서 아래 원칙이 서로 충돌하지 않도록 맞춘다.

### 3-1. 기존 해설 보존

기존 운영 중인 JS 파일의 solution은 일괄 수정하지 않는다.

금지:

```text
기존 archive/exams/**/*.js의 solution 전면 재작성
기존 solution을 새 v2.1 형식으로 자동 변환
기존 [키포인트] 해설 일괄 삭제
기존 SVG/image 일괄 변환
```

허용:

```text
신규 생성 파일부터 v2.1 적용
사용자가 특정 문항 수정을 승인한 경우 해당 문항만 v2.1 기준으로 수정
검수 결과 중대 오류가 확인되고 사용자가 승인한 경우 해당 solution만 수정
```

### 3-2. 신규 해설 v2.1 적용

신규 해설은 더 이상 `[키포인트]`, `조건 정리`, `풀이 방향`, `정석 풀이` 같은 고정 라벨 구조를 강제하지 않는다.

기존 금지 대상:

```text
[키포인트] ...
조건 정리: ...
풀이 방향: ...
정석 풀이: ...
빠른 풀이 포인트: ...
```

신규 권장 흐름:

```text
문제 조건을 자연스럽게 해석한다.
필요한 식을 세운다.
실제 수식 전개를 생략하지 않는다.
범위, 부호, 위치관계, 교점, 중심, 반지름 등을 계산으로 확정한다.
확정된 결과를 수직선/그래프/원/직선 그림으로 보여준다.
마지막 결론은 answer와 일치시킨다.
```

### 3-3. 표가 아니라 실제 그림

사용자가 원하는 것은 부호표나 구간표가 아니다.
해설 안에 실제 시각 이미지가 들어가는 것이다.

금지 방향:

```text
부호표 중심 해설
구간표 중심 해설
글만으로 때우는 해설
표로만 범위를 정리하는 해설
```

권장 방향:

```text
부등식 → 수직선 그림
연립부등식 → 각 범위와 공통범위를 수직선 그림
절댓값 부등식 → 기준점과 최종 해집합을 수직선 그림
이차함수 → 좌표축 위 포물선 개형
두 함수 비교 → 두 그래프의 교점과 상하관계 그림
원의 방정식 → 좌표평면 위 중심, 반지름, 원 그림
직선의 방정식 → 좌표평면 위 직선 그림
직선과 원 → 원, 직선, 접점 또는 교점 그림
```

### 3-4. 자유작도 금지

AI가 감으로 그래프나 도형을 그리면 안 된다.

해설용 그림은 반드시 다음 순서를 따른다.

```text
1. 문제를 먼저 직접 푼다.
2. 근, 경계값, 꼭짓점, 교점, 중심, 반지름, 기울기, 절편 등을 계산으로 확정한다.
3. 확정된 수학적 데이터만 SVG에 반영한다.
4. SVG 표시값과 풀이 결과가 일치하는지 검산한다.
5. 그래프나 원문 이미지가 불명확하면 그림을 만들지 않는다.
6. 정답에 맞추어 그래프를 역산하지 않는다.
```

금지 예:

```text
그래프가 대충 이렇게 생긴다.
정답이 ⑤이므로 그래프를 ⑤에 맞춰 해석한다.
원문이 흐릿하지만 아마 이 점일 것이다.
보기와 맞추기 위해 교점을 이 위치로 둔다.
```

## 4. 신규 solution 작성 규칙

### 4-1. solution 기본 원칙

신규 solution은 학생이 실제로 읽는 최종 풀이만 포함한다.

필수:

```text
직접 풀이
수식 전개
중간 계산 생략 최소화
범위 판단 명시
교육과정 내 풀이
answer와 결론 일치
필요 시 해설용 SVG 삽입
```

금지:

```text
정답 끼워맞추기
공식명만 쓰고 바로 결론
계산하면, 정리하면, 쉽게 알 수 있다로 핵심 단계 생략
교육과정 외 풀이
운영 메모
OCR 메모
검수 필요 문장
ChatGPT/Gemini 언급
PASS/FAIL 문구
[키포인트] 강제 라벨
```

### 4-2. 결론 형식

객관식은 마지막에 answer와 일치하는 결론을 둔다.

```text
따라서 정답은 ③이다.
```

단답형/서술형은 다음처럼 둔다.

```text
따라서 구하는 값은 $12$이다.
```

여러 값을 묻는 경우:

```text
따라서 구하는 값은 $a=2$, $b=5$이다.
```

결론 뒤에 운영 메모를 붙이지 않는다.

## 5. 해설용 시각자료 규칙

### 5-1. 해설용 시각자료의 정의

해설용 시각자료는 원문 문제의 그림을 복사하는 것이 아니다.
학생이 풀이 과정을 이해하도록 도와주는 작은 설명용 그림이다.

예:

```text
부등식 풀이 후 해집합을 수직선으로 표시
이차함수의 근과 꼭짓점을 그래프 개형으로 표시
원의 방정식에서 중심과 반지름을 좌표평면에 표시
직선과 원의 위치관계를 좌표평면에 표시
```

### 5-2. 발문용 시각자료와 해설용 시각자료 구분

발문용 원문 그림:

```text
content 바로 아래
또는 image 필드
또는 content 내부 기존 SVG/img/table
```

해설용 설명 그림:

```text
solution 문자열 내부
<div class="sol-visual ...">...</div> 형태 허용
```

중요:

기존 문서에 있는 “표나 도형을 solution에 잘못 넣지 않는다” 취지의 규칙은 다음처럼 바꾼다.

```text
원문 발문에 속하는 표·도형·그래프를 solution으로 옮기는 것은 금지한다.
단, 풀이 이해를 돕기 위해 새로 만든 해설용 소형 SVG 시각자료는 solution 내부 삽입을 허용한다.
```

## 6. SVG 구현 규칙

### 6-1. 공통 SVG 규칙

solution 내부 해설용 그림은 우선 inline SVG로 작성한다.

기본 구조:

```html
<div class="sol-visual sol-numberline">
  <svg viewBox="0 0 260 56" width="240" height="52" aria-label="수직선">
    ...
  </svg>
</div>
```

또는:

```html
<div class="sol-visual sol-graph">
  <svg viewBox="0 0 260 180" width="240" height="166" aria-label="그래프 개형">
    ...
  </svg>
</div>
```

또는:

```html
<div class="sol-visual sol-circle">
  <svg viewBox="0 0 260 180" width="240" height="166" aria-label="원의 방정식 그림">
    ...
  </svg>
</div>
```

### 6-2. SVG 내부 금지

SVG 내부에는 아래를 넣지 않는다.

```text
<br>
$...$
\frac
\dfrac
\sqrt
\text{}
MathJax 수식
한국어 LaTeX
```

SVG 내부 라벨은 평문 텍스트로만 둔다.

허용:

```html
<text x="120" y="20" font-size="10" text-anchor="middle">x=2</text>
```

금지:

```html
<text>$x=\\dfrac{1}{2}$</text>
```

수식 라벨이 복잡하면 SVG 밖의 HTML/LaTeX 해설 문장으로 처리한다.

### 6-3. SVG 필수 조건

모든 해설용 SVG는 다음을 만족해야 한다.

```text
viewBox 필수
width/height 지정 권장
SVG 내부 <br> 0개
SVG 내부 LaTeX 0개
font-size는 8px, 9px, 10px 중심
흑백 인쇄에서 구분 가능해야 함
과도한 색상 의존 금지
그래프/도형의 의미가 풀이 결과와 일치해야 함
```

## 7. 문항 유형별 해설 그림 규칙

### 7-1. 부등식 / 연립부등식

부등식 해설은 부호표가 아니라 수직선 그림을 우선한다.

대상:

```text
일차부등식
연립부등식
이차부등식
절댓값 부등식
정수해 개수
매개변수 부등식
```

표시 요소:

```text
수직선
경계값
열린 점
닫힌 점
해당 구간 굵은 선
공통범위가 있으면 공통범위 강조
정수해를 묻는 경우 정수 점 표시
```

좋은 예:

```js
solution: "주어진 부등식을 정리하면 $x^2-x-2\\gt0$이다.\\n$(x-2)(x+1)\\gt0$이므로 경계값은 $-1$, $2$이다.\\n계수가 양수인 이차식은 두 근의 바깥쪽에서 양수이므로 $x\\lt-1$ 또는 $x\\gt2$이다.\\n<div class=\"sol-visual sol-numberline\"><svg viewBox=\"0 0 260 58\" width=\"240\" height=\"54\" aria-label=\"x<-1 또는 x>2\"><line x1=\"20\" y1=\"30\" x2=\"240\" y2=\"30\" stroke=\"black\"/><line x1=\"20\" y1=\"30\" x2=\"34\" y2=\"24\" stroke=\"black\"/><line x1=\"20\" y1=\"30\" x2=\"34\" y2=\"36\" stroke=\"black\"/><line x1=\"240\" y1=\"30\" x2=\"226\" y2=\"24\" stroke=\"black\"/><line x1=\"240\" y1=\"30\" x2=\"226\" y2=\"36\" stroke=\"black\"/><circle cx=\"90\" cy=\"30\" r=\"4\" fill=\"white\" stroke=\"black\"/><circle cx=\"170\" cy=\"30\" r=\"4\" fill=\"white\" stroke=\"black\"/><line x1=\"24\" y1=\"30\" x2=\"86\" y2=\"30\" stroke=\"black\" stroke-width=\"4\"/><line x1=\"174\" y1=\"30\" x2=\"236\" y2=\"30\" stroke=\"black\" stroke-width=\"4\"/><text x=\"90\" y=\"48\" font-size=\"10\" text-anchor=\"middle\">-1</text><text x=\"170\" y=\"48\" font-size=\"10\" text-anchor=\"middle\">2</text></svg></div>따라서 정답은 ③이다."
```

나쁜 예:

```text
부호표를 그리면 +, -, + 이므로 답은 ③이다.
```

나쁜 이유:

```text
사용자가 원하는 것은 부호표가 아니라 실제 수직선 이미지다.
```

### 7-2. 함수 그래프

함수 해설은 그래프 개형 그림을 우선한다.

대상:

```text
이차함수의 부호
이차함수의 최댓값/최솟값
두 함수의 대소 비교
직선과 포물선
절댓값 함수
유리함수/무리함수 개형
그래프 해석형 참거짓
```

표시 요소:

```text
좌표축
그래프 개형
x절편
y절편
꼭짓점
교점
상하관계
필요한 구간
```

좋은 예:

```js
solution: "$y=x^2-4x+3$을 인수분해하면 $y=(x-1)(x-3)$이다.\\n따라서 x절편은 $1$, $3$이고, 축은 $x=2$이다.\\n$x=2$를 대입하면 $y=-1$이므로 꼭짓점은 $(2,-1)$이다.\\n<div class=\"sol-visual sol-graph\"><svg viewBox=\"0 0 260 180\" width=\"240\" height=\"166\" aria-label=\"위로 열린 포물선\"><line x1=\"25\" y1=\"135\" x2=\"235\" y2=\"135\" stroke=\"black\"/><line x1=\"55\" y1=\"20\" x2=\"55\" y2=\"160\" stroke=\"black\"/><path d=\"M75 55 Q130 165 185 55\" fill=\"none\" stroke=\"black\" stroke-width=\"2\"/><circle cx=\"110\" cy=\"135\" r=\"3\" fill=\"black\"/><circle cx=\"150\" cy=\"135\" r=\"3\" fill=\"black\"/><circle cx=\"130\" cy=\"155\" r=\"3\" fill=\"black\"/><text x=\"110\" y=\"150\" font-size=\"10\" text-anchor=\"middle\">1</text><text x=\"150\" y=\"150\" font-size=\"10\" text-anchor=\"middle\">3</text><text x=\"130\" y=\"170\" font-size=\"10\" text-anchor=\"middle\">(2,-1)</text></svg></div>그래프가 x축보다 아래에 있는 구간은 $1\\lt x\\lt3$이다.\\n따라서 정답은 ②이다."
```

나쁜 예:

```text
그래프를 보면 $1<x<3$이다.
```

나쁜 이유:

```text
그래프를 실제로 보여주지 않았고, 판단 근거가 생략됐다.
```

### 7-3. 원의 방정식

원의 방정식은 좌표평면 위 원 그림을 우선한다.

대상:

```text
중심과 반지름
점과 원의 위치관계
직선과 원의 위치관계
접선
두 원의 위치관계
원의 이동
```

표시 요소:

```text
좌표축
중심
반지름
원
점
직선
접점 또는 교점
```

좋은 예:

```js

```

나쁜 예:

```text
중심과 반지름을 구하면 알 수 있다.
```

나쁜 이유:

```text
원 위치관계를 눈으로 보여주지 않는다.
```

### 7-4. 직선의 방정식

직선 문제도 필요한 경우 좌표평면 그림을 넣는다.

```text
좌표축
두 점
직선
```

## 8. 교육과정 제한 규칙

해설은 해당 학년·과목의 교육과정 안에서 작성한다.

특히 고1 공통수학1/공통수학2에서는 아래를 주의한다.

금지:

```text
삼차방정식의 세 근의 합을 고차방정식 근과 계수 관계로 바로 사용

미분 사용
수열의 합 공식 사용
극한 사용
고등 이후 정리 사용
```

예시:

나쁜 풀이:

```text
삼차방정식의 세 근의 합은 근과 계수의 관계에 의해 ...
```

좋은 풀이:

```text
주어진 근을 대입하여 계수를 먼저 구한다.
그다음 인수정리로 일차인수를 확인한다.
다항식을 나누어 남은 이차방정식을 만든다.
남은 두 근에 대해서만 이차방정식의 근과 계수 관계를 사용한다.
```

## 9. 불확실 문항 처리 규칙

아래 경우에는 solution을 억지로 쓰지 않는다.

```text
원문 그래프가 흐림
좌표 눈금이 불명확함
도형 조건이 잘림
보기와 계산 결과가 충돌함
정답표와 풀이 결과가 충돌함
정답에 맞춰 그래프를 역산해야만 함
교육과정 내 풀이가 확정되지 않음
```

처리 방식:

```text
solution은 빈 문자열로 둔다.
오류 목록 또는 review_needed 목록에 기록한다.
학생용 solution 안에는 "원문 확인 필요", "검수 필요", "OCR" 같은 운영 메모를 넣지 않는다.
```
