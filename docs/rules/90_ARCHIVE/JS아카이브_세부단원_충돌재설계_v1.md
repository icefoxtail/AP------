# JS아카이브 세부단원 충돌 재설계 v1

상태: `DRAFT`  
대상: 기존 PILOT 검토에서 충돌이 확인된 6개 표준단원, 12개 세부 키  
운영 반영: `금지`

## 공통 판정 순서

1. 문제의 핵심 대상(삼각형, 사각형, 함수, 방정식 등)을 먼저 판정한다.
2. 문제의 요구 행동(정의·성질 확인, 식 풀이, 그래프 해석, 실생활 모델링)을 판정한다.
3. 해설의 첫 번째 논리 앵커가 어느 세부 단원의 핵심인지 확인한다.
4. 본문과 해설이 다른 세부 단원을 지지하면 `MULTI_CONCEPT_REVIEW`로 보류한다.
5. 일반 단어가 아니라 아래의 강한 경계 단서를 우선한다.

## 자동화 안전 규칙

- 강한 포함 단서가 양쪽 세부 키에 동시에 나타나면 자동 확정하지 않는다.
- `활용`, `구하기`, `성질` 같은 일반 단어는 단독 판정 단서로 사용하지 않는다.
- 시각자료가 핵심이면 본문 텍스트만으로 확정하지 않고 `VISUAL_REVIEW`로 보류한다.
- 본문과 해설의 대표 단원이 다르면 `source_solution_disagreement`를 기록한다.
- 하나의 문항에 모델링과 그래프 해석이 모두 있으면 대표 목표를 기준으로 고르고, 보조 개념은 별도 태그로 남긴다.

## 재검증 표본 설계

각 충돌 쌍마다 다음 표본을 별도로 만든다.

- 각 세부 키의 강한 포함 단서 문항 20개
- 두 키의 단서가 동시에 나타나는 경계 문항 20개
- 본문·해설 불일치 후보 10개

총 50개씩 검토한 뒤, `경계 정확도 90% 이상`과 `본문·해설 일치율 85% 이상`을 모두 만족할 때만 `PILOT_EVIDENCE_READY`로 재승격한다.
