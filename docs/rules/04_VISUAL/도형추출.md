1. 눈대중(hand-tuned) 도형 생성 금지

[1-1. Python 의무]
- 도형/그래프/좌표 기반 SVG 작업은 반드시 Python 수치 검증을 선행한다.

[1-2. 눈대중 금지]
- 사람이 보기에 그럴듯한 곡선, 선분, 점 위치를 손으로 추정하여 배치하는 행위를 금지한다.

[1-3. Python 결과값 기반 좌표만 허용]
- SVG의 모든 좌표값은 Python 실행 결과에서 나온 값만 사용한다.
- `cx`, `cy`, `x`, `y`, `points`, `d` 등은 Python 출력값에 근거해야 한다.
- "대충 이쯤" 식 배치는 금지한다.

[1-4. 엔진 호환 우선]
- 최종 산출물은 JS아카이브 엔진에서 바로 사용할 수 있어야 한다.
- SVG 내부 `<br>` 금지
- SVG 내부 LaTeX 금지
- 표는 발문 바로 아래 배치 원칙 준수
- 발문 표는 `.question-table-wrap` 또는 `.question-table` 전용 전략을 우선한다.
- PNG 자산은 `assets/images/시험지전체명/q{id}.png` 규칙을 따른다.

[1-5. 원본 충실성]
- 원본 도형이 있으면 선의 상대적 길이, 위치, 점 배치, 방향, 비율을 최대한 유지한다.
- 원본보다 더 예쁘게 그리려는 미화는 금지한다.
- 원본에 없는 요소를 임의로 추가하지 않는다.

5. 곡선 / 함수 그래프 규칙
--------------------------------------------------

### 5-1. bezier 눈대중 금지
- 함수 그래프를 `M ... C ... Q ...` 식 bezier로 감으로 만들면 실패다.
- 포물선, 유리함수, 지수함수, 로그함수 등은 Python 샘플링으로 생성한다.

### 5-2. polyline 샘플링 의무
- 함수 곡선은 Python에서 좌표를 sampling하여 `polyline points="..."` 또는 이에 준하는
  방식으로 넣는다. 고정된 총점만으로 품질을 판정하지 않는다.

### 5-3. 샘플 수 기준
- branch를 먼저 분리한 뒤 각 연속 branch에 대해 아래 density 기준을 적용한다.
- 일반 연속 branch: `max(200, ceil(plotWidthPx / 1.5))`
- 점근선·급격한 변화가 있는 branch: `max(300, ceil(plotWidthPx / 1.0))`
- 위 값은 branch별 기본값이며, 실제 점 수는 endpoint·교점·급격한 곡률 변화·점근선
  근처·화면상 chord가 긴 구간을 추가 세분화한 뒤의 값으로 기록한다.

### 5-4. Adaptive refinement 및 불연속 처리
- 가능하면 screen-space error 기반 adaptive refinement를 사용한다.
- 권장 목표는 `SCREEN_SPACE_CHORD_ERROR <= 0.35px`다.
- endpoint, 교점, 점근선 부근, 급격한 곡률 변화 및 화면상 chord가 긴 구간은 기본
  density만 믿지 말고 추가 샘플을 삽입한다.
- 불연속 branch는 절대로 연결하지 않는다. 정의역 경계·점근선·NaN·Inf·화면 밖 발산
  구간은 branch를 나누거나 제외하고, 제외 근거를 기록한다.
- 샘플 수, branch 수, refinement 적용 여부와 screen-space error 결과를 검수 기록에 남긴다.

### 5-4-1. 점근선 발산 clipping 및 branch separation 구현 계약

점근선·정의역 단절·무한 발산이 있는 그래프는 수치값 제거만으로 clipping을 완료한 것으로
보지 않는다. 최종 rendering path는 아래 deterministic contract를 따른다.

- **Branch separation:** 연속 branch마다 별도 `<polyline>` 또는 `<path>`를 만들거나,
  하나의 `<path>` 안에서 branch가 바뀌는 지점마다 새 `M` 명령으로 재시작한다.
- 점근선 양쪽 좌표를 하나의 연속 `L` 또는 단일 `polyline`으로 연결하지 않는다.
  `BRANCH_SEPARATION_PASS`는 이 연결이 없을 때만 PASS다.
- **Plot safe boundary:** 실제 canvas safe area에서 다음 네 경계를 계산한다.
  `PLOT_SAFE_TOP`, `PLOT_SAFE_BOTTOM`, `PLOT_SAFE_LEFT`, `PLOT_SAFE_RIGHT`.
  이 값은 임의의 y 절댓값이 아니라 plot 영역과 safe margin으로부터 도출한다.
- branch가 safe area 밖으로 나가면 현재점과 다음점의 선분과 해당 plot boundary의
  교점을 선형 보간으로 계산하고, **첫 boundary intersection에서 해당 branch path를
  종료**한다. 단순 `abs(y) > 임의 숫자` clipping은 허용하지 않는다.
- 다음 조건 중 하나가 성립하면 해당 방향의 refinement를 종료한다:
  `boundary intersection 확정`, `non-finite 도달`, `domain exclusion 도달`,
  `configured recursion/depth safety cap 도달`.
- safety cap이 먼저 작동하면 cap 값·branch 방향·마지막 유한점·미확정 error를 WARN 및
  evidence에 기록한다. cap 작동만으로 출판 PASS를 선언하지 않는다.

### 5-5. 특이점 주변 처리
- 점근선, 정의역 끊김, 루트 함수 경계 등은 샘플링 시 적절히 제외한다
- 정의역 밖 값, 발산 구간, NaN/Inf 값은 제거한다
- 그래프가 축을 잘못 관통하지 않도록 범위 클리핑을 한다

--------------------------------------------------
6. 도형 / 기하 규칙
--------------------------------------------------

### 6-0. 공통 인쇄 원칙 상속 범위

도형 규칙은 그래프 규칙과 공통 인쇄 원칙을 공유하며 이를 override하지 않는다. 다음
항목은 도형·기하·입체도형·hybrid에 동일하게 상속한다.

- safe area / margin 및 print physical target 운영 원칙
- 정상적인 stroke scaling, SVG root contract, `viewBox`, `preserveAspectRatio`
- TEXT_FONT / MATH_FONT typography system, mathematical italic, U+2212 minus
- color / grayscale invariant, style metadata, style lint 및 golden-set 운영 구조
- 공통 z-order 원칙. 단, 레이어 종류와 의미는 geometry용으로 아래에서 재정의한다.

geometry-specific 규칙은 공통 원칙을 확장할 뿐 대체하지 않는다. 세부 stroke·label·indicator·
hatching·3D·hybrid token은 이 문서의 geometry canonical 장에서만 정의한다.

### 6-1. 좌표 기반 생성
- 기하 도형은 가능한 한 좌표를 먼저 설정하고 SVG로 변환한다.
- 선분 길이, 각도, 중점, 분할점은 Python 계산으로 검증한다.
- 원, 호, 접선, 평행선, 수선 등은 기하 조건에 맞는 좌표를 계산한 후 그린다.

### 6-2. 비율 유지
- axis equal 개념이 필요한 도형은 비율을 왜곡하지 않는다.
- 삼각형, 원, 좌표도형은 가로세로 비율이 틀어지면 실패 가능 요소다.

### 6-3. 원본 없는 임의 개선 금지
- 더 예쁜 삼각형, 더 보기 좋은 배치를 이유로 원본 비율을 바꾸지 않는다.
- 점 위치가 원본 대비 과하게 달라지면 실패다.

### 6-4. 텍스트 라벨 배치
- 점 이름, 길이 표기, 축 문자 등은 원본과의 상대 위치를 유지한다.
- 텍스트가 선 위에 겹치지 않게 최소 범위에서만 이동한다.
- 라벨 위치도 가능하면 Python 좌표 또는 계산 근거를 둔다.

### 6-5. Geometry stroke hierarchy

그래프의 `MAIN_CURVE > AXIS > GUIDE` 위계를 도형에 그대로 적용하지 않는다. 도형은
다음 geometry 전용 hierarchy를 사용한다.

| token | Pilot 시작값 | 조정 범위 | 적용 |
|---|---:|---:|---|
| `MAIN_SHAPE_STROKE` | `2.05px` | `2.0~2.1px` | 주어진 도형의 외곽·핵심 선 |
| `SECONDARY_SHAPE_STROKE` | `1.6px` | `1.5~1.7px` | 보조 도형·내부 경계 |
| `AUXILIARY_LINE_STROKE` | `1.0px` | `0.9~1.1px` | 수선·중선·이등분선 등 |
| `INDICATOR_STROKE` | `0.8px` | `0.7~0.9px` | 직각·각·합동·평행 표기 |
| `COORDINATE_AXIS_STROKE` | `1.2px` | `1.1~1.3px` | hybrid에서만 |
| `HIDDEN_LINE_STROKE` | `1.8px` | `1.6~2.0px` | 3D 은선 |

HARD hierarchy는 `MAIN_SHAPE > SECONDARY_SHAPE > AUXILIARY_LINE > INDICATOR`다. 좌표축이
있는 hybrid에서는 `MAIN_SHAPE > COORDINATE_AXIS`를 기본으로 한다. 색상만으로 위계를
표현하지 않고 stroke weight와 line type을 함께 사용한다.

#### 6-5-1. Geometry DOM z-order

geometry SVG는 CSS `z-index`에 의존하지 않고 다음 DOM layer order를 canonical로 사용한다.

```text
Z00 background
Z10 fill / hatch
Z20 construction / auxiliary / hidden
Z30 secondary shape
Z40 main shape
Z50 dimension line
Z60 geometry indicator
Z70 point / special point
Z80 leader line
Z90 label
```

같은 layer 안에서는 원문·수학 의미를 보존하는 순서를 유지한다. `GEOMETRY_STYLE_LINT`는
이 `GEOMETRY_Z_ORDER`와 fill/hatch의 border 아래 배치를 함께 검사한다.

### 6-6. 모서리·선 접합·점 표시

- geometry 기본값은 `stroke-linejoin: round`, `stroke-linecap: round`다.
- 예각에서 miter spike가 생길 수 있으므로 miter join은 원문 재현에 꼭 필요한 경우만
  허용하고, `miter-limit`와 실제 렌더 결과를 evidence에 기록한다.
- 일반 꼭짓점 점표시는 기본 OFF다. 선분 교점·중심·접점·특별점처럼 문제 이해에 필요한
  경우에만 geometry point marker를 표시한다.
- point marker 시작값은 radius `2.0px`, 조정 범위는 `1.8~2.2px`다. 꼭짓점은 점보다
  선의 교차와 라벨로 인식하게 하는 것을 기본으로 한다.

### 6-7. Geometry label policy

도형 라벨은 `VERTEX_LABEL`, `EDGE_LABEL`, `ANGLE_LABEL`, `REGION_LABEL`로 구분한다.

| 라벨 | 시작값·기본 위치 | 핵심 규칙 |
|---|---|---|
| `VERTEX_LABEL` | `13.25px`, 꼭짓점 내각 이등분선 반대 방향으로 `8~12px` | 외부 배치 우선, math italic |
| `EDGE_LABEL` | `12px`, 변의 중점 normal 방향 `5~8px` | 숫자·연산자·단위는 upright, 수학 변수·함수 기호는 mathematical italic |
| `ANGLE_LABEL` | `11.75px`, angle arc 중심부 | 내각 이등분 방향, arc·tick·변과 비충돌 |
| `REGION_LABEL` | `12px`, 내부 빈 공간 | 부족하면 leader line 또는 외부 배치 |

`ANGLE_LABEL`의 `θ`, `α`, `β` 등 수학 변수 역할의 Greek glyph는 mathematical italic으로
표시하고, `30°`, `45°`, `60°`의 숫자와 degree sign은 upright로 표시한다. 복합식은
변수·함수·숫자·연산자별 math typography를 적용한다.

label collision 대상은 최소 다음을 포함한다.

```text
VERTEX_LABEL ↔ EDGE
VERTEX_LABEL ↔ ANGLE_MARK
VERTEX_LABEL ↔ OTHER_LABEL
EDGE_LABEL ↔ SHAPE
ANGLE_LABEL ↔ ARC
TICK_LABEL ↔ TICK_LABEL
LABEL ↔ HATCHING
```

도형 내부에 라벨을 억지로 넣지 않으며, 충돌 회피가 우선이다. leader line을 쓰는 경우에도
핵심 선·점·다른 라벨을 관통하지 않는다.

### 6-7-1. Student-facing coordinate label precision

학생에게 직접 노출되는 점·중심·교점·접점 라벨의 좌표 표기는 내부 계산값과 분리한다.

- 계산 과정에서 나온 Python/JS 부동소수점 근삿값을 학생용 좌표 라벨에 그대로 출력하지 않는다.
  `0.6667`, `1.3333`, `2.7692`, `4.8284`처럼 원래 수학적 값을 보장하지 않는 소수 표기는
  `STUDENT_DECIMAL_POINT_LABEL_FAIL` 대상이다.
- 검증된 정확한 값이 있으면 정수·기약분수·근호·기호식 중 가장 간결한 평문으로 표시한다.
  SVG 내부 LaTeX 금지 원칙은 유지하며, 예시는 `1/2`, `−3/2`, `√2`, `2+2√2`다.
- 정확한 표현을 독립적으로 확정할 수 없으면 점 marker와 점 이름만 표시하고 좌표 접미사를 생략한다.
  임의의 분수나 근호를 추정하여 만들지 않는다.
- `data-point-x`, `data-point-y`, `cx`, `cy`, `points` 등 내부 geometry 사실값은 보존한다.
  학생용 `<text>` 라벨을 단순화하는 것은 geometry 좌표를 수정하는 것이 아니다.
- 원문 자체가 유한소수 좌표를 조건으로 제시한 경우에는 예외로 둘 수 있으나,
  `SOURCE_DECIMAL_LABEL` 사유와 원문 근거를 evidence에 기록한다. 계산 중간값이나
  이진 부동소수점 출력은 원문 소수 예외로 취급하지 않는다.
- 우측 수치 패널·solution 본문에 정확한 값을 제공하는 경우 점 라벨은 이름만으로 충분하다.
  라벨을 제거하거나 단순화한 뒤에도 점의 의미와 정확한 값이 다른 학생용 영역에서 확인되어야 한다.

### 6-8. Geometry indicators

모든 indicator는 `INDICATOR_STROKE`를 사용하고 메인 도형보다 두껍게 만들지 않는다.

- **Right angle mark:** 작은 정사각형 꺾쇠를 사용한다. 한 변 시작값 `7.5px`, 조정 범위
  `7~8px`, fill은 `none` 또는 `white`다.
- **Angle arc:** 반지름 시작값 `14px`, 조정 범위 `12~16px`다. 동일각을 구분할 때
  double/triple arc를 사용하며 arc 간 간격 시작값 `3.5px`, 조정 범위 `3~4px`다.
- **Congruent tick marks:** 단일·이중·삼중 slash로 같은 길이 집합을 구분한다. 길이
  시작값 `7px`, 조정 범위 `6~8px`, slash 간 간격 `2.75px`, 조정 범위 `2.5~3px`다.
- **Parallel mark:** 변의 중점 부근에 얇은 V 또는 chevron을 배치한다. 크기 시작값은
  `8px`, 조정 범위는 `7~9px`로 하고, 단일·이중 평행은 mark 개수로 구분한다. 좌표축
  arrow와 혼동되지 않는 geometry 전용 모양을 사용한다.
- 원에서 radius는 중심에서 원주로, diameter는 중심을 통과하는 직선으로, chord는 중심을
  통과하지 않을 수 있는 현으로 구분한다. arc length 표시는 원호를 따라 배치하고 일반
  선분 길이 표기와 섞지 않는다. tangent에는 필요 시 radius와의 직각관계를 표시한다.

#### 6-8-1. Indicator orientation contract

indicator의 크기만 고정하고 화면 방향을 임의로 그리지 않는다. 각 선분·ray의 local
좌표를 계산해 다음 계약을 따른다.

- **Congruent tick:** 대상 선분의 midpoint를 기준점으로 잡고, edge tangent vector와
  unit normal vector를 계산한다. tick mark는 이 local frame에서 길이 방향을 정한 뒤
  edge 방향에 맞게 회전하며, 이중·삼중 tick은 tangent 방향으로 일정 간격을 이동한다.
- **Parallel mark:** 대상 변의 midpoint와 unit tangent를 기준으로 local chevron을
  생성하고, 해당 segment의 화면 회전각만큼 함께 회전한다. 화면 수평 기준의 고정 slash나
  축 arrow와 같은 marker를 재사용하지 않는다.
- **Right angle mark:** 꼭짓점에서 나가는 두 ray의 unit vector로 square corner와 두
  변을 계산한다. 두 ray의 방향과 무관하게 화면 축에 맞춘 정사각형을 배치하지 않는다.
- **Angle arc:** 두 ray의 실제 polar angle에서 arc의 start angle·end angle·sweep 방향을
  계산한다. arc 중심은 vertex에서 정한 반지름으로 두며, ray와 indicator가 끊기거나
  반대쪽 각을 표시하지 않도록 확인한다.

계산에 사용한 midpoint·tangent·normal·unit ray·polar angle은 geometry evidence에
기록한다. 좌표 계산 없이 `/`·`V`·정사각형·호를 눈대중으로 회전한 경우 FAIL이다.

indicator가 문제 조건에 없는 관계를 암시하거나 선보다 튀면 FAIL이다.

### 6-9. 보조선 의미 분리

geometry 보조선은 그래프의 guide 또는 asymptote와 같은 의미로 취급하지 않는다. 최소한
다음 의미를 별도로 기록한다.

| 의미 | 기본 line type | 시작값·비고 |
|---|---|---|
| construction line | short dash 또는 light solid | `4 3`, 작도 흔적은 더 연하게 |
| altitude / perpendicular helper | light solid | 기본은 실선, 원문·projection 필요 시에만 dash |
| median / bisector helper | light solid | 기본은 실선, 원문·작도 흔적 필요 시에만 dash |
| extension line | long dash | `5 3`, 원래 변과 구분 |
| auxiliary circle | solid 또는 light dash | `SECONDARY_SHAPE` 이하 |
| incircle / circumcircle | solid | `AUXILIARY_LINE` 또는 secondary 계층 |
| hidden line | geometry hidden dash | 3D 규칙을 따름 |

도형의 보조선은 왜 필요한지와 어떤 의미인지 evidence에 기록한다. geometry dash는 graph
점근선 dash와 재사용하지 않으며, line type만으로 수학적 관계를 새로 암시하지 않는다.

### 6-10. 치수선·길이 표시

- 문제의 출제 의도상 필요한 경우에만 dimension line을 사용한다. 단순 길이값은 변 가까이
  직접 표기할 수 있지만, 선 위에 겹쳐 읽기 어려우면 별도 치수선을 사용한다.
- 변 위 직접 표기는 label과 변 사이 최소 clearance를 확보하고, 도형의 선과 길이값이
  하나의 선으로 오인되지 않게 한다.
- 별도 치수선은 도형과 평행하게 두며, 도형과 치수선 사이 간격·길이값과 치수선 사이
  간격을 기록한다. 양끝은 narrow arrow 또는 perpendicular bar 중 하나의 스타일로
  일관되게 표시한다.
- 치수선이 실제 도형의 변·보조선·indicator를 가리거나, 문제에 없는 측정 관계를 암시하면
  FAIL이다.

### 6-11. 음영·빗금·영역 강조

- opacity만으로 영역 의미를 전달하지 않는다. grayscale에서도 영역 구분이 유지되어야 한다.
- 허용 방식은 연한 gray fill, hatching, 필요 시 cross-hatching이다.
- 기본 hatching 시작값은 각도 `45°`, 간격 `4.5px`, 조정 범위는 `4~5px`다. hatch stroke는
  `INDICATOR_STROKE` 이하를 우선한다.
- 서로 다른 영역은 hatch 방향 또는 밀도 중 하나만 바꾸어 구분한다. 필요하지 않은
  cross-hatching과 장식용 음영은 금지한다.
- z-order는 6-5-1의 `GEOMETRY_Z_ORDER`를 따른다. 즉 fill/hatch는 border에 해당하는
  secondary/main shape보다 아래에 두고, 핵심 도형 선과 라벨을 덮지 않는다.
- 색을 제거한 뒤에도 영역 의미가 유지되지 않거나 음영이 핵심 변을 가리면
  `GEOMETRY_PRINT_PUBLICATION_FAIL`이다.

### 6-12. 원·원호 전용 규칙

- 원, 부채꼴, 현, 접선, 할선, 반지름, 지름을 서로 다른 구조로 기록한다.
- 원 외곽은 `MAIN_SHAPE` 또는 `SECONDARY_SHAPE`, 보조원은 `AUXILIARY_LINE` 계층을
  사용한다.
- 중심각과 원주각은 angle vertex와 arc 범위를 구분해 표시한다. 원호는 일반 함수 곡선과
  같은 graph curve로 표현하지 않는다.
- 접선은 필요할 때 접점과 중심-접점 반지름의 직각관계를 함께 표시한다.
- 중심 `O` 라벨은 `VERTEX_LABEL` 정책을 따르며, radius·diameter·chord·arc label은
  geometry 의미에 맞게 배치한다.

### 6-13. 축척 정직성(scale honesty)

- 도식적 단순화는 허용하지만, 실제 길이·각도·평행·직각·합동 관계를 시각적으로 오인하게
  만드는 왜곡은 금지한다.
- 길이·각도의 시각적 비율이 수학적 근거가 아니거나 정확한 축척이 보장되지 않는 경우에는
  `solutionImageCaption` 또는 metadata에 “그림은 정확하지 않을 수 있음” 또는 “도형은
  이해를 돕기 위한 모식도임”을 기록한다.
- 해당 문구는 왜곡을 정당화하는 면책문이 아니다. 발문 이해에 정확한 비율이 핵심이면
  geometry 좌표를 보존하고, 필요한 경우 `EQUAL_UNIT` 또는 명시된 scale mode를 사용한다.

### 6-14. 입체도형(3D)

- visible edge와 hidden edge를 구조적으로 분리한다. 은선은 `HIDDEN_LINE_STROKE`와
  hidden-line dash를 사용하며, 시작 dash는 `4 4`, 조정 범위는 `4 4` 또는 `5 4`다.
- hidden line은 main보다 같거나 약간 약하게 유지하되 지나치게 연하게 만들어 깊이 정보를
  잃지 않는다.
- 사시도 depth direction의 Pilot 시작값은 `30°`, 조정 범위는 `30~45°`, depth ratio는
  `0.65`, 조정 범위는 `0.6~0.8`이다. 이 값은 도식용 시작값이며 실제 도형 조건을 override하지
  않는다.
- occlusion에 따라 뒤쪽 선을 숨기고, canvas safe area 밖으로 나가는 visible/hidden line은
  동일한 clipping contract로 처리한다.
- 3D label은 앞면·윗면·깊이 방향 선과 겹치지 않게 배치하고, 은선 위에 직접 올리지 않는다.

### 6-15. COORDINATE_GEOMETRY_HYBRID_RULE

좌표평면 위의 도형·도형의 방정식·좌표기하 문항은 graph와 geometry가 동시에 적용되는
hybrid로 기록한다.

- 좌표축·tick·좌표 숫자·axis scale은 graph 규칙을 우선한다.
- 선분·원·점·보조선·도형 label·geometry indicator는 geometry 규칙을 우선한다.
- 학생이 축과 도형을 동시에 읽어야 하므로 `MAIN_SHAPE > COORDINATE_AXIS`를 유지한다.
- hybrid SVG root에는 가능하면 `data-geometry-mode="COORDINATE_GEOMETRY_HYBRID"`와
  graph/geometry style version 및 axis scale mode를 기록한다.
- graph gate와 geometry gate를 각각 판정하고, 어느 한쪽이라도 FAIL 또는 NOT_TESTED이면
  최종 visual PASS로 승격하지 않는다.

### 6-16. AP_GEOMETRY_PRINT_STYLE token

도형 SVG의 canonical style token은 다음 객체로 기록한다. 아래는 geometry main preset의
Pilot 시작값이며 `AP_GEOMETRY_PRINT_V1_0_DRAFT`는 **FINAL HARD FREEZE가 아니다**.

```text
AP_GEOMETRY_PRINT_STYLE = {
  version: "AP_GEOMETRY_PRINT_V1_0_DRAFT",
  preset: "GEOMETRY_STANDARD",
  margin: 32,
  mainShapeStrokeWidth: 2.05,
  secondaryShapeStrokeWidth: 1.6,
  auxiliaryLineStrokeWidth: 1.0,
  indicatorStrokeWidth: 0.8,
  coordinateAxisStrokeWidth: 1.2,
  hiddenLineStrokeWidth: 1.8,
  hiddenLineDash: "4 4",
  rightAngleSize: 7.5,
  angleArcRadius: 14,
  congruentTickLength: 7,
  congruentTickGap: 2.75,
  parallelMarkSize: 8,
  vertexLabelSize: 13.25,
  edgeLabelSize: 12,
  angleLabelSize: 11.75,
  pointRadius: 2.0,
  hatchSpacing: 4.5,
  hatchAngle: 45
}
```

metadata 적용 범위는 asset 상태에 따라 구분한다.

- 기존 untouched legacy SVG는 `data-geometry-*` metadata가 없어도 보존할 수 있다.
- 신규·수정·migration geometry SVG에는 `data-geometry-style-version`, `data-geometry-preset`,
  `data-geometry-fact-hash`, `data-visual-provenance`를 REQUIRED로 둔다.
- 신규·수정·migration hybrid SVG에는 `data-geometry-mode="COORDINATE_GEOMETRY_HYBRID"`를
  추가로 REQUIRED로 둔다.
- 위 REQUIRED metadata가 없으면 `GEOMETRY_STYLE_LINT_FAIL`이며, legacy 예외를 적용한
  경우에만 `LEGACY_METADATA_EXEMPTION` 사유를 evidence에 남긴다.

각 token의 허용 범위와 의미는 이 장의 geometry 규칙을 따른다. `MINI_GRAPH`를 geometry에
적용할 때는 향후 `MINI_GEOMETRY` preset을 별도로 추가할 수 있으며, 현재 단계에서
geometry main token을 단순 축소해 MINI에 재사용하지 않는다.

### 6-17. GEOMETRY_STYLE_LINT contract

`GEOMETRY_STYLE_LINT`는 geometry SVG style contract의 독립 결과다. 다음 항목을 최소
검사한다.

- `viewBox`, `preserveAspectRatio`, safe margin, geometry style version
- 신규·수정·migration이면 required geometry metadata와, hybrid이면 required geometry mode
- geometry stroke hierarchy와 indicator size/width
- label size hierarchy, point marker overuse, geometry z-order
- hatch spacing/angle, hidden line, right-angle mark, congruent tick, parallel mark
- hybrid이면 graph/geometry mode metadata와 우선순위
- 학생에게 보이는 점 좌표 라벨에 계산 근삿값 소수가 없는지 확인한다. 정확한 값 또는
  점 이름만 표시하는 fallback을 사용하며, 원문 소수 예외는 `SOURCE_DECIMAL_LABEL`로 기록한다.

결과는 아래 상태 중 하나로 기록한다.

```text
GEOMETRY_STYLE_LINT
- status: PASS | FAIL | NOT_TESTED
- GEOMETRY_STYLE_LINT_FAILURE_COUNT: <integer>
- failures: <empty list or named checks>
```

`GEOMETRY_STYLE_LINT_FAILURE_COUNT == 0`이고 `status: PASS`일 때만
`GEOMETRY_STYLE_LINT_PASS`를 선언한다. validator를 실행하지 않았거나 실제 SVG를 확인하지
않은 경우는 `GEOMETRY_STYLE_LINT_NOT_TESTED`이며 PASS로 취급하지 않는다.

### 6-18. GEOMETRY_PRINT_PUBLICATION_GATE

geometry·hybrid·3D SVG가 있는 신규·수정 문항은 다음 항목을 모두 확인한다.

- [ ] 메인 도형이 가장 먼저 읽힌다.
- [ ] 보조선이 메인 도형보다 약하다.
- [ ] indicator가 과하게 튀지 않는다.
- [ ] geometry label collision이 없다.
- [ ] 꼭짓점·변·각 표시가 명확하다.
- [ ] 음영·빗금이 흑백 인쇄에서 식별된다.
- [ ] clipping이 없다.
- [ ] 3D visible/hidden 구분이 명확하다.
- [ ] hybrid에서는 축보다 도형이 우선적으로 읽힌다.
- [ ] 시험지 도형처럼 자연스럽고 불필요한 장식이 없다.
- [ ] 학생용 점·중심·교점·접점 라벨에 계산 근삿값 소수가 없고, 정확한 값 또는 점 이름만 표시된다.

위 항목 전체와 `GEOMETRY_STYLE_LINT_PASS`가 확인될 때만
`GEOMETRY_PRINT_PUBLICATION_PASS`를 기록한다. 최종 geometry visual PASS는 다음
composite 조건을 모두 만족해야 한다.

```text
GEOMETRY_MATH_PASS
AND GEOMETRY_SEMANTIC_PASS
AND GEOMETRY_STYLE_LINT_PASS
AND GEOMETRY_PRINT_PUBLICATION_PASS
AND GEOMETRY_RENDER_PASS
```

7. SVG 및 그래프 출판 규칙
--------------------------------------------------

### 7-0. SVG Root 및 Canvas
- 신규 또는 수정 그래프의 SVG root에는 `viewBox`와 `preserveAspectRatio`를 모두 둔다.
- 기본 `preserveAspectRatio`는 비례 축소를 보장하는 값으로 하고, 인쇄용 canonical SVG에
  `vector-effect="non-scaling-stroke"`를 전역 강제하지 않는다. 기본은 정상적인 비례축소다.
- Pilot canvas preset은 다음을 사용한다.
  - `STANDARD_SQUARE`: `560 × 560`
  - `STANDARD_LANDSCAPE`: `620 × 500`
  - `SOLUTION_WIDE`: `640 × 360`
  - `MINI`: `240 × 200` 또는 `280 × 220`
- 기본 safe margin은 `32px`다. Pilot 조정 범위는 `30~36px`이며, clipping이 없고
  축·라벨·핵심점이 모두 읽히는 값을 선택한다.
- `STANDARD_SQUARE`, `STANDARD_LANDSCAPE`, `SOLUTION_WIDE`, `MINI` preset의 최종 physical
  mm-width는 지금 FINAL LOCK하지 않는다. 실제 인쇄 Pilot에서 clipping·가독성·시험지 폭을
  함께 확인한 뒤 결정한다.

### 7-1. SVG 내부 `<br>` 금지
- `<svg>...</svg>` 내부에는 `<br>`를 넣지 않는다.
- 줄 구분은 JS 문자열 `\n` 또는 SVG 내부 `<tspan>`으로 처리한다.

### 7-2. SVG 내부 LaTeX 금지
- `<text>` 안에 `$...$`, `\frac`, `\sqrt`, `\text` 등 LaTeX를 넣지 않는다.
- 수식 라벨이 필요하면 평문으로만 쓴다.
- LaTeX가 꼭 필요하면 SVG 밖 HTML에 둔다.

### 7-2-1. Exact-value label 및 SVG 전용 stacked fraction

SVG 내부 LaTeX 금지는 유지하되, tick·point label·간단한 function label에는 아래와 같은
exact-value 평문 표현을 허용한다.

```text
1/2   −3/2   3/4   √2   −√3   π   e
```

- slash 양옆에는 공백을 넣지 않는다. `1 / 2`는 금지하고 `1/2`만 허용한다.
- exact value를 임의로 decimal로 바꾸지 않는다. 예를 들어 `1/2 → 0.5`, `√2 → 1.41`
  변환은 금지한다. 단, 원문 자체가 소수값을 사용하거나 그래프 tick 성격상 소수값이
  canonical인 경우는 예외로 기록한다.
- `π`는 math glyph, `e`는 mathematical italic constant, `√`는 Unicode radical로
  취급한다. 집합기호 등 복잡한 typography는 핵심 그래프 정보가 아니면 SVG 안에 과도하게
  넣지 않고 solution/caption으로 이동한다.
- `SOLUTION_GRAPH`에서 핵심 label에 세로 분수가 꼭 필요할 때만 SVG 전용
  `svg-fraction` group을 허용한다. LaTeX macro는 사용하지 않는다.

```svg
<g class="svg-fraction">
  <text class="numerator">1</text>
  <line class="fraction-bar" />
  <text class="denominator">2</text>
</g>
```

- 단순 tick label은 solidus를 우선한다.
- complex stacked fraction은 필요한 핵심 label에만 사용한다.
- nested fraction은 SVG 내부에서 금지한다. 복잡한 수식은 SVG 밖 solution/caption으로
  이동한다.

### 7-3. Typography
- 일반 설명 text는 다음 fallback stack을 사용한다.
  `"Noto Sans KR", "Pretendard", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`
- 수학 기호는 다음 fallback stack을 사용한다.
  `"STIX Two Math", "Cambria Math", "Times New Roman", serif`
- 특정 폰트 설치를 전제로 하지 않으며, 폰트 파일을 embed하지 않는다.
- Pilot 시작값은 axis label `13px`, point label `13px`, function label `13.5px`,
  general text `13px`, tick label `11.5px`, annotation `12px`, mini text `11~12px`다.
- Pilot 조정 범위는 function font `13~14px`, tick font `11~12px`다.
- TEXT_FONT와 MATH_FONT의 baseline, x-height, relative scale은 `105%` 같은 수치로 HARD
  LOCK하지 않는다. 실제 Pilot 렌더를 비교해 결정하고 evidence에 기록한다.

### 7-4. Math Italic 및 수학 라벨
- `x, y`, `a, b, c`, `f, g, h`, `A, B, C`, `O`는 mathematical italic을 기본으로 한다.
- 숫자·연산자·괄호는 upright로 표시한다.
- `sin`, `cos`, `tan`, `log`, `ln`, `exp`는 upright 함수명으로 표시한다.
- 음수 표기는 수학 라벨에서 U+2212 `−`를 사용한다. ASCII hyphen-minus U+002D `-`는
  수학적 음수 부호로 사용하지 않는다.

### 7-5. 다중 줄 텍스트
- `<text>` 안 줄바꿈은 `<tspan>`을 사용한다.
- SVG 내부 LaTeX와 `<br>`는 사용하지 않는다.

### 7-6. Label 배치 및 clearance
- 함수식 label은 임의 좌표에 고정하지 않고 후보 위치를 평가한다. 우상·좌상·우하·좌하·
  leader line 순으로 시도하며, 가능하면 curve arc의 `78%`, `22%`, `62%`, `38%` 근방을
  후보로 사용한다.
- 곡선 법선 방향 offset은 `10~14px`를 기본으로 한다.
- collision 대상은 curve, axis, point, asymptote, other label, canvas edge다.
- 권장 최소 clearance는 label↔curve `6px`, label↔point `5px`, label↔axis `5px`,
  label↔label `6px`다.
- collision 회피가 우선이며, 불가피한 경우에만 white stroke + `paint-order: stroke fill`
  halo를 사용한다. halo 기본값은 `2.0px`, Pilot 범위는 `1.8~2.4px`이며 전역 `3px`는
  사용하지 않는다.
- leader line은 필요한 경우에만 `stroke: #666`, `stroke-width: 0.8`, arrow 없음으로
  사용하고, 권장 최대 길이는 `50px`다. 핵심 point나 다른 label을 관통하지 않는다.
- tick label collision은 `TICK_LABEL ↔ TICK_LABEL`, `TICK_LABEL ↔ AXIS_LABEL`,
  `TICK_LABEL ↔ POINT_LABEL`도 검사 대상으로 포함한다.

### 7-7. Stroke hierarchy 및 Z-order
- Pilot stroke token은 axis `1.4`, main curve `2.1`, secondary curve `1.7`,
  asymptote `1.05`, guide `0.95`, tick `1.0`, point outline `1.0`, point radius `3.0`다.
- 항상 `MAIN_CURVE > AXIS > GUIDE`를 만족한다. Pilot 조정 범위는 axis `1.3~1.5`,
  curve `2.0~2.2`, guide `0.9~1.05`다.
- `stroke-linecap: round`, `stroke-linejoin: round`, `shape-rendering: geometricPrecision`
  을 권장한다.
- SVG DOM order는 `Z00 background → Z10 grid → Z20 guide/asymptote → Z30 axis/tick →
  Z40 secondary curve → Z50 main curve → Z60 point/endpoint → Z70 leader line → Z80 text/halo`
  로 통일한다. CSS `z-index`에 의존하지 않는다.

### 7-7-1. MINI_GRAPH 전용 style token

`MINI_GRAPH`는 `STANDARD_*` 그래프의 단순 축소가 아닌 독립 preset이다. 아래는 Pilot
시작값이며 **FINAL HARD FREEZE가 아니다**.

| token | Pilot 시작값 | 조정 범위 |
|---|---:|---:|
| canvas | `240 × 200` | `240 × 200` 또는 `280 × 220` |
| `miniMargin` | `20px` | `18~22px` |
| `miniAxisStroke` | `1.15px` | `1.1~1.2px` |
| `miniMainCurveStroke` | `1.7px` | `1.6~1.8px` |
| `miniSecondaryCurveStroke` | `1.45px` | `1.4~1.5px` |
| `miniGuideStroke` | `0.85px` | `0.8~0.9px` |
| `miniTickStroke` | `0.85px` | `0.8~0.9px` |
| `miniPointRadius` | `2.4px` | `2.2~2.6px` |
| `miniAxisLabelSize` | `11.5px` | `11~12px` |
| `miniTickLabelSize` | `10px` | `9.5~10.5px` |
| `miniFunctionLabelSize` | `11.5px` | `11~12px` |

MINI 전용 token을 적용하며 STANDARD token을 기계적으로 축소해 대체하지 않는다. 최종
선택값, 실제 mm-width, grayscale 및 70% 축소 결과는 Pilot evidence에서 결정한다.

### 7-8. Tick 및 축 숫자
- normal tick은 `4px`, major tick은 `5px`다.
- 기본 방향은 x-axis 아래쪽, y-axis 왼쪽이다. 양쪽으로 긴 cross tick은 기본 금지한다.
- major tick interval은 `1`, `2`, `5 × 10^k` nice-number 체계를 사용하고, 축당 권장
  major tick 수는 `4~7개`다.
- `TICK_LABEL_SIZE`는 `11.5px`다. x축 숫자는 축에서 아래로 `6~8px`, `text-anchor: middle`,
  y축 숫자는 축에서 왼쪽으로 `6~8px`, `text-anchor: end`로 배치한다.
- 눈금 숫자는 `-0 → 0`, `2.0 → 2`, `1.50 → 1.5`처럼 정규화한다. 수학 라벨의 음수는
  U+2212 `−`를 사용한다.

### 7-9. Arrow
- 좌표축 arrow는 공통 marker definition의 filled narrow triangle, 약 `6×6px`를 사용한다.
- 함수 곡선 양끝 arrow는 default OFF다. 원문 또는 수학적 의미상 꼭 필요한 경우만 허용한다.

### 7-10. Axis scale
- 모든 그래프에 `1 unit = 고정 pixel`을 강제하지 않는다.
- `EQUAL_UNIT`과 `UNEQUAL_UNIT_DECLARED` mode를 사용한다.
- 역함수, `y=x` 대칭, 원, 거리, 기하적 위치 관계, 실제 기울기 의미가 핵심이면
  `EQUAL_UNIT`을 우선한다.
- 축척이 다르면 tick 체계로 명확히 드러내며, 학생이 동일 축척으로 오인할 수 있으면 FAIL이다.

### 7-11. 실제 삽입 후 마커 삭제
- 실제 도형/SVG가 들어갔으면 기존 `[도형필요]`, `[해설도형필요]` 마커는 삭제해야 한다.
- 마커가 남아 있으면 실패다.

### 9-1. PNG 자산 저장 경로
- PNG 자산은 반드시 아래 구조를 따른다.

- 파일명은 문항번호 기반 `q{id}.png`를 기본 원칙으로 한다.
- 고2 이상 문항은 반드시 과목명까지 포함된 시험지전체명 기준 폴더를 사용한다.

- `assets/images/25_순천여고_1학기_중간_고2_미적분/q08.png`
- `assets/images/25_순천여고_1학기_중간_고2_확률과통계/q03.png`

### 9-2. PNG 저장 전 정리 규칙
- 불필요한 격자 제거
- 불필요한 축 숫자 제거
- Export 라벨 제거
- 과도한 여백 제거
- 문제와 무관한 보조 객체 제거
- 그래프 본체가 중앙에 오도록 정리

### 9-3. JS 연결 규칙
- 신규 데이터는 `image` 선택 필드를 우선한다.
- image 필드 값은 PNG 자산 경로 문자열로 넣는다.
- content에는 발문만 두고, 이미지는 image 필드로 분리한다.
- 기존 자료 호환이 필요한 경우에만 `content` 내부 `<img>`를 허용한다.
- image와 content 내부 `<img>`를 동시에 유지하는 것은 지양한다.

예:
- `image: "assets/images/25_순천여고_1학기_중간_고2_대수/q20.png"`

### 9-4. PNG와 엔진의 역할 분리
- PNG의 실제 제작 품질은 자산 단계에서 확보한다.
- 엔진은 PNG 파일 자체를 재압축/재저장하지 않는다.
- 엔진은 비율 유지 축소와 발문 바로 아래 배치만 담당한다.

### 9-5. Problem / Solution preset
- 공식 preset은 `PROBLEM_GRAPH`, `SOLUTION_GRAPH`, `COMPARISON_GRAPH`, `MINI_GRAPH`다.
- `PROBLEM_GRAPH`는 정답 힌트를 과도하게 주지 않는다.
- `SOLUTION_GRAPH`는 풀이 재현에 필요한 핵심점·점근선·교점·endpoint·필요 좌표·보조선을
  허용하되, 그래프가 해설 텍스트 자체를 대신하지 않게 한다.

### 9-6. 흑백 인쇄 및 정보 보존
- 기본 palette는 primary `#111`, secondary `#555`, guide `#777`, grid `#ddd`,
  background `#fff`다.
- 색을 제거해도 모든 수학적 정보가 유지되어야 하며,
  `GRAYSCALE_INFORMATION_PARITY == PASS`를 hard gate로 둔다.

### 9-7. Style metadata
- 가능하면 신규/수정 SVG root에 다음 metadata를 기록한다.
  - `data-graph-style-version`
  - `data-graph-preset`
  - `data-axis-scale-mode`
  - `data-fact-hash`
  - `data-visual-provenance`
- Pilot 기본 style version은 `data-graph-style-version="AP_GRAPH_PRINT_V1_1_DRAFT"`다.
- `AP_GRAPH_PRINT_V1`과 `ADOPTED`는 30개 대표 그래프 Pilot과 조정 기록이 끝난 뒤에만 사용한다.

### 9-8. GRAPH_PRINT_PUBLICATION_GATE
그래프가 있는 신규·수정 문항은 다음 항목을 모두 확인한다.

- [ ] 함수식과 곡선 일치
- [ ] branch별 sampling 및 adaptive refinement 충분
- [ ] 불연속 branch 분리
- [ ] main curve가 axis보다 강함
- [ ] guide가 axis보다 약함
- [ ] tick 숫자가 읽힘
- [ ] U+2212 minus
- [ ] math italic
- [ ] label collision 없음
- [ ] clipping 없음
- [ ] z-order 정상
- [ ] arrow 통일
- [ ] 불필요 curve arrow 없음
- [ ] grayscale 정상
- [ ] 80% 축소 정상
- [ ] 70% 축소 정상
- [ ] 문제/해설 preset 적합
- [ ] 시험지 전체 그래프 스타일 통일

위 항목 전체 통과 시에만 `GRAPH_PRINT_PUBLICATION_PASS`를 기록한다. 이 gate는
`GRAPH_MATH_PASS`, `GRAPH_SEMANTIC_PASS`, `GRAPH_STYLE_LINT_PASS`,
`GRAPH_PRINT_PUBLICATION_PASS`, `GRAPH_RENDER_PASS`의 composite 조건으로 최종 검수에 연결한다.

### 9-8-1. GRAPH_STYLE_LINT_PASS contract

`GRAPH_STYLE_LINT_PASS`는 그래프의 수학적 의미가 아니라 SVG style contract의 독립 결과다.
validator를 실행하지 않았거나 실제 SVG를 확인하지 않은 경우에는 PASS가 아니라
`GRAPH_STYLE_LINT_NOT_TESTED`로 기록한다.

검사 대상은 최소 다음과 같다.

- SVG root의 `viewBox`, `preserveAspectRatio`, canvas preset, graph preset, axis scale mode,
  safe margin, style version
- axis·curve·guide/asymptote의 stroke token과 dash pattern
- TEXT_FONT/MATH_FONT fallback, font size, math italic, U+2212 minus
- point radius, arrow marker, z-order, label clearance
- `MINI_GRAPH` 전용 token 적용 여부

결과는 다음 구조로 기록한다.

```text
GRAPH_STYLE_LINT
- status: PASS | FAIL | NOT_TESTED
- STYLE_LINT_FAILURE_COUNT: <integer>
- failures: <empty list or named checks>
```

`STYLE_LINT_FAILURE_COUNT == 0`이고 `status: PASS`일 때만
`GRAPH_STYLE_LINT_PASS`를 선언할 수 있다. 하나라도 실패하면 `GRAPH_STYLE_LINT_FAIL`,
validator 미실행·실제 SVG 미확인 상태는 `GRAPH_STYLE_LINT_NOT_TESTED`이며 어느 경우에도
PASS로 승격하지 않는다.

--------------------------------------------------
9-9. 시각요소 tags 유지 규칙
--------------------------------------------------

최종 산출물이 SVG, PNG, HTML table, content 내부 img 중 무엇이든 시각요소가 있으면 tags를 유지한다.

- 도형/SVG/기하 그림/좌표 그림: tags에 "도형" 포함
- 함수 그래프/좌표평면 그래프/곡선 그래프: tags에 "그래프" 포함
- HTML table/로그표/제곱근표/조건표: tags에 "표" 포함
- 공통자료가 여러 문항에 걸쳐 쓰이면 tags에 "공통자료" 포함 가능

image 필드가 있어도 tags는 생략하지 않는다.
content 내부 SVG/table/img가 있어도 tags는 생략하지 않는다.
tags는 배치 기준이 아니다.
tags만 보고 layoutTag 또는 wide를 변경하지 않는다.
layoutTag 특수값과 wide:true는 마스터 명시 지시가 있을 때만 사용한다.
