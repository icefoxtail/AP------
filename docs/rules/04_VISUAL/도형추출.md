5. 곡선 / 함수 그래프 규칙
--------------------------------------------------

### 5-1. bezier 눈대중 금지
- 함수 그래프를 `M ... C ... Q ...` 식 bezier로 감으로 만들면 실패다.
- 포물선, 유리함수, 지수함수, 로그함수 등은 Python 샘플링으로 생성한다.

### 5-2. polyline 샘플링 의무
- 함수 곡선은 Python에서 좌표를 sampling하여 `polyline points="..."` 또는 이에 준하는
  방식으로 넣는다. 고정된 총점만으로 품질을 판정하지 않는다.

### 5-3. 샘플 수 기준
- branch를 먼저 분리한 뒤 각 연속 branch에 대해 아래 density 기준을 적용한다.
- 일반 연속 branch: `max(200, ceil(plotWidthPx / 1.5))`
- 점근선·급격한 변화가 있는 branch: `max(300, ceil(plotWidthPx / 1.0))`
- 위 값은 branch별 기본값이며, 실제 점 수는 endpoint·교점·급격한 곡률 변화·점근선
  근처·화면상 chord가 긴 구간을 추가 세분화한 뒤의 값으로 기록한다.

### 5-4. Adaptive refinement 및 불연속 처리
- 가능하면 screen-space error 기반 adaptive refinement를 사용한다.
- 권장 목표는 `SCREEN_SPACE_CHORD_ERROR <= 0.35px`다.
- endpoint, 교점, 점근선 부근, 급격한 곡률 변화 및 화면상 chord가 긴 구간은 기본
  density만 믿지 말고 추가 샘플을 삽입한다.
- 불연속 branch는 절대로 연결하지 않는다. 정의역 경계·점근선·NaN·Inf·화면 밖 발산
  구간은 branch를 나누거나 제외하고, 제외 근거를 기록한다.
- 샘플 수, branch 수, refinement 적용 여부와 screen-space error 결과를 검수 기록에 남긴다.

### 5-4-1. 점근선 발산 clipping 및 branch separation 구현 계약

점근선·정의역 단절·무한 발산이 있는 그래프는 수치값 제거만으로 clipping을 완료한 것으로
보지 않는다. 최종 rendering path는 아래 deterministic contract를 따른다.

- **Branch separation:** 연속 branch마다 별도 `<polyline>` 또는 `<path>`를 만들거나,
  하나의 `<path>` 안에서 branch가 바뀌는 지점마다 새 `M` 명령으로 재시작한다.
- 점근선 양쪽 좌표를 하나의 연속 `L` 또는 단일 `polyline`으로 연결하지 않는다.
  `BRANCH_SEPARATION_PASS`는 이 연결이 없을 때만 PASS다.
- **Plot safe boundary:** 실제 canvas safe area에서 다음 네 경계를 계산한다.
  `PLOT_SAFE_TOP`, `PLOT_SAFE_BOTTOM`, `PLOT_SAFE_LEFT`, `PLOT_SAFE_RIGHT`.
  이 값은 임의의 y 절댓값이 아니라 plot 영역과 safe margin으로부터 도출한다.
- branch가 safe area 밖으로 나가면 현재점과 다음점의 선분과 해당 plot boundary의
  교점을 선형 보간으로 계산하고, **첫 boundary intersection에서 해당 branch path를
  종료**한다. 단순 `abs(y) > 임의 숫자` clipping은 허용하지 않는다.
- 다음 조건 중 하나가 성립하면 해당 방향의 refinement를 종료한다:
  `boundary intersection 확정`, `non-finite 도달`, `domain exclusion 도달`,
  `configured recursion/depth safety cap 도달`.
- safety cap이 먼저 작동하면 cap 값·branch 방향·마지막 유한점·미확정 error를 WARN 및
  evidence에 기록한다. cap 작동만으로 출판 PASS를 선언하지 않는다.

### 5-5. 특이점 주변 처리
- 점근선, 정의역 끊김, 루트 함수 경계 등은 샘플링 시 적절히 제외한다
- 정의역 밖 값, 발산 구간, NaN/Inf 값은 제거한다
- 그래프가 축을 잘못 관통하지 않도록 범위 클리핑을 한다

- 라벨 위치도 가능하면 Python 좌표 또는 계산 근거를 둔다.

--------------------------------------------------
7. SVG 및 그래프 출판 규칙
--------------------------------------------------

### 7-0. SVG Root 및 Canvas
- 신규 또는 수정 그래프의 SVG root에는 `viewBox`와 `preserveAspectRatio`를 모두 둔다.
- 기본 `preserveAspectRatio`는 비례 축소를 보장하는 값으로 하고, 인쇄용 canonical SVG에
  `vector-effect="non-scaling-stroke"`를 전역 강제하지 않는다. 기본은 정상적인 비례축소다.
- Pilot canvas preset은 다음을 사용한다.
  - `STANDARD_SQUARE`: `560 × 560`
  - `STANDARD_LANDSCAPE`: `620 × 500`
  - `SOLUTION_WIDE`: `640 × 360`
  - `MINI`: `240 × 200` 또는 `280 × 220`
- 기본 safe margin은 `32px`다. Pilot 조정 범위는 `30~36px`이며, clipping이 없고
  축·라벨·핵심점이 모두 읽히는 값을 선택한다.
- STANDARD, LANDSCAPE, WIDE, MINI preset의 최종 physical mm-width는 지금 FINAL LOCK하지
  않는다. 실제 인쇄 Pilot에서 clipping·가독성·시험지 폭을 함께 확인한 뒤 결정한다.

### 7-1. SVG 내부 `<br>` 금지
- `<svg>...</svg>` 내부에는 `<br>`를 넣지 않는다.
- 줄 구분은 JS 문자열 `\n` 또는 SVG 내부 `<tspan>`으로 처리한다.

### 7-2. SVG 내부 LaTeX 금지
- `<text>` 안에 `$...$`, `\frac`, `\sqrt`, `\text` 등 LaTeX를 넣지 않는다.
- 수식 라벨이 필요하면 평문으로만 쓴다.
- LaTeX가 꼭 필요하면 SVG 밖 HTML에 둔다.

### 7-2-1. Exact-value label 및 SVG 전용 stacked fraction

SVG 내부 LaTeX 금지는 유지하되, tick·point label·간단한 function label에는 아래와 같은
exact-value 평문 표현을 허용한다.

```text
1/2   −3/2   3/4   √2   −√3   π   e
```

- slash 양옆에는 공백을 넣지 않는다. `1 / 2`는 금지하고 `1/2`만 허용한다.
- exact value를 임의로 decimal로 바꾸지 않는다. 예를 들어 `1/2 → 0.5`, `√2 → 1.41`
  변환은 금지한다. 단, 원문 자체가 소수값을 사용하거나 그래프 tick 성격상 소수값이
  canonical인 경우는 예외로 기록한다.
- `π`는 math glyph, `e`는 mathematical italic constant, `√`는 Unicode radical로
  취급한다. 집합기호 등 복잡한 typography는 핵심 그래프 정보가 아니면 SVG 안에 과도하게
  넣지 않고 solution/caption으로 이동한다.
- `SOLUTION_GRAPH`에서 핵심 label에 세로 분수가 꼭 필요할 때만 SVG 전용
  `svg-fraction` group을 허용한다. LaTeX macro는 사용하지 않는다.

```svg
<g class="svg-fraction">
  <text class="numerator">1</text>
  <line class="fraction-bar" />
  <text class="denominator">2</text>
</g>
```

- 단순 tick label은 solidus를 우선한다.
- complex stacked fraction은 필요한 핵심 label에만 사용한다.
- nested fraction은 SVG 내부에서 금지한다. 복잡한 수식은 SVG 밖 solution/caption으로
  이동한다.

### 7-3. Typography
- 일반 설명 text는 다음 fallback stack을 사용한다.
  `"Noto Sans KR", "Pretendard", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`
- 수학 기호는 다음 fallback stack을 사용한다.
  `"STIX Two Math", "Cambria Math", "Times New Roman", serif`
- 특정 폰트 설치를 전제로 하지 않으며, 폰트 파일을 embed하지 않는다.
- Pilot 시작값은 axis label `13px`, point label `13px`, function label `13.5px`,
  general text `13px`, tick label `11.5px`, annotation `12px`, mini text `11~12px`다.
- Pilot 조정 범위는 function font `13~14px`, tick font `11~12px`다.
- TEXT_FONT와 MATH_FONT의 baseline, x-height, relative scale은 `105%` 같은 수치로 HARD
  LOCK하지 않는다. 실제 Pilot 렌더를 비교해 결정하고 evidence에 기록한다.

### 7-4. Math Italic 및 수학 라벨
- `x, y`, `a, b, c`, `f, g, h`, `A, B, C`, `O`는 mathematical italic을 기본으로 한다.
- 숫자·연산자·괄호는 upright로 표시한다.
- `sin`, `cos`, `tan`, `log`, `ln`, `exp`는 upright 함수명으로 표시한다.
- 음수 표기는 수학 라벨에서 U+2212 `−`를 사용한다. ASCII hyphen-minus U+002D `-`는
  수학적 음수 부호로 사용하지 않는다.

### 7-5. 다중 줄 텍스트
- `<text>` 안 줄바꿈은 `<tspan>`을 사용한다.
- SVG 내부 LaTeX와 `<br>`는 사용하지 않는다.

### 7-6. Label 배치 및 clearance
- 함수식 label은 임의 좌표에 고정하지 않고 후보 위치를 평가한다. 우상·좌상·우하·좌하·
  leader line 순으로 시도하며, 가능하면 curve arc의 `78%`, `22%`, `62%`, `38%` 근방을
  후보로 사용한다.
- 곡선 법선 방향 offset은 `10~14px`를 기본으로 한다.
- collision 대상은 curve, axis, point, asymptote, other label, canvas edge다.
- 권장 최소 clearance는 label↔curve `6px`, label↔point `5px`, label↔axis `5px`,
  label↔label `6px`다.
- collision 회피가 우선이며, 불가피한 경우에만 white stroke + `paint-order: stroke fill`
  halo를 사용한다. halo 기본값은 `2.0px`, Pilot 범위는 `1.8~2.4px`이며 전역 `3px`는
  사용하지 않는다.
- leader line은 필요한 경우에만 `stroke: #666`, `stroke-width: 0.8`, arrow 없음으로
  사용하고, 권장 최대 길이는 `50px`다. 핵심 point나 다른 label을 관통하지 않는다.
- tick label collision은 `TICK_LABEL ↔ TICK_LABEL`, `TICK_LABEL ↔ AXIS_LABEL`,
  `TICK_LABEL ↔ POINT_LABEL`도 검사 대상으로 포함한다.

### 7-7. Stroke hierarchy 및 Z-order
- Pilot stroke token은 axis `1.4`, main curve `2.1`, secondary curve `1.7`,
  asymptote `1.05`, guide `0.95`, tick `1.0`, point outline `1.0`, point radius `3.0`다.
- 항상 `MAIN_CURVE > AXIS > GUIDE`를 만족한다. Pilot 조정 범위는 axis `1.3~1.5`,
  curve `2.0~2.2`, guide `0.9~1.05`다.
- `stroke-linecap: round`, `stroke-linejoin: round`, `shape-rendering: geometricPrecision`
  을 권장한다.
- SVG DOM order는 `Z00 background → Z10 grid → Z20 guide/asymptote → Z30 axis/tick →
  Z40 secondary curve → Z50 main curve → Z60 point/endpoint → Z70 leader line → Z80 text/halo`
  로 통일한다. CSS `z-index`에 의존하지 않는다.

### 7-7-1. MINI_GRAPH 전용 style token

`MINI_GRAPH`는 `STANDARD_*` 그래프의 단순 축소가 아닌 독립 preset이다. 아래는 Pilot
시작값이며 **FINAL HARD FREEZE가 아니다**.

| token | Pilot 시작값 | 조정 범위 |
|---|---:|---:|
| canvas | `240 × 200` | `240 × 200` 또는 `280 × 220` |
| `miniMargin` | `20px` | `18~22px` |
| `miniAxisStroke` | `1.15px` | `1.1~1.2px` |
| `miniMainCurveStroke` | `1.7px` | `1.6~1.8px` |
| `miniSecondaryCurveStroke` | `1.45px` | `1.4~1.5px` |
| `miniGuideStroke` | `0.85px` | `0.8~0.9px` |
| `miniTickStroke` | `0.85px` | `0.8~0.9px` |
| `miniPointRadius` | `2.4px` | `2.2~2.6px` |
| `miniAxisLabelSize` | `11.5px` | `11~12px` |
| `miniTickLabelSize` | `10px` | `9.5~10.5px` |
| `miniFunctionLabelSize` | `11.5px` | `11~12px` |

MINI 전용 token을 적용하며 STANDARD token을 기계적으로 축소해 대체하지 않는다. 최종
선택값, 실제 mm-width, grayscale 및 70% 축소 결과는 Pilot evidence에서 결정한다.

### 7-8. Tick 및 축 숫자
- normal tick은 `4px`, major tick은 `5px`다.
- 기본 방향은 x-axis 아래쪽, y-axis 왼쪽이다. 양쪽으로 긴 cross tick은 기본 금지한다.
- major tick interval은 `1`, `2`, `5 × 10^k` nice-number 체계를 사용하고, 축당 권장
  major tick 수는 `4~7개`다.
- `TICK_LABEL_SIZE`는 `11.5px`다. x축 숫자는 축에서 아래로 `6~8px`, `text-anchor: middle`,
  y축 숫자는 축에서 왼쪽으로 `6~8px`, `text-anchor: end`로 배치한다.
- 눈금 숫자는 `-0 → 0`, `2.0 → 2`, `1.50 → 1.5`처럼 정규화한다. 수학 라벨의 음수는
  U+2212 `−`를 사용한다.

### 7-9. Arrow
- 좌표축 arrow는 공통 marker definition의 filled narrow triangle, 약 `6×6px`를 사용한다.
- 함수 곡선 양끝 arrow는 default OFF다. 원문 또는 수학적 의미상 꼭 필요한 경우만 허용한다.

### 7-10. Axis scale
- 모든 그래프에 `1 unit = 고정 pixel`을 강제하지 않는다.
- `EQUAL_UNIT`과 `UNEQUAL_UNIT_DECLARED` mode를 사용한다.
- 역함수, `y=x` 대칭, 원, 거리, 기하적 위치 관계, 실제 기울기 의미가 핵심이면
  `EQUAL_UNIT`을 우선한다.
- 축척이 다르면 tick 체계로 명확히 드러내며, 학생이 동일 축척으로 오인할 수 있으면 FAIL이다.

### 7-11. 실제 삽입 후 마커 삭제
- 실제 도형/SVG가 들어갔으면 기존 `[도형필요]`, `[해설도형필요]` 마커는 삭제해야 한다.
- 마커가 남아 있으면 실패다.

- 신규 데이터는 `image` 선택 필드를 우선한다.

예:

### 9-4. PNG와 엔진의 역할 분리
- PNG의 실제 제작 품질은 자산 단계에서 확보한다.
- 엔진은 PNG 파일 자체를 재압축/재저장하지 않는다.
- 엔진은 비율 유지 축소와 발문 바로 아래 배치만 담당한다.

### 9-5. Problem / Solution preset
- 공식 preset은 `PROBLEM_GRAPH`, `SOLUTION_GRAPH`, `COMPARISON_GRAPH`, `MINI_GRAPH`다.
- `PROBLEM_GRAPH`는 정답 힌트를 과도하게 주지 않는다.
- `SOLUTION_GRAPH`는 풀이 재현에 필요한 핵심점·점근선·교점·endpoint·필요 좌표·보조선을
  허용하되, 그래프가 해설 텍스트 자체를 대신하지 않게 한다.

### 9-6. 흑백 인쇄 및 정보 보존
- 기본 palette는 primary `#111`, secondary `#555`, guide `#777`, grid `#ddd`,
  background `#fff`다.
- 색을 제거해도 모든 수학적 정보가 유지되어야 하며,
  `GRAYSCALE_INFORMATION_PARITY == PASS`를 hard gate로 둔다.

### 9-7. Style metadata
- 가능하면 신규/수정 SVG root에 다음 metadata를 기록한다.
  - `data-graph-style-version`
  - `data-graph-preset`
  - `data-axis-scale-mode`
  - `data-fact-hash`
  - `data-visual-provenance`
- Pilot 기본 style version은 `data-graph-style-version="AP_GRAPH_PRINT_V1_1_DRAFT"`다.
- `AP_GRAPH_PRINT_V1`과 `ADOPTED`는 30개 대표 그래프 Pilot과 조정 기록이 끝난 뒤에만 사용한다.

### 9-8. GRAPH_PRINT_PUBLICATION_GATE
그래프가 있는 신규·수정 문항은 다음 항목을 모두 확인한다.

- [ ] 함수식과 곡선 일치
- [ ] branch별 sampling 및 adaptive refinement 충분
- [ ] 불연속 branch 분리
- [ ] main curve가 axis보다 강함
- [ ] guide가 axis보다 약함
- [ ] tick 숫자가 읽힘
- [ ] U+2212 minus
- [ ] math italic
- [ ] label collision 없음
- [ ] clipping 없음
- [ ] z-order 정상
- [ ] arrow 통일
- [ ] 불필요 curve arrow 없음
- [ ] grayscale 정상
- [ ] 80% 축소 정상
- [ ] 70% 축소 정상
- [ ] 문제/해설 preset 적합
- [ ] 시험지 전체 그래프 스타일 통일

위 항목 전체 통과 시에만 `GRAPH_PRINT_PUBLICATION_PASS`를 기록한다. 이 gate는
`GRAPH_MATH_PASS`, `GRAPH_SEMANTIC_PASS`, `GRAPH_STYLE_LINT_PASS`,
`GRAPH_PRINT_PUBLICATION_PASS`, `GRAPH_RENDER_PASS`의 composite 조건으로 최종 검수에 연결한다.

### 9-8-1. GRAPH_STYLE_LINT_PASS contract

`GRAPH_STYLE_LINT_PASS`는 그래프의 수학적 의미가 아니라 SVG style contract의 독립 결과다.
validator를 실행하지 않았거나 실제 SVG를 확인하지 않은 경우에는 PASS가 아니라
`GRAPH_STYLE_LINT_NOT_TESTED`로 기록한다.

검사 대상은 최소 다음과 같다.

- SVG root의 `viewBox`, `preserveAspectRatio`, canvas preset, graph preset, axis scale mode,
  safe margin, style version
- axis·curve·guide/asymptote의 stroke token과 dash pattern
- TEXT_FONT/MATH_FONT fallback, font size, math italic, U+2212 minus
- point radius, arrow marker, z-order, label clearance
- `MINI_GRAPH` 전용 token 적용 여부

결과는 다음 구조로 기록한다.

```text
GRAPH_STYLE_LINT
- status: PASS | FAIL | NOT_TESTED
- STYLE_LINT_FAILURE_COUNT: <integer>
- failures: <empty list or named checks>
```

`STYLE_LINT_FAILURE_COUNT == 0`이고 `status: PASS`일 때만
`GRAPH_STYLE_LINT_PASS`를 선언할 수 있다. 하나라도 실패하면 `GRAPH_STYLE_LINT_FAIL`,
validator 미실행·실제 SVG 미확인 상태는 `GRAPH_STYLE_LINT_NOT_TESTED`이며 어느 경우에도
PASS로 승격하지 않는다.

9-9. 시각요소 tags 유지 규칙
--------------------------------------------------

최종 산출물이 SVG, PNG, HTML table, content 내부 img 중 무엇이든 시각요소가 있으면 tags를 유지한다.

- 도형/SVG/기하 그림/좌표 그림: tags에 "도형" 포함
- 함수 그래프/좌표평면 그래프/곡선 그래프: tags에 "그래프" 포함
- HTML table/로그표/제곱근표/조건표: tags에 "표" 포함
- 공통자료가 여러 문항에 걸쳐 쓰이면 tags에 "공통자료" 포함 가능

image 필드가 있어도 tags는 생략하지 않는다.
content 내부 SVG/table/img가 있어도 tags는 생략하지 않는다.
tags는 배치 기준이 아니다.
tags만 보고 layoutTag 또는 wide를 변경하지 않는다.
layoutTag 특수값과 wide:true는 마스터 명시 지시가 있을 때만 사용한다.
