# 0. 문서 목적과 지위

본 문서는 특정 학년의 `기하와 벡터` 또는 고등학교 `기하` 과목에만 적용되는 규정이 아니다.

본 문서의 목적은 **중학교 기본도형부터 고등학교 도형의 방정식, 이차곡선, 평면벡터, 공간도형, 공간좌표까지 이어지는 전체 기하 문항**에 대해 다음을 하나의 일관된 운영 기준으로 정하는 것이다.

1. 어떤 문항에 시각자료가 필요한가.
2. 쉬운 문항에서도 시각자료가 교육적으로 필요한 경우를 어떻게 판정하는가.
3. 문제용 그림과 해설용 그림의 역할을 어떻게 분리하는가.
4. 해설의 핵심 수학 사실을 어떤 구조로 시각화하는가.
5. 2차원·3차원 도형을 어떤 절차로 정확하게 생성하는가.
6. 제작자 자기검수와 독립검수를 어떻게 분리하는가.
7. 실제 SVG/PNG의 geometry를 어떻게 역산하여 수학적 정합성을 확인하는가.
8. 공간도형처럼 표현 난도가 높은 영역에서 자동 생성의 한계를 어떻게 fail-closed로 관리하는가.
9. 실제 브라우저 렌더까지 포함해 학생이 읽을 수 있는 최종 결과를 어떻게 봉인하는가.

본 문서는 Common Protocol을 대체하지 않는다.

## 0.1 실행 권위 잠금 — 본 문서는 UNIT_OVERLAY가 아니다

상위 Common Protocol의 실행 권위는 다음 구조를 유지한다.

```text
COMMON_PROTOCOL_v1.2.10
+
UNIT_OVERLAY
=
EFFECTIVE_RULESET
```

본 문서는 **중·고등 기하 전체에서 재사용하는 `GEOMETRY_DOMAIN_POLICY`**이며,
프로젝트별 `UNIT_OVERLAY`를 대체하거나 단독으로 `EFFECTIVE_RULESET`을 만들지 않는다.

실제 기하 프로젝트가 본 정책을 적용하려면 해당 프로젝트의 `UNIT_OVERLAY` 또는
`PROJECT_CONFIG`가 최소 다음을 raw-byte SHA와 함께 고정해야 한다.

```text
geometryPolicyRef:
  path: docs/rules/04_VISUAL/기하_시각자료_해설_독립검수_통합운영규정_v1.1_QUALIFICATION_READY.md
  version: v1.1
  sha256: <RAW_FILE_SHA256>
```

그리고 해당 작업의 batch/run evidence `appliedRuleRefs`에도 같은 path/version/SHA를 기록한다.

```text
POLICY_FILE_EXISTS == true
POLICY_FILE_RAW_SHA == PINNED_POLICY_SHA
APPLIED_RULE_REF_PARITY == PASS
```

중 하나라도 성립하지 않으면 본 정책은 그 프로젝트의 활성 실행 규칙으로 간주하지 않는다.

본 정책의 path/version/SHA가 `UNIT_OVERLAY` 또는 `PROJECT_CONFIG`에 결박되면,
Common Protocol의 기존 `UNIT_OVERLAY_SHA` 또는 `PROJECT_CONFIG_SHA`를 통해
`EFFECTIVE_RULESET_SHA`에 간접 결박된다. 따라서 별도의 Common Protocol hash 공식을
새로 만들지 않는다.

본 정책은 다음만 정한다.

- 기하 문항의 visual necessity 기본값
- 쉬운 기하의 concept-anchor 정책
- 이차곡선·벡터·공간도형의 pedagogy/semantic profile
- geometry visual의 expected/observed fact 요구
- 2D/3D 시각자료의 독립검수·표현 위험도 기준

본 정책이 정하지 않는 것은 다음과 같다.

- 프로젝트별 `targetStandardUnitKeys`
- curriculum boundary
- approved modification fields
- required render mode/profile
- final seal token
- 실제 promotion/reopen 권한

위 항목은 반드시 프로젝트별 `UNIT_OVERLAY`가 정한다.

본 정책은 상위 문서의 독립검수·same-SHA·coverage·REAL RENDER·release/seal HARD gate를
약화할 수 없으며, 단원별 규정은 본 정책보다 더 강한 기준만 추가할 수 있다.

## 0.2 기존 규칙과 역할 분리

```text
도형추출.md v3.0
→ 제작 좌표·Python·stroke·typography·sampling·3D projection·publication canonical source

본 GEOMETRY_DOMAIN_POLICY
→ visual necessity·교육 역할·conic/vector/space semantic policy

도형의방정식_해설_SVG_독립검수_운영규정
→ 도형의 방정식 단원-specific 강화 규정

프로젝트 UNIT_OVERLAY
→ 실제 scope·교육과정·허용 수정·render·seal
```

충돌 시:

1. 상위 Common/실행계약 HARD gate
2. 최신 canonical 룰북·마스터
3. `도형추출.md`의 제작/출판 수치
4. 본 정책의 geometry-wide necessity/semantic 규칙
5. 단원별 규정의 추가 강화 조항
6. 프로젝트 `UNIT_OVERLAY`의 scope/config

순으로 해석하되, 하위 문서는 상위 HARD gate를 약화할 수 없다.

## 0.3 기존 sealed 프로젝트 비회귀

본 파일을 `04_VISUAL`에 등록하고 source-pack MANIFEST에 포함했다는 사실만으로
기존 sealed 시험지·프로젝트를 자동 `STALE` 또는 `REOPEN` 처리하지 않는다.

```text
REGISTRATION_ONLY
→ NO_EXISTING_PROJECT_STALE
```

다음 프로젝트부터 또는 사용자가 명시적으로 reopen한 프로젝트만 본 정책을 opt-in한다.

이미 본 정책 path/version/SHA를 참조한 active 프로젝트에서는 다음 변화가 발생하면
기존 visual evidence를 stale 처리한다.

- policy raw bytes 변경
- policy version 변경
- pinned SHA 변경
- geometry fact schema/projection/generator/verifier 변경

이는 기존 공통 파이프라인의 `rule change → evidence stale` 규칙을 그대로 사용한다.

## 0.4 v1.1 실제 기출 Calibration 근거

v1.1은 추상적 설계만으로 강화하지 않았다. 다음 실제 시험지들을 직접 관찰하여
**문제에 원본 그림이 있는 경우와 없는 경우, 쉬운 기본형과 복합형, 평면기하와 공간기하가
실제로 어떻게 출제되는지**를 기준으로 Visual Default를 보강했다.

```text
2026_매산고2_기하_1중간
2026_제일고2_기하_1중간
강남여고2_기하와벡터_이과_2중간_2015
매산고2_기하와벡터_이과_2중간_2016
2022_금당고2_기하_2중간
2023_매산고2_기하_2중간
2023_매산고2_기하_2기말
2020_매산고3_기하_1기말
2022_매산고2_기하_1기말
```

관찰 결과 다음 패턴이 반복적으로 확인되었다.

1. **포물선·타원·쌍곡선 기본형은 원본 그림 없이 식만 제시되는 경우가 매우 많다.**
   초점, 준선, 장축·단축, 점근선처럼 본질적으로 기하적인 개념도 계산 문제 형태로만 출제된다.
   따라서 `SOURCE_HAS_NO_FIGURE`는 해설 visual 면제 근거가 될 수 없다.

2. **학교 시험의 고난도 이차곡선 문항은 실제로 그림을 적극 사용한다.**
   접선, 초점, 준선, 점근선, 수선의 발, 두 곡선의 교점 등이 한 그림 안에서 풀이 구조를 이룬다.
   즉 쉬운 문항과 고난도 문항의 차이는 "그림 필요/불필요"보다
   **필요한 시각자료의 깊이** 차이에 가깝다.

3. **벡터의 식이 원·영역·선분·삼각형 같은 도형으로 바뀌는 문항이 반복된다.**
   예를 들어 `AP·BP=0`, 거리 벡터의 부등식, 내분·외분, 벡터합·차의 크기는
   대수 계산만 보여 주는 것보다 도형으로 번역해 보여 줄 때 개념 연결이 분명해진다.

4. **공간도형 문제는 전체 입체도보다 풀이에 사용되는 특정 평면·삼각형이 decisive한 경우가 많다.**
   정육면체·정사면체·사면체·원기둥 등의 원본 3D 그림을 그대로 반복하는 것보다
   `공간 맥락 → 결정적 2D 평면/단면`으로 분해하는 해설 visual이 더 적합한 문항이 반복된다.

5. **원본 문제에 그림이 있어도 그 그림만으로 해설 visual이 충분하지 않은 경우가 많다.**
   해설에서 새 수선의 발, 접선, 단면, 투영, 벡터 분해선을 추가한다면
   solution visual은 별도 semantic artifact로 검수해야 한다.

따라서 v1.1은 다음을 명시적으로 강화한다.

```text
SOURCE_FIGURE_PRESENCE != SOLUTION_VISUAL_REQUIREMENT

EASY_GEOMETRY != VISUAL_EXEMPT

EXPLICIT_CONIC_OBJECT
→ VISUAL_REQUIRED by default

GEOMETRY_EQUATION_OR_VECTOR
→ if it encodes a geometric object/region/relationship,
   show the geometry in solution

SPACE_3D_CONTEXT
→ when reasoning reduces to a plane,
   show CONTEXT_3D + DECISIVE_2D
```

# 1. 핵심 철학

## 1.1 기하에서 시각자료는 장식이 아니라 개념 구조다

기하 문항의 시각자료는 단순히 문제를 예쁘게 보이게 하기 위한 부속물이 아니다.

기하에서 학생이 이해해야 하는 것은 자주 다음과 같은 **관계의 구조**다.

- 점과 점의 위치
- 점과 직선의 거리
- 평행·수직
- 각의 크기와 대응
- 합동·닮음
- 중심·반지름·현·접선·호
- 초점·준선·축·꼭짓점
- 두 초점까지 거리의 합 또는 차
- 벡터의 방향·합·분해·내적
- 면·모서리·꼭짓점의 공간 관계
- 단면과 교선
- 정사영과 수선의 발
- 좌표와 실제 도형의 대응

따라서 기하 해설의 시각자료는 **해설의 수학적 관계를 학생이 다시 볼 수 있게 만드는 학습 장치**로 본다.

## 1.2 쉬운 문항이라고 시각자료가 불필요한 것은 아니다

기하에서는 난이도와 시각자료 필요성을 동일시하지 않는다.

예를 들어

```math
\frac{x^2}{9}+\frac{y^2}{4}=1
```

에서 초점 좌표만 구하는 기본 문항이라도, 학생에게 다음을 함께 보여 주는 것은 교육적 가치가 있다.

- 중심
- 장축과 단축의 방향
- 꼭짓점
- 두 초점
- `a`, `b`, `c`의 위치 관계

따라서 다음 규칙을 고정한다.

```text
EASY_GEOMETRY != VISUAL_EXEMPT
```

문항이 쉽다는 이유만으로 시각자료를 제외하지 않는다.

## 1.3 기하 문항은 “정답 도출용”과 “개념 강화용” 시각자료를 구분한다

시각자료의 역할을 최소 다음으로 나눈다.

```text
DECISIVE_REASONING
DEFINITION_REINFORCEMENT
RELATIONSHIP_EXPLANATION
REPRESENTATION_SUPPORT
SOURCE_RECONSTRUCTION
NONE
```

- `DECISIVE_REASONING`: 그림이 핵심 풀이 단계 자체를 전달한다.
- `DEFINITION_REINFORCEMENT`: 정의·기본 구조를 다시 확인시킨다.
- `RELATIONSHIP_EXPLANATION`: 평행·수직·닮음·접선·초점 관계 등을 보여 준다.
- `REPRESENTATION_SUPPORT`: 계산은 가능하지만 도형의 의미를 함께 이해하게 한다.
- `SOURCE_RECONSTRUCTION`: 원본 문제의 필수 시각자료를 정확히 복원한다.
- `NONE`: 시각화가 학습상 이득이 없거나 오히려 오해를 만든다.

이 값은 **sidecar evidence용 분류**이며, 사용자 승인 없이 JS 기본 스키마 필드를 새로 추가하지 않는다.

## 1.4 Geometry Visual Depth — 난이도가 아니라 시각자료의 깊이를 분류한다

실제 기출에서는 쉬운 이차곡선 기본형과 복합 접선·초점 문제 모두 시각화 가치가 있었지만,
필요한 그림의 복잡도는 달랐다. 따라서 "시각자료 유무"만 판정하지 않고 다음 depth를 sidecar에 기록할 수 있다.

```text
MINIMAL_CONCEPT_ANCHOR
DECISIVE_SOLUTION_DIAGRAM
COMPOSITE_CONTEXT_REDUCTION
```

### `MINIMAL_CONCEPT_ANCHOR`

기본 개념을 한 번 더 눈으로 확인시키는 최소 해설 visual이다.

예:
- 포물선: 꼭짓점·초점·준선·축
- 타원: 중심·장축/단축·꼭짓점·초점
- 쌍곡선: 중심·꼭짓점·초점·점근선
- 두 벡터의 크기와 끼인각
- 내분·외분점의 위치

목표는 풀이를 길게 그림으로 재현하는 것이 아니라 **계산한 값이 도형에서 어디에 있는지 확인**시키는 것이다.

### `DECISIVE_SOLUTION_DIAGRAM`

풀이의 핵심 단계가 그림의 관계를 직접 사용한다.

예:
- 접선과 접점
- 초점과 준선의 거리
- 수선의 발
- 닮음·합동 대응
- 벡터의 합·차
- 영역/자취
- 단면·정사영

### `COMPOSITE_CONTEXT_REDUCTION`

복잡한 기하, 특히 공간도형에서 한 장에 모든 정보를 넣지 않고
**전체 맥락과 실제 계산 평면을 분리**한다.

```text
Panel A: 전체 3D context
Panel B: decisive 2D plane / section / triangle
```

문항이 쉽다는 이유로 `MINIMAL_CONCEPT_ANCHOR`까지 제거하지 않는다.
반대로 쉬운 문항에 고난도용 `COMPOSITE_CONTEXT_REDUCTION`을 억지로 붙이지 않는다.

# 2. 적용 범위

## 2.1 중학교

다음을 포함하되 이에 한정하지 않는다.

- 기본도형
- 점·선·면과 위치 관계
- 각과 평행선
- 삼각형·사각형·다각형
- 작도

# 4. 전수 Triage와 시각자료 필요성

## 4.1 canonical visual decision은 기존 enum을 유지한다

최종 registry에서는 다음 값만 사용한다.

```text
NO_VISUAL
KEEP_EXISTING
REBUILD_EXISTING
ADD_NEW_VISUAL
```

별도 필드:

```text
visualRequirement:
VISUAL_REQUIRED
VISUAL_OPTIONAL
VISUAL_EXEMPT

visualAction:
NONE
KEEP
REBUILD
ADD
REMOVE_INVALID_VISUAL
```

본 문서는 새 canonical enum을 임의 도입하지 않는다.

## 4.2 Geometry Visual Default Principle

기하 문항은 시각화가 수학적 구조를 명확히 보여 줄 수 있는 경우 **시각자료를 긍정적으로 검토하는 것**을 기본값으로 한다.

특히 다음은 난이도와 무관하게 `VISUAL_REQUIRED` 후보로 우선 검토한다.

- 정의 자체가 도형 구조인 경우
- 점·선·면의 위치 관계가 핵심인 경우
- 각, 길이, 평행, 수직, 접선, 합동, 닮음이 핵심인 경우
- 초점·준선·거리합·거리차가 핵심인 경우
- 벡터 방향·분해·내적의 기하 의미가 핵심인 경우
- 공간 배치, 단면, 투영, 수선, 교선이 핵심인 경우
- 해설을 식으로만 제시하면 학생이 도형 의미를 놓치기 쉬운 경우
- 기본 개념 문항이지만 대표 구조를 한 번 더 보여 주는 교육 효과가 큰 경우

## 4.3 VISUAL_EXEMPT는 적극적 근거가 있어야 한다

다음은 `VISUAL_EXEMPT`의 충분한 근거가 아니다.

```text
문제가 쉽다
계산이 짧다
정답이 바로 나온다
해설이 한두 줄이다
이미 학생이 알 것 같다
```

`VISUAL_EXEMPT`는 최소 다음 중 하나를 근거로 한다.

- 시각자료가 새로운 학습 정보를 거의 제공하지 않는다.
- 시각화가 오히려 실제 조건을 왜곡할 위험이 크다.
- 동일 해설/공통자료에서 같은 개념 구조가 이미 충분히 제시되며 반복 그림이 불필요하다.
- 도형화할 수 없는 순수 기호 관계이며 기하적 의미를 억지로 만들게 된다.
- 현재 generator capability로 정확한 시각화를 만들 수 없어 잘못된 그림보다 미제공이 안전하다. 이 경우 `VISUAL_EXEMPT`가 아니라 `BLOCKED/UNSUPPORTED`가 더 적절한지 우선 판정한다.

## 4.4 VISUAL_OPTIONAL

다음은 `VISUAL_OPTIONAL` 후보가 될 수 있다.

- 그림이 있으면 도움이 되지만 핵심 정의·관계를 새로 보여 주지는 않는 경우
- 동일 유형이 연속 반복되고 앞 문항에서 완전한 개념 시각화가 제공된 경우
- 문제의 모든 geometry fact가 텍스트만으로 매우 명확하며 그림 추가 효과가 제한적인 경우

단, 이차곡선에서 곡선 자체가 명시되고 초점·준선·축·점근선·접선 등 geometry parameter를
구하거나 사용하는 경우에는 §8의 `CONIC_VISUAL_DEFAULT_LOCK`이 우선한다.

## 4.5 SOURCE FIGURE INDEPENDENCE LOCK

원본 문제 그림의 존재 여부와 해설 visual requirement를 분리한다.

```text
SOURCE_HAS_FIGURE == true
```

라고 해서 solution visual이 자동 PASS가 아니다.

```text
SOURCE_HAS_FIGURE == false
```

라고 해서 `VISUAL_EXEMPT`도 아니다.

실제 기출에서 초점·준선·장축·단축·점근선 같은 기하 개념이 원본 그림 없이 식으로만
제시되는 기본 문항이 반복 확인되었으므로, **해설 visual은 원본 편집 선택이 아니라
학생의 개념 이해와 풀이 decisive step을 기준으로 판정**한다.

## 4.6 EXPLICIT GEOMETRIC OBJECT DEFAULT LOCK

문항이 다음과 같은 geometric object를 명시적으로 정의하거나 결과로 만든다면
해설에서 그 object를 시각적으로 확인하는 것을 기본값으로 한다.

```text
circle
parabola
ellipse
hyperbola
segment / triangle / polygon
locus
region
vector configuration
plane / section / projection
polyhedron
```

특히 방정식·벡터식이 계산 후 도형으로 번역되는 경우:

```text
ALGEBRAIC_REPRESENTATION
→ GEOMETRIC_OBJECT
→ SOLUTION_VISUAL_REQUIRED
```

를 기본으로 한다.

예:
- `AP·BP=0` → 지름이 `AB`인 원
- 거리 벡터 부등식 → 원의 내부/교집합/반평면
- 내분·외분 공식 → 선분 위/연장선 위의 점
- 이차곡선 표준형 → 실제 곡선과 초점/축/점근선
- 공간 좌표 조건 → 실제 점·직선·평면 관계

순수 성분 계산처럼 geometry translation이 학습상 새로운 정보를 거의 제공하지 않는 경우만
`VISUAL_OPTIONAL` 또는 `VISUAL_EXEMPT`를 검토한다.

# 5. 해설 품질과 시각자료의 관계

## 5.1 해설 먼저, 시각자료는 나중

기존 production 해설 업그레이드의 순서는 다음과 같다.

```text
문항 범위 확정
→ 문제 원문 확인
→ A1 독립 풀이
→ A2 answer/solution 비교
→ 해설의 논리 점프·교육성 판정
→ visual necessity 판정
→ EXPECTED FACT freeze
→ Python 계산
→ SVG/PNG 생성
→ 독립 visual 검수
→ 실제 solution render
```

기존 solution을 보고 그림을 역설계하지 않는다.

## 5.2 시각자료가 해설을 대신할 수 없다

```text
GOOD_VISUAL != COMPLETE_SOLUTION
```

그림 하나로 계산·정의·경우 나누기를 생략하지 않는다.

반대로 해설에 식이 모두 있다고 해서 geometry visual의 교육적 필요성이 자동으로 사라지는 것도 아니다.

## 5.3 학생 재현 가능성

최종 해설과 시각자료를 함께 본 학생이 다음을 추적할 수 있어야 한다.

- 어떤 점이 왜 중요한가
- 어떤 선이 왜 그어졌는가
- 어떤 길이/각/거리 관계를 이용하는가
- 식이 도형의 어느 요소를 나타내는가
- 다음 단계로 왜 넘어가는가

`STUDENT_REPRODUCIBLE_PASS`는 시각자료 존재 여부와 별개로 판정하되, 시각자료가 required인 문항에서 그림이 누락되면 pedagogy closure를 PASS로 만들 수 없다.

## 5.4 BASE GEOMETRY + SOLUTION OVERLAY

기하 해설용 visual은 가능한 경우 다음 두 층으로 사고한다.

```text
BASE_GEOMETRY
+
SOLUTION_OVERLAY
```

`BASE_GEOMETRY`:
- 곡선/도형의 기본 형태
- 중심, 축, 꼭짓점, 초점 등 변하지 않는 핵심 구조
- 기본 vertex/edge topology

`SOLUTION_OVERLAY`:
- 해당 문항의 점 `P`
- 접선
- 수선의 발
- 보조선
- 거리 표시
- 각 표시
- 색칠 영역
- 단면
- 정사영
- 벡터 분해

이 구조는 다음 목적을 가진다.

1. 쉬운 문항에는 base만으로 `MINIMAL_CONCEPT_ANCHOR`를 제공한다.
2. 고난도 문항에는 같은 base 위에 solution overlay를 추가한다.
3. 표준 conic/polyhedron generator를 재사용하면서 문항 고유 fact만 overlay로 분리한다.
4. 해설 그림이 원본 그림을 무비판적으로 복사하는 것을 방지한다.

## 6.5 SEMANTIC FACT와 PRESENTATION FACT를 분리한다

특히 공간도형에서는 원본 그림과 solution visual의 투영 방향이 달라도 수학적으로 같은 도형일 수 있다.
따라서 fact를 다음 두 축으로 분리한다.

### `SEMANTIC_GEOMETRY_FACT`

반드시 동일해야 한다.

- incidence
- collinearity
- parallel/perpendicular
- 길이·각·비율
- 접선
- 초점/준선
- 교점
- 단면 topology
- vector direction/relation
- face/edge/vertex 연결 관계

### `PRESENTATION_GEOMETRY_FACT`

교육적 가독성을 위해 바뀔 수 있다.

- camera/viewpoint
- label offset
- 전체 도형의 화면 회전
- 여백
- 선의 시각적 길이(실제 길이비가 decisive하지 않은 모식도)
- panel 분리 방식

규칙:

```text
SEMANTIC_PARITY = HARD
PRESENTATION_PARITY = NOT_REQUIRED
PRESENTATION_READABILITY = HARD
```

문제용 source reconstruction에서는 원본 표시 fidelity를 우선하지만,
해설용 solution visual은 semantic fact를 잠근 상태에서 더 잘 보이는 viewpoint로 바꿀 수 있다.

# 7. 2D Geometry 제작 원칙

## 7.1 Python 의무

도형·그래프·좌표 기반 SVG의 신규 생성·재구성·수정은 `도형추출.md` v3.0의 Python Mandatory Precision Protocol을 따른다.

```text
SOURCE
→ EXPECTED FACT
→ PYTHON NUMERIC MODEL
→ SVG
```

눈대중 좌표 배치는 금지한다.

## 7.2 좌표계가 없는 순수 기하도 좌표 모델을 만든다

삼각형, 사각형, 원, 닮음, 접선 문제처럼 원문에 좌표가 없어도 제작 단계에서는 내부적으로 좌표 모델을 둘 수 있다.

단,

- 내부 좌표는 문제의 수학 관계를 보존해야 한다.
- 원문에서 길이 비율이 의미를 가지면 해당 비율을 보존한다.
- 실제 축척이 의미 없으면 scale honesty를 기록한다.
- 도식적 단순화를 실제 수학 사실처럼 보이게 만들지 않는다.

## 7.3 보조선

보조선은 단순 미관 요소가 아니다.

각 보조선은 최소 다음 중 하나의 의미를 가져야 한다.

- 수선
- 중선
- 각의 이등분선
- 평행선
- 연장선
- 반지름
- 접점 연결선
- 닮음/합동 관계를 드러내는 선
- 정사영
- 단면 생성선

보조선의 존재 이유가 해설에서 설명되지 않고 그림에도 학습 역할이 없으면 삭제 후보다.

# 8. 이차곡선 Visual Profile

## 8.1 공통 원칙 — CONIC_VISUAL_DEFAULT_LOCK

실제 기출에서는 이차곡선의 가장 기본적인 초점·준선·장축·단축·점근선 문제조차
원본 그림 없이 식으로만 제시되는 경우가 반복되었다. 반면 복합 문항은 같은 개념을 그림으로
직접 활용한다. 따라서 이차곡선은 난이도에 따라 visual 유무를 나누지 않고 **시각자료 깊이**를 나눈다.

다음 조건이면 해설 `VISUAL_REQUIRED`를 기본값으로 한다.

```text
문항의 주된 대상이 포물선/타원/쌍곡선이다.
AND
곡선의 equation, focus, directrix, axis, vertex, asymptote,
tangent, chord, focal-distance 중 하나 이상을 실제로 사용한다.
```

즉 다음도 required 기본값이다.

- 표준형에서 초점만 구하는 문제
- 준선만 구하는 문제
- 장축·단축의 길이만 구하는 문제
- 점근선 기울기만 구하는 문제
- 방정식이 어떤 이차곡선인지 판별하는 문제

다만 이러한 기본 문항은 `MINIMAL_CONCEPT_ANCHOR`면 충분할 수 있다.

복합 문항은 `DECISIVE_SOLUTION_DIAGRAM` 또는 `COMPOSITE_CONTEXT_REDUCTION`을 사용한다.

기본 표시 후보:

- 초점
- 준선
- 중심
- 축
- 꼭짓점
- 거리 정의
- 접선
- 점근선
- 현
- 두 초점과 점의 관계

## 8.2 포물선

정의 기반 문항에서 기본 표시 후보:

- 포물선
- 초점 `F`
- 준선
- 축
- 꼭짓점 `V`
- 포물선 위의 점 `P`
- `PF`
- `P`에서 준선까지의 수선
- 두 거리의 대응

핵심 fact 예:

```text
FOCUS
DIRECTRIX
VERTEX
PERPENDICULAR_FOOT
DISTANCE_EQUALITY
```

단순 표준형·초점 좌표 문항에서도 초점과 준선의 상대 위치를 보여 주는 시각자료를 우선 검토한다.

## 8.3 타원

기본 표시 후보:

- 타원
- 중심
- 장축
- 단축
- 꼭짓점
- 두 초점 `F1`, `F2`
- 필요 시 타원 위 점 `P`
- `PF1`, `PF2`

정의 적용 문항에서는

```text
PF1 + PF2 = constant
```

의 의미가 그림에서 드러나야 한다.

단순 초점 좌표 문항도 `DEFINITION_REINFORCEMENT` 또는 `REPRESENTATION_SUPPORT` 목적으로 시각자료를 붙일 수 있으며, “문제가 쉽다”는 이유로 자동 제외하지 않는다.

## 8.4 쌍곡선

기본 표시 후보:

- 두 branch
- 중심
- 꼭짓점
- 두 초점
- 점근선
- 필요 시 쌍곡선 위 점 `P`
- 두 초점까지의 거리 관계

정의 기반 문항에서는

```text
|PF1 - PF2| = constant
```

가 도형에서 이해 가능해야 한다.

점근선은 실제 곡선 branch와 혼동되지 않게 guide/asymptote 시각 문법을 따른다.

## 8.5 이차곡선 접선

접선 문항에서는 가능한 경우 다음을 표시한다.

- 접점
- 접선
- 곡선
- 필요 시 초점·준선·반사/각 관계
- 법선 또는 보조선
- 문제의 decisive relation

단순히 접선 방정식을 텍스트로 옮겨 적는 그림은 불충분하다.

## 8.6 이차곡선 visual depth preset

### C1 — `CONIC_ANCHOR`

기본 계산형.

예:
- 포물선 초점/준선
- 타원 초점/장축/단축
- 쌍곡선 초점/주축/점근선
- 표준형 판별

필수 목표:

```text
계산한 parameter가 실제 곡선의 어디에 놓이는지 보인다.
```

### C2 — `CONIC_CONSTRUCTION`

접선·수선·교점·현·초점거리처럼 풀이에 보조선이 필요한 문항.

필수 목표:

```text
해설의 decisive relation이 그림에서 직접 추적된다.
```

### C3 — `CONIC_COMPOSITE`

다음과 같이 여러 관계가 동시에 있는 문항.

- 두 이차곡선
- 이차곡선 + 원
- 이차곡선 + 접선 + 점근선
- 초점 + 접선 + 삼각형/사각형
- 자취/영역

필수 목표:

```text
BASE CURVE
+
QUESTION-SPECIFIC OVERLAY
```

를 분리하여 과밀한 한 장 그림을 피한다.

## 8.7 정의 유도형 문항

포물선·타원·쌍곡선의 정의에서 방정식을 유도하거나,
거리합/거리차를 직접 사용하는 문항은 `DEFINITION_REINFORCEMENT`가 아니라
사실상 `DECISIVE_REASONING`으로 본다.

예:

```text
PF = distance(P, directrix)
PF1 + PF2 = constant
|PF1 - PF2| = constant
```

이 관계가 visual에서 확인되지 않으면 `GEOMETRY_CONIC_DEFINITION_VISUAL_MISSING` 후보로 판정한다.

# 9. 평면벡터 Visual Profile

## 9.1 벡터는 방향을 보여 주어야 한다

벡터 시각자료에서 핵심은 단순 선분이 아니라 **방향과 시작점/끝점의 관계**다.

기본 후보:

- 위치벡터
- 자유벡터의 평행이동
- 벡터합
- 벡터차
- 스칼라배
- 내분·외분
- 평행/수직
- 내적의 기하적 의미

## 9.2 벡터합·분해

가능하면

```text
a + b
a - b
λa
```

를 삼각형법 또는 평행사변형법 등 실제 풀이 맥락에 맞는 도형으로 표현한다.

도형이 answer에 맞춰 그려져서는 안 되며, 독립 풀이에서 결정된 벡터 fact를 먼저 freeze한다.

## 9.3 내적

내적 문항에서 각·수직·정사영이 풀이 핵심이면 다음을 required 후보로 본다.

- 두 벡터
- 끼인각
- 수직 관계
- projection
- 필요 시 성분과 geometry의 대응

## 9.4 VECTOR-TO-GEOMETRY TRANSLATION LOCK

실제 기출에서 벡터식이 곧바로 원·영역·선분 관계로 바뀌는 문항이 반복되었다.
이 경우 대수식만 풀고 끝내지 않는다.

다음 translation은 `VISUAL_REQUIRED` 기본값이다.

```text
AP · BP = 0
→ ∠APB = 90°
→ diameter AB circle

|OP - OA| ≤ r
→ disk centered at A

OP · n ≤ c
→ half-plane

internal/external division formula
→ point on segment / extension

|a-b| with |a|, |b|, angle
→ vector triangle / parallelogram

parallel / collinear vector condition
→ line configuration
```

해설은 가능하면

```text
VECTOR/ALGEBRA
→ GEOMETRIC INTERPRETATION
→ CALCULATION
```

순서로 학생에게 연결한다.

## 9.5 벡터 visual 면제 후보

다음은 `VISUAL_OPTIONAL` 또는 `VISUAL_EXEMPT`가 가능하다.

- 순수 성분 덧셈·뺄셈만 묻고 geometry interpretation이 풀이에 새 정보를 주지 않는 경우
- 이미 같은 해설 안에서 동일 방향/내분 구조가 완전히 제시된 반복 문항
- 단순 스칼라 계수 비교만으로 끝나는 경우

단, 크기·각·평행·수직·내분·외분·자취·영역으로 이어지면 다시 required를 우선한다.

# 11. 공간도형·공간좌표 Visual Profile

## 11.1 핵심 원칙

공간도형의 위험은 Python 계산 자체보다 다음에 있다.

- 3D → 2D 투영
- visible / hidden edge
- occlusion
- 단면
- 라벨 충돌
- 복합 보조선
- 앞뒤 관계
- 학생이 실제로 읽을 수 있는 시점 선택

따라서

```text
PYTHON_CORRECT != 3D_VISUAL_PASS
```

로 고정한다.

## 11.2 3D 생성 기본 pipeline

가능한 경우 다음 구조를 사용한다.

```text
3D WORLD GEOMETRY
→ TOPOLOGY
→ CAMERA / PROJECTION MODEL
→ 2D PROJECTED COORDINATES
→ VISIBILITY / OCCLUSION
→ SVG
→ OBSERVED FACT REVIEW
→ REAL RENDER
```

Python은 최소 다음을 계산할 수 있어야 한다.

- 3차원 점 좌표
- 모서리 연결 관계
- 평면/직선/점 위치 관계
- 수선의 발
- 거리
- 각
- 단면 교점
- 투영된 2D 좌표

단, occlusion·라벨 배치·학생 가독성은 별도 visual review 대상이다.

## 11.3 SPACE_VISUAL_TIER

### TIER 1 — STANDARD_3D

대상 예:

- 정육면체
- 직육면체
- 삼각기둥
- 사각기둥
- 각뿔
- 단순 정사면체
- 기본 공간좌표

조건:

- vertex/edge topology가 단순
- 단면이 없거나 매우 단순
- projection이 안정적
- visible/hidden edge 분리가 명확

처리:

```text
deterministic Python generation 허용
standard 3D projection
visible/hidden edge gate
independent review 필수
```

### TIER 2 — STRUCTURED_COMPLEX_3D

대상 예:

- 단면
- 수선의 발
- 교선
- 두 평면의 위치 관계
- 직선과 평면의 각
- 여러 보조선
- 부분적으로 가려지는 내부선
- 공간벡터와 polyhedron 결합

추가 요구:

- explicit topology
- section/intersection facts
- projection evidence
- occlusion evidence
- label collision review
- 고위험 3~5문항 calibration batch

### TIER 3 — HIGH_COMPLEXITY_3D

대상 예:

- 복합 절단
- 다중 단면
- 내부 구조가 많은 입체
- 시점에 따라 의미가 크게 달라지는 도형
- 자동 occlusion이 불안정한 도형
- 현 generator가 표현 의미를 보장하지 못하는 도형

규칙:

```text
AUTO_PASS 금지
HAND_TUNED 눈대중 SVG 금지
```

선택지는 다음 순서로 검토한다.

1. 원본 문제의 고품질 raster/vector 시각자료 재사용
2. 검증 가능한 전문 deterministic generator 사용
3. 좌표/투영/occlusion을 명시적으로 검증할 수 있는 별도 제작 pipeline
4. 위가 불가능하면 `GENERATOR_CAPABILITY_BLOCKED`

정확하게 만들 수 없는 시각자료를 “대충 이해용”으로 만들어 PASS시키지 않는다.

## 11.4 visible / hidden edge

최신 `도형추출.md` v3.0의 3D 규칙을 그대로 따른다.

- visible edge와 hidden edge 구조 분리
- hidden line style 분리
- occlusion에 따른 은선 처리
- label을 은선 위에 직접 두지 않음
- safe area clipping
- depth direction / ratio는 canonical VISUAL 문서의 현행 값을 따름

본 문서는 숫자 token을 재정의하지 않는다.

## 11.5 공간 단면

단면 문항은 최소 다음을 검증한다.

- 절단 평면이 어떤 edge/face를 통과하는가
- 실제 교점 순서
- section polygon의 vertex
- section polygon의 연결 순서
- 가려진 선과 보이는 선
- 원문 도형과 solution의 단면 설명 일치

단면 polygon을 화면상 그럴듯하게 손으로 이어 그리는 것은 금지한다.

## 11.6 SPACE CONTEXT → DECISIVE 2D REDUCTION LOCK

실제 공간기하 문제의 많은 풀이가 최종적으로 특정 삼각형·사각형·단면·수직단면 안에서 끝난다.
이 경우 full 3D diagram 한 장에 모든 계산선을 억지로 넣지 않는다.

기본 전략:

```text
Panel A — SPACE_CONTEXT
전체 입체, 필요한 점/면/모서리의 위치

Panel B — DECISIVE_2D
실제 계산에 사용하는 평면, 단면, 삼각형, 정사영
```

다음은 강한 적용 후보이다.

- 두 평면이 이루는 각
- 직선과 평면이 이루는 각
- 정사영
- 수선의 발
- 공간에서의 거리
- 사면체/정육면체 내부 삼각형
- 원기둥·각기둥의 특정 평면 단면
- 접힌/펼친 도형의 결정적 평면

학생이 실제 계산하는 대상이 2D라면 **2D reduction을 보여 주는 것이 full 3D를 더 복잡하게 그리는 것보다 우선**한다.

## 11.7 VIEWPOINT FREEDOM WITH SEMANTIC LOCK

해설용 공간도형은 원본 문제와 동일한 카메라 시점을 강제하지 않는다.

다음 조건을 모두 만족하면 더 이해하기 쉬운 시점으로 회전/투영할 수 있다.

```text
world topology preserved
semantic facts preserved
visible/hidden relation recomputed
labels remain unambiguous
scale honesty preserved
```

즉,

```text
SOURCE_VIEWPOINT != SOLUTION_VIEWPOINT
```

일 수 있다.

단, 문제용 source reconstruction은 원본 시각 fidelity를 별도로 유지한다.

## 11.8 CURVED SOLID / SURFACE RULE

원기둥·원뿔·구·곡면처럼 occlusion과 surface intersection이 복잡한 대상은
직선 polyhedron generator와 같은 수준으로 자동 지원한다고 추정하지 않는다.

다음 순서를 우선한다.

1. decisive plane/section이 있으면 정확한 2D section을 먼저 만든다.
2. full 3D context가 필요한 경우 전문 surface-capable generator 또는 검증 가능한 투영을 사용한다.
3. 원본 고품질 그림이 있고 재구성이 오히려 위험하면 원본 context를 유지하고 별도 2D solution visual을 만든다.
4. surface intersection/occlusion을 검증할 수 없으면 `GEOMETRY_GENERATOR_CAPABILITY_BLOCKED`.

공간도형을 "입체처럼 보인다"는 이유만으로 PASS하지 않는다.

# 12. 시각자료 파일·필드 운영

## 12.1 문제용과 해설용 분리

문제용:

```text
image
content 내부 기존 안정화 img/SVG
```

해설용:

```text
solutionImage
solutionImageAlt
solutionImageCaption
solutionImageSize
```

기존 엔진·룰북이 허용하는 범위 안에서 사용한다.

문제용 원본 그림을 그대로 해설용 그림으로 재사용하여 “해설 시각자료 추가”로 간주하지 않는다.

## 12.2 해설용 이미지의 목적

`solutionImage`는 최소 하나의 명확한 학습 역할을 가져야 한다.

예:

```text
초점과 준선 관계 확인
닮음 대응 확인
접선과 반지름의 수직 확인
벡터합의 방향 확인
공간 단면의 교점 순서 확인
```

`solutionImageCaption`은 학생이 그림에서 무엇을 볼지 알려 주는 짧은 문장으로 작성한다.

## 12.3 원본 충실성과 해설 추가 정보

문제용 시각자료는 SOURCE FIDELITY가 우선이다.

해설용 시각자료는 원본에 없던 보조선을 추가할 수 있으나 다음을 만족해야 한다.

- solution의 실제 풀이에 사용됨
- 독립 계산으로 근거가 확정됨
- 문제에 없는 새로운 조건으로 오인되지 않음
- 보조선임이 시각적으로 구분됨

## 12.4 기존 문제 그림은 해설 visual의 자동 대체물이 아니다

기출에서 제공된 문제 그림이 다음 조건을 모두 만족하면 해설에서 reference로 재사용할 수 있다.

- 풀이에 필요한 핵심 점/선/곡선이 이미 존재
- 추가 construction이 거의 필요 없음
- 학생이 해설 문장과 그림을 직접 연결할 수 있음
- crop 품질과 라벨 가독성이 충분함

반대로 다음 중 하나라도 해당하면 별도 solution visual을 만든다.

- 수선의 발·접선·보조선·단면을 새로 도입
- 원본 그림이 너무 작거나 복잡함
- 풀이가 다른 평면/시점으로 환원됨
- source figure는 문제 조건만 보여 주고 decisive step을 보여 주지 않음
- 기존 raster 위에 표시를 덧붙이면 의미/가독성이 불안정함

```text
PROBLEM_VISUAL_PASS
!=
SOLUTION_VISUAL_PASS
```

# 13. 독립 검수 계약

## 13.1 A — 독립 수학

먼저 문제 원문과 problem visual만 보고 직접 푼다.

금지:

- source answer
- 기존 solution
- 수정 solution
- builder verdict
- 이전 PASS report

## 13.2 B — pedagogy

최종 solution이 다음을 만족하는지 본다.

- 수학적으로 정확
- 교육과정 내 풀이
- 논리 점프 없음
- 학생 재현 가능
- visual이 required이면 해설과 실제로 연결됨

## 13.3 C1 — V1 Source-only visual expectation

V1은 다음을 본다.

- content
- choices
- problem visual dependency

숨김:

- answer
- solution
- solutionImage
- alt/caption
- 이전 visual verdict

V1에서 확정:

- visualRequirement
- geometryVisualRole
- expected visual type
- decisive step
- critical EXPECTED FACT

## 13.4 C2 — V2 Artifact-only observed fact

V2는 실제 asset만 본다.

숨김:

- V1 expected fact
- answer
- solution
- 이전 verdict
- alt/caption의 정답 유도 정보

검수자는 가능한 범위에서 실제 SVG element 좌표를 읽어 OBSERVED FACT를 역산한다.

## 13.5 C3 — V3 parity

V1/V2 freeze 후에만 비교한다.

```text
EXPECTED_FACT
↔
OBSERVED_FACT
```

필수 상태:

```text
EXPECTED_FACT_PASS
ELEMENT_EXTRACTION_PASS
OBSERVED_FACT_PASS
EXPECTED_OBSERVED_PARITY_PASS
PROBLEM_SOLUTION_VISUAL_3WAY_PARITY_PASS
```

하나라도 `FAIL` 또는 `NOT_TESTED`이면 최종 geometry math PASS를 선언하지 않는다.

## 13.6 render와 math는 분리한다

```text
GEOMETRY_RENDER_PASS != GEOMETRY_MATH_PASS
```

그림이 예쁘게 렌더되더라도 geometry가 틀리면 FAIL이다.

geometry가 수학적으로 정확해도 clipping, label overlap, unreadability가 있으면 최종 visual PASS가 아니다.

```text

↔

↔

## 18.1 실행 스키마 승격 잠금

본 문서에 정의한 확장 geometry fact type, failure code, visual depth 값은

- pipeline-core enum에 문서만 보고 자동 추가

- verifier가 지원하지 않는 fact를 문자열 존재만으로 PASS

→ positive fixture
→ negative/mutation fixture
→ legacy compatibility check
→ protocol regression check
→ independent qualification
```

따라서 본 정책을 rules source-pack에 등록하는 것 자체는
`pipeline-core` 코드 수정을 요구하지 않는다.

## 22.1 Conic minimum anchor contract

`MINIMAL_CONCEPT_ANCHOR`는 장식용 미니그래프가 아니다.
최소한 해당 문항에서 실제 계산한 parameter를 포함해야 한다.

### 포물선

```text
curve + vertex + axis + focus + directrix
```

### 타원

```text
curve + center + major/minor axis direction + vertices + foci
```

### 쌍곡선

```text
branches + center + vertices + foci + asymptotes
```

문항이 일부 요소만 묻더라도 전체 anchor를 과밀하지 않은 범위에서 보여 주고,
**이번 문제에서 구한 값은 더 명확하게 표시**한다.

## 22.2 Visual overload 방지

`REQUIRED`는 "모든 보조요소를 최대한 많이 그려라"는 뜻이 아니다.

```text
REQUIRED
→ minimum sufficient geometry
→ question-specific emphasis
```

를 따른다.

불필요한 좌표, 모든 가능한 보조선, 쓰지 않는 초점/점근선까지 강조하여
학생의 시선을 분산시키면 `GEOMETRY_VISUAL_REDUNDANT` 후보로 판정한다.

## 24.3 `MANIFEST.md` 재생성

현재 rules source-pack은 draft를 제외하고 operational rules의 byte count와 SHA를 잠근다.

본 정책을 `QUALIFICATION_READY` operational candidate로 등록하면:

- 새 정책 파일 포함
- 변경된 `00_RULES_INDEX.md`의 byte/SHA 갱신
- cross-reference를 추가했다면 `도형추출.md` byte/SHA 갱신

이 필요하다.

기존 MANIFEST line을 손으로 부분 수정하여 맞추지 말고,
repository의 현행 manifest 생성/검증 경로가 있으면 그 경로를 사용한다.
현행 생성기가 없다면 raw-byte 기준으로 전체 source-pack 목록을 재계산하고
누락/중복/경로 drift가 없는지 별도 검증한다.

# 27. 최종 원칙

기하 시각자료의 품질은 그림 수량으로 판단하지 않는다.

최종 목표는 다음이다.

> **학생이 문제의 수학적 구조를 눈으로 다시 확인하고, 해설의 각 단계가 도형의 어떤 관계를 이용하는지 이해하며, 제작된 시각자료 자체도 독립 계산·실제 geometry·실제 렌더로 검증되는 것.**

이를 위해 다음을 고정한다.

```text
수학 fact가 먼저다.
그림은 fact를 따른다.
원본 그림의 유무는 해설 visual requirement를 결정하지 않는다.
쉬운 기하도 개념 시각화를 배제하지 않는다.
이차곡선은 최소 concept anchor를 기본값으로 한다.
벡터식이 도형으로 번역되면 그 geometry를 보여 준다.
공간도형은 Python 계산과 시각 표현 검수를 분리한다.
공간 풀이가 한 평면으로 환원되면 3D context + decisive 2D를 우선한다.
해설용 3D viewpoint는 semantic lock 아래에서 바꿀 수 있다.
정확하게 만들 수 없는 그림은 억지로 만들지 않는다.
Builder SELF_CHECK는 최종 PASS가 아니다.
RENDER PASS는 MATH PASS를 대신하지 않는다.
최종 PASS는 동일 artifact와 실제 브라우저 렌더에 결박한다.
```
