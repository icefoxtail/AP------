# APMath 공통 파이프라인 실행 계약 v1

적용일: 2026-09-06. 구현: `archive/tools/pipeline-core/`.

본 문서는 Common v1.2.10의 독립성·동일 artifact SHA·coverage·fail-closed 원칙을
여러 실행기에 연결하는 계약이다. 새 release/seal 권한을 만들지 않는다. 코드의
회귀검사 PASS, 생성기 BUILD_SIDE_ONLY, 실제 문항의 독립 검수 PASS를 구분한다.

## 1. 적용 경로와 판정 범위

집합·명제, 도형의 방정식, 함수군, 고1 전수 시각자료, 집합 시각자료 pilot,
기출 추출·승격, 교재, ALIVE 유사문항은 공통 QUESTION_QUALITY closure를 사용한다.
태그 보강, intelligence 단원 분류와 JS bank cleanup은 METADATA_ONLY closure이며 수학·문항 품질 PASS를
대신하지 않는다. metadata-only에서는 content/choices/answer/solution/image와
layoutTag/wide를 바꾸면 범위 위반이다.

과거 batch별 report builder와 수기 PASS 보고서는 진단 자료다. 새 최종 판정은
`node archive/tools/pipeline-core/cli.mjs audit --manifest <run.json>`으로 검증한다.
기출 promotion, geometry seal, 고1 line final, Logic Visual final, ALIVE final
closure는 공통 gate가 없거나 실패하면 승격/봉인/최종 PASS를 차단한다.
교재는 extraction 실행 결과와 quality closure를 별도 필드로 보고한다.

## 2. 단일 schema와 hash

- run: `APMATH_PIPELINE_RUN_v1`
- review evidence: `APMATH_PIPELINE_EVIDENCE_v1`
- typed visual fact: `APMATH_VISUAL_FACT_v2`
- generator witness: `APMATH_GENERATOR_WITNESS_v1`
- closure report: `APMATH_PIPELINE_CLOSURE_v1`

시각 fact의 필수 타입·값·collection 의미는
`archive/tools/pipeline-core/visual-contract.json`과 validator를 함께 동결한다.
free-form legacy fact를 field rename이나 expected→observed 복사로 승격하지 않는다.
v1 evidence는 보존하고 새 v2 attempt에서 검수한다.

실제 파일 SHA는 raw bytes, 객체 SHA는 공통 canonical serializer로 계산한다.
semantic hash는 UID/reviewer/provenance/픽셀 좌표를 제외하고 의미 필드만 사용한다.
서로 다른 UID의 동일 의미 비교와 동일 UID의 expected/observed 비교를 구분한다.
집합은 schema가 지정한 필드만 정렬하며 proof 순서·구간 순서·table 열 순서는 보존한다.

## 3. 생성과 독립 검수

생성기는 Python 좌표 계산·지원 관계 검증을 실행하고 BUILD_SIDE_ONLY witness를 쓴다.
현재 공통 생성기는 집합 영역/포함/원소 수, 수직선, 경우표, 다항식 좌표 그래프,
지원 geometry 관계, proof flow, quantifier negation을 지원한다. 일반 함수식·임의
기하 증명·임의 정규화는 지원한다고 추정하지 않는다. 기존 전문 생성기는 유지하되
candidate-only 출력과 같은 evidence contract에 연결한다.

V1은 현재 학생용 content/choices/problem dependency만 보고 necessity와 expected를
동결한다. V2는 실제 artifact/witness만 보고 observed를 동결한다. 서로의 first-pass,
answer/solution/외부 alt/caption은 숨긴다. V3는 두 freeze 이후에만 비교한다.
모델명 자체는 독립성 증거가 아니다. 별도 session, input bundle raw SHA, first-pass
file SHA, 시작·종료 input SHA, prior visibility와 reviewer identity를 보존한다.

모든 target은 V1 necessity를 거친다. required/optional/exempt는 임의로 바꿔 PASS를
만들지 않는다. disagreement는 새 adjudication/revision으로 처리한다. 수학 A1 blind
solve와 A2 정답·해설 비교는 시각 C와 분리한다.

## 4. UID/revision/분모

UID는 `sourceJsPath|examId|qid`다. 같은 source/qid의 별칭 중복도 금지한다.
active canonical revision은 UID마다 하나이며 명시적인 supersedes lineage를 요구한다.
파일명 final, batch 번호 증가, 동일 evidence 재실행은 canonical 근거가 아니다.

C required는 required requirement OR actual attached OR problem dependency OR shared
dependency로 계산한다. EXEMPT와 실제 attached/dependency의 공존은 허용하지 않는다.
최종 map의 adjudication evidence와 실제 candidate/asset bytes가 일치해야 freeze한다.
source/solution/answer/alt/caption/linkage/rule/schema/generator/verifier 변경은 input SHA를
바꾸며 이전 분모·영향 evidence를 stale 처리한다. UID 수가 같아도 재검이 필요하다.

## 5. 실제 렌더와 최종 집계

프로필별 필수 mode와 desktop/mobile을 공통 profiles.json에서 읽는다. 전체 문항 수,
마지막 문항, font/MathJax/image decode, 실제 asset 연결, clipping/overflow/readability,
viewport PNG witness의 파일·SHA·해상도를 확인한다. DOM load 또는 screenshotCaptured
boolean만으로 PASS하지 않는다. render PASS로 semantic PASS를 계산하지 않는다.

렌더 input은 `engine.html` 단일 파일이 아니라 실제 로컬 runtime closure를 사용한다.
최소 `native_print.js`, print/image optimizer, MathJax render loop·loader·font,
metadata helper, theme CSS와 browser가 사용한 외부 response body SHA를 결박한다.
로컬 runtime file이 run input에 없으면 렌더 서버가 읽지 않고 FAIL한다. 어느 dependency든
바뀌면 동일 engine SHA여도 이전 capture/review는 stale이다.

browser 수집 결과는 `render-capture` evidence로 먼저 불변 동결한다. 별도 reviewer는
capture file SHA·runtime bundle SHA·response bundle SHA·각 screenshot SHA를 참조하는
새 `render` evidence를 작성한다. reviewer session/identity는 collector와 달라야 하고
capture freeze 이후 시작해야 한다. 최종 render PASS는 capture의 기계 측정과 reviewer의
clipping/overflow/readability 판정을 reducer가 결합해 계산한다. capture lineage 없는
수기 PASS, reviewer가 바꾼 capture 측정값, 누락 문항은 FAIL이다.

최종 PASS는 모든 적용 gate의 명시적 PASS와 현재 input binding을 요구한다.
FAIL/BLOCKED/WARN/NOT_TESTED/누락/불명확한 적용 여부가 하나라도 있으면 차단한다.
진행 완료와 품질 PASS를 구분하고, source defect를 발견한 검수도 작업 완료로 기록한다.

공통 closure의 `productionAuthorized:false`는 정보성 문구가 아니다. production write
caller는 별도 authority gate 없이 question-quality PASS만으로 파일을 복사할 수 없다.

## 6. 운영·회귀·migration

새 run은 `prepare`로 candidate/원문과 blind bundle 초안을 만들 수 있다. 이 초안은
REQUIRES_REVIEW이며 reviewer·PASS·final requirement를 자동 생성하지 않는다.
후속 evidence는 append-only 새 경로에 쓰고 core/spec/hash 변경 시 새 revision을 만든다.
이미 닫힌 run, production JS/SVG, 원본 스캔을 이번 계약 도입만으로 다시 쓰지 않는다.

잘못된 포함관계, 누락된 경우, 역전된 방향, invalid fact, stale source/asset/spec,
duplicate UID, missing/failed render, optional visual 분모 누락, self-review, 조기 V3,
wrong output scope를 거부하는 테스트와 정상 fixture를 통과시키는 테스트를 함께 유지한다.
미공개 holdout과 실제 대표 문항 qualification은 소프트웨어 fixture와 별도다.

운영 상세와 executable schema 예시는 `archive/tools/pipeline-core/README.md`를 따른다.
