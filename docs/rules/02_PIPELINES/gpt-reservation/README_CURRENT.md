## 0. 이 문서는 모든 GPT가 예약라인을 개설하거나 수정할 때 찾아야 할 첫 번째 공용 정본이다

이 디렉터리는 2026-10-17 HIGH_DYNAMIC 5개 예약에서 실물로 쓰는 규칙을 **캠페인에 독립적인 재사용 템플릿**으로 일반화한 원본이다. 신규 예약 담당 GPT/Work/Codex는 사용자가 처음부터 긴 프롬프트를 새로 작성하게 하지 말고 이 CURRENT 문서와 자기 역할 파일을 실제 본문으로 읽어 구성한다. 기존 프롬프트에는 별도 업데이트를 수행하지 않는 한 자동 적용됐다고 선언하지 않는다. 이미 운영 중인 다른 캠페인의 frozen manifest·stream·library·role·시간표와 활성 ON/OFF는 임의 변경하지 않는다.

### 권위 및 필독 순서

1. 사용자 최신 명시 범위·승인/정지·종료 조건 → **해당 캠페인 현재 manifest·실제 예약 설정** → **이 Git 공용 예약 정본 + 해당 역할 CURRENT 한 곳**. Notion 공통/Archive 생명주기는 **작업 예외·실제 충돌 발생 시에만 필요한 절을 열람**한다.
2. **공용 README_CURRENT + 해당 역할 CURRENT 정확히 하나 + 자기 캠페인 manifest/인테이크·source authority·기존 stage 실물**을 확인한다. 실제 Git 수정/원본 비교를 수행할 때는 최신 main SHA와 대상 Git 파일/blob SHA를 읽는다. `AGENTS.md`/`archive/AGENTS.md`는 권한 충돌·도구/운영 규칙 판단이 실제 필요할 때 해당 절을 추가 열람하며, 모든 예약 회차에서 장문 전부를 선열람하지 않는다.
3. 실제 이번 작업 적용 범위에 따라 `docs/rules/02_PIPELINES/JS_Archive_2.0_GPT_Scheduled_Execution_v1.md`, `docs/rules/02_PIPELINES/JS_Archive_2.0_GPT_Campaign_Generation_v1.md`, `docs/architecture/JS_Archive_Metadata_Required_On_Create_Edit_Review_CURRENT_v1.md`, `docs/architecture/Archive_Correction_Owner_EndToEnd_Closeout_CURRENT_v1.md`, `docs/rules/03_REVIEW/JS아카이브_PHYSICAL_EVIDENCE_BEFORE_PASS_v1.md`, `docs/rules/01_CANONICAL/JS아카이브_문항메타_파운데이션_운영규칙_v1.md`, `docs/rules/01_CANONICAL/JS아카이브_학생용해설_운영규칙_v1.md`, `docs/rules/02_PIPELINES/해설프로토콜.md`와 CURRENT RPM Primary/crosswalk/GLOBAL ACTIVE/PT·TPL/binding, Golden/Negative, Visual/교육과정 정본을 실제 읽는다. 적용되는 문서만 추가로 읽고 구버전 HISTORY의 충돌 규칙은 사용하지 않는다.
4. 링크/목차 확인만으로 READ 주장 금지. 읽은 정본 path/URL, Git blob SHA·Notion 수정시각(가능한 경우), 적용한 조항·실제 결과를 해당 회차에 기록한다. 실제 독립풀이·학생 설명·정밀 Meta·검증을 정본 문구 확인으로 대체하지 않는다.

## 1. 예약 생성 시 공통 본문 + 정확히 한 역할 본문을 조립한다

다음 입력을 **실제 manifest/사용자 지시/예약 설정에서 확인하여** 바인딩한다. 모르면 질문 또는 `UNRESOLVED_INPUT`; 자동 추측·다른 캠페인 값 복사 금지.

| 변수 | 의미 |
| --- | --- |
| `{CAMPAIGN_ID}` · `{GENERATION_ROOT}` · `{LIBRARY_NAMESPACE}` | 실제 campaign/generation 및 작업 파일 Library 폴더 |
| `{ROLE}` | MASTER / CREATE / R1 / R2 / R3 중 하나 |
| `{SOURCE_AUTHORITY}` · `{SOURCE_PACKET_POLICY}` | Drive/Git 원본 조회 권위, 준비된 source-only JS·필수 PNG/SVG 경로 |
| `{ASSIGNMENT_SOURCE}` · `{ELIGIBLE_SELECTOR}` | 캠페인 배정 명세(동적 인테이크 vs frozen stream roster) 및 처리 우선순위 |
| `{STREAM}` · `{CAMPAIGN_MANIFEST}` | partition 캠페인에서만 사용. 없는 동적 캠페인에 A/B/C를 발명하지 않는다 |
| `{HANDOFF_STAGE}` · `{RECEIVER}` | 현재 역할의 산출물·다음 단계, 인계 포맷 및 식별자 |
| `{SCHEDULE}` · `{TIMEZONE}` · `{IS_ENABLED}` | **실제 사용자 승인**에 근거한 캘린더 RRULE·시간대·ON/OFF. HIGH_DYNAMIC 예시의 :00/:12/:24/:36/:48은 공통 기본값이 아니다 |

| `{CLOSURE_BOUNDARY}` | 실제 기술 executor와 중간 Git/출판 허용 범위. 기본 예약 5레인은 Library만 수정, Git read 허용, production/main 쓰기 금지 |

조립한 프롬프트 상단에는 `canonicalPromptRoot`, `canonicalVersion=1.0.0`, `canonicalGitMainSha`, `canonicalRolePath`, `canonicalRoleBlobSha`, `campaignManifestIdentity`를 고정한다. 런타임 자체에서 매회 CURRENT로 다시 조회하고 상위 변경이 발견되면 사용자 지시와 충돌 없는 범위에서 즉시 반영하며, 예약의 물리 prompt 갱신은 승인·쓰기 성공·재조회가 있어야만 완료라고 한다. 프롬프트 안에 `{...}` 미해결 변수가 남으면 개설 실패/미완성.

## 2. 공통 예약 실행 블록 — 역할 파일과 함께 그대로 적용

### 2.1 NONSTOP 및 진짜 작업 입력 선점

- 매회 **자기 캠페인의 Library 최신 물리 입력**과 누적 ledger를 확인한다. `examUid + artifact file ID + revision 또는 bytes SHA256 + stage + campaign`로 이전 stage 최신 완료 여부, 동일 stage 기처리, 다른 worker 점유를 검증한다. frozen roster는 자기 stream만; 동적 캠페인은 MASTER가 실제 배정한 `READY_CREATE`만. 이미 main에 출시된 동일본/다른 캠페인/유효 완료 stage 중복 처리 금지.
- 할 입력이 없으면 `NO_INPUT`과 실조회 분모를, 도구·Notion·Git·Drive·Library가 실패하면 `INFRA_RETRY`와 실제 error/재시도 위치를 남기고 **그 회차만 종료**한다. 사용자의 별도 활성/정지 지시 없이 예약 자체를 OFF/disable/delete하거나 타 예약 일정을 바꾸지 않는다.
- 동일 stage 실수정 writer는 하나. 다른 writer가 수정 중이면 원본이나 ledger를 덮어쓰지 않고 SKIP/다른 eligible 또는 다음 회차로.
- 한 회차 실질 수정 시험지는 기본 최대 하나. 시험지 내 qid 및 설명·SVG·Meta 수리 개수/길이에 인위적인 cap 없음. 시간이 부족하면 동일 stage checkpoint + firstMissingStep를 실제 Library에 저장한 뒤 다음 회차 재개한다.

### 2.2 DOC_READ_RECEIPT 실제 본문 열람 증빙

- 새로운 exam·단계 착수 시, 산출물 수정 전에 Git main·해당 ROLE·실제 이 stage에 적용되는 수학/Meta/품질 정본만 **실제 본문까지** 읽는다. 과거 Notion 공통 라우터·생명주기 전체 선열람은 강제하지 않는다. 노션 링크나 Git 파일 이름을 단순 나열해서 필독 완료로 처리하지 않는다.
- 각 exam+stage actual attempt의 `DOC_READ_RECEIPT.json`에는 최소 `campaignId, examUid, role, inputArtifactSha, readAtUtc, notionRead:[{url,lastEditedAtIfAvailable,appliedClause}], gitRead:[{path,blobSha,mainSha,appliedClause}], applicableRequirements, resultSummary, exactReadErrors, originalOwner, nextOwner, receiptRemoteReadback`가 필요하다. 장문 발췌·모든 문서 역사 로그는 불필요.
- 실제 패킷과 같은 Library namespace에 물리 저장한 다음 remote file ID/revision/SHA256을 재조회한다. **저장 실패/미열람/이전 작업의 없는 영수증 소급 생성 금지**. `DOC_READ_UNVERIFIED` 시 품질 PASS 불가하나 캠페인 비차단 인계 경계와는 별도다.

### 2.3 수학·학생 해설·정밀 메타 실제 작업

- 모든 제작·검수 stage가 직접 해당 qid의 원본(발문·보기·문제 시각), 풀이, 학생 해설, 학년 교육과정, 필요 problem/solution SVG/PNG, 난이도를 검토하고 확인된 결함을 자기 locus에서 최소 수정한다. **작은칠판**: 조건과 목표 → 전략·공식 선택 이유 → 학생이 따라갈 중간 수식 → 부호·구간·경우·경계·보기/오답 → 단 하나의 정답과 자연스러운 결론. 답이 맞는 것만으로 해설 PASS 금지. 이미 충분하면 근거 있는 KEEP.
- 신규/검수된 각 qid Meta는 원본과 실제 최종 풀이를 근거로 `standardUnitKey/subUnitKey`, RPM L1→L4 semantic(Primary, current scope+허용 lower-only prerequisite), grade crosswalk, GLOBAL ACTIVE PT/TPL taxonomy/aliases/ownerPack, exact curriculum binding, CrossConcept/Condition/Integration, `level=하|중|상` 및 독립 `difficultyBucket=1..5`를 확인한다. 실제 authority lookup 증거를 qid별 `META_LOOKUP_EVIDENCE`에 남기고 바로 고칠 수 있는 오류는 수정. 있는 ACTIVE key 대신 null 유지, 가짜 NONE/[]·임의 key 발명, 전체 qid 포괄 `CANONICAL_UNVERIFIED` 후 작업완료 주장은 금지.
- Golden 2~3 + 관련 Negative(복성고1 false PASS 포함) 실제 sample/sha/관찰로 stage 품질 기준을 calibrate하고, 적용 가능한 공식 validator/Node·브라우저/렌더 검사를 실제 실행하거나 `NOT_RUN`, 실패·기술 executor 경계를 정확히 남긴다. baseline 판정에 필요한 preflight를 하지 않았다면 `STAGE_QUALITY_PASS=false`. 이전 실제 유효한 freeze·수정·검사 결과는 보존하고 동일 검증 반복 금지.

### 2.4 OWN_AND_FIX 원 소유자 책임과 비차단 상태

- `OWNER_INCOMPLETE`: 그 역할의 조회·검수·수리/실행 시도가 없는데 부채로만 넘긴 상태. qid/축/원 담당 stage와 정확히 연결. `DOC_READ_UNVERIFIED`: 필독 증거 없음. `EVIDENCE_DEBT`: 실제 source/authority 조회와 수정 시도 이후에도 정당하게 미해결. `INFRA_RETRY`: 실제 기술 장애 및 재시도 위치. `NOT_RUN`은 미수행 결과이고 PASS 아님.
- 누락의 원 소유자가 바뀌지 않으며, 수신 역할은 자기 검수 범위의 실제 해결 가능한 부분을 고친다. MASTER는 타 writer 없을 때 개별 unresolved qid를 추가로 수리한다. 미완을 이유로 **새로운 전시험지 HOLD/기존 valid R1 재블라인드/R2·R3 전수 재실행/별도 품질 승인**을 만들지 않는다.
- `ROUTED` / `READY_R1` / `READY_R2` / `READY_R3` / `READY_MASTER_DECISION`은 transport 상태로서 품질 PASS·배포승인이 아니다. 인계 가능한 실제 최신 JS·필수 이미지·ledger·메타·정본열람 영수증의 정확한 식별자와 아직 열린 항목을 보존한다. 소유자/검증 없는 성공 선언 금지.
- 예약 GPT의 중간 Git commit/push/PR/main/운영배포 금지. Git의 원본·정본·검증기 읽기는 계속 가능. 별도 상위 감독 GPT와 인가된 Work/Codex/출판 담당자가 최종 출고 판정·핀포인트 재검·Git 운영 병합·런타임 QA를 맡는다.

## 3. 역할 파일 5개 — 복사/수정은 여기서 시작

- [MASTER_CURRENT.md](MASTER_CURRENT.md): 신규 동적 인테이크 배정 + 기존 못 닫은 qid 핀포인트 수리 + 문서열람/미완 책임 추적. 캠페인 고정 roster의 MASTER는 신규 수집 임무를 자동 부여하지 않는다.
- [CREATE_CURRENT.md](CREATE_CURRENT.md): 원본 faithful 제작·작은칠판 초안·정밀 메타·source-only/blind 입력.
- [R1_CURRENT.md](R1_CURRENT.md): source-only 독립 풀이/먼저 freeze, stored 답 비교 뒤 설명·정밀 Meta 직접 보강.
- [R2_CURRENT.md](R2_CURRENT.md): 전 qid 설명 적극 심화·전 qid 정밀 Meta 독립 재검, R1 freeze 반복 금지.
- [R3_CURRENT.md](R3_CURRENT.md): 최종 전 문항 구조/원본/Visual/Meta/기술 축 검토 + 변경/미해결 qid 핀포인트 수리.
- [CHANGELOG.md](CHANGELOG.md): 사용자 발견 누락 → 재현 → 조항/역할/검증 반영 → 호환성 확인 → Git main/Notion 링크/실제 예약 적용 여부를 분리한 이력.

## 4. 새 예약 개설/기존 프롬프트 갱신 절차

1. Git 정확 경로의 이 CURRENT 파일과 역할 파일 1개, 실제 캠페인 manifest/적용되는 정본만 확인한다. 전역 Notion 라우터·역사 문서 순회는 기본 수행하지 않는다.
2. 필수 변수 모두 바인딩하고 공통 블록+ROLE 블록을 합쳐 사용자가 지정한 예약만 구성한다. 특정 캠페인의 frozen roster를 동적 인테이크로 바꿔치기하거나 과거 NEW14 MASTER 최종판정 조항을 재사용하지 않는다.
3. 무입력, Git/Notion 조회 실패, 이미 처리됨, 동시 writer, 원본 자료 누락, 진짜 qid 수리, R1 freeze-before-compare, Meta null 실제 lookup, Golden NOT_RUN의 대표 입력을 조항별로 점검한다. 문서 정적 리뷰는 실행 증거가 아니며 스모크 실제 수행 여부를 구별한다.
4. 예약 생성/수정은 **사용자 승인한 대상·시간·활성 상태만** 변경한다. 생성 후 목록에서 제목/role/prompt version/바인딩/RRULE/ON-OFF를 재조회. “문서 저장 완료”와 “예약 실물 적용 성공”을 별도 기록한다.
5. 실제 첫 예약 실행의 Library DOC_READ_RECEIPT, qid ledger/Meta lookup/Golden result, 학생 JS/assets packet ID/SHA와 다음 stage를 readback해 이 설계가 기능했는지 별도로 판정한다.

## 5. 틈 발견시 지속 업데이트 규칙 (Living Canonical)

- 문제 제보 → 실제 예약 prompt와 실제 Library packet/ledger, Git/Notion CURRENT 직접 대조 → **원인 분류(프롬프트 누락/정본 규칙 누락/문서 미숙독/기능·권한 장애/실제 풀이 결함)** → 필요한 가장 작은 공통/ROLE 조항 수정 → 반례 및 정상 케이스 확인 → `CHANGELOG.md`에 이유·영향 role·Git commit·예약 실물 변경 여부 기록.
- 단순 문구·절차 보강은 patch version; ROLE 책임 변경·상호작용 강화는 minor; 이전 작업·스키마를 깨는 변경은 major. 파일 경로는 계속 CURRENT를 유지하여 모든 GPT가 같은 링크에서 최신판을 읽는다. 과거판은 Git SHA로 추적한다.
- 최신 적용 정본과 충돌하는 레거시 문구는 상단 변경이 명확히 우선하도록 표시하되, 과거 캠페인의 자료/완료 증거/manifest/예약을 무단 삭제·변경하지 않는다.
- Git 문서 병합 후 노션 Skill/라우터가 새 **Git main URL과 버전**을 가리키는지 검증한다. 이미 실행 중인 예약은 자동 갱신되는 게 아니다. 사용자가 허용한 예약만 개별 prompt 수정→actual automation readback→첫 실행 실증거 검사한다.
- “완벽하다”거나 실제 실험 검증 없이 PASS라고 보고하지 않는다. 미래의 문서/예약 편집이나 주기적인 개선은 그때 도구·권한·명시 지시가 있을 때 실행한다.
