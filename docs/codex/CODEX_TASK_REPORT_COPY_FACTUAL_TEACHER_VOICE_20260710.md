# CODEX TASK — 리포트 문구 사실 기반 교사 문체 정리 (2026-07-10)

## 목적

시험결과 리포트의 학부모 문구를 "담당 선생님이 실제로 보내는 안내"에 더 가깝게 만든다.
핵심은 **근거 없는 학생 원인 단정 제거**다. 문구 다양화 작업이 아니다.

## 절대 제약 (위반 시 반려)

1. **선생님 입력 부담을 1도 늘리지 않는다.** 새 입력 필드·태그 UI·필수 단계 추가 금지.
   현재 워크플로(오답 입력 + 시험 성적 입력)만으로 모든 문구가 생성되어야 한다.
2. **완료 시제 전제는 유지한다.** 리포트는 오답 정리 수업 후 발송이 확정 워크플로다(원장 결정).
   "수업에서 다시 풀어 정리했습니다" 계열을 미래형으로 바꾸지 않는다.
3. **만점(perfect) 밴드 문구는 변경 금지.** 원장 승인 문구다
   ("전 문항을 정확히 해결했습니다. 시험 범위 개념 이해와 계산 모두 흔들림 없이 마무리했습니다.").
4. **장기플랜(reportCenterBuildLongTermPlanMessage) 구조·분량 변경 금지.** 축소 여부는 원장 별도 결정 대기.
5. 가정 지도 제안 금지·학원 책임 강조 원칙 유지. `reportCenterAssertParentSafe` 가드 약화 금지.

## 배경: 현재 구조의 문제

`reportCenterBuildParentQuestionParagraph`(apmath/js/report-center.js ~4063)는 오답 원인을 이렇게 정한다:

- `reviewData.tag` — 선생님이 시험 분석표에 **직접 기록한** 오류 태그 (있으면 교사 판정 = 근거 있음)
- 태그가 없으면 `reportCenterResolveErrorTag`(~3876)가 **정답률만으로** '계산·검산'/'풀이 순서'/'조건 해석'/'개념 재정리'를 추정

문제: 태그가 없는 경우(대부분)에도 meanings 문장이 **학생 개인의 원인을 판정하는 문장**으로 나간다.

> "개념 부족만의 문제라기보다 계산, 부호, 검산 과정의 점검이 더 필요했던 실점으로 보입니다."

학생이 실제로는 개념을 몰라 틀렸는데 리포트가 "계산 실수"라고 안내하면, 학부모-학생 대화에서 어긋나며 리포트 전체 신뢰가 무너진다.

## Task 1 — 문항 코멘트 이원화 (최우선)

`reportCenterBuildParentQuestionParagraph` 수정:

- **선생님 명시 태그가 있을 때** (`reviewData.tag`가 `reportCenterErrorTags()` 목록에 있는 explicit 값일 때만):
  현행 판정형 문장 유지 가능. 학생 원인 서술 허용.
- **태그가 없을 때** (정답률 fallback으로 family가 정해진 경우):
  meanings 문장을 **문항 특성 서술로 교체**한다. 학생 원인·심리·능력을 추측하는 표현 금지.

  | 현행 (학생 원인 단정) | 교체 방향 (문항 사실만) |
  |---|---|
  | 이번 오답은 조건을 식으로 옮기고 범위까지 확인하는 과정에서 정리가 더 필요했던 것으로 보입니다 | 이 문항은 주어진 조건을 식으로 정확히 옮기는 과정이 중요한 문제였습니다 |
  | 개념 부족만의 문제라기보다 계산, 부호, 검산 과정의 점검이 더 필요했던 실점으로 보입니다 | 이 문항은 계산과 부호를 끝까지 확인해야 답을 지킬 수 있는 문제였습니다 |
  | 알고 있는 개념을 낯선 형태의 문제에 적용하는 순서에서 정리가 더 필요했던 것으로 보입니다 | 이 문항은 기본 개념을 낯선 형태에 적용해야 하는 문제였습니다 |

- 판별 방법: `reportCenterResolveErrorTag`의 반환값이 explicit인지 fallback인지 호출부에서 구분할 수 있어야 한다.
  (예: explicit 여부를 함께 반환하거나, explicit 체크를 호출부에서 수행. 함수 시그니처 변경 시 기존 호출부 2곳 확인: ~2363, ~3855)
- `family` 분류(condition/calc/geometry/concept) 자체는 opener 선택용으로 유지해도 된다.
  금지 대상은 "학생이 그 원인으로 틀렸다"고 읽히는 **문장**이다.
- "~것으로 보입니다" 헤지 4곳이 있어도 학부모는 교사 판정으로 읽는다. 헤지 추가로 때우지 말 것.

## Task 2 — 리포트 자기 설명 문장 제거

`reportCenterBuildRichParentMessage`의 `wrongText`(~4400):

- 현행: "오답 N개 중 M번을 중심으로 수업에서 다시 짚었고, **이 리포트에도 정리해 두었습니다**"
- 학부모는 이미 리포트를 보고 있다. 리포트가 리포트를 설명하지 않는다.
- 교체 방향: "오답은 N문항이었고, M번을 중심으로 수업에서 다시 짚었습니다" (완료 시제 유지)
- 오답 1개 단수형 분기(4401)와 perfect 분기("이 리포트에는 강점이 드러난 문항과…" ~4403)도 같은 원칙으로 정리.
  perfect 교체 예: "기본 문항부터 어려운 문항까지 빠짐없이 해결했습니다" 등 결과 서술로.

## Task 3 — 정답률 이중 언급 제거

`reportCenterBuildParentQuestionParagraph` 조립부(~4156):

- 현행: `${opener} ${rateText} 기준으로 보면 ${meaning}` — hard 밴드 opener에 이미
  "전체 정답률 32%의 고난도 문항"이 있어 정답률이 두 번 나오고, "기준으로 보면"이 분석기 말투를 만든다.
- 교체 방향: opener에 rateText가 이미 포함된 경우 중간 연결부를 생략하고
  `${opener} ${meaning}`으로 조립. rateText가 opener에 없는 밴드는
  "전체 정답률은 N%였습니다." 같은 독립 문장 1회로 정리.
- "기준으로 보면" 표현은 전면 제거.

## Task 4 — 근거 없는 능력 단정 제거 (담임 총평)

`reportCenterBuildSchoolExamTeacherSummary`(~4680)의 state 분기:

- 현행(hasHard 분기): "**기본기는 갖춰져 있으며**, 정답률이 낮은 고난도 문항에서 한 단계를 더 이어가는 힘을 키우는 단계입니다."
  — 저점수·오답 다수 학생에게 점수만으로 "기본기 갖춤"을 단정.
- 교체 방향: 확인된 사실 범위로. "맞힌 문항에서는 기본 개념을 적용한 것이 확인됐습니다. 정답률이 낮았던 고난도 문항은 수업에서 개념부터 다시 짚었습니다."
- 같은 함수의 다른 분기도 점검: "실수로 이어진 부분만 다듬으면 더 좋은 결과로 이어질 수 있는 상태입니다" 등
  점수·오답 데이터로 뒷받침되지 않는 단정이 있으면 같은 원칙으로 교체.
- 만점 분기(오답 0)는 변경 금지(제약 3).

## 문체 기준 (전 Task 공통)

- 확인된 사실(점수·평균·오답 수·정답률·단원)만 단정한다.
- 학생의 심리·습관·능력은 데이터 근거(선생님 태그) 없이 말하지 않는다.
- 조치는 학원 주어, 완료한 것은 완료형, 예정은 미래형 — 한 문장에 섞지 않는다.
- "기준으로 보면", "확인되었습니다"체 남발, 리포트 자기 언급 금지.
- 이름 호칭은 기존 `reportCenterFamiliarName` 사용 규칙 유지.
