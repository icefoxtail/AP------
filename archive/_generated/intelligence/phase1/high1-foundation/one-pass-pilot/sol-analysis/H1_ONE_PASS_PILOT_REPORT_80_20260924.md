# 고1 공통수학1 통합 1회 판독 파일럿 평가 (80문항)

**판정: `INTEGRATED_ONE_PASS_RECOMMENDED_WITH_CHANGES`**

**상태: 파일럿 평가. 기존 고1 본작업과 production canonical에 자동 반영하지 않음.**

## 판단

한 문항의 발문·보기·이미지·정답·해설을 한 번 정밀 판독해 L1부터 L4, CrossConcept, Condition, IntegrationPattern까지 채우는 방식은 **실행 가능**하다. A/B는 각각 80개 완성 레코드를 제출했고, L3의 문구를 수학적 의미로 정규화하면 75/80문항에서 같은 유형을 가리켰다. 기존 단계별 L3 후보와 다른 판정 25문항은 기존 결과까지 다시 확인할 근거를 만들었다. 기존 후보를 정답지로 간주하지 않았다.

그러나 통합 판독의 **원장 그대로 FINAL 투입은 부적합**하다. A/B의 전체 메타 튜플이 문자 그대로 같은 문항은 3/80이고, L3·L4 표현을 Sol이 같은 의미로 묶어도 나머지 활성 키까지 모두 맞는 문항은 24/80이다. 신규 L3/L4 후보의 이름이 문항마다 늘어났고, 한 워커는 80번에 다른 문항의 판정을 통째로 옮겨 적었다. 따라서 향후 과목 확장에는 통합 판독을 쓰되, 아래의 입력 차단·기계 검사·source 복구·전역 taxonomy 정규화를 **필수 단계**로 둔다. 현재 진행 중인 고1 본작업을 이 파일럿으로 대체하지 않는다.

2015 교육과정 35문항, 2022 교육과정 45문항이다. 이미 본작업 A/B가 판독한 문항 28개, 기존 source 문제 인접 문항 8개, L3 경계 참고 문항 12개, 참조 이미지가 있는 문항 10개를 포함한다. 표본은 임의 숫자 추출이 아니라 풀이 구조·난도·결함 인접성을 섞어 선택했다.

초기 파일럿 A/B는 UID 사용 목록이 들어 있는 원시 registry를 열어 블라인드가 훼손될 위험이 생겼다. 두 워커는 **원장 작성 전에 폐기**했고, UID 배정값을 제거한 ACTIVE 용어집으로 새 A/B를 시작했다. 새 A/B/C에게 기존 문항별 L3/L4/CrossConcept/difficulty와 기존 결과 일치율을 보여주지 않았다. 기존 결과 대조는 두 A/B 원장이 80개씩 완료된 뒤 Sol만 수행했다. 일치율은 파일럿 워커에게 사후에도 전달하지 않았다.

## source·해설 및 워커 품질

**고유 문항 7개**에서 발문·보기·도형·해설 결함 후보를 확인했다: 4, 5, 6, 7, 8, 70, 78번이다. 초기 A HOLD 6건, B HOLD 2건이었고, C가 이견 문항 5·6·8·70번을 모두 HOLD로 판정했다. 78번은 (z=-1) 분기에서 99항의 합을 (+99)로 쓴 해설 부호 오류다. 유효 A/B가 모두 이 오류를 놓쳤으므로 **확인된 상관 오류 1건**이다. 최종 정답은 바뀌지 않는다.

4번은 D가 원본 시험지와 공식 해설로 정답 120을 확정해 JS를 수정했다. 동결된 원래 80행 입력과 A/B 원장은 보존하고, 바뀐 4번 한 행만 새 source fingerprint로 만든 뒤 새로운 블라인드 A/B에게 재판정시켰다. 둘 다 독립 계산으로 120과 같은 L1·L2·L3·L4·CrossConcept·Condition·IntegrationPattern을 제출해 REVIEWED가 되었다. 이 성과를 **초기 80문항의 품질 수치에 소급 합산하지 않았다**.

70번은 원본 인쇄 시험지에도 같은 대진표가 있으며, 답안 표시 자료는 315를 의도한다. 하지만 인쇄 발문은 네 팀 쪽의 두 1회전 위치를 교환하면 같은 대진인지 명시하지 않는다. 고정 위치로 세면 630이므로 원본 대조 후에도 수정프로토콜 HOLD다. 7번도 D가 원본 시험지·답안 PDF 전체 페이지와 600 DPI 확대를 확인했지만 경로 가닥을 식별할 수 없어 source HOLD를 유지했다.

원장 품질 검사에서 A의 52번 보기 누락 오독과 ACTIVE에 없는 L4 키 3개를 수정시켰다. A의 처음 61–80 제출은 80번 행렬 문제에 71번 자동차 조합 판정을 통째로 복사한 것이 확인되어 **배치 전체를 기각**하고 새 블라인드 A가 20문항을 다시 읽었다. B는 41–60 초안에서 60번을 빠뜨렸고 첫 20문항의 CrossConcept 이유가 반복적이어서 제출 전 고쳤다. 이미지 참조 47·59번의 픽셀 관찰 근거도 물리 원장에서 확인했다. 이런 결함은 해시·행 수 검사만으로는 모두 잡히지 않으므로 문항 근거와 문제 유형의 교차 UID 검사가 필요하다.

## canonical 재사용과 과분류

| 항목 | A | B |
|---|---:|---:|
| ACTIVE L3 재사용 | 33/80 (41.3%) | 27/80 (33.8%) |
| ACTIVE L4 재사용 | 25/80 (31.3%) | 14/80 (17.5%) |
| 신규 L3 **문항별 제안** | 47 | 53 |
| 신규 L4 **문항별 제안** | 55 | 66 |

두 원장을 합치면 신규 L3 제안의 서로 다른 **표현은 98개**, L4는 **120개**다. 신규 CrossConcept 후보는 **0개**이고, 사용된 CrossConcept/Condition 키는 ACTIVE 용어집에 속한다. 낮은 L3/L4 재사용률은 워커 잘못만을 뜻하지 않는다. 제공한 ACTIVE 용어집에는 고1 기존 Stage3/Stage4의 다수 **candidate**와 행렬 L3/L4 초안이 포함되지 않았다. 문항별 옛 배정은 숨기되, 다음 과목에는 UID를 제거한 **승인된 후보 정의·동의어와 L1/L2 parent 경계**를 추가해야 한다.

Sol은 파일럿 안에서만 source HOLD로 기존 가족이 없는 7번의 L3/L4 후보 표현 각 2개를 보류하고, 나머지 새 이름을 유형·골격별로 묶었다. L3는 **96개 표현 → 28개 검토 가족**으로 **68개 표현 병합**, L4는 **118개 표현 → 47개 검토 골격**으로 **71개 표현 병합**했다. L4의 47개는 기존 후보 골격을 참고해 정리한 **잠정값**이며 실질 A/B 골격 충돌 8건을 별도로 남겼다. 이 병합은 파일럿 장부에서만 이루어졌고, **production canonical 변경 0건**이다. 기존 후보를 자동 정답으로 삼아 묶은 것은 아니며, L3에서 원문에 반하는 기존 후보는 별도 Sol 교정 가족으로 분리했다.

## 현재 단계별 방식과 비교

| 평가축 | 현재 단계별 방식 | 통합 1회 판독 파일럿 |
|---|---|---|
| 같은 표본의 기존 산출 상태 | L3·L4 후보 각각 79/80, 본작업 독립 A/B 판독 28/80. 후보는 FINAL 아님. | A/B 각각 80/80의 전체 semantic 레코드와 문항별 근거. |
| 문항 읽기 구조 | L1/L2/L3/L4/관계 메타 단계를 따라 반복 판독. | A/B 각각 한 번의 정밀 판독으로 전 필드 생성. |
| 기존 L3에 대한 독립 검증 | 기존 단계 산출만으로는 같은 UID의 오류를 드러내기 어려움. | source 근거가 있는 재검토 후보 25개와 명백한 경계 오류 후보를 분리. |
| taxonomy 정규화 비용 | 단계마다 이름과 경계를 조정. | 한꺼번에 신규 이름이 급증: L3 98, L4 120 표현을 Sol이 묶어야 함. |
| 무검수 출력의 일관성 | 후보가 분리되어 있어 전 필드 동시 충돌을 직접 측정하기 어려움. | 전 필드 문자 일치 3/80, 의미상 L3 75/80, L4 72/80; 사람·검증기 관문 필수. |
| 시간·토큰 비용 | 같은 80문항의 통제된 시간 측정 없음. | 재판독·C·Sol 정규화 비용이 있었으므로 실제 속도 우위는 이번 자료로 단정하지 않음. |

**결정 근거:** L3의 의미상 독립 합치와 기존 L3 결함 발견 능력 때문에 과목 전체를 여러 stage로 반복 읽는 방식을 앞으로 그대로 복제할 이유는 약하다. 다만 현재의 원장 품질과 신규 key 증식으로는 통합 출력을 곧바로 쓰지 못한다. 따라서 확장용 표준은 `문항 1회 정밀 판독 A/B → source/HOLD 분리·정확 복구 → 이견에만 C → Sol 전역 taxonomy 정규화·과분류 제거 → difficulty → fail-closed validator → FINAL`로 권고한다. 현재 고1 본작업은 기존 승인 절차대로 끝내고, 다음 과목부터 아래 변경을 적용해 작은 첫 배치를 통과시킨 뒤 확대한다.

### 적용 전 필수 변경

1. **블라인드 용어집 확장:** UID·사용 목록·이전 배정은 숨긴 채, ACTIVE 정의와 Sol이 승인한 과목별 candidate 정의·동의어·parent 경계를 넣는다. 새 key 제안 전 semantic equivalent 검색을 강제한다.
2. **원장 게이트:** 80/80 UID·원문/해설 hash·보기를 묻는 문항의 choices·ACTIVE key 유효성·참조 이미지의 실제 픽셀 영수증·문항별 서로 다른 근거를 검사한다. 근거가 다른 UID의 내용과 맞는지도 표본 또는 자동 교차검사한다.
3. **source 수리:** D는 원본 1:1로 확인한 JS만 수정하고 전후값·원본 페이지·이미지·해시를 남긴다. 바뀐 UID만 새 블라인드 payload로 A/B 재판정한다. 원본도 모호하면 HOLD와 수정프로토콜로 보낸다.
4. **Sol 전역 정규화:** L4 골격과 CrossConcept 중복을 구별하고 문항별 신규 표현을 과목 전체에서 합친다. 파일럿의 신규 이름이나 기존 hidden L3를 자동으로 canonical/production에 쓰지 않는다.
5. **과목별 진입 검사:** 새 과목 첫 묶음에서 source 결함률, A/B 의미 충돌, 과분류와 C/Sol 부담을 재측정한다. 이번 고1 수치가 그대로 중학교·고2에 적용된다고 가정하지 않는다.
