# SVG 캠페인 — Codex 실행 인계

> **2026-11-04 배치의 역사적 모델 배정:** 당시 관리자는 Astra medium, 제작자는 `gpt-6-luna` high, 독립 검수자는 `gpt-6-luna` xhigh였다. 이 배정과 승인 10개 묶음의 병합·종료 조건은 당시 캠페인에만 적용한다. 현재 작업은 §2와 최신 사용자 지시를 따른다. 과거의 모델·수량·종료 문구를 새 큐 작업에 자동 적용하지 않는다.

이 문서는 Codex가 기존 SVG 엔진으로 기출 해설 그림 캠페인을 이어갈 때의 역할과 실행 계약이다.
Claude용 `HANDOFF_SVG_ENGINE.md`는 유지한다. Codex의 모델·역할·동시 실행은 이 문서를 따른다.
그림의 수학·교육 기준은 기존 정본을 따른다. 이 문서 작성은 생산·게시·검수 완료가 아니다.

## 1. 시작 전에 읽을 것

- 저장소 루트 `AGENTS.md`, `docs/agents/visual-svg.md`, `docs/agents/common.md`, `archive/AGENTS.md`.
- `archive/tools/geometry-equation/HANDOFF_SVG_ENGINE.md` 전체, 특히 최신 상태와 기준이 있는 §00.
- `production/AUTHOR_GUIDE.md`는 plan 계약 정본이다. 경로 기준은 `archive/tools/geometry-equation/`.
- `ops/svg-m1/briefs/plan.md`, `briefs/plan-current.md`, `briefs/review1.md`와 교체용 `briefs/review.md`. 여기서 `briefs/`와 `guide/` 축약 경로는 모두 `ops/svg-m1/` 기준이다.
- `ops/svg-m1/guide/guide-tips.md`, `guide-core.md`, 해당 형태별 guide 및 유사 골든 plan.
- `.codex/skills/apmath-visual-upgrade/SKILL.md`는 시각 작업 단일 진입점이다. 이 문서는 공통 그림 기준, 관련 골든 회귀 및 실제 SVG 수학 검증을 대체하지 않는다.
- 지침 충돌은 최신 사용자 지시와 적용 범위가 좁은 최신 기준을 우선해 해결하고 근거를 남긴다.

## 2. 역할과 권한

- **ROOT**: 최신 대기열·원문·실제 문제 그림·해설·정답·기존 자산·소유권을 확인하고, 정확한 문항 단위로 여러 작업자를 배정한다. 큐·시험지 요약·입력 브랜치의 단일 작성자이며 질문별 run 경로와 쓰기 허용 파일을 정한다. 렌더 시도 상한을 두지 않고 이력·공유 잠금·결과를 관리한다. 인계된 최종 SVG와 PNG 및 독립 검수 결과를 확인하고, 사용자가 허가한 게시·원장·Git 작업만 수행한다.
- **구현자**: 동시에 가능한 최대 수의 구현자가 서로 다른 문항을 맡아 실제 item·plan·publish 작성, 수리, 공식 렌더와 학생용 화면 확인까지 진행한다. 각 작업자는 배정된 문항의 원문·정답·해설·원본 그림을 확인하고 고유한 run 경로만 쓴다. 엔진, 시험지 JS, 대기열·공유 원장, 다른 문항의 run을 수정하지 않는다. 허용 경로 밖 변경이 필요하면 경로·이유·재현 근거를 ROOT에 보고한다.
- **독립 검수자**: 여러 검수자가 가능한 수만큼 동시에 검수할 수 있다. ROOT는 문항이 겹치지 않도록 나눠 배정한다. 각 검수자는 배정된 문항을 원문·정답·해설과 대조하고, 실제 SVG·after 이미지·alt·caption을 독립 검수한다. 검수 지적의 수리는 별도 검수 소유 경로에서만 한다. 수정된 해시는 원래 검수자와 다른 검수자가 독립 재검한다. 지정 검수자 한 명이 검수·수리 완료 후 시험지별 reviewer branch의 통합 commit/push owner가 된다. ROOT가 맡은 큐·입력 브랜치·공용 원장은 수정하지 않는다.
- 별도 인스턴스에는 필요한 원문·필수 조건·정확한 문항·경로·쓰기 허용 목록을 명시한다. 사용자 지시 없는 재위임은 금지한다. 실행별 사용자 지시가 정한 모델·런타임을 사용하며, 호출 불가 시 정확한 실패 사유를 ROOT에 보고하고 조용히 대체하지 않는다.
- **엔진 업그레이드·진단**: 현재 문항 구현과 별도인 엔진 작업은 사용자가 범위·담당·허용 경로를 따로 지정한 경우에만 시작한다. 모델과 런타임은 해당 실행의 최신 사용자 지시를 따른다. 이전 진단 기록은 역사 자료로 보존하고 현행 담당 배정으로 해석하지 않는다. 엔진 작업과 제작자의 개별 plan·그림 수리를 혼동하지 않는다.

## 3. 대상과 중복 방지

- 기준 범위는 `archive/exams/original/**`의 해당 기출이며, 문제용·해설용 필요성은 독립 판정한다.
- 인계 당시 다음 순서는 ⑤ 23년 중1 3개 + 중2 5개, ⑥ 23년 중3 5개 + 고1 3개,
  ⑦ 23년 고2 13개, 그다음 G14(중1 위치관계)다. 숫자는 계획 당시의 대상 수이며 자동 착수 지시가 아니다.
- 당시 승인된 10개 시험지 묶음과 G14 순서는 이전 캠페인의 범위다. 현재 대기열의 순서·준비 상태·시작·종료 조건으로 자동 적용하지 않는다. 새 작업은 그 작업의 최신 사용자 지시와 입력 브랜치 queue를 따른다.
- 착수 전에 실제 `production/exam-figure-ledger.json`, 시험지의 현재 그림과 최근 관련 커밋을
  확인하여 이미 처리된 시험지는 건너뛰고, OPEN·누락·교체 필요 항목만 정확히 배정한다.
- 인계 문서의 303 PUBLISHED / 192 EXEMPT / 6 OPEN은 ③④ 당시 수치이며 현재 집계가 아니다.
- 기존 그림은 ROOT가 문제 그림 옆에서 직접 보고 풀이 방식·중간값·가독성을 판단한다.
  엔진 밖 그림은 교체를 기본으로 삼되 실제 교육 가치와 필요성을 확인한다.
- 학년별 약 10개 시험지를 모아 원본 전체 문항 분모를 고정하고 각 문항을 FIGURE / REPLACE / KEEP / EXEMPT / CONTENT / UNSUPPORTED로 근거와 함께 분류한다.
  문제·해설과 원문 그림을 읽고 결정 관계, 기존 그림, 새 시각 정보와 판정 근거를 남긴다.
  원문이나 필수 그림이 없거나 내용이 불일치하면 사실과 근거를 기록하고 임의로 PASS하지 않는다.

## 4. Windows 준비와 이식 상태

- 이 환경은 Windows/PowerShell이다. 기존 Linux 예제의 `/home/user/AP------`, `python3`,
  `timeout`, 셸 환경변수 구문을 Windows에서 그대로 실행하지 않는다.
- `ops/svg-m1/`의 도구·지시서를 `.tmp/svg-m1/`에 복원하고 `runs/`, `packets/`를 분리한다.
  기존 run·증거를 덮어쓰지 않도록 ROOT가 실제 경로와 상태를 먼저 확인한다.
- 저장소의 Windows 이식 도구로 `make-packet` 3건 실행과 legacy source 별칭 개선을 확인했다.
  portable publish 5개 테스트와 packet 1개 테스트는 초기 검증을 통과했다. 이 결과는 실제 게시 완료가 아니다.
- 새 게시 인터페이스는 `py <도구경로>/pubflow.py --batch <manifest.json>`이다.
  manifest는 `exam`, `review`, `rows`, `triage`, `camp`를 명시하며 상대 경로는 manifest 폴더 기준이다.
  Windows 도구 포팅과 이 문서에 적힌 관련 실행 검증은 당시 묶음을 위한 것이다. 이 문서의 오래된 상태 문구를 현재 큐 진행 상태로 사용하지 않는다. 기존 Linux 인자와 고정 Sonnet 문구를 사용하지 않는다.
- 각 단계에서 종료 코드와 JSON 분모·결과를 확인하고 Windows 경로·공백은 argv 배열로 전달한다.
  UTF-8과 실제 Chrome 경로를 확인한다. 임시 `.tmp` helper를 Git 정본 필수 도구로 취급하지 않는다.
- 도구 보정과 실제 게시·검사는 ROOT가 소유한다. 시험지 제작자에게 공용 도구 수정 권한을 주지 않는다.
- Python 의존성, Chromium/Chrome 및 브라우저 경로는 실제 설치를 확인한 뒤 설정한다.
  Windows에서 직접 require/import할 때 경로와 file URL 처리는 기존 HANDOFF §3을 참고해 검증한다.

## 5. 시험지별 처리

1. ROOT가 원장·최근 커밋·현재 자산을 확인하고 학년별 약 10개 시험지의 원본 전체 문항을 triage한다.
2. 원본과 packet의 문항 수·발문·이미지 참조를 대조해 분모 누락을 막고 중간값과 쓰기 경로를 정한다.
3. ROOT가 형태·시험지 분모·파일 소유 상태를 확인해 서로 겹치지 않는 qNN을 가능한 많은 구현자에게 배정한다. 각 구현자는 자기 문항의 run만 소유한다.
4. 각 구현자는 원문 packet과 실제 원본 그림을 확인하고 자기 문항의 item·plan·publish를 작성·수리한다. 문항별 고정 시도 예산은 없다. 실제 호출 전후에 attempt 번호, 수정 사유, 입력·출력 해시와 결과를 기록하고 기존 기록은 덮어쓰거나 초기화하지 않는다. 시도 수가 불명확하면 `UNKNOWN`으로 둔다.
5. 구현자는 공식 렌더를 직접 수행할 수 있다. 공용 전역 렌더 잠금은 실제 `render-plan.mjs` 호출 동안에만 잡아 한 번에 하나의 엔진 프로세스만 실행한다. 다른 작업자는 입력 작성·수리·정적 확인·검수를 계속 병렬로 진행할 수 있다. 별도 출력 폴더를 사용하고 잠금을 얻지 못하면 기다린다. 같은 출력 폴더 재렌더 전에 기존 산출물을 보존하고 새 attempt 경로를 쓴다.
6. ROOT는 대기열 순서를 우선순위로 유지하면서 가능한 최대 수의 독립 구현 작업을 동시에 배정한다. 한 작업의 구현·검수가 끝날 때까지 다른 안전한 작업을 대기시키지 않는다. `ROOT_PREPARING`은 기본적으로 렌더 금지이며, READY 이전 작업은 해당 시험지·문항을 특정한 명시적 사용자 허가가 있을 때만 `.tmp` 후보로 진행한다. 이 예외는 queue status를 `READY_FOR_RENDER`나 `REVIEW_READY`로 바꾸지 않으며 게시 승인도 아니다.
7. ROOT는 실제 후보·입력 해시·엔진 결과·학생용 after 이미지·오류·미실행 사유를 공유 경로에 결속한다. 구현자 자기 보고만으로 PASS하지 않는다. 같은 문항의 산출물은 동시 수정하지 않으며 시험지 요약·대기열은 ROOT만 쓴다.
8. 여러 독립 검수자가 서로 겹치지 않는 문항 묶음을 받아 병렬 검수한다. 검수 요청은 해당 시험지의 지정 검수 대화에 전달하고, 각 문항의 정확한 산출물 해시와 `NOT_RUN` 항목을 함께 제공한다. 수정된 candidate는 다른 검수자가 변경 해시를 독립 재검한다. 검수가 끝나면 한 명의 지정 검수자만 시험지별 reviewer branch에 commit/push한다. ROOT는 입력 브랜치와 대기열을 소유한다. main 병합·게시 여부는 별도 지시 전 수행하지 않는다.
9. 각 단계의 SVG·PNG·publish.json 세 SHA-256을 검수·게시 기록에 결속한다. 셋 중 하나가 바뀌면 영향 범위를 다시 확인하고 재검한다.
10. 검증된 게시 경로에서만 실제 게시·표시 확인·관련 테스트·원장 갱신을 수행한다.
   승인된 묶음 안에서 처리된 시험지의 상태, 소요 시간과 잔여 사유를 기록한다.

## 6. 그림과 독립 검수 기준

- 학생이 해설의 풀이를 따라갈 수 있도록 문제 그림의 점 이름·배치와 실제 풀이 관계를 보존한다.
  핵심 중간값은 넣되 과밀을 피하고 정답·보기 번호·서술형 각 소문항의 답은 caption 끝에 둔다.
- 범위·최솟값의 경계 곡선과 직선은 풀이 핵심이므로 그린다. 정답인 점근선 값이나 교점 값 자체는
  `hideLabels` 등으로 숨긴다. 중간값을 정답 노출로 오인하여 제거하지 않는다.
- 같은 각·길이·평행·대응·넓이 등 핵심 관계는 읽기 쉬운 색으로 묶는다.
  떠 있거나 헷갈리는 필수 라벨은 지시선·끌어낸 패널부터 시도하고 삭제로 통과시키지 않는다.
- 점 이름은 안쪽, 길이 치수선은 바깥에 두고, 짧은 치수선을 안쪽에 둔다.
  학생에게 보이는 텍스트에 `^2`, `sqrt`, `*` 등 입력 표기를 그대로 남기지 않는다.
- 그래프의 함수 이름과 풀이에 필요한 교점이 보이게 한다. 예시 값은 caption에 예시임을 밝히고,
  근사로 만든 좌표를 주어진 값처럼 쓰지 않는다. 필요한 경우 등축척을 쓴다.
- 독립 검수자는 실제 candidate를 보기 전에 문제 그림과 content·solution에서 기대 관계·배치·중간값을 `expected`로 정리한다.
  이어 실제 SVG와 PNG, alt·caption을 보고 수학 관계, 잘림·겹침, 정답 노출 및 가독성을 확인한다. 검수자들은 서로 겹치지 않는 문항 묶음을 받아 동시에 수행할 수 있다.
- 과거 `review1.md`의 A-only 입력과 A/B 출력 문구 충돌은 아래의 A-only/A-B 검수 구분으로 처리한다.
- **신규 그림**은 A만 판정한다. A에 PASS / FAIL / MISSING과 구체적 근거를 기록하며 B·better를 만들지 않는다.
- **기존 그림 교체**는 새 A와 기존 B를 독립 판정하고 `better` A / B / TIE와 이유를 기록한다.
  A PASS와 better=A를 기본 게시 조건으로 한다. TIE는 원장이 OPEN일 때만 기존 규칙에 따라 판단한다.
  교체 rows에는 `replace: true`를 넣는다. ROOT는 실제 기존 그림과 비교해 최종 결정한다.
- 검수 기록에는 시험지·ord, expected, 각 판정·결함, SVG SHA-256, 검수 인스턴스와 시점을 남긴다.
  수리 후 최종 SVG의 해시와 일치하는 PASS가 없으면 게시하지 않는다.

## 7. 병렬성·실패·게시

- 서로 다른 문항과 파일 경로가 분리되면 구현·수리·독립 검수를 가능한 최대한 병렬 배정한다. 2~3개 같은 임의의 낮은 동시 작업 상한을 두지 않는다. 대기열 행 순서는 우선 배정 순서이며 안전하게 분리된 뒤 순번 항목을 동시에 진행할 수 있다.
- 같은 문항·같은 파일에는 writer 한 명만 둔다. ROOT는 대기열과 시험지 요약의 단일 writer다. 공식 렌더는 공유 전역 잠금으로 실제 엔진 호출만 하나씩 직렬화하고, 잠금을 기다리는 동안 다른 작업은 계속한다. 무거운 검사 실행은 저장소 자원 제약에 맞춰 순차화할 수 있다.
  구현 병렬화는 최초 전체 FIGURE 확인이나 독립 검수를 줄이는 근거가 아니다. 검수도 서로 겹치지 않는 문항 할당으로 동시에 수행하고, 수정된 해시만 지정된 변경 범위에 따라 재검한다.
- GPT/Codex 구현 라인에는 문항별 고정 렌더 시도 상한이 없다. 토큰 절약을 이유로 렌더·실물 확인을 생략하거나 시도를 중단하지 않는다. 모든 실제 호출·입출력 해시·오류·계획 수정 사유를 누적 기록하고, 과거 시도·승인 이력을 덮어쓰거나 횟수를 초기화하지 않는다. 불명확한 과거 횟수는 `UNKNOWN`으로 남긴다.
  실패 뒤에는 구체 원인을 진단하고 계획·환경을 실제로 수정한 뒤 재시도한다. 같은 입력·계획을 이유 없이 반복하지 않는다. 전역 렌더 잠금은 실제 엔진 호출만 직렬화하고 검증 기준은 유지한다. 과거 `5/5` 또는 `retryAllowed:false` 기록은 당시 사실로 보존한다.
- 엔진 기능이 부족하면 오류 코드·필요 기능·시도한 plan을 UNSUPPORTED로 남긴다.
  엔진 확장은 시험지 작업자 범위 밖이다. ROOT가 공백을 수납하고 별도 지시서·소유 경로·독립 검수·관련 골든 회귀를 배정한다.
  사용자 승인 범위를 벗어나는 확장만 먼저 보고하여 승인을 받는다.
- CONTENT 오류는 문제와 원문 근거로 다시 계산한다. 확실한 수정의 범위와 공유 데이터 영향은 ROOT가 판단한다.
  불확실하거나 선택지에 답이 없거나 복수면 근거를 보고하고 추측해 바꾸지 않는다.
- 실패, 누락, 미실행은 정확한 명령·종료 코드·영향 문항과 함께 FAILED / MISSING / NOT_RUN 등으로 기록한다.
  근거가 부족하면 EVIDENCE_DEBT로 남기며 검사 약화나 허위 PASS를 금한다.
- 원본 JS 수정 시 `docs/agents/common.md`의 공유 데이터 고정값을 지키고 관련 테스트를 실행한다.
  병합 전 PR CI가 모두 녹색인지 확인한다. 병합·CI·Pages·학생 배포 결과는 따로 보고한다.
- 생성과 독립 검수가 끝나면 ROOT가 모든 최종 SVG와 PNG를 원문과 직접 비교하고 평면·입체·그래프·확률 등 검수 통과 대표 최종 그림 여러 장(기본 4~6개)을 모아 사용자에게 먼저 보여준다.
  필수 CI가 녹색인지 확인한 뒤 main을 병합하고 remote readback 및 실제 학생 페이지 QA 결과를 확인해 보고한 후 멈춘다.
  다음 묶음·G14 등 후속 작업은 별도 사용자 지시를 기다린다. 별도 승인 질문은 추가하지 않는다.
- `.tmp` run의 렌더 SVG·PNG는 임시 QA 출력이며 Git에 넣지 않는다. 검증 후 Archive에 게시하는 자산과 QA 출력은 구분한다. Git에는 ROOT가 지정한 운영물만 명시적으로 추가하고 원시 로그·검수 증거는 Drive 정책에 따라 보관한다.
  증거가 없거나 접근할 수 없다면 PASS로 바꾸지 않는다. 타 작업자의 변경을 되돌리지 않는다.
- 완료 보고에는 시험지별 판정·실제 게시 문항·SVG 해시·렌더/검수/테스트 결과, 미실행과 남은 문제를 적는다.
