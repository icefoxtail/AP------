# SVG 캠페인 — Codex 실행 인계

> **최신 모델 지시(2026-11-04):** 관리자는 Astra medium. 기존 Terra·Sol 작업은 중지하고 산출물·검수 증거를 인계한다. 제작은 `gpt-6-luna` high 여러 인스턴스에 유형과 허용 파일을 겹치지 않게 배정하고, 독립 검수는 별도 `gpt-6-luna` xhigh가 맡는다. 아래 Terra/Sol 표기는 이전 배정의 인계 맥락이며 재개 지시가 아니다. 동일 해시의 유효 PASS를 승계하고 변경분만 재검한다. 모델 변경으로 검수 기준을 낮추지 않는다. 이번 승인 10개 묶음의 main 병합·보고 후 멈춘다.

이 문서는 Codex가 기존 SVG 엔진으로 기출 해설 그림 캠페인을 이어갈 때의 역할과 실행 계약이다.
Claude용 `HANDOFF_SVG_ENGINE.md`는 유지한다. Codex의 모델·역할·동시 실행은 이 문서를 따른다.
그림의 수학·교육 기준은 기존 정본을 따른다. 이 문서 작성은 생산·게시·검수 완료가 아니다.

## 2. 역할과 권한

- **ROOT(관리자 Astra medium)**: 시험지와 정확한 문항별 배정을 확정하고, 원문·실제 문제 그림·해설·정답 및 현재 자산을 직접 확인한다. 질문별 run 경로와 쓰기 허용 파일을 지정하고, 전역 렌더 큐와 시도 예산을 관리한다. 최종 SVG와 PNG를 모두 직접 확인하고 독립 검수 결과를 수납한 뒤 게시·원장·Git을 책임진다.
- **Luna 제작자**: 서로 다른 `gpt-6-luna` high 인스턴스 여러 명이 맡는다. 각 인스턴스에는 겹치지 않는 정확한 문항과 그 문항의 쓰기 경로만 배정한다. 제작자는 packet의 발문·정답·해설과 실제 원본 그림을 직접 읽고, 소유한 run 안에서 item·plan·publish 초안을 작성하고 해당 문항 지적만 수리한다. 엔진, 시험지 JS, 공유 원장, 공용 파일, 다른 문항 run은 변경하지 않는다. 허용 경로 밖 변경이 필요하면 경로·이유·재현 근거를 ROOT에 보고한다.
- **독립 검수자**: 별도 `gpt-6-luna` xhigh 인스턴스가 실제 SVG·PNG, 원문·정답·해설 및 alt·caption을 독립 검수한다. 최초 배정분 전체를 확인하고, 이후에는 바뀐 해시의 문항만 재검한다. 검수자는 원문 읽기, 해시 계산, 독립 수학 계산과 실제 그림 확인을 수행한다. 허용된 검수 결과물 외 파일 수정, 그림 수리, 렌더, 테스트 실행, 게시와 Git은 맡지 않는다.
- 별도 인스턴스에는 필요한 원문·필수 조건·정확한 문항·경로·쓰기 허용 목록을 명시한다. 사용자 지시 없는 재위임은 금지한다. DeepSeek/OpenCode를 호출하지 않으며, 모델을 사용할 수 없으면 정확한 실패 사유를 ROOT에 보고하고 대체하지 않는다.
- **엔진 업그레이드·진단**: `gpt-6.1-sol` high가 엔진 업그레이드와 공백 진단, 어려운 문항·배치 차단 분석을 맡는다. 관리자 추론 수준 Astra medium은 유지하며, 난도·범위·실패 횟수를 근거로 Astra에 자동 승격하지 않는다. 담당 변경은 사용자의 별도 지시가 있어야 한다. Astra가 이전에 완료한 진단은 역사 기록으로 보존하고 현행 담당 배정으로 해석하지 않는다. 제작자의 개별 plan·그림 수리 역할과 혼동하지 않는다.

## 3. 대상과 중복 방지

- 기준 범위는 `archive/exams/original/**`의 해당 기출이며, 문제용·해설용 필요성은 독립 판정한다.
- 인계 당시 다음 순서는 ⑤ 23년 중1 3개 + 중2 5개, ⑥ 23년 중3 5개 + 고1 3개,
  ⑦ 23년 고2 13개, 그다음 G14(중1 위치관계)다. 숫자는 계획 당시의 대상 수이며 자동 착수 지시가 아니다.
- 현재 승인된 10개 시험지 묶음을 마친 뒤 보고하고 멈춘다. 다음 묶음이나 G14는 별도 사용자 지시 전 시작하지 않는다.
- 착수 전에 실제 `production/exam-figure-ledger.json`, 시험지의 현재 그림과 최근 관련 커밋을
  확인하여 이미 처리된 시험지는 건너뛰고, OPEN·누락·교체 필요 항목만 정확히 배정한다.
- 인계 문서의 303 PUBLISHED / 192 EXEMPT / 6 OPEN은 ③④ 당시 수치이며 현재 집계가 아니다.
- 기존 그림은 ROOT가 문제 그림 옆에서 직접 보고 풀이 방식·중간값·가독성을 판단한다.
  엔진 밖 그림은 교체를 기본으로 삼되 실제 교육 가치와 필요성을 확인한다.
- 학년별 약 10개 시험지를 모아 원본 전체 문항 분모를 고정하고 각 문항을 FIGURE / REPLACE / KEEP / EXEMPT / CONTENT / UNSUPPORTED로 근거와 함께 분류한다.
  문제·해설과 원문 그림을 읽고 결정 관계, 기존 그림, 새 시각 정보와 판정 근거를 남긴다.
  원문이나 필수 그림이 없거나 내용이 불일치하면 사실과 근거를 기록하고 임의로 PASS하지 않는다.

## 4. Windows 준비와 이식 상태

- 이 환경은 Windows/PowerShell이다. 기존 Linux 예제의 `/home/user/AP------`, `python3`,
  `timeout`, 셸 환경변수 구문을 Windows에서 그대로 실행하지 않는다.
- `ops/svg-m1/`의 도구·지시서를 `.tmp/svg-m1/`에 복원하고 `runs/`, `packets/`를 분리한다.
  기존 run·증거를 덮어쓰지 않도록 ROOT가 실제 경로와 상태를 먼저 확인한다.
- 저장소의 Windows 이식 도구로 `make-packet` 3건 실행과 legacy source 별칭 개선을 확인했다.
  portable publish 5개 테스트와 packet 1개 테스트는 초기 검증을 통과했다. 이 결과는 실제 게시 완료가 아니다.
- 새 게시 인터페이스는 `py <도구경로>/pubflow.py --batch <manifest.json>`이다.
  manifest는 `exam`, `review`, `rows`, `triage`, `camp`를 명시하며 상대 경로는 manifest 폴더 기준이다.
  Windows 도구 포팅과 이 문서에 적힌 관련 실행 검증은 완료됐다. 현재 승인된 10개 묶음의 실제 게시가 진행 중이며, 묶음 전체 완료로 보지 않는다. 기존 Linux 인자와 고정 Sonnet 문구를 사용하지 않는다.
- 각 단계에서 종료 코드와 JSON 분모·결과를 확인하고 Windows 경로·공백은 argv 배열로 전달한다.
  UTF-8과 실제 Chrome 경로를 확인한다. 임시 `.tmp` helper를 Git 정본 필수 도구로 취급하지 않는다.
- 도구 보정과 실제 게시·검사는 ROOT가 소유한다. 시험지 제작자에게 공용 도구 수정 권한을 주지 않는다.
- Python 의존성, Chromium/Chrome 및 브라우저 경로는 실제 설치를 확인한 뒤 설정한다.
  Windows에서 직접 require/import할 때 경로와 file URL 처리는 기존 HANDOFF §3을 참고해 검증한다.

## 5. 시험지별 처리

1. ROOT가 원장·최근 커밋·현재 자산을 확인하고 학년별 약 10개 시험지의 원본 전체 문항을 triage한다.
2. 원본과 packet의 문항 수·발문·이미지 참조를 대조해 분모 누락을 막고 중간값과 쓰기 경로를 정한다.
3. ROOT가 GRAPH / GEOMETRY / PROBABILITY 형태와 시험지별 분모를 바탕으로 정확한 문항을 여러 Luna high 제작자에게 겹치지 않게 배정한다. 각 제작자는 자기 문항의 run만 소유한다.
4. Luna 제작자는 원문 packet과 실제 원본 그림을 확인한 뒤 item·plan·publish를 작성한다. 계획이 끝나면 ROOT가 승인한 예산과 고유 revision으로 `render-request.json`을 준비한다. `.rendering`이 있는 동안 입력을 수정하지 않는다.
5. ROOT만 전역 큐를 한 번에 하나씩 실행한다. `.tmp/svg-m1/runs/.../out/`의 실제 SVG와 PNG는 시각 QA용 임시 출력이며 Git에 넣지 않는다. 같은 출력 폴더 재렌더 전에 ROOT가 provenance 충돌을 방지하고 상태·오류·경로·시도 수를 기록한다.
6. 순서는 draft → ROOT 큐 → 실제 SVG·PNG → 독립 검수다. ROOT는 실제 SVG와 PNG를 원문·해설·정답에 직접 대조하며, 계획이나 제작자 보고만으로 PASS하지 않는다.
7. 별도 Luna xhigh가 실제 SVG·PNG와 alt·caption을 독립 검수한다. FAIL은 같은 문항 소유 Luna에게 구체적으로 돌려주고, 실제 렌더 후 바뀐 문항만 같은 xhigh가 재검한다. PASS는 게시 필요조건이며 최종 게시 여부는 ROOT가 판단한다.
8. 각 단계의 SVG·PNG·publish.json 세 SHA-256을 검수·게시 기록에 결속한다. 셋 중 하나가 바뀌면 영향 범위를 다시 확인하고 재검한다.
9. 검증된 게시 경로에서만 실제 게시·표시 확인·관련 테스트·원장 갱신을 수행한다.
   승인된 묶음 안에서 처리된 시험지의 상태, 소요 시간과 잔여 사유를 기록한다.

## 6. 그림과 독립 검수 기준

- 학생이 해설의 풀이를 따라갈 수 있도록 문제 그림의 점 이름·배치와 실제 풀이 관계를 보존한다.
  핵심 중간값은 넣되 과밀을 피하고 정답·보기 번호·서술형 각 소문항의 답은 caption 끝에 둔다.
- 범위·최솟값의 경계 곡선과 직선은 풀이 핵심이므로 그린다. 정답인 점근선 값이나 교점 값 자체는
  `hideLabels` 등으로 숨긴다. 중간값을 정답 노출로 오인하여 제거하지 않는다.
- 같은 각·길이·평행·대응·넓이 등 핵심 관계는 읽기 쉬운 색으로 묶는다.
  떠 있거나 헷갈리는 필수 라벨은 지시선·끌어낸 패널부터 시도하고 삭제로 통과시키지 않는다.
- 점 이름은 안쪽, 길이 치수선은 바깥에 두고, 짧은 치수선을 안쪽에 둔다.
  학생에게 보이는 텍스트에 `^2`, `sqrt`, `*` 등 입력 표기를 그대로 남기지 않는다.
- 그래프의 함수 이름과 풀이에 필요한 교점이 보이게 한다. 예시 값은 caption에 예시임을 밝히고,
  근사로 만든 좌표를 주어진 값처럼 쓰지 않는다. 필요한 경우 등축척을 쓴다.
- Luna xhigh 검수자는 실제 candidate를 보기 전에 문제 그림과 content·solution에서 기대 관계·배치·중간값을 `expected`로 정리한다.
  이어 실제 SVG와 PNG, alt·caption을 보고 수학 관계, 잘림·겹침, 정답 노출 및 가독성을 확인한다.
- 과거 `review1.md`의 A-only 입력과 A/B 출력 문구 충돌은 아래의 A-only/A-B 검수 구분으로 처리한다.
- **신규 그림**은 A만 판정한다. A에 PASS / FAIL / MISSING과 구체적 근거를 기록하며 B·better를 만들지 않는다.
- **기존 그림 교체**는 새 A와 기존 B를 독립 판정하고 `better` A / B / TIE와 이유를 기록한다.
  A PASS와 better=A를 기본 게시 조건으로 한다. TIE는 원장이 OPEN일 때만 기존 규칙에 따라 판단한다.
  교체 rows에는 `replace: true`를 넣는다. ROOT는 실제 기존 그림과 비교해 최종 결정한다.
- 검수 기록에는 시험지·ord, expected, 각 판정·결함, SVG SHA-256, 검수 인스턴스와 시점을 남긴다.
  수리 후 최종 SVG의 해시와 일치하는 PASS가 없으면 게시하지 않는다.

## 7. 병렬성·실패·게시

- 같은 학년·회차의 시험지를 묶고 그림 형태별 담당자를 고정한다.
  서로 겹치지 않는 묶음 2~3개를 병렬 배정할 수 있고 각 run 소유자는 하나다.
  묶음 크기가 커져도 전 문항 분모·시험지별 상태·최종 자산별 검수는 유지한다(2026-11-04 사용자 지시).
- 무거운 렌더와 테스트는 전역에서 동시에 하나만 실행한다. ROOT가 큐와 결과를 관리한다.
  계획 병렬화는 독립 검수나 최초 대상 전수 확인을 줄이는 근거가 아니다.
- 5회 실패하면 제작자는 멈추고 모든 시도·오류·남은 문제를 ROOT에 넘긴다. 추가 시도는 ROOT가 별도 예산으로 명시적으로 허용할 때만 수행하고 횟수와 근거를 기록한다.
  실패 횟수를 숨기거나 한도를 조용히 올리고 기존 검사를 약화하지 않는다.
- 엔진 기능이 부족하면 오류 코드·필요 기능·시도한 plan을 UNSUPPORTED로 남긴다.
  엔진 확장은 시험지 작업자 범위 밖이다. ROOT가 공백을 수납하고 별도 지시서·소유 경로·독립 검수·관련 골든 회귀를 배정한다.
  사용자 승인 범위를 벗어나는 확장만 먼저 보고하여 승인을 받는다.
- CONTENT 오류는 문제와 원문 근거로 다시 계산한다. 확실한 수정의 범위와 공유 데이터 영향은 ROOT가 판단한다.
  불확실하거나 선택지에 답이 없거나 복수면 근거를 보고하고 추측해 바꾸지 않는다.
- 실패, 누락, 미실행은 정확한 명령·종료 코드·영향 문항과 함께 FAILED / MISSING / NOT_RUN 등으로 기록한다.
  근거가 부족하면 EVIDENCE_DEBT로 남기며 검사 약화나 허위 PASS를 금한다.
- 원본 JS 수정 시 `docs/agents/common.md`의 공유 데이터 고정값을 지키고 관련 테스트를 실행한다.
  병합 전 PR CI가 모두 녹색인지 확인한다. 병합·CI·Pages·학생 배포 결과는 따로 보고한다.
- 생성과 독립 검수가 끝나면 ROOT가 모든 최종 SVG와 PNG를 원문과 직접 비교하고 평면·입체·그래프·확률 등 검수 통과 대표 최종 그림 여러 장(기본 4~6개)을 모아 사용자에게 먼저 보여준다.
  필수 CI가 녹색인지 확인한 뒤 main을 병합하고 remote readback 및 실제 학생 페이지 QA 결과를 확인해 보고한 후 멈춘다.
  다음 묶음·G14 등 후속 작업은 별도 사용자 지시를 기다린다. 별도 승인 질문은 추가하지 않는다.
- `.tmp` run의 렌더 SVG·PNG는 임시 QA 출력이며 Git에 넣지 않는다. 검증 후 Archive에 게시하는 자산과 QA 출력은 구분한다. Git에는 ROOT가 지정한 운영물만 명시적으로 추가하고 원시 로그·검수 증거는 Drive 정책에 따라 보관한다.
  증거가 없거나 접근할 수 없다면 PASS로 바꾸지 않는다. 타 작업자의 변경을 되돌리지 않는다.
- 완료 보고에는 시험지별 판정·실제 게시 문항·SVG 해시·렌더/검수/테스트 결과, 미실행과 남은 문제를 적는다.
