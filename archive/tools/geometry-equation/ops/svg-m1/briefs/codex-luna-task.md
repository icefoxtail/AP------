# Codex Luna 문항별 작업 배정 계약

ROOT가 작성해 제작 Luna high와 별도 검수 Luna xhigh에 같은 대상 목록을 전달한다. 이유: 유형 이름만 전달하면 불필요한 그림, 필수 중간값 누락, 배정 누락과 중복이 생긴다.

## 배정 전 ROOT 확인
- 승인된 시험지 묶음 안의 정확한 sourcePath/ordinal을 고정한다.
- 원본 그림만으로 충분한 문항과 단순 확률 계산은 EXEMPT로 정리한다. 그림을 만들 수 있다는 이유로 배정하지 않는다.
- 같은 문항을 두 제작자에게 배정하지 않는다. 기존 담당자의 결과와 시도 이력을 먼저 수납한다.
- 문제·보기·답·해설·모든 소문항 및 inline 이미지를 확인한다. 불확실한 사실은 확정값처럼 지시하지 않는다.

## 작업지시서 필수 항목
1. **대상:** 시험지명, sourcePath, ordinal, 원본/inline 이미지의 정확한 경로.
2. **판정:** FIGURE/REPLACE와 교육적 추가 정보 한 줄. KEEP/EXEMPT를 임의로 재제작하지 않는다.
3. **필수 사실:** 주어진 조건, 핵심 보조선·관계, 반드시 표시할 중간값과 각 값의 owner.
4. **정답 분리:** 구하는 값과 소문항별 답. SVG에 노출하지 않을 항목을 지정하고 caption 끝에 둔다.
5. **구현 범위:** 사용할 capability/관련 guide 절, 실제 통과한 유사 plan과 실제 렌더 샘플 경로. 원문에 없는 조건을 샘플에서 복사하지 않는다.
6. **현재 상태:** 기존 plan/SVG/검수 결과, 마지막 정확한 오류, 이미 사용한 렌더 횟수와 전문 수리 이력.
7. **소유권:** 쓸 수 있는 정확한 파일/폴더 목록, 읽기만 가능한 원문·엔진·타 작업자 파일. 공유 변경을 되돌리지 않는다.
8. **제출:** item.json, plan.json, publish.json, ready marker. 게시 크기는 실제 render-result의 sizeClass와 맞춘다.
9. **검수 연결:** 담당 검수자 이름과 같은 대상 목록. 안정본 전달→독립 검수→같은 제작자 수리→변경분 재검을 직접 이어간다.
10. **완료 조건:** 실제 SVG 생성, 원문 대조, 최종 SVG/미리보기/publish 해시 결속 PASS. 초안 작성은 완료가 아니다.

## 제작자·검수자 공통
- 지시서의 수학적 사실도 원문과 대조한다. 충돌하면 정확한 문항·조건·계산을 보고하며 추측해 덮지 않는다.
- 정답과 핵심 중간값을 구별하고, source 점 이름·소유 관계를 보존한다.
- 기존 지원 필드부터 확인한다. 필수 라벨 삭제·폰트 축소·관측기 완화로 통과시키지 않는다.
- `.rendering` 중인 입력은 수정하지 않는다. 시도 한도를 숨기거나 새 폴더로 초기화하지 않는다.
- 검수자는 제작자 자기보고를 PASS 근거로 삼지 않고 실제 최종 SVG와 원문을 확인한다.
- 범위 밖 문항·메타·원본 내용·엔진·Git·배포 작업은 임의로 시작하지 않는다.
