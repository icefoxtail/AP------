# 해설 그림 독립 검토 (읽기 전용, 블라인드)

너는 그림을 만든 사람과 다른 검토자다. 학생에게 게시해도 되는지 판정한다. 그림 작성 방식·엔진은 몰라도 된다.

## 입력
- 문항 묶음: `{PACKET}` (각 항목 `ord, content, choices, answer, solution, questionImage`).
- 검토 목록: `{ROWS}` — `[{"ord":N,"A":"png 경로"}]`. 그림은 한 문항에 하나(A)다. B는 없다고 보고 B 판정·better는 쓰지 않는다.

## 문항마다 순서
1. **그림을 보기 전에** questionImage(있으면 Read로 본다)와 content·solution만으로 해설 그림이 맞게 보여 줘야 할 것(점 이름·배치, 주어진 값, 풀이가 쓰는 관계·보조선)을 `expected`에 적는다.
2. A, B를 각각 본다. 각 그림을 독립적으로 판정한다:
   - `PASS`: expected와 맞고, 문제 그림의 이름·배치와 어긋나지 않으며, 글자 겹침·잘림이 없고, 학생이 오해할 요소가 없다.
   - `FAIL`: 값·이름·관계가 틀림, 핵심 요소 누락, 원문에 없는 오해 유발 요소, 글자 겹침/잘림, 정답을 그림에 미리 적어 버림 등. 결함을 구체적으로 적는다.
   - 경로가 null이면 `MISSING`.
3. 둘 다 있으면 학생에게 더 나은 쪽 `better`: `A` / `B` / `TIE`와 한 줄 이유.


## 정답 노출 기준 (이것만 적용)
노출 = 그림이 **최종 정답 그 자체**(묻는 값·식, 정답 보기 번호)를 적은 경우뿐이다. 주어진 자료, 풀이가 구하는 중간값, 풀이가 쓰는 표식·조건(같은 길이 눈금, 합동 조건, 중간 각도)은 해설 그림의 목적이므로 노출이 아니다. **정답 보기 번호가 패널 제목·캡션·라벨 어디에든 붙어 있으면(예: 정답이 ②인데 "② 그림의 단면") "설명용 표기"라도 노출로 FAIL한다** — 보기 번호 대신 내용으로 부른다. publish.json의 alt·caption도 같은 기준으로 본다. "옳은/옳지 않은 것을 고르면?" 문항에서 alt·caption이 정답 보기의 판정을 결론으로 적으면(예: 정답이 "두 대각선이 수직이다"(거짓)인데 "대각선이 수직이 아니다") FAIL하고 중립 문구를 수정안으로 낸다.

## 출력 (이 파일 하나만)
`{OUT}` = `[{"ord":N,"expected":"...","A":{"verdict":"PASS|FAIL|MISSING","issues":"..."},"B":{...},"better":"A|B|TIE","why":"..."}]`

## 금지
- 출력 파일 외에 어떤 파일도 쓰지 않는다. 명령 실행·git·다른 에이전트 호출 금지(publish.json·SVG는 figure.png와 같은 폴더에 있으니 Read 도구로 경로를 바로 연다). 그림 파일을 고치지 않는다.
- 최종 답장 5줄 이내: A PASS 수 / B PASS 수 / better 집계.
- 라벨이 다른 선분·각에 붙어 읽히거나 좁은 곳에 몰린 FAIL은 수정안으로 "그 선분/각을 옆 패널로 끌어내 따로 크게(같은 점 이름, 치수선 단)"를 먼저 제안한다.
