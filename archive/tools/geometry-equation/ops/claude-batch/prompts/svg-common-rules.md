# 해설 SVG 공통 규칙 (집 PC·학원 PC 공통)

두 PC의 해설 SVG 라인이 같은 기준으로 그리고 검수하도록 공통 규칙을 한곳에 모은 문서다. 각 PC 지시서(sonnet-exam-create/impl/brief, 학원 sonnet-impl/sonnet-review-final)는 이 파일을 참조하고, 겹치는 규칙 줄은 지시서에서 지운다.
- 이유: 두 PC 지시서가 따로 갈라져, 같은 그림(좌표 띠)을 한쪽은 결함, 다른 쪽은 정상으로 판정한 일이 있었다.
- 고치는 방법: 먼저 고친 쪽이 다음 출고 PR에 함께 넣는다. 상대 PC는 main을 받아서 쓴다. 같은 파일을 두 PC가 동시에 쓰지 않는다.

## 1. 흐름

1. **Sonnet A (시험지 1개당 1명).** 판정, 플랜, 구현, 자체검수를 맡는다. 이유: 시험지 2개를 맡기면 문맥이 섞인다.
2. **Sonnet B (다른 인스턴스).** 최종 검수를 맡는다. 보고에 "직접 연 PNG 수/그림 문항 수"(예: 11/11)를 꼭 적는다. 그림 문항의 PNG는 전부 직접 열고, compare.png가 있으면 그것도 연다.
3. **출고 작업자 (Sonnet, effort low).** build-pub, manifest, 고정값 테스트, PR 준비를 맡는다.
4. **메인.** 표본 PNG와 필수 PNG를 직접 확인하고 PR을 만든다. CI가 녹색이면 머지한다.
5. **배치 회고.** 머지할 때마다 상대 PC에 짧게 보낸다. 항목: 배치 번호·시험지 수, 시험지당 토큰, B 반려 건수와 유형, 새 규칙, 엔진 공백.

## 2. 그림 내용

- **정답 노출 금지.** 그림, alt, SVG `<title>`에 정답 값을 넣지 않는다. 길이·좌표처럼 문장 속에 섞인 값도 해당한다(예: alt "길이 5인 변 BC"). 보조선(중앙값 점선 등)이 답 일부를 드러내지 않는지도 본다. title은 플랜 caption에서 가져오므로 plan.json caption에는 정답 값과 "정답은 …" 끝맺음을 넣지 않는다. 정답 끝맺음은 publish.json caption에만 쓴다(SVG title은 마우스를 올리면 보인다, 학원 사례). 정답이 경계값이면 범위 안의 예시를 그린다.
- **좌표 라벨.** 기본은 점 곁에 둔다. 점이 빽빽하면 그림 위에 점 이름을 붙인 `A(x, y)` 띠를 써도 정상이다.
  - 결함으로 보는 경우: 자리가 넉넉한데 띠로 밀린 것, 띠에 점 이름이 없는 것, 띠에 정답 값이 있는 것, 가리키는 대상 없이 떠 있는 식이나 글자.
- **색 구분.**
  - 색 순서는 BLUE → WARM(주황) → GREEN → ROSE로 한다.
  - 직선은 곡선과 다른 색을 쓴다.
  - S₁과 S₂처럼 다른 영역은 다른 색, 넓이가 같은 영역은 같은 색으로 칠한다.
  - caption에 색 이름을 적는다.
  - 통계 점그림은 `pointGroups`로 점 색을 나눌 수 있다. 구현자가 자주 놓친다(학원 22 연향 Q13~15·Q21).
  - 엔진에 색 옵션이 없는 계열(정규분포 영역, numberLine 등)은 진하기 두 단계나 점선·실선 같은 다른 수단으로 구분한다. 이 경우 TABLE에 "색 옵션 없음"을 적고 ENGINE_GAPS에 올린다.
- **표기.**
  - 분자가 여러 항인 분수는 읽는 말에 괄호를 붙인다("2분의 (k−1)").
  - `^C`, `^2` 같은 입력 표기를 남기지 않는다(ᶜ, ²).
  - caption, alt, condition에 대문자 4자 이상이 이어진 점 이름("ABCDE")을 쓰지 않는다. check-archive2-runtime의 학생 언어 검사에 걸린다.
- **합동·닮음은 두 그림을 함께(사용자 지시 2026-11-10).** 합동·닮음 해설 그림은 composite-panels-v1 한 장에 담는다. ① 문제 배치 그대로 ② 대응하는 두 도형을 떼어 같은 방향으로 나란히 펼친 그림. 대응하는 변·각은 두 패널에서 같은 색과 같은 표시를 쓴다. ②가 없으면 검수 FAIL이다. 문제에서 이미 두 도형이 떨어져 같은 방향이면 ②는 생략할 수 있다. 이유: 중등 학생은 펼쳐 보지 않으면 대응을 이해하지 못한다(원문: PR #1616, docs/agents/visual-svg.md).
- **축 비율.** 기울기 ±1인 직선이나 원이 있으면 축을 1:1로 한다.
- **곡선 구간.** 곡선은 꼭짓점·점근선 같은 핵심 점을 가운데 둔 대칭 구간으로 그린다. 축에서 뚝 끊겨 정의역이 잘린 것처럼 보이면 결함이다(23 팔마 1final Q07).
- **수직선 끝값.** 정답이 끝값에서 바로 나오면(p+q 등) 끝값 대신 문자로 표시한다(23 매산 1final Q17).
- **정답만 가린다.** 정답 노출을 피할 때는 최종 정답 값만 문자나 "?"로 가리고, 해설이 거쳐 가는 중간값은 그림에 남긴다. 숫자를 모두 지우면 학생이 해설을 따라갈 수 없다(23 순천여 2mid Q21 벤다이어그램).
- **한 페이지에 맞추려고 그림을 미리 줄이지 않는다.** 해설 길이를 이유로 그림을 작게 하거나 패널·내용을 빼지 않는다(사용자 결정 2026-11-10: 양질의 해설이 우선). 게시 검사 verify-published가 실제로 MEASURED_SOLUTION_CHUNK_EXCEEDS_PAGE로 막을 때만(지금까지 2건: 학원 18 연향 Q17, 집 25 팔마 1final Q20) 그 문항을 메인에 보고하고, 내용을 덜지 않는 구성 변경(가로로 넓은 구도, 빈 공간 줄이기)으로 푼다. 검사는 끄거나 완화하지 않는다.
- **크기 등급은 full이 기본.** 해설 SVG는 모두 size "full"로 요청한다(사용자 결정 2026-11-10). 이유: full이 아닌 등급은 학생 화면에서 높이가 눌려(medium 145px, large 180px) 세로로 긴 그림이 심하게 작아진다. 도형은 캔버스를 채우게 그리고, 위치가 자유로운 예시 곡선은 서로 붙여 빈 공간을 남기지 않는다.
- **단순한 그림만 너무 커지지 않게 한다.** 복잡한 그림(패널 여럿, 라벨 많은 그래프)이 커지는 것은 괜찮다. 막을 것은 삼각형 하나·벤다이어그램 하나처럼 라벨 서너 개뿐인 그림이 화면을 가득 채우는 경우다(사용자 결정 2026-11-11). 그래프는 coordinateCanvas를 작게(최소 384) 잡아 라벨 크기는 그대로 두고 그림만 작게 한다. 캔버스가 고정인 도형·집합 그림은 엔진 지원 전까지 full로 두고 TABLE.md에 "단순 그림"이라고 적어 둔다(나중에 작은 캔버스로 다시 낸다). 라벨을 줄이거나 크기 등급을 낮춰 작게 만들지 않는다.
- **그림은 여러 개가 낫다.** 풀이가 여러 단계나 여러 표현(도형과 그래프, 경우 나누기, 변형 전후)을 거치면 단계마다 패널을 두어 여러 그림으로 보인다(사용자 결정 2026-11-10: 학생이 도형을 여러 개 보는 편이 낫다). 한 장으로 줄이려고 패널을 빼지 않는다. 패널마다 무엇을 보이는지 한 줄 제목을 달고, 각 패널이 작아지지 않게 full로 요청한다.
- **축 이름은 바꿀 수 있다.** 가로·세로축이 x, y가 아니면(t와 넓이 S, 시간과 거리) 그래프 plan에 `graphPlan.axisTitles:{"x":"t","y":"S"}`를 쓴다. composite-panels-v1의 그래프 패널도 패널마다 쓴다. 축 이름 때문에 패널을 빼거나 UNSUPPORTED로 두지 않는다(22 강남여 1mid Q20에서 이 필드를 몰라 넓이 그래프 패널을 뺐다). 수학 기호(S, t)가 한글 이름보다 굵고 또렷하게 나온다.
- **증명 문항.** caption 끝은 "증명 과정은 해설과 같다." 식으로 쓴다. "정답은 증명이다."처럼 쓰지 않는다.
- **집합 원소 글자.** 벤다이어그램·집합 그림의 원소 식은 ASCII 하이픈("43-x")으로 쓴다. 유니코드 −("43−x")는 가는 일반 글꼴로 나온다(23 매산여 2mid, 이미 게시된 23 강남여 2mid Q04도 해당 — 학원 title 정리 PR 병합 뒤 재게시).
- **교육과정.** 그 학년 교육과정 밖의 그래프는 EXEMPT로 둔다(예: 고1의 삼차 이상 함수 그래프).
- **곡선 이름 머리글.** 곡선 하나에 엔진이 자동으로 붙이는 식 머리글은 정답을 드러내지 않으면 그대로 둔다.
- **같은 내용을 두 번 쓰지 않는다.** 축 눈금 "1"과 "x=1" 라벨처럼 같은 값을 두 번 보이지 않는다. 하나만 남긴다.
- **정답이 도형 모양이면 그 모양을 그리지 않는다.** 정답이 "빗변이 b인 직각삼각형"처럼 도형의 모양이면 그 모양을 그려 정답을 노출하지 말고 일반 모양의 도형을 그리거나 EXEMPT로 둔다(22 강남여 1mid Q18).
- **곡선 이름 지시선의 점은 곡선 중간에 둔다.** 끝에 두면 끝점으로 읽힌다. 문제에 주어진 식이면 점 없는 자동 식 라벨을 쓴다.
- **겹치는 구간의 길이는 펴 그린다.** AB와 AD처럼 겹치는 구간의 길이는 그림 아래에 따로 펴 그린 선분과 치수 표시로 보인다.

## 3. 판정·이어받기

- **KEEP_EXISTING.** 신형 엔진 마커를 확인한 뒤에만 쓴다(정규분포는 z축 포함). SVG `<title>`에 정답 값이 있으면 REPLACE한다.
  - 사례: 25 강남여고 수학II Q06·Q07·Q11·Q15·Q16·Q24.
- **이어받기.** 기존 qNN 결과물을 그대로 믿지 않는다. figure-result가 지금 plan의 렌더 결과인지(시간과 내용), 한글이 ?로 깨지지 않았는지 확인한다. 의심되면 다시 렌더한다.
- **직접 지정한 좌표 검산.** 선분 끝점·점 좌표를 손으로 정했으면 문제의 식과 조건(교점, 지나는 점)에 대입해 확인한다. 엔진은 틀린 값을 그대로 그린다(23 복성 1final Q14: l′ 끝점이 다른 직선 위에 있어 핵심 교점 조건이 깨졌는데 A가 놓쳤고 B가 찾음).
- **플랜 본뜨기.** 비슷한 기존 플랜을 본떠도 된다. 그때는 출처 경로를 TABLE 비고에 한 줄 적고, 값·점·식은 원문 기준으로 다시 확인한다.

## 4. 원문 문제

- **기계적 데이터 손상.** `"$1"→","`, 이중 역슬래시처럼 기계적으로 깨진 데이터는 그림 작업 전에 별도 PR로 먼저 복구하고, 나중에 보고한다(사용자 지시).
- **정답·해설 오류.** 정답이나 해설이 직접 계산과 어긋나면 그리지 않고 CONTENT로 넘긴다. 보고에는 근거를 붙인다(직접 계산, answerSource가 정답표인지 독립 풀이인지). 메인이 원문 그림까지 확인한 뒤 사용자 승인을 받아 별도 PR로 고친다. 원본을 고치면 sourceFingerprint도 갱신한다.
- **원문 오류는 최소 수정으로 고친다.** 문제 글·보기·해설이 수학적으로 성립하지 않으면 원본 스캔 대조를 기다리지 않고, 문항이 성립하는 최소한의 수정(값·부호)으로 고친다(사용자 결정 2026-11-11: 원본 보존보다 학생이 풀 수 있는 문항이 우선). 제작자와 검수자가 각각 직접 계산해 같은 결론일 때만, 그림 출고와 별도 PR로, 공유 데이터 고정값 절차(docs/agents/common.md)를 따른다. 정답이 바뀌거나 문항 의도를 바꿔야 하는 경우도 메인이 판단해 진행한다(사용자 결정 2026-11-11: 자연스러운 수정이고 건수도 적다). 그때는 정답·해설·보기를 함께 맞추고 PR 본문과 사후 보고에 바뀐 정답을 적는다. 작업자는 원문을 직접 고치지 않고 보고에 before/after와 계산 근거를 적는다.
- 생성문항은 건드리지 않는다.

## 5. 작업 위생

- 게시 도구(make-dec-exam·build-pub·pubflow)는 `PYTHONUTF8=1`로 실행한다. 없으면 한글 콘솔에서 UnicodeEncodeError가 난다. 문자열 문항 id(q01, s01) 시험지도 지원한다: ord는 id 그대로, 파일 이름은 `<id>-solution.svg`, TABLE·폴더 번호는 문제은행 순서.

- 대기용 모니터나 감시 스크립트를 남기지 않는다. 정리할 때는 자기가 띄운 PID만 끈다.
- Sonnet은 PC당 동시에 2개까지 돌린다.
