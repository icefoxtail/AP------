# Frozen source condition inventory comparison v1

`compareFrozenSourceConditionInventories({root,leftRef,rightRef})` is a synchronous, local-file diagnostic for two already frozen `CONDITIONS_SOURCE_BLIND` records. It reads each JSON document through the existing `readBoundFile` byte/path binding, parses the bytes it read, and returns new derived data. It does not call a provider, retry, write files, or modify caller-owned values.

## Accepted record contract

Each bound JSON file must be a plain object with `output.status === "PASS"`, an accepted closed `CONDITIONS` blind payload, nonempty `payload.sourceConditions`, and empty `payload.uncoveredConditions`. Every condition row has exactly `{id, condition}`; both values must be nonblank strings. Raw IDs must be unique and their NFC forms must not collide. Row indices in results are zero-based positions in the frozen inventory.

`inputPacket` has exactly `instruction`, `visibility`, `source`, `policySha256`, and `inputBindingSha256`. It must be a nonblank instruction with `visibility: "SOURCE_ONLY"`, and a source with exactly `{content, choices, sourceImageRequired}`. Content is a string; choices is null or an array of strings; the image-required flag is boolean. Student-only leak checks apply. Policy, input binding, `inputSha256`, and every ordered `imageShas` entry use the existing prefixed SHA-256 form. `inputSha256` must equal `objectSha(inputPacket)`. The frozen file itself is separately checked against `leftRef` or `rightRef` for raw byte length, SHA, and safe path.

The two student source objects are compared with Node's `isDeepStrictEqual`: text is raw and exact here, including Unicode representation. Ordered image hash lists and policy hashes must also match. Mismatches throw `SOURCE_INPUT_MISMATCH`, `SOURCE_IMAGE_BINDING_MISMATCH`, or `SOURCE_POLICY_MISMATCH`. `inputBindingSha256` values are retained as opaque legacy provenance and may differ. If the shared source says an image is required but the records have no image hash claims, the function throws `REQUIRED_IMAGE_BINDING_MISSING`; it does not inspect physical assets or diagnose whether an image file exists.

## Text matching and result

Only complete condition text is normalized, using Unicode NFC and no other transformation. There is no trimming, whitespace normalization, line-ending rewrite, delimiter removal, NFKC conversion, token/entity reordering, or algebraic simplification. Matching walks left rows in original order and pairs each with the first still-unmatched right row whose NFC text is equal. IDs are local and are preserved as witnesses, never used for alignment. Repeated rows retain multiplicity. Pairing duplicate occurrences is bookkeeping only; it does not claim source location or mathematical alignment.

The result has `schemaVersion: "SOURCE_INVENTORY_COMPARISON_v1"` and `normalizationPolicy: {version: "NFC_ONLY_v1", form: "NFC", ...}`. `comparisonStatus` is `TEXTUALLY_AGREED` only when all normalized text occurrences match, otherwise `UNRESOLVED_INVENTORY_DIFFERENCES`. `matched` preserves original left/right `{index,id,condition}` witnesses, the normalized text, and whether normalization changed either spelling. `onlyLeft` and `onlyRight` preserve each unmatched row plus normalized text and reason `UNRESOLVED_TEXTUAL_INVENTORY_DIFFERENCE`. These are textual inventory differences, not proven omissions from the question and not semantic conflicts. This version never emits `SOURCE_EXTRACTION_CONFLICT`.

`normalizedConditionsSha.left/right` are `objectSha` values for each side's explicitly code-unit-sorted array of normalized condition strings, with duplicates retained. They identify normalized text multisets only; they are neither raw file hashes nor source-completeness or semantic hashes. Each side also retains its exact frozen `ref`, claimed `inputSha256`, `policySha256`, `inputBindingSha256`, ordered `imageShas`, and claimed metadata. Nonblank `model`, `contextId`, and `providerInvocationId` values are retained; missing or blank values become null with side-specific metadata debt. `subagentToolsEnabled` is retained only when boolean, otherwise null with debt. Reused context or invocation identifiers add `REUSED_CONTEXT_OR_INVOCATION_METADATA`; these claims never establish independence.

Every result has `evidenceStatus: "EVIDENCE_DEBT"`, `productionAuthorized: false`, and at least these debts: `SOURCE_LOCATION_UNVERIFIED`, `SEMANTIC_EQUIVALENCE_NOT_VERIFIED`, `EXTRACTION_COMPLETENESS_NOT_VERIFIED`, `INDEPENDENCE_NOT_VERIFIED`, and `PHYSICAL_SOURCE_IMAGE_BINDING_UNVERIFIED`. Text agreement is not semantic agreement, completeness, independent extraction, source provenance verification, or production authority. Physical source/image files and source-JS provenance are outside this diagnostic's checks. Browser rendering, SVG qualification, and publication are also outside its scope.

Malformed JSON, invalid bindings/shapes, leaked data, nonclosed records, and stale refs fail with stable error codes (the existing bound-file helper retains its own path/ref/stale-byte errors). No result status grants PASS, READY, qualification, receipt, reuse, or production authority.
