## BLOCKED 독립 반례 및 정정 필요

- **q05 문제·해설 2축:** 호와 원주각을 독립적으로 추적하면 ∠BAD40°가 보는 호 BD는 80°, ∠CBD30°가 보는 호 CD는 60°이므로 호 BC20°다. 그러면 x=∠BDC=호 BC/2=10°이고 y=∠BCD=180°−∠BAD=140°이므로 합은 **150°**다. 실제 선택지는 **95, 98, 100, 105, 110°**뿐이므로 정답이 존재하지 않는다. 작성된 해설 역시 y=140°·x=10°를 맞게 구한 다음 근거 없이 y=65°·x=35°로 변경해 ③=100°를 선택한다. 원문 발문 또는 선지와 해설을 정정하기 전에는 문제·해설 plan 모두 중단한다.
- **q16 문제·해설 2축:** JS에 `image`/`solutionImage`가 없고 레거시 `q16-problem.plan.json`도 `EXEMPT`이므로 발문에서 말한 6경기 꺾은선그래프가 연결되어 있지 않다. 총점만 같으면 평균만 같고 분산은 어느 쪽이든 클 수 있다. 위 두 수열의 평균은 모두 10이지만 분산은 각각 0, 100/6 및 그 역이다. 같은 발문으로 보기 ④ 또는 ⑤가 될 수 있으므로 도표 또는 6×2 숫자 자료를 보강하기 전 공식 문제·해설 plan을 만들지 않는다.

## 정확성/제작 범위

- **REQUIRED 8, BENEFICIAL 14, EXEMPT 24, BLOCKED 4 = 50축.** 공식 실행형 plan 22개(문제10, 해설12). 다른 축은 임의 EXEMPT JSON을 공식 production plan으로 넣지 않음.
- 원문 JS·기존 PNG/SVG·레거시 plan은 불변. Construction plan의 `sourceQuote`는 각 축의 실제 JS `content`/`solution`과 정확히 일치. Stat chart는 capability 계약상 `sourceQuote` 미지원이므로 자료를 `chart`와 `sourceConditions`로 결속.
- 각 신규 plan의 `sourceConditions[].mappedTo`는 실제 그리기 필드 경로만 사용한다. `PRESERVED_ARCHIVE_BANK` 같은 비실행 표식으로 패리티를 대신하지 않는다.
- q21의 원본 SVG `data-role=point` 18개, q22 10개를 읽고 공식 chart의 실제 좌표 목록과 대조한다. q22 순서쌍은 원문 10쌍과 일치해야 한다.
- 전체 52개 공식 plan에 대한 shallow/full lint, source 필드 매핑, 원문 문자열 대조와 독립 수학 검산은 동산중 장부와 합산하여 보고한다. 정적 PASS는 실제 SVG 렌더 PASS가 아니다.
- 공식 렌더 직접 실행 결과: q01 문제 plan을 공식 `render-plan.mjs`로 실제 시도했다. **RENDER_NOT_RUN** — stage=`measure`, code=`ARCHIVE_PREFLIGHT_FAIL`. `/usr/bin/chromium` 실행 래퍼가 `/usr/lib/chromium/chromium`을 찾지 못해 Playwright 자식이 exit 127로 종료한다. `/opt/google/chrome/chrome`도 부재. 따라서 생성된 학생용 SVG·PNG·A4가 없으며 lint PASS를 렌더 PASS라 기록하지 않는다.
- 독립 자동 교차 검산: 전체 50개 plan에서 그리기 필드 248/248 실존, construction 실제 `sourceQuote` 45/45 문항축 원문 일치, 통계 chart 5개, 원본 SVG 산점도 픽셀-자료 대응 28/28점, 50문항을 아우른 독립 수학식·반례 54개 불일치0. `plan-lint --shallow` 50/50 PASS, full lint 50/50 PASS (두 시험지 합계).
- 원격 main 병합 SHA·blob readback 값은 최종 PR·보고서에 정확히 기록한다. q05·q16은 해결 전 시험지 전체 COMPLETE 및 큐 체크를 하지 않는다.
