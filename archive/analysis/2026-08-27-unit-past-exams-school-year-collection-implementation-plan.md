# 단원별 기출 학년·연도·학교 모아뽑기 구현 계획서

- 작성일: 2026-08-27
- 수정일: 2026-08-27
- 상태: IMPLEMENTATION PLAN — 구현 전
- 대상: `archive/unit-past-exams.html` 교사 출제 흐름
- 기능명(가칭): `기출 모아뽑기`
- 범위: 학년·과목, 단원·단원 범위, 특정 연도, 최근 3·5개 자료연도, 여러 학교, 학교별·통합 문제지
- 수정 요약: 지역 필터 제외, `2025 기출` 같은 특정 연도 모드와 과목 전체 scope 추가

## 0. 결정 요약

### 0.1 사용자와 합의된 결정

1. 학교는 한 곳 또는 여러 곳을 선택할 수 있다.
2. 여러 학교를 선택한 뒤 출력하는 방식은 둘 다 제공한다.
   - 학교별 분리: 학교마다 별도 문제지를 만든다.
   - 전체 통합: 선택 학교의 문항을 한 문항군으로 합친다.
3. `최근 3개년`, `최근 5개년`은 연속된 달력 연도가 아니라 **해당 조건의 문항 자료가 실제로 존재하는 최근 자료연도**로 해석한다.
4. 자료연도는 학교별로 독립 산정한다. 여러 학교를 통합해도 각 학교에서 최근 N개 자료연도를 먼저 확정한 뒤 문항을 합친다.
5. 한 학교의 자료연도가 N개보다 적으면 다른 학교나 다른 단원으로 몰래 보충하지 않는다. `2/3개년`처럼 부족 상태와 실제 채택 연도를 명시한다.
6. `2025 기출`처럼 특정 연도를 정확히 지정하여 현재 학년·과목·단원 조건에 맞는 여러 학교 기출을 모을 수 있어야 한다.
7. 특정 연도 모드에서는 모든 선택 학교에 같은 연도를 적용하고, 그 연도 자료가 없는 학교를 다른 연도로 대체하지 않는다.
8. 현재 학원이 사용하는 학교 아카이브를 대상으로 하므로 지역 필터와 지역 메타데이터는 이번 기능 범위에 포함하지 않는다.

### 0.2 권장 기본값

- 진입 범위: 현재 클릭한 단원
- 연도 방식: 특정 연도
- 초기 연도: 현재 학년·과목·단원 조건에서 가장 최신 자료가 존재하는 연도
- 빠른 전환: 최근 3개 자료연도·최근 5개 자료연도
- 시험 시기: 전체 학기·중간·기말
- 출력 방식: 학교별 분리
- 문항 방식: 조건에 맞는 전체 문항
- 문항 순서: 학교 → 자료연도 최신순 → 시험 시기 → 원본 문항 번호
- 중복 처리: 동일 원본 문항 ID만 제거하고 학교 간 반복·유사 문항은 유지
- 학교별 문제지가 80문항을 넘으면 자동 분할
- 학생용 문제지는 출처를 숨기고, 교사용 정답·해설에는 출처를 표시

### 0.3 MVP와 후속 기능의 경계

#### MVP

- 현재 단원, 같은 과목 안의 연속 단원 범위 또는 해당 과목 전체
- 현재 선택된 학년·과목 profile 유지
- 학교 단일·다중 선택
- 특정 연도 선택
- 최근 3개·5개 자료연도
- 학교별 분리·전체 통합
- 전체 문항·문항 수 지정
- 학교·연도별 자료 현황 미리보기
- 일반 출력·학생 출제 연결
- 시험·정답·해설 모드 검증

#### MVP 이후

- 저장된 학교 묶음
- 학교별·연도별 사용자 지정 배분
- 동일 본문 중복 후보 탐지
- 빈출 단원·소단원 분석
- A형·B형 무중복 문제지
- 이전 출제 문항 제외
- 학교 시험범위 프리셋
- 연도 범위 직접 지정

## 1. 목표와 비목표

### 1.1 목표

교사가 단원별 기출 화면을 떠나지 않고 다음 질문에 답할 수 있게 한다.

1. 이 단원 또는 범위에 어느 학교 자료가 있는가?
2. `2025년`처럼 특정 연도의 해당 학년 기출에는 어떤 학교·문항이 있는가?
3. 각 학교에서 최근 3개 또는 5개 자료연도는 정확히 언제인가?
4. 학교별로 몇 문항이 있고, 어떤 시험지에서 왔는가?
5. 학교별 문제지 또는 학교 통합 문제지를 바로 출력·학생 출제할 수 있는가?

### 1.2 비목표

- 원본 시험지 문항의 내용·보기·정답·해설을 수정하지 않는다.
- AI 의미 유사도만으로 문항을 자동 삭제하지 않는다.
- 서로 다른 과목을 하나의 시작~끝 범위로 묶지 않는다.
- 자료가 부족한 학교에 다른 단원·연도·학교 문항을 자동 보충하지 않는다.
- 학교 이름을 근거로 지역을 추정하거나 지역별 학교 completeness를 판정하지 않는다.
- 기존 `mixed_engine.html`과 학생 출제 엔진을 새로 만들지 않는다.

## 2. 용어와 판정 기준

### 2.1 자료연도

`자료연도`는 다음 조건을 모두 통과한 문항이 한 개 이상 존재하는 시험 연도다.

```text
학년·과목 범위
  → 선택 단원 또는 단원 범위
    → 선택 학교
      → 선택 시험 시기
        → 문항 단원 분류가 유효함
          → 해당 연도를 자료연도로 인정
```

학교에 시험지가 존재하더라도 선택 단원 문항이 0개면 그 연도는 해당 기능의 자료연도로 세지 않는다.

### 2.2 연도 선택 모드

연도는 세 가지 방식으로 해석한다.

#### 특정 연도 — MVP 기본값

- 선택한 `examYear`와 정확히 같은 문항만 포함한다.
- 모든 선택 학교에 같은 연도를 적용한다.
- 해당 연도 문항이 없는 학교는 `2025년 해당 범위 자료 없음`으로 표시한다.
- 다른 연도 자료로 자동 대체하지 않는다.

예:

```text
학년: 고2
연도: 2025
범위: 도함수
학교: 전체 또는 직접 선택
```

#### 최근 N개 자료연도

- 학교별로 조건에 맞는 실제 자료연도를 계산한다.
- 각 학교에서 최근 3개 또는 5개 자료연도를 독립적으로 선택한다.
- 선택 학교마다 실제 채택 연도가 달라도 허용한다.

#### 연도 범위 — 후속 기능

- `2023~2025`처럼 시작·끝 연도를 직접 지정한다.
- 범위 안에서 실제 문항이 있는 연도만 결과에 표시한다.
- 연속 연도를 강제로 채우거나 범위 밖 연도로 보충하지 않는다.

### 2.3 최근 N개 자료연도

학교별로 자료연도를 내림차순 정렬하고 앞에서 N개를 선택한다.

예:

```text
순천고 도함수 자료연도: 2025, 2023, 2022
최근 3개 자료연도:     2025, 2023, 2022

매산고 도함수 자료연도: 2025, 2023
최근 3개 자료연도:     2025, 2023  (2/3개년)
```

여러 학교 통합 모드에서도 학교별 채택 연도는 서로 다를 수 있다. 결과 제목과 미리보기에는 `2023~2025` 같은 연속 범위 대신 실제 연도 목록을 표시한다.

### 2.4 단원 범위

- `현재 단원`: 클릭한 표준 단원 하나
- `시작~끝`: 같은 표준 과목 안에서 순서가 연속된 단원
- `현재 단원까지 누적`: 같은 과목의 첫 단원부터 현재 단원까지
- `과목 전체`: 선택 학년의 특정 과목에 속한 모든 표준 단원

문항 포함 여부는 시험지 DB의 전체 범위가 아니라 단원별 기출 코어가 확정한 문항별 `mappedUnitKey`를 기준으로 한다. DB의 `courseRanges`는 범위 프리셋과 설명에 사용할 수 있지만 문항 포함의 최종 근거로 사용하지 않는다.

`2025 고2 수학II 기출`처럼 단원을 지정하지 않은 학년별 모음은 `과목 전체` scope로 처리한다. 한 학년에 여러 과목이 있으면 과목을 반드시 선택하고, 서로 다른 과목을 하나의 문제지에 섞지 않는다.

### 2.5 출력 묶음

- 학교별 분리: `학교`가 최상위 그룹이다.
- 전체 통합: 모든 선택 학교의 문항을 하나의 후보군으로 합친다.
- 원본 시험지 안에서는 문항 순서를 유지한다.
- 동일 원본 시험지를 가능한 한 한 덩어리로 유지하되 80문항 제한을 우선한다.

## 3. 현재 구조와 확인된 격차

### 3.1 현재 데이터 흐름

```text
archive/exams/original/**/*.js
        ↓
archive/db.js
        ↓
archive/tools/build-question-index.mjs
        ↓
archive/question-index.js
        ↓
archive/unit-past-exams-core.js
        ↓
archive/unit-past-exams.js

```

### 3.2 재사용 가능한 부분

- 표준 단원·소단원 분류
- 난이도 정규화
- 문항 UID 및 원본 파일·문항 번호
- 중복 UID 방지와 deterministic seed
- 최대 80문항 문제지 분할
- 원본 시험지 JS 지연 로딩과 파일 캐시
- 일반 출력·학생 출제 snapshot 전달
- 시험·정답·해설 렌더러

### 3.3 보강해야 할 부분

현재 `question-index.js`의 문항 레코드에는 학교·연도·학기·시험 종류가 충분히 포함되어 있지 않다. 파일명 파싱만으로 구현하면 학교 이름 변형과 레거시 파일명에 취약하므로 `db.js`를 기준으로 인덱스를 보강해야 한다.

필수 메타데이터:

```js
{
  sourceExamKey: "original/high/h2/2mid/25_학교_...js",
  schoolKey: "school:<canonical-key>",
  school: "학교명",
  examYear: 2025,
  semester: "2",
  examType: "mid",
  subject: "수학II"
}
```

추가 격차:

- 학교별 가용 연도 집계 함수가 없다.
- 특정 연도와 최근 N개 자료연도를 하나의 연도 선택 계약으로 처리하는 함수가 없다.
- 단일 단원을 넘어 여러 단원의 문항을 합치는 scope 함수가 없다.
- 학교별 문제지와 통합 문제지의 배분 정책이 없다.
- URL과 snapshot에 학년·연도 방식·학교·자료연도·범위 조건이 포함되지 않는다.
- 학교·연도별 자료 부족을 설명하는 UI가 없다.

## 4. 목표 사용자 흐름

### 4.1 빠른 흐름

```text
대단원 카드 선택
  → 기출 모아뽑기 선택
    → 현재 단원 또는 단원 범위 선택
      → 학교 선택
        → 특정 연도 또는 최근 3개·5개 자료연도 선택
          → 학교별 분리 또는 전체 통합 선택
            → 자료 현황 확인
              → 문제지 만들기
                → 일반 출력 또는 학생 출제
```

### 4.2 기본 화면

```text
┌────────────────────────────────────────────────────┐
│ 기출 모아뽑기                                      │
├────────────────────────────────────────────────────┤
│ 학년·과목  고2 · 수학II                            │
│                                                    │
│ 범위  (●) 현재 단원: 도함수  ( ) 단원 범위        │
│       ( ) 과목 전체: 수학II                        │
│                                                    │
│ 학교  [순천고 ✓] [매산고 ✓] [제일고 ✓] [더보기]   │
│                                                    │
│ 연도  (●) 특정 연도 [2025]                         │

```

### 4.3 자료 현황 미리보기

```text
연도 방식: 특정 연도 2025 · 고2 · 도함수

학교        채택 연도     상태      문항   원본 시험지
매산고      2025          자료 있음    4        1개
매산여고    2025          자료 있음    6        2개
순천고      2025          자료 있음    2        1개
제일고      2025          자료 있음    3        2개

합계: 4개 학교 · 2025년 · 15문항 · 6개 시험지
```

최근 N개 자료연도 모드에서는 기존처럼 `2025·2023·2022`, `3/3개년`을 표시한다. 각 학교 행은 펼칠 수 있어야 하며, 연도별 중간·기말 문항 수와 원본 시험지를 보여준다. 문항이 없는 선택 학교도 행을 없애지 않고 `2025년 해당 범위 자료 없음` 또는 `해당 범위 자료 없음`으로 표시한다.

### 4.4 고급 설정

- 학기: 1학기·2학기
- 시험 종류: 중간·기말
- 난이도: 하·중·상·미분류
- 통합 배분: 학교 균등·보유 문항 비율
- 연도 배분: 자료연도 균등·보유 문항 비율
- 순서: 학교·연도순·난이도순·무작위
- 출처: 학생용 숨김·표시
- 중복: 원문 유지·완전 동일 문항만 1개

고급 설정은 기본적으로 접어 두고, 조건을 변경하면 미리보기와 URL 상태를 즉시 갱신한다.

## 5. 기능 규칙

### 5.1 필터 적용 순서

필터 순서를 고정하여 UI 집계와 실제 출력이 달라지지 않게 한다.

```text
1. 학년·과목 profile scope
2. 단원 또는 단원 범위
3. 선택 학교
4. 학기·시험 종류
5. 연도 방식 적용
   - 특정 연도: 모든 학교에 동일 examYear 적용
   - 최근 N개 자료연도: 학교별 실제 자료연도 계산
   - 연도 범위: 시작~끝 examYear 적용
6. 난이도·소단원 조건
7. 원본 문항 identity 중복 제거
8. 학교별 분리 또는 통합 배분
9. 문제지당 최대 80문항 분할
```

연도 조건을 적용할 때 난이도까지 포함할지는 혼동을 막기 위해 다음처럼 구분한다.

- 특정 연도: 단원·학교·시험 시기 기준으로 지정 연도 문항 존재 여부 계산
- 최근 자료연도: 단원·학교·시험 시기 기준으로 실제 자료연도 계산
- 최종 문항: 연도 확정 후 난이도·소단원 조건 적용
- 난이도 때문에 문항이 0개가 된 연도는 미리보기에서 `선택 난이도 0문항`으로 설명

### 5.2 학교별 분리

- 선택 학교마다 독립 후보군을 만든다.
- 특정 연도 모드에서는 학교별 후보군에 같은 지정 연도만 적용한다.
- 최근 자료연도 모드에서는 학교별로 확정된 실제 연도 목록을 적용한다.
- `전체 문항`이면 학교별 후보를 모두 포함한다.
- `문항 수 지정`이면 입력한 수를 학교마다 적용한다.
- 학교의 후보가 부족하면 그 학교만 `부족 N문항`으로 표시한다.
- 부족분을 다른 학교에서 자동 보충하지 않는다.
- 80문항을 넘으면 같은 학교 안에서 여러 문제지로 분할한다.

### 5.3 전체 통합

#### 전체 문항

선택한 연도 방식과 학교 조건에 일치하는 모든 문항을 포함하고 80문항 단위로 분할한다. 별도 가중치는 적용하지 않는다.

#### 문항 수 지정

기본 배분은 학교 균등이다.

1. 총 요청 문항 수를 선택 학교 수로 균등 배분한다.
2. 학교 내부에서는 채택 자료연도를 round-robin으로 순환한다.
3. 후보가 부족한 학교의 잔여 할당량을 다른 학교에 균등 재배분한다.
4. 같은 seed와 같은 조건은 항상 같은 문항을 반환한다.
5. 결과 보고서에 학교별·연도별 실제 배분을 표시한다.

고급 설정의 `보유 문항 비율`은 학교 후보 수에 비례하여 할당하되 특정 학교가 100%를 차지하지 않도록 선택 학교가 두 곳 이상이면 가능한 범위에서 학교별 최소 1문항을 보장한다.

### 5.4 단원 범위

- 시작과 끝은 같은 과목에 속해야 한다.
- 끝 단원 순서가 시작보다 앞이면 UI에서 즉시 교정하거나 오류를 표시한다.
- legacy 단원 키는 기존 `classifyRecord()`의 `mappedUnitKey`로 변환한 뒤 범위를 판정한다.
- 과목 전체 모드는 profile의 course 단위로 문항을 모으고 다른 과목 문항을 제외한다.
- 소단원 필터는 단일 단원일 때 우선 제공한다.
- 여러 단원 범위에서는 소단원 목록을 부모 단원별로 묶어 표시한다.

### 5.5 문항 순서와 출처

학교별 분리의 기본 순서:

```text
자료연도 최신순
  → 1학기 중간
  → 1학기 기말
  → 2학기 중간
  → 2학기 기말
  → 원본 문항 번호
```

전체 통합의 기본 순서는 학교 균등 배분 결과를 유지하되, 출력에서는 원본 시험지 문항이 과도하게 흩어지지 않도록 source block을 구성한다.

출처 정책:

- 학생용 시험지: 기본 숨김
- 교사용 정답·해설: 학교·연도·학기·시험 종류·원본 번호 표시
- 출처 숨김은 렌더링 표시만 바꾸며 snapshot 메타데이터에서는 제거하지 않는다.

### 5.6 중복 정책

MVP 기본 중복 키는 canonical question UID 또는 `sourceFile#sourceQuestionNo`다.

- 같은 원본 문항의 중복 선택은 금지한다.
- 서로 다른 학교에서 같은 문항이 반복 출제된 경우는 유지한다.
- 본문·보기·이미지가 완전히 같은 문항은 후속 단계에서 content hash로 `완전 동일 후보`를 표시할 수 있다.
- 유사 문항은 학교 출제 경향일 수 있으므로 자동 제거하지 않는다.

## 6. 데이터 계약 변경

### 6.1 question-index 보강

`archive/tools/build-question-index.mjs`가 `db.js`의 시험지 메타데이터를 문항 레코드에 포함하도록 변경한다.

추가 필드:

- `sourceExamKey`
- `schoolKey`
- `school`
- `examYear`
- `semester`
- `examType`
- `sourceExamTitle` 또는 표시용 파생 label

필드 원칙:

- `sourceExamKey`는 정규화된 `sourceFile`과 동일한 안정 키를 사용한다.
- `school`은 표시명, `schoolKey`는 필터·URL·snapshot용 안정 키다.
- `examYear`는 파일명 파싱보다 DB의 숫자형 `year`를 우선한다.
- DB 레코드가 없으면 임의 추정하지 않고 metadata-missing 감사 대상으로 남긴다.
- 지역·도시 필드는 이번 기능에 추가하지 않는다. 현재 아카이브에 수록된 학교 목록을 전체 또는 직접 선택하여 사용한다.

### 6.2 학교 식별자

MVP에서는 DB의 canonical 학교명을 정규화하여 `schoolKey`를 생성한다. 이름 변형이 확인되면 후속으로 학교 master를 추가한다.

정규화 예:

```text
앞뒤 공백 제거
연속 공백 축약
Unicode 정규화
표시명은 보존
```

`고`, `고등학교` 같은 접미사를 기계적으로 제거해 서로 다른 학교를 합치지 않는다. 별칭 병합은 명시적인 alias table만 허용한다.

### 6.3 DB/index 정합성 gate

인덱스 생성 및 CI에서 다음을 검증한다.

- 모든 `original/**` 시험지 인덱스 레코드는 DB 메타데이터를 정확히 한 건 가진다.
- `school`, `examYear`, `semester`, `examType`이 비어 있지 않다.
- DB `qCount`, 시험지 JS 문항 수, question-index 문항 수가 일치한다.
- 같은 `sourceExamKey`에 서로 다른 학교·연도 메타데이터가 섞이지 않는다.
- index rebuild 후 학교·연도별 집계가 deterministic하다.

### 7.1 추가할 순수 함수

`archive/unit-past-exams-core.js`에 다음 책임을 추가한다.

```js
getSchoolKey(record)
```

함수는 DOM과 전역 상태에 의존하지 않으며 동일 입력에 동일 결과를 반환해야 한다.

### 7.2 기존 필터와의 결합

기존 `filterUnitRecords()`의 소단원·난이도 필터는 유지한다. 학년·학교·연도 조건은 별도 collection scope로 먼저 적용한 뒤 기존 필터로 전달하여 책임을 분리한다.

```text
collection scope
  학년·학교·연도 방식·학기·시험·단원 범위
        ↓
existing detail filter
  소단원·난이도·미분류 허용
        ↓
selection / paper split
```

### 7.3 로딩 성능

- 미리보기는 `question-index.js`만 사용한다.
- 실제 시험지 JS는 출력·학생 출제를 눌렀을 때만 로드한다.
- 동일 `sourceFile`은 기존 `fileCache`로 한 번만 로드한다.
- 여러 파일은 동시 로드하되 브라우저 부하를 막기 위해 제한된 concurrency를 사용한다.
- 일부 파일 로드 실패 시 어떤 학교·연도·시험지가 실패했는지 표시하고 전체를 무조건 성공 처리하지 않는다.

## 9. 예외와 부족 처리

### 9.1 특정 연도 자료가 없는 경우

```text
복성고 · 2025년 · 도함수
2025년 해당 범위 자료 없음
```

- 학교 선택 상태와 행은 유지한다.
- 다른 연도로 자동 대체하지 않는다.
- 해당 학교 출력 버튼만 비활성화한다.
- `최근 3개 자료연도로 전환` 또는 다른 범위 선택을 제안할 수 있지만 사용자가 눌렀을 때만 적용한다.

### 9.2 학교 자료연도가 부족한 경우

```text
매산고 · 최근 3개 자료연도 요청
확보: 2025·2023 (2/3개년)
문항: 7개
```

- 학교 선택은 유지한다.
- 생성 가능 문항이 있으면 경고와 함께 생성할 수 있다.
- 0문항이면 그 학교의 출력 버튼을 비활성화한다.
- 다른 범위·5개 자료연도·시험 종류 전체로 완화하는 선택지를 제안하되 자동 적용하지 않는다.

### 9.3 문항 수가 부족한 경우

- 학교별 분리: 해당 학교에 부족 수를 표시한다.
- 전체 통합: 재배분 뒤에도 부족하면 최종 부족 수를 표시한다.
- 인접 난이도·미분류·다른 단원은 기존 정책처럼 명시적으로 허용했을 때만 포함한다.

### 9.4 메타데이터가 없는 경우

- 학교·연도가 없는 문항은 학교별 모아뽑기 후보에서 제외한다.
- 제외 문항 수와 원본 파일을 감사 보고서에 기록한다.
- 파일명에서 조용히 추정해 운영 결과에 포함하지 않는다.

### 9.5 같은 학교의 같은 연도에 시험지가 여러 개인 경우

- 모든 일치 시험지를 포함한다.
- 학기·시험 종류 filter를 적용한다.
- 미리보기에는 시험지 수와 시험별 문항 수를 펼쳐서 보여준다.

### 9.6 범위가 과목을 넘는 경우

- 한 범위로 생성하지 않는다.
- 과목별 별도 묶음을 만들도록 안내한다.

- deterministic selection과 snapshot key 확장

완료 기준:

- 모든 함수가 순수 단위 테스트를 가진다.
- 같은 입력·seed의 결과가 반복 실행에서 동일하다.
- 학교별 채택 연도와 출력 문항이 미리보기 결과와 일치한다.

### Phase 3 — 빠른 UI와 자료 현황 미리보기

- `기출 모아뽑기` 진입 탭 또는 mode 추가
- 현재 학년·과목 profile 표시
- 현재 단원·단원 범위·과목 전체 선택

- 특정 연도와 최근 3·5개 자료연도 선택
- 학교별 분리·전체 통합 선택
- 전체 문항·문항 수 지정
- 학교·연도·시험별 미리보기와 부족 경고
- URL 상태·뒤로 가기·새로고침 복원

완료 기준:

- 기본 화면에는 핵심 조건만 노출된다.
- 학교가 많아도 검색·전체 선택·선택 해제가 가능하다.
- 자료가 없는 학교를 조용히 숨기지 않는다.
- 320px·768px·desktop에서 가로 overflow가 없다.

### Phase 4 — 문제지 생성·출력·학생 출제

- 학교별 generated paper 카드 생성
- 전체 통합 generated paper 카드 생성
- 80문항 자동 분할
- 원본 시험지 JS 복원 및 이미지 로딩
- 교사용 출처 metadata 연결
- 일반 출력과 학생 출제 snapshot 전달
- 실제 채택 연도·문항 UID 고정

완료 기준:

- 미리보기 수와 실제 exam·ans·sol 문항 수가 일치한다.
- 학교별 문제지가 다른 학교 문항을 포함하지 않는다.
- 전체 통합의 학교·연도 배분이 결과 보고서와 일치한다.
- 기존 단원별 빠른 출제·고급 조합이 회귀하지 않는다.

### Phase 5 — 고급 설정

- 학기·중간·기말 필터

완료 기준:

- 배포 후 실제 URL에서 대표 학교별·통합 출력 PASS

## 12. 테스트 계획

### 12.1 코어 단위 테스트

- 학교 목록은 canonical key로 중복 없이 생성된다.
- 특정 연도 모드는 모든 선택 학교에 동일한 연도를 적용한다.
- 특정 연도 자료가 없는 학교를 다른 연도로 대체하지 않는다.
- 과목 전체 모드는 선택 과목 밖 문항을 포함하지 않는다.
- 자료연도는 범위 일치 문항이 있는 연도만 포함한다.
- 최근 3개 자료연도는 비연속 연도를 정확히 선택한다.
- 자료가 두 연도뿐이면 `2/3` 상태를 반환한다.
- 같은 학교·연도에 여러 시험지가 있어도 연도는 한 번만 센다.
- 범위 밖 문항과 다른 과목 문항이 섞이지 않는다.
- 학교별 분리 결과는 학교 간 오염이 없다.
- 통합 균등 배분은 가능한 학교에 최소 문항을 분배한다.
- 부족분 재배분 후 총 요청 수가 정확하다.
- UID 중복이 없다.
- 80문항 제한을 넘지 않는다.
- 같은 seed 결과가 동일하다.

### 12.2 UI/runtime 테스트

- 학교 multi-select 상태가 URL에 반영된다.
- 새로고침·popstate에서 조건이 복원된다.
- 특정 연도 선택과 최근 자료연도 전환이 URL과 결과에 반영된다.
- 특정 연도 모드에서 지정 연도 밖 문항이 0건이다.
- 3개·5개 자료연도 전환 시 실제 연도와 문항 수가 갱신된다.
- 학교별·통합 전환 시 결과 카드 구조가 바뀐다.
- 자료가 없는 학교와 부족 학교가 명시된다.
- 빠른 설정과 고급 설정 상태가 충돌하지 않는다.
- 출처 숨김은 표시만 바꾸고 snapshot identity를 보존한다.

### 12.3 브라우저 QA

대표 시나리오 A — 특정 연도:

1. 고2 → 도함수
2. 특정 연도 2025 선택
3. 매산고·매산여고·순천고·제일고 선택
4. 학교별 분리 생성
5. 각 학교 일반 출력
6. 전체 통합으로 전환 후 고정 문항 수 생성
7. exam·sol·ans 확인

대표 시나리오 B — 최근 자료연도:

1. 같은 단원에서 최근 3개 자료연도로 전환
2. 비연속 자료연도가 있는 학교의 실제 채택 연도 확인
3. `2/3개년` 부족 학교 표시 확인
4. 학교별·통합 출력 확인

검증 항목:

- alert·fallback·console warning/error 0건
- 출력 문항 수와 미리보기 문항 수 일치
- `.q-box`, `.ans-n`, `.sol-exp` 수 일치
- 모든 이미지 `naturalWidth > 0`
- solutionImage 로딩·크기 정상
- 가로 overflow 없음
- 학교·연도 출처 표시 정책 정상
- 학생 출제 handoff와 snapshot 복원 정상

## 13. 완료 기준

다음 조건을 모두 만족해야 기능 완료로 판정한다.

- 학교 단일·다중 선택이 동작한다.
- 학교별 분리·전체 통합 출력이 모두 동작한다.
- 학년·과목 profile과 특정 연도 조건이 정확히 적용된다.
- `2025 기출`에서 2025년 밖의 문항이 포함되지 않는다.
- `2025 고2 수학II 기출`에서 다른 과목·학년 문항이 포함되지 않는다.
- 특정 연도 자료가 없는 학교가 다른 연도로 자동 대체되지 않는다.
- 최근 3·5개 자료연도가 학교별 실제 자료 기준으로 정확히 계산된다.
- 실제 채택 연도와 `N개년 확보 상태`가 미리보기와 출력에 명시된다.
- 단일 단원과 같은 과목의 연속 범위가 정확히 동작한다.
- 학교별·연도별 문항 수와 실제 출력 수가 일치한다.
- 통합 고정 문항 수에서 학교·연도 균등 배분과 부족분 재배분이 정확하다.
- 원본 문항·정답·해설·이미지가 변형되지 않는다.
- exam·sol·ans 출력과 학생 출제에 회귀가 없다.
- DB·JS·index 메타데이터와 문항 수가 일치한다.
- console error, broken image, horizontal overflow가 없다.
- 현재 작업 트리의 무관한 변경이 덮어써지지 않는다.

## 14. 롤백·중단 기준

- DB와 index의 학교·연도 메타데이터가 일치하지 않으면 UI 구현보다 데이터 정합성부터 수정한다.
- 기존 단원별 기출 catalog count 또는 문항 UID가 변하면 index 산출물을 승격하지 않는다.
- 학교별 미리보기 수와 실제 출력 수가 다르면 완료로 보고하지 않는다.
- 학교 간 문항 오염 또는 snapshot 재현 실패가 있으면 학생 출제 연결을 활성화하지 않는다.
- 브라우저에서 시험·정답·해설 중 하나라도 로드 실패하면 배포하지 않는다.
- 롤백은 전체 dirty worktree가 아니라 이번 기능 파일과 생성 산출물만 대상으로 한다.

## 15. 후속 아이디어

### 15.1 저장된 학교 묶음

- `주요 고2 학교`
- `비교학교 5곳`
- 최근 사용 학교

학교 묶음은 localStorage 또는 교사 설정에 저장하고 URL 공유를 지원한다.

### 15.2 출제 경향 요약

- 학교별 단원·소단원 빈도
- 자료연도별 난이도 분포
- 여러 학교에서 반복 출제된 개념
- `빈출 문항으로 20문제 만들기`

### 15.3 A형·B형

같은 조건과 난이도 분포를 유지하면서 서로 겹치지 않는 두 문제지를 만든다. 후보가 부족하면 겹치는 예상 문항 수를 먼저 표시한다.

### 15.4 이전 출제 문항 제외

학생 출제 이력 또는 교사 문제지 생성 이력과 question UID를 연결하여 최근 사용 문항을 제외한다.

### 15.5 중복 후보 검토

본문·보기·이미지 hash가 완전히 같은 문항만 exact duplicate 후보로 표시한다. 학교 간 반복 출제 정보는 보존하고, 교사가 선택했을 때만 하나로 합친다.

## 16. 권장 실행 순서

```text
대표 fixture와 baseline 확정
  → question-index 시험 메타데이터 보강
    → 특정 연도·자료연도 코어 함수와 단위 테스트
      → 자료 현황 미리보기 UI
        → 학교별 분리 출력
          → 전체 통합·균등 배분
            → 학생 출제·snapshot
              → 고급 설정
                → 브라우저 QA·CI·배포 smoke test
```

첫 end-to-end 구현은 고2 `도함수` 한 단원에서 완료한 뒤 다른 학년·과목·범위로 확대한다. 대표 fixture가 통과하기 전에는 전체 아카이브에 기능 완료로 표시하지 않는다.
