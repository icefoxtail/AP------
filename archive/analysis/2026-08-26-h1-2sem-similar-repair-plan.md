## 수정 착수 전 공통 체크리스트

1. 각 문항의 원문 fingerprint와 위 변형 계획을 먼저 확정한다. 계획과 다른 변형은 별도 기록 없이는 적용하지 않는다.
2. 유사문항 본문은 원문 참조 없이 단독으로 읽혀야 한다. 누락된 증명 블록·정의·함수식·조건을 복원한다.
3. 현재 확인된 결함은 계획에 반영했다: 순천고 2중 q11 선지 중복, 팔마고 2기 q12 증명 블록 누락, 효천고 2기 q14 정의 참조, 효천고 2기 q18 유리함수 식 누락.
4. 시각문항 21건은 변형된 수치/레이블/그래프와 일치하는 새 에셋을 만든다. 모든 이미지 경로는 _유사 폴더를 사용하고 naturalWidth를 확인한다.
5. 수정 후 문항별 독립 해설을 작성하고 answer/solution을 교차 검산한다. 객관식은 선지 중복·복수정답·정답 위치 편향을 확인한다.
6. 마지막에 node --check, archive audit, exam/sol/ans 렌더 QA를 실행하고, 통과 전에는 완료로 보고하지 않는다.

## 답 형태와 수치 품질 게이트

1. 문항을 만들 때 목표 답 형태를 먼저 잠근다. 우선순위는 정수·자연수, 그다음 작은 기약분수, 그다음 단순한 a√b(b는 제곱인수가 없는 수)이다.
2. 정수가 아닌 값은 소수로 쓰지 않고 \dfrac{p}{q}로 표기한다. 반드시 gcd(p,q)=1로 약분하고, 기본 목표는 |p|≤100, 1≤q≤12로 한다.
3. 분모가 12보다 크거나 분자·분모가 불필요하게 커지는 경우, 답만 바꾸지 않고 좌표·계수·조건을 설계 단계에서 다시 선택한 뒤 문항 전체를 독립 재검산한다.
4. 좌표·길이·넓이·기울기·교점·최댓값·최솟값은 가능한 한 정수 또는 작은 기약분수로 떨어지게 역산한다. 소수 근사, 37/156 같은 난해한 분수, 의미 없는 큰 수는 유사문항에서 폐기한다.
5. 객관식은 정답과 오답을 모두 exact 값으로 비교한다. 보기의 소수 근사·동치 분수·동일 의미 표현이 섞이면 실패다.
6. 답이 복잡하거나 성립하지 않으면 정답/보기를 맞춰 쓰지 않고 해당 Candidate를 폐기한 뒤, 같은 원문 핵심 개념으로 수치·조건을 다시 설계하고 재생성한다.

## 시각자료 제작·첨부 공통 계획

- 원문에 image가 있거나 inline img가 있는 21문항은 모두 visualDependency=ESSENTIAL로 둔다. 그림을 삭제하고 텍스트 조건으로만 바꾸지 않는다.
- 각 문항에 visualSpecVersion=0.1, visualSpec.type, width/height, 좌표축·범위, points/segments/curves/regions/table, visualTopology, semanticRoles, sourceCoordinatesOrRelations, essentialVisualFacts, mutableVisualParameters, forbiddenVisualTransforms를 기록한다.
- 새 시험지의 에셋은 archive/assets/images/<examTitle>_유사/q{id}.svg 또는 .png에 저장하고, JS의 image가 그 파일을 직접 가리키게 한다. 현재 연결된 _기출 폴더 경로는 전부 교체 대상이다.
- 좌표평면·삼각형·원·수선·매핑도·단순 그래프는 흑백 결정론적 SVG를 우선 사용한다. 증명 과정 표와 여러 곡선·음영이 겹친 복합 자료는 결정론적 PNG를 사용한다.
- 수학용 도형·그래프·표는 생성형 이미지 모델이나 눈대중 SVG를 사용하지 않는다. Python exact 계산 또는 명시적 SVG/PNG renderer로 생성한다.
- 생성 순서는 문항 조건과 정답 설계 → visualSpec → exact 수치 검증 → 에셋 렌더 → 파일 재오픈 → 문항-에셋 1:1 대조이다. 그림을 먼저 만든 뒤 숫자를 끼워 맞추지 않는다.
- 에셋 검수는 좌표·길이·각도·기울기·교점·점근선·중심/반지름·대칭/평행이동, 필수 라벨·선·점, 안전 여백·인쇄 판독성, 정답 누설 여부를 모두 확인한다.
- 에셋 또는 문항의 핵심 수치가 바뀌면 Candidate를 다시 FREEZE하기 전 V1 수학 독립 검산부터 재실행한다. VISUAL_PARAM_MISMATCH, VISUAL_LABEL_MISMATCH, VISUAL_CROP_FAIL, MATH_VISUAL_CONFLICT, STALE_ASSET_REUSE가 하나라도 있으면 PASS하지 않는다.

## 생성 후 독립 검산 및 재생성 계획

1. 문항별로 원문과 새 문항을 별도 context에서 직접 풀고, 고위험 문항(시각자료, 매개변수, 접선, 교점, 최댓값/최솟값, 정수 조건)은 정석 풀이와 exact 계산을 이중으로 수행한다.
2. 객관식은 5개 선지를 모두 판정한다. 정답이 정확히 1개이고, 오답은 실제 오류 경로에서 나온 서로 다른 값인지 확인한다.
3. 단답형·서술형은 발문 조건만으로 답이 하나로 확정되는지, 답 형식(정수·기약분수·간단한 근호)이 조건과 일치하는지 확인한다.
4. 시각문항은 문항 수학 검산이 PASS한 뒤에만 에셋을 렌더한다. 렌더 후 파일을 다시 열고 visualSpec·본문·solutionGraph·answer를 1:1로 대조한다.
5. 수학 검산과 시각 검산 중 하나라도 FAIL이면 answer/choices만 부분 수정하지 않는다. 해당 문항과 에셋 Candidate 전체를 폐기하고, 수치·조건·visualSpec을 다시 설계한 뒤 처음부터 재검산한다.
6. 모든 변경 후 internal-review-engine, visual asset link audit, PNG crop quality audit, node --check, exam/sol/ans 렌더 QA를 다시 실행한다. 최종 PASS 전에는 Candidate+Asset을 FREEZE하지 않는다.

이번 보강으로 계획서는 기존 178문항 변형 계획에 더해 시각문항 21건의 구체적인 신규 에셋 종류·변형 요소·첨부 경로·exact 검산 항목과 답의 정수/기약분수 품질 게이트까지 포함한다.
