## 2. 재검수 판정

- 469개 archive JS를 파싱·평가했고, 집합 문항 236개를 추출했다. 파싱 오류와 집합 문항의 자산 경로 누락은 없다.
- 숫자형·선택형으로 결론을 자동 확인할 수 있는 집합 문항 220개 중 187개는 해설 결론과 정답이 일치했다. 나머지 33개는 해설에 정답 숫자를 직접 반복하지 않는 서술형·구형 해설이며, 불일치로 판정할 근거는 없었다.
- 원본 기출 38개 파일에 대해 문항 수, DB 등록 수, question-index 등록 수, 필수 필드, 문제·해설 자산 경로를 재확인했다. 집합 문항 자체의 오류는 발견되지 않았다.
- candidate-production 비교는 집합 문항만 비교한 것이 아니라 시험 파일 전체를 비교하는 파일 단위 감사다. 최초 확인된 `22_순천여고 2final q9`, `22_강남여고 2mid q16`, `22_팔마고 2mid q18` 및 후속 확인된 `23_금당고 2mid q21`, `23_순천여고 2mid q13·q17`, `23_팔마고 2mid q15·q16·q18`의 차이는 모두 집합이 아닌 원·직선·격자점 문항의 해설 자산 메타데이터 차이다. 집합 문항 데이터에는 영향이 없다.

### 범위 분리 원칙

집합 전수조사는 `standardUnit=집합` 또는 `originalCategory=집합`인 문항만 추출하는 문항 단위 검사다. 반면 production/candidate 동기화 검사는 후보 JS가 시험 파일 단위로 생성되기 때문에 해당 파일의 모든 문항을 대상으로 한다. 따라서 파일 전체 감사에서 비집합 문항이 발견되는 것은 혼입이 아니라, 집합 결과와 파일 무결성 결과가 한 작업 로그에 함께 출력된 것이다. 이후 보고서는 `집합 문항 판정`과 `비집합 파일 잔여 차이`를 별도 섹션으로 구분한다.
- 기존 검수 기록의 49개 해설 SVG는 모두 `svg/viewBox/title 또는 desc`를 갖고 크기도 정상이다. PNG 원본 중 5개는 직접 시각 확인했고, Venn 영역·선택지·정답 해설이 서로 맞았다. SVG 원본 2개는 현재 이미지 뷰어가 SVG를 직접 표시하지 않아 구조·참조 검사를 적용했다.

### 기존에 유지해야 할 주의사항

1. `21_강남여고 2mid q14`, `21_금당고 2mid q3`은 원본 스캔의 `⊂`와 JS의 `⊆` 표기가 다르다. 현재 엔진의 해당 연도 안내문에서 원본 표기를 포괄적 부분집합으로 해석한다는 점을 안내하고 있으므로, 자산 보강 시 이 해석을 바꾸지 않는다.
2. `21_팔마고 2mid q15`는 원본 스캔 조건의 `10`과 현재 JS에 반영된 `8`, 정답 `80`이 다르다. 현재 보정 및 원본 근거는 기존 worklog에 기록되어 있으므로, 신규 도형 제작 때 원본 스캔을 조용히 덮어쓰지 않는다.

## 6. 제작·검수 기준

1. 문제에 있는 원본 도형과 해설용 도형은 분리한다. 원본 문제 이미지가 있는 경우 원본 이미지를 수정·대체하지 않고 `solutionImage`를 별도로 추가한다.
2. Venn diagram은 단순 장식이 아니라 식의 각 연산 단계가 어느 영역을 남기고 지우는지 보여 줘야 한다. 집합 이름, 전체집합, 색칠 영역을 반드시 표시한다.
3. 수직선은 열린 끝점 `○`, 닫힌 끝점 `●`, 구간의 포함 방향을 명확히 하고, 부호·경계값을 실제 식과 일치시킨다.
4. 좌표 그래프는 축, 눈금, 곡선 이름, 교점 또는 접선 경계를 포함한다. 그래프에서 읽은 결론과 JS 해설의 대수적 결론을 독립적으로 대조한다.
5. 유사 문항은 원본 문항의 이미지·SVG를 재사용하지 않는다. 각 문항의 계수, 경계, 색칠 영역, 정답을 기준으로 별도 자산을 만든다.
6. 자산 제작 뒤에는 JS 평가, 참조 경로, SVG 구조, answer·solution 결론, exam/solution/answer 3모드 렌더링을 다시 통과시킨다.
