# 단원별 기출 세부단원·난이도 출제 고도화 세부계획서

> 버전: v1.0  
> 작성일: 2026-08-25  
> 상태: IMPLEMENTATION PLAN  
> 대상: JS Archive `단원별 기출` 교사 출제 흐름  
> 핵심 사용자: 수업용 문제지를 빠르게 만들고 학생에게 배포하는 선생님

---

## 0. 결정 요약

### 0.1 목표

현재 `단원별 기출`은 대단원 단위로 문항을 모아 출력·학생 출제할 수 있다. 이를 다음 계층으로 확장한다.

```text
학년
  → 과목
    → 대단원
      → 소단원
        → 난이도
          → 문항 수 / 난이도 배합
            → 미리보기
              → 일반 출력 또는 학생 출제
```

학생에게 난이도가 갑자기 섞인 문제지를 제공하는 문제를 줄이고, 선생님이 별도 Mixer 화면으로 이동하지 않아도 단원별 기출 안에서 바로 수업용 문제지를 만들 수 있게 한다.

### 0.2 기본 방향

- 기존 `unit-past-exams` 화면을 고도화한다.
- 기존 `question-index`, 승인 메타데이터, `ArchiveMixerSelector`, `mixed_engine`을 재사용한다.
- 새로운 문제 렌더러나 별도 출제 엔진은 만들지 않는다.
- 문항 원문·정답·해설·이미지·문항 ID는 변경하지 않는다.
- 소단원 선택의 실제 기준은 표시명 `subUnit`이 아니라 `subUnitKey`로 한다.
- 난이도는 정규화된 `difficultyBucket`을 사용하고, 원래 `level`은 원본 보존 필드로 유지한다.

### 0.3 권장 MVP

1. 대단원 안의 소단원 선택
2. 난이도 단일 선택 및 다중 선택
3. 조건별 문항 수·난이도 분포 표시
4. 선택 조건으로 문제지 만들기
5. 기존 일반 출력·반 학생 출제 연결
6. 미분류·검토 필요 문항의 명시적 표시

난이도 비율 배합과 학교별 균형 선별은 MVP 이후 2단계로 분리한다.

## 1. 현재 구현과 변경 범위

### 1.1 현재 구현된 흐름

```text
archive/exams/**/*.js
        ↓
archive/question-index.js
        ↓
unit-past-exams-core.js
        ↓
unit-past-exams.js
        ↓
mixed_engine.html
        ↓
일반 출력 / APMS 학생 출제
```

현재 단원별 기출 코어는 `standardUnitKey` 기준으로 문항을 분류하고, 대단원별 문항을 여러 문제지로 분할한다. 화면에는 학년 탭, 대단원 카드, 문제지별 일반 출력과 학생 출제 버튼이 있다.

### 1.2 재사용할 구현

| 영역 | 기존 기능 | 재사용 방식 |
|---|---|---|
| 문항 메타데이터 | `subUnitKey`, `subUnit`, confidence/depth | 필터와 그룹핑 기준으로 사용 |
| 난이도 | `level`, 승인 `difficultyBucket` | `상·중·하·미분류`로 정규화 |
| 선택 조건 | Mixer의 소단원·난이도 hard constraint | 세부 출제 구성표에 재사용 |
| 선별 알고리즘 | `ArchiveMixerSelector.selectCandidates` | 난이도 배합·중복 방지에 사용 |
| 출력 | `mixed_engine.html` | 선택된 문항 payload만 전달 |
| 학생 출제 | `assignPaper()` 및 기존 APMS 연동 | 제목·메타데이터만 확장 |

### 1.3 현재 부족한 부분

- 단원별 기출 화면에는 소단원 선택 UI가 없다.
- 단원별 기출 화면에는 난이도 필터 UI가 없다.
- 현재 문제지 분할은 대단원 전체 문항을 정렬한 뒤 분할한다.
- 소단원·난이도별 문항 수와 부족 문항 정보가 보이지 않는다.
- `unit-past-exams.html`은 현재 `question-index.js`만 직접 로드하며 승인 메타데이터 sidecar를 직접 연결하지 않는다.
- 레거시 난이도 표기와 일부 미분류 문항을 UI에서 구분할 정책이 필요하다.

### 1.4 변경 대상 파일

#### 1차 필수

- `archive/unit-past-exams-core.js`
- `archive/unit-past-exams.js`
- `archive/unit-past-exams.html`
- `archive/unit-past-exams.css`
- `tests/archive-unit-past-exams-core.test.js`

#### 1차 연동 확인

- `archive/question-meta.js`
- `archive/data/question_metadata.json`
- `archive/mixed_engine.html`
- `archive/mixer-selector.js`

#### 변경하지 않는 파일

- `archive/exams/**/*.js`의 문항 원문·정답·해설
- `archive/engine.html`의 기본 렌더링 엔진
- 기존 DB 스키마
- 기존 학생 오답 데이터 구조

## 2. 교사 출제 UX 원칙

### 2.1 교사의 실제 작업을 기준으로 한다

선생님이 문제지를 만들 때 필요한 판단은 다음 네 가지다.

1. 어느 학년·과목인가?
2. 어느 대단원·소단원인가?
3. 어느 정도 난이도인가?
4. 몇 문항을 어떤 방식으로 출제할 것인가?

화면은 이 네 판단을 한 번에 처리하도록 구성한다. 필터를 바꿀 때마다 결과 수와 난이도 분포가 즉시 갱신되어야 한다.

### 2.2 `빠른 출제`와 `세부 설정`을 분리한다

#### 빠른 출제

선생님이 자주 사용할 기본 경로다.

- 소단원 선택
- 난이도 프리셋 선택
- 문항 수 선택
- `문제지 만들기` 또는 `학생에게 출제`

#### 세부 설정

필요한 경우에만 펼친다.

- 하·중·상 문항 수 직접 입력
- 학교 중복 최소화
- 최근 출제 문항 제외
- 소단원별 최소 문항 수
- 미분류 문항 포함 여부

기본 화면에서 고급 조건을 모두 노출하지 않아 선생님이 처음부터 복잡한 출제표를 작성하지 않도록 한다.

### 2.3 항상 현재 결과를 설명한다

출제 버튼 주변에 다음 정보를 고정 표시한다.

```text
현재 조건
중3 · 이차함수와 그래프 · 이차함수의 그래프 · 중 난이도

사용 가능
총 188문항 · 하 44 · 중 118 · 상 36

이번 출제
8문항 · 학교 5곳 · 미분류 0
```

문항이 부족하면 버튼을 비활성화하는 대신 부족 원인과 완화 방법을 함께 보여준다.

예:

```text
상 난이도 문항이 3개뿐입니다.
다음 중 하나를 선택하세요.
· 문항 수를 3개로 줄이기
· 중 난이도 2개를 함께 사용하기
· 다른 소단원 포함하기
```

### 2.4 상태를 잃지 않는다

- 대단원에서 소단원으로 들어가도 필터 상태를 유지한다.
- 브라우저 뒤로 가기 시 학년·대단원·소단원·난이도를 복원한다.
- URL query에 출제 조건을 반영하여 새로고침과 북마크를 지원한다.
- `초기화` 버튼은 필터만 초기화하고, 출제 중인 상태나 로그인 상태는 건드리지 않는다.

### 2.5 색상만으로 난이도를 구분하지 않는다

- `하`, `중`, `상` 텍스트를 항상 표시한다.
- 색상은 보조 수단으로만 사용한다.
- 색맹·저대비 환경에서도 버튼과 상태가 구분되도록 한다.
- 키보드 포커스, `aria-selected`, `aria-expanded`, `aria-live`를 지원한다.

## 3. 목표 화면 구조

### 3.1 대단원 상세 화면

대단원 카드를 클릭하면 기존 문제지 목록 대신 다음 구조를 우선 표시한다.

```text
┌──────────────────────────────────────────────────────────────┐
│ 이차함수와 그래프                                             │
│ 총 198문항 · 소단원 2개 · 문제지 만들기                       │
├──────────────────────────────────────────────────────────────┤
│ 소단원                                                       │
│ [전체] [이차함수의 그래프 188] [이차함수의 활용 10]            │
│                                                              │
│ 난이도                                                       │
│ [전체] [하 44] [중 118] [상 36] [미분류 0]                    │
│                                                              │
│ 출제 방식                                                    │
│ (●) 빠른 출제  ( ) 세부 배합                                  │
│                                                              │
│ 문항 수 [ 8 ]     정렬 [난이도순 / 원본순 / 학교 분산]         │
│                                                              │
│ 결과 118문항 · 예상 문제지 1개                                │
│ [선택 문항 미리보기] [일반 출력] [학생에게 출제]               │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 소단원 선택 방식

MVP에서는 소단원 수가 적은 중등 단원은 segmented chip을 사용하고, 소단원이 많은 고등 단원은 검색 가능한 select 또는 multi-select를 사용한다.

- 1~4개: 칩 버튼
- 5개 이상: 검색 가능한 목록
- 복수 소단원 선택 가능
- 표시명은 `subUnit`, 내부값은 `subUnitKey`
- 동일한 표시명이 다른 부모 단원에 있을 수 있으므로 key만으로 구분

### 3.3 난이도 프리셋

선생님이 직접 비율을 계산하지 않아도 되도록 기본 프리셋을 제공한다.

| 프리셋 | 하 | 중 | 상 | 용도 |
|---|---:|---:|---:|---|
| 기초 연습 | 100% | 0% | 0% | 개념 직후 |
| 개념 확인 | 60% | 40% | 0% | 기본 숙제 |
| 시험 대비 | 20% | 60% | 20% | 내신 대비 |
| 도전 문제 | 0% | 30% | 70% | 상위권·심화 |
| 한 난이도만 | 사용자가 선택 | 사용자가 선택 | 사용자가 선택 | 난이도 혼합 방지 |

프리셋은 제안값이며, 사용자가 직접 문항 수를 수정할 수 있다.

### 3.4 오른쪽 고정 출제 요약 패널

데스크톱에서는 화면 오른쪽에 다음 패널을 고정한다.

- 현재 조건
- 총 사용 가능 문항 수
- 소단원별 분포
- 난이도별 분포
- 예상 학교 수
- 중복·미분류 경고
- 최종 문항 수
- `문제지 만들기`
- `학생에게 출제`

모바일에서는 상단 접이식 요약 패널로 전환한다.

### 3.5 미리보기

미리보기는 전체 문항을 본문까지 모두 렌더링하지 않고, 우선 다음 목록으로 제공한다.

```text
1. 25 순천고 · 14번 · 이차함수의 그래프 · 중
2. 24 제일고 · 8번 · 이차함수의 그래프 · 중
3. 23 팔마고 · 19번 · 이차함수의 그래프 · 상
```

문항 본문 확인이 필요할 때만 기존 mixed engine 미리보기로 이동한다. 초기 화면의 렌더링 부담과 MathJax 지연을 줄인다.

## 4. 기능 요구사항

### FR-01. 계층형 탐색

- 학년·과목별 대단원 목록은 현재 구조를 유지한다.
- 대단원 선택 시 해당 대단원의 소단원 목록을 계산한다.
- 소단원 수와 문항 수를 표시한다.
- 빈 소단원은 기본적으로 숨기거나 비활성화한다.

### FR-02. 소단원 필터

- 전체·단일·복수 소단원을 지원한다.
- 소단원 필터는 `subUnitKey` exact match다.
- 소단원 필터와 대단원 필터가 동시에 적용된다.
- 부모 대단원과 다른 소단원 key가 들어온 문항은 결과에서 제외하고 검토 리포트에 남긴다.

### FR-03. 난이도 필터

- 전체·하·중·상·미분류를 지원한다.
- 기본 필터는 전체다.
- `상`, `중`, `하` 단일 선택은 즉시 사용 가능해야 한다.
- 복수 난이도 선택은 세부 설정에서 지원한다.
- `[중]`은 `중`으로 정규화한다.
- `중1`, `고2`처럼 난이도가 아닌 표기는 `미분류`로 처리한다.
- 원본 `level` 값은 변경하지 않는다.

### FR-04. 결과 집계

필터가 변경될 때마다 다음을 다시 계산한다.

- 전체 문항 수
- 소단원별 문항 수
- 난이도별 문항 수
- 학교 수
- 연도 범위
- 이미지 포함 문항 수
- 검토 필요 문항 수

### FR-05. 빠른 출제

- 필터 조건에 맞는 문항 중 사용자가 지정한 수를 선택한다.
- 기본 정렬은 기존 원본 순서를 보존한다.
- 선택 결과는 deterministic seed를 사용해 같은 조건에서 재현 가능해야 한다.
- 동일 문항 UID 중복을 허용하지 않는다.
- 선택된 문항은 기존 출력·학생 출제 경로로 전달한다.

### FR-06. 세부 배합 출제

다음 조건을 구성표 행으로 표현한다.

```text
행 1: 소단원 A · 하 · 3문항
행 2: 소단원 A · 중 · 4문항
행 3: 소단원 B · 중 · 2문항
행 4: 소단원 B · 상 · 1문항
```

각 행은 다음 조건을 가진다.

- 소단원
- 난이도
- 문항 수
- 선택적 학교·연도 조건
- 선택적 태그 조건

기존 `ArchiveMixerSelector`를 행별로 호출하고, 최종적으로 `validateBlueprintSet`으로 중복·개수·조건 불일치를 검증한다.

### FR-07. 부족 문항 처리

문항이 부족할 때 자동으로 어려운 문항을 섞지 않는다. 다음 선택지를 명시적으로 제시한다.

- 목표 문항 수 낮추기
- 인접 난이도 허용
- 다른 소단원 추가
- 미분류 포함
- 학교·연도 제한 완화

사용자의 명시적 선택 없이 필터 조건을 자동 완화하지 않는다.

### FR-08. 문제지 분할

- 필터 또는 구성표로 최종 선택된 문항을 대상으로 기존 `splitIntoPapers`를 적용한다.
- 한 문제지 최대 80문항 제한을 유지한다.
- 소단원별 출제 문제지는 가능하면 소단원 경계를 유지한다.
- 한 문제지 제목에 선택 조건을 포함한다.
- 문제지 수와 각 문제지 문항 수를 출제 전에 표시한다.

### FR-09. 출력·학생 출제

기존 버튼을 유지하되 버튼 주변에 동작 결과를 명확히 표시한다.

- `일반 출력`
- `학생에게 출제`
- `문제지 미리보기`

학생 출제 시 다음 메타데이터를 함께 저장한다.

- 학년
- 과목
- 대단원 key/name
- 선택된 소단원 key/name 목록
- 난이도 조건 또는 배합표
- 최종 문항 수
- 미분류 포함 여부
- metadata revision

### FR-10. 조건 URL 저장

기존 `grade` query에 다음 조건을 추가한다.

```text
grade=h1
unit=H22-C-05
subUnit=H22-C-05-GRAPH
difficulty=중
mode=quick
count=8
```

복수 값은 comma-separated 또는 반복 query parameter 중 하나로 통일한다. 초기 구현은 URL 길이를 고려해 `sessionStorage` snapshot key와 짧은 query 조합을 사용할 수 있다.

## 5. 데이터·메타데이터 설계

### 5.1 런타임 표준 레코드

필터·선별용 내부 레코드는 다음 필드를 사용한다.

```js
{
  key,
  questionUid,
  sourceFile,
  sourceQuestionNo,
  standardUnitKey,
  standardUnit,
  standardCourse,
  subUnitKey,
  subUnit,
  difficultyBucket,
  levelRaw,
  subUnitConfidence,
  subUnitClassificationDepth,
  school,
  year,
  tags,
  raw
}
```

`raw`는 출력용 원본 문항을 보존한다. 필터용 정규화 값과 원본 필드를 혼용하지 않는다.

### 5.2 메타데이터 join 정책

현재 `unit-past-exams` 화면은 `question-index.js`를 직접 사용한다. 다음 순서로 확장한다.

1. `question-index.js`를 기본 목록으로 읽는다.
2. `question_metadata.json`을 source file + ordinal 또는 `questionUid`로 join한다.
3. `questionUid`, `subUnit*`, `difficultyBucket` 등 세부 메타데이터를 보완한다.
4. 대단원 분류에 사용되는 기존 `standardUnitKey` 매핑은 먼저 보존한다.
5. sidecar의 부모 단원이 현재 profile과 불일치하면 자동 재분류하지 않고 검토 상태로 남긴다.

이 정책은 승인 sidecar의 세부 메타데이터를 활용하면서도, 학년별 legacy standard-unit mapping을 한 번에 깨뜨리지 않기 위한 것이다.

### 5.3 난이도 정규화

```js
function normalizeDifficulty(raw) {
  const value = String(raw || '').trim().replace(/^\[|\]$/g, '');
  if (value === '상' || value === '중' || value === '하') return value;
  return '미분류';
}
```

원본 값과 정규화 값의 역할을 분리한다.

- `levelRaw`: 원본 보존 및 QA
- `difficultyBucket`: 출제 조건 및 표시

현재 데이터에서 확인된 예외는 다음과 같다.

- 고2: `고2` 표기 23문항
- 중1: `중1` 표기 117문항
- 중2: 난이도 공란 44문항
- 중3: `[상]`, `[중]`, `[하]` 표기 72문항

괄호 표기는 정규화하고, 학년 표기·공란은 `미분류`로 분류한다.

### 5.4 소단원 표시명

소단원 key는 마스터 테이블 검증을 통과한 값을 사용한다. 표시명에 legacy 영어 문자열이나 부모 단원과 불일치하는 명칭이 있으면 UI에서 임의 번역하지 않고 canonical master label을 우선한다.

필터 옵션에는 다음을 포함한다.

```js
{
  key: subUnitKey,
  label: canonicalSubUnitLabel,
  count: total,
  difficultyCounts: { '하': 0, '중': 0, '상': 0, '미분류': 0 },
  confidenceCounts: {}
}
```

### 5.5 검토 문항 정책

현재 profile별 검토 대상은 기본 출제 결과에 조용히 섞지 않는다.

- 기본: 결과에서 제외
- 선택: `검토 필요 포함` 체크 시 별도 섹션에 포함
- 표시: `소단원 검토 필요`, `난이도 미분류` 배지
- 출력: 최종 문제지 메타데이터에 포함 여부 기록

## 6. 선별 알고리즘 설계

### 6.1 필터 단계

```text
profile scope
  → standardUnitKey
    → subUnitKey
      → difficultyBucket
        → optional school/year/tags
          → eligible pool
```

필터는 항상 교집합이다. 사용자가 조건을 줄였을 때 결과가 늘어나는 역전 현상이 없어야 한다.

### 6.2 빠른 출제 알고리즘

1. eligible pool을 구성한다.
2. 미분류 문항을 기본 제외한다.
3. 선택 난이도가 단일이면 해당 bucket만 사용한다.
4. 기존 순서 또는 사용자가 선택한 정렬 기준으로 후보를 정렬한다.
5. `questionUid` 기준 중복을 제거한다.
6. deterministic seed로 목표 수만큼 선별한다.
7. 결과 distribution을 검증한다.

### 6.3 세부 배합 알고리즘

구성표를 blueprint row로 변환한다.

```js
[
  { subUnitKey: '...', difficultyBucket: '하', count: 3 },
  { subUnitKey: '...', difficultyBucket: '중', count: 4 },
  { subUnitKey: '...', difficultyBucket: '상', count: 1 }
]
```

행마다 다음을 수행한다.

1. `ArchiveMixerSelector.evaluateHardConstraints`
2. `ArchiveMixerSelector.selectCandidates`
3. 이미 선택된 UID 제외
4. 학교·원본 시험지 다양성 점수 적용
5. 최종 `validateBlueprintSet`

선택 결과가 부족하면 자동으로 다른 난이도를 사용하지 않고, 부족 리포트를 반환한다.

### 6.4 정렬 옵션

MVP:

- 원본 순서
- 난이도 낮은 순
- 난이도 높은 순

2단계:

- 학교 분산
- 연도 분산
- 최근 출제 문항 제외
- 같은 유형·template 반복 제한

### 6.5 문제지 snapshot

현재 snapshot key에 다음 조건을 포함한다.

```text
profileId
standardUnitKey
subUnitKeys
difficultyPlan
selectionSeed
selectedQuestionUids
```

같은 조건과 seed로 재생성할 수 있어야 하며, 학생 출제 후 원본 필터 변경이 기존 문제지에 영향을 주지 않아야 한다.

## 8. 화면별 상세 상호작용

### 8.1 대단원 카드

- 클릭 시 상세 영역으로 이동
- 카드에는 전체 문항 수와 소단원 수를 표시
- 마지막 선택 소단원·난이도가 있으면 작은 상태 배지 표시
- 선택된 카드에는 키보드 focus와 시각적 active 상태 제공

### 8.2 소단원 컨트롤

- 전체 선택
- 선택 해제
- 검색
- 현재 선택 수 표시
- 소단원별 문항 수와 난이도 분포 표시

소단원 이름이 길어도 숫자만 남기지 않고 tooltip 또는 확장 표시를 제공한다.

### 8.3 난이도 컨트롤

- `전체`는 기본 선택
- 단일 선택 시 즉시 결과 갱신
- 다중 선택은 세부 설정에서 사용
- `미분류`는 경고 스타일이지만 선택 가능
- 난이도별 문항 수는 필터가 적용되기 전과 후를 혼동하지 않도록 현재 결과 기준으로 표시

### 8.4 출제 방식 전환

```text
(●) 빠른 출제
    [시험 대비 ▾]   [10문항 ▾]

( ) 세부 배합
    소단원 / 난이도 / 문항 수 구성표
```

모드 전환 시 기존 필터는 유지한다. 빠른 출제에서 세부 배합으로 이동해도 대단원·소단원 조건은 초기화하지 않는다.

### 8.5 출제 확인

출제 전 확인 카드에 다음을 표시한다.

- 문항 수
- 소단원별 수
- 난이도별 수
- 학교 수
- 미분류 수
- 이미지 문항 수
- 문제지 수

확인 문구는 기술 용어보다 작업 결과 중심으로 작성한다.

```text
중3 이차함수의 그래프 문제 8문항을 만듭니다.
중 6문항, 상 2문항이며 5개 학교의 기출을 사용합니다.
```

## 9. 오류·빈 상태·예외 상태

### 9.1 문항 없음

```text
현재 조건에 맞는 문항이 없습니다.

· 난이도를 전체로 바꾸기
· 다른 소단원 추가하기
· 미분류 문항 포함하기
```

### 9.2 문항 부족

```text
선택한 조건에서는 5문항만 사용할 수 있습니다. 목표는 8문항입니다.

[5문항으로 만들기] [조건 수정하기]
```

### 9.3 메타데이터 로드 실패

- sidecar 로드 실패 시 question-index 기반 기본 모드로 동작
- 소단원·난이도 정확도가 제한될 수 있음을 상태 메시지로 표시
- 자동으로 모든 문항을 전체 조건으로 출제하지 않는다.

### 9.4 검토 문항

- 기본 결과에서 제외
- 검토 필요 수를 summary에 표시
- 사용자가 켠 경우에만 별도 배지와 함께 포함

### 9.5 세션 만료

- 필터 조건은 보존
- 출력·학생 출제 버튼을 잠시 비활성화
- 로그인 후 같은 조건으로 복귀

## 12. 롤아웃·롤백

### 12.1 단계적 적용

1. 개발 환경에서 feature flag 활성화
2. 고1·중3 pilot
3. 전체 학년 활성화
4. 세부 배합 기능 활성화

feature flag 예시:

```text
UNIT_PAST_EXAMS_V2=off|mvp|advanced
```

### 12.2 fallback

다음 상황에서는 기존 대단원 문제지 목록을 표시한다.

- core 확장 로드 실패
- 메타데이터 join 실패가 기준 초과
- 필터 결과 정합성 검사 실패
- mixed payload 생성 실패

fallback으로 전환할 때 현재 조건과 오류 원인을 상태 메시지에 남긴다.

### 12.3 롤백 기준

- 출력 문항 수와 선택 문항 수 불일치
- 학생 출제 payload의 UID 불일치
- 기존 answer/solution 렌더링 회귀
- 필터 조건과 다른 문항 포함
- session/localStorage 데이터 손상

롤백은 문항 JS나 DB를 되돌리는 방식이 아니라 feature flag를 `off`로 전환하는 방식으로 우선 처리한다.
