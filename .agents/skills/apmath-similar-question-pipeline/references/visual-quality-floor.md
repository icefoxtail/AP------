# Student-Safe Visual Quality Floor

이 문서는 유사문제의 문제·해설 도형과 그래프를 확장할 때 지켜야 할
학생용 품질 최저선이다. SVG로 그릴 수 있다는 사실만으로 품질을 인정하지
않는다. 수학 모델, 결정론적 계산, SVG 렌더, 실제 브라우저 표시가 모두
연결되어야 자동 `PASS`다.

## 1. 절대 원칙

SVG는 계산기가 아니라 표시 계층이다.

~~~text
수학 모델/계산·검증 → Visual Spec → 결정론적 SVG → production render
~~~

모델이 좌표나 곡선 모양을 눈대중으로 정해 최종 도형을 직접 확정하지
않는다. 식, 정의역, 매개변수, 교점, 접선, 영역 경계 같은 수학 데이터를
먼저 고정하고 SVG는 그 결과를 표시한다.

다음 네 층을 모두 통과해야 학생용 도형을 사용한다.

1. `Math correctness`: 좌표·교점·기울기·수직·넓이·부등식 방향이 계산과 일치
2. `Semantic completeness`: 풀이에 사용한 점·선·곡선·영역·관계가 표시
3. `Readability`: 축·눈금·라벨·범례가 겹치거나 잘리지 않음
4. `Render provenance`: 결정론적 재생성·해시·production 브라우저 렌더 통과

## 2. 판정 등급

| 등급 | 의미 | 학생용 최종 처리 |
|---|---|---|
| `AUTO_PASS` | 수학 관계와 표시를 코드·검수·실렌더로 모두 확인 | 사용 가능 |
| `MANUAL_REVIEW` | 도형은 만들 수 있으나 교점·위상·영역 등의 자동 검증이 부족 | 자동 최종 PASS 금지 |
| `NO_DIAGRAM` | 잘못 그릴 위험이 이득보다 큼 | 텍스트·수식 해설만 사용 |

필수 시각문항이 `MANUAL_REVIEW` 또는 `NO_DIAGRAM`이면 Run 전체를 `HOLD`한다.
선택적 해설 도형은 `NO_DIAGRAM`으로 내릴 수 있지만, 부정확한 그림을
대신 넣어서는 안 된다.

## 3. 공통 자동 PASS 기준

모든 분야는 다음 기준을 공통으로 사용한다.

- 수식·매개변수·정의역 또는 영역 조건이 Visual Spec에 남아 있다.
- 중요한 점은 계산된 좌표와 라벨을 가진다.
- 곡선 위 점·교점·접점은 해당 식의 잔차 또는 관계 검사를 통과한다.
- 정확한 관계(수직·접선·중점·대칭 등)는 눈대중이 아니라 수치 조건으로 확인한다.
- 표본화 곡선은 선언된 정의역 전체를 덮고, 불연속·점근선·급격한 변화에서
  샘플을 세분화한다.
- 경계선(실선/점선), 음영, 화살표, 축 범위가 문제의 의미와 일치한다.
- 라벨·도형이 안전 여백 안에 있고, clipping·겹침·판독 불가가 없다.
- `visualSpec`와 SVG가 결정론적으로 재생성되고 asset/spec/report 해시가 같다.
- 실제 production engine의 `exam`, `solution`, `answer` 화면과 마지막 문항을
  확인한다. 해설 필수 도형은 `solutionVisualCoverage`에 모두 기록한다.

구현 시 수치 관계는 상대 스케일을 반영한 잔차 기준을 사용하고, 표본화
곡선은 최종 viewport에서 최대 1px 수준의 표시 오차를 목표로 한다. 이 수치를
만족시키지 못하는 곡선은 자동 PASS가 아니라 `MANUAL_REVIEW`로 보낸다.

## 4. 분야별 마지노선

| 분야 | `AUTO_PASS` 범위 | 반드시 보여야 하는 것 | 자동 PASS를 보류하는 경우 |
|---|---|---|---|
| 함수 | 유한 정의역의 다항·유리·절댓값·지수·로그·삼각·구간별 함수 | 정의역, 축, 절편·극값 등 핵심점, 불연속·점근선, 필요한 화살표 | 수식 파싱 불가, 고주파 진동, 곡선 위상·교점 수 미확정 |
| 부등식 | 수직선 해집합, 일차·이차·유리 부등식, 검증 가능한 평면 영역 | 실선/점선 경계, 올바른 음영 방향, 시험점 또는 부호 검증, 구간 끝점 | 음영 쪽을 계산하지 않음, 경계가 닫히지 않음, 여러 영역의 연결 관계 불명 |
| 도형의 방정식 | 평면좌표·직선·원·타원·포물선·쌍곡선과 유한 개의 관계 도형 | 좌표·두 점 기울기/절편, 중심·꼭짓점·초점·준선·점근선·접선·현·교점 중 풀이에 필요한 요소 | 일반 고차 implicit 곡선, 교점 개수·위상이 자동 검증되지 않음 |
| 미적분 | 함수·도함수, 접선·할선, 극값·증감, 극한 접근, 정적분 영역 | 기준 함수, 도함수/접선 관계, 임계점, 증가감소 구간, 적분 경계·음영 | 도함수·적분 결과 미검증, 복잡한 다중 교점, 3차원·애니메이션 의존 |

표의 `AUTO_PASS` 범위 안에서도 문제에서 실제로 사용하는 관계만 넣는다.
단순 원 방정식에 존재하지 않는 접선을 추가하거나, 함수에 의미 없는 점을
장식으로 넣는 것은 품질 향상이 아니다.

## 5. 현재 capability와 확장 순서

현재 staged 경로에서 활성인 것은 `circle_geometry` 기반 해설 SVG와 기본
좌표·선분·곡선·표 렌더다. 일반 함수식을 계산해 그래프로 만드는 컴파일러,
부등식 음영, 타원·포물선·쌍곡선, 미적분 오버레이는 capability report에
활성으로 표시되기 전까지 자동 PASS 대상이 아니다.

권장 순서는 다음과 같다.

1. 공통 primitive: 곡선 샘플링, 음영, 화살표, 구간, 라벨 충돌·clipping 검사
2. 함수식·정의역 compiler와 핵심점/불연속 검증
3. 부등식 경계·시험점·영역 검증
4. 원에서 타원·포물선·쌍곡선으로 확장
5. 도함수·접선·극값·적분 영역·극한 접근 오버레이

새 분야를 추가할 때는 먼저 이 문서의 `AUTO_PASS` 조건을 구현하고,
capability report와 회귀 테스트에 등록한 뒤에만 Builder가 해당 도형을
반환하도록 허용한다.

## 6. 실험 lane과 production 승격

장기 목표 분야는 production capability를 바로 넓히지 않고
`visual-benchmark` 실험 lane에서 대표 사례를 반복 실행할 수 있다. 이 lane은
평면좌표·직선의 방정식·도형의 이동·함수·부등식·타원·미적분의 수학 모델,
핵심 관계, SVG 결정성만 빠르게 확인한다.
실험 결과의 `PASS_WITH_MANUAL_BROWSER_GATE`는 다음을 의미한다.

- 모델과 SVG 검사는 통과했다.
- 같은 입력을 여러 번 렌더한 해시가 같다.
- 아직 production `exam`·`solution`·`answer` 브라우저 화면을 통과하지 않았다.

따라서 실험 타입은 `visual_lane.py`의 production 타입과 분리하고, Builder가
자동 반환하거나 staged Run의 `visualTopicCapabilities`를 `ACTIVE`로 바꾸지
않는다. production 승격에는 분야별 자동 검증, 회귀 fixture, 실제 브라우저
렌더 증거, 마지막 문항과 해설 도형 coverage가 모두 필요하다.
