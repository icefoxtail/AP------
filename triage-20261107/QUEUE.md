## 인수 규칙

1. ROOT만 이 대기열에서 시험지를 `READY_FOR_RENDER`로 올리고 시험지 단위 담당을 정한다. ROOT 준비 중인 시험지를 공식 인수로 처리하지 않는다. 현재의 별도 병렬 초안 허가는 22 복성고·22 효천고에만 적용하며, 각 산출물은 `.tmp` 후보로만 둔다. 22 금당고·22 순천여고·23 강남여고처럼 개별 인계에서 READY 전 렌더 금지를 유지한 시험지에는 적용하지 않는다.
2. 구현·검수는 하나의 코덱스 ROOT가 같은 공유 파일시스템에서 서로 다른 작업자로 실행한다. 공용 교환 디렉터리는 저장소 루트의 `.tmp/svg-worker-queue/`이고, 이 경로가 양쪽에서 같은 파일로 보이는지 먼저 검증한다. 공유가 확인되지 않으면 인수하지 않고 ROOT에 알린다.
3. 작업자는 이 브랜치의 최신 원격 HEAD와 본 파일을 다시 읽고, 각 시험지의 FIGURE 전체와 해당 입력 3종, 소스와 기존 이력·담당자를 대조한다. 한 시험지 쓰기 소유자는 동시에 하나뿐이다. 구현자가 소유권을 놓은 후 검수자가 인수한다. 장부와 파일이 충돌하면 새 작업을 시작하지 않는다.
4. 공용 디렉터리에서 시험지별 원자적 잠금과 전역 렌더 잠금을 취득한다. 잠금 생성의 성공으로만 소유권을 인정하며 기존 잠금의 생존 상태를 확인할 수 없으면 임의 제거하지 않는다. 잠금·시도 원장 또는 공유 경로를 사용할 수 없으면 `OPEN`으로 보고하고 렌더하지 않는다.
5. GPT/Codex 구현 라인에는 문항별 고정 렌더 시도 상한이 없다. 렌더 시작 전후 실제 결과를 공용 원장에 기록한다. 횟수가 불명확하면 `UNKNOWN`으로 보존하며 추정·초기화하지 않는다. 정상 종료, 실패, 차단과 재시도의 구체 수정 사유를 구분해 기록.
6. 구현자는 공식 엔진 결과·학생용 after 이미지·입력/결과 해시·검증 기록을 공용 디렉터리에 넘긴다. 독립 검수자는 실제 그림과 원문 수학을 보고 반려 또는 통과시킨다. 검수자가 직접 수정한 부분은 다른 작업자가 다시 독립 확인한다.
7. 검수자 한 명만 시험지별 별도 작업 브랜치에 통과분을 커밋·push하고 SHA와 파일을 원격에서 재확인한다. ROOT의 입력 브랜치와 다른 시험지의 소유 파일을 덮어쓰지 않는다. main 병합, 검증 완화, CI 우회, 수동 SVG 및 임의 게시는 금지한다.
8. 계속 실행되는 ROOT가 빈 구현/검수 라인을 새로 호출하고, 기존 세션이 종료되면 실제로 다시 실행한다. 단순 배정·메시지를 작업 진행으로 기록하지 않는다. READY 항목이 없으면 `WAITING_FOR_INPUT`을 기록하며 존재하지 않는 일을 추측하지 않는다. 프로세스가 종료된 뒤 스스로 계속 실행된다고 가정하지 않는다.

## 22 순천여고 기존 결과·소유 이력 확인

- ROOT가 Q04·Q05·Q11을 최신 사용자 기준에 따라 `FIGURE`로 재판정했다. 함수·유리함수·무리함수는 학생 이해에 조금이라도 도움이 되면 그래프를 만든다는 사용자 지시를 적용하며, 기존 그림이 있다는 이유만으로 제외하지 않는다.
- Q09의 기존 `OPEN` 상태를 유지한다. Q12는 사전검사 `sign` 필드 실패 후 `amplitude`로 수정한 이력을 함께 보존한다.
- 이 입력 15문항은 ROOT 초안이며 전부 `NOT_RENDERED`다. 기존 결과·승인·누적 시도와 기존 로컬 초안의 실제 소유를 대조하기 전까지 시험지 상태를 `ROOT_PREPARING`으로 둔다.
- 한 문항 폴더의 item/plan/publish/STATUS 가운데 하나라도 업로드 심사에서 거절되면 그 qNN 폴더의 나머지 파일도 올리지 않는다. 정확한 거절 경로·사유·기존 이력·다음 조치를 기록하고, 거절된 요청은 재시도하지 않는다. 모든 폴더가 완전한 네 파일 세트일 때만 게시한다.
