# 학습지 생성기 업그레이드 비교 메모

작성일: 2026-08-31

## Audit scope

첨부된 매스홀릭 화면 3장을 기준으로, 현재 저장소의 JS 아카이브 메인·믹서·단원별 기출 흐름을 비교했다. 첨부 이미지는 기능 지시문이 아니라 현재 화면을 설명하는 참고 증거로만 취급했다.

## User goal

선생님이 원하는 단원·출처·난이도·문항 수를 빠르게 정하고, 결과를 믿고 미리 본 뒤, 디자인을 적용해 출력하거나 학생에게 출제하는 것.

## Overall verdict

아카이브는 출제 조건을 설명하고 검증하는 힘이 강하다. 여기서 매스홀릭의 디자인을 통째로 가져올 필요는 없고, **설정 사이드바·접이식 그룹·토글 체계·템플릿 선택·하단 고정 액션바** 같은 UI 패턴만 차용하는 것이 맞다.

## What the archive should borrow from Massholic

### 1. 오른쪽 고정 설정 패널

아카이브의 본문은 단원·소단원·난이도·문항 수에 집중하고, 오른쪽에는 출력 관련 설정을 고정한다.

```text
[출제 조건 본문]                 [설정 사이드바]
단원 / 소단원 / 난이도             출력물
문항 수 / 분할 / 회차               문제지 · 답안지 · 풀이
                                   페이지
                                   디자인
```

현재 아카이브 확인 화면의 `출제 요약` 패널을 이 역할로 확장하면 된다. 실제 미리보기는 왼쪽에 남겨 두고, 설정을 바꿀 때 결과가 즉시 갱신되도록 한다.

### 2. 출력물별 토글과 종속 옵션

매스홀릭의 `문제지`, `답안지`, `빠른정답`, `풀이` 구조는 아카이브에도 유용하다. 다만 들여쓰기만으로 관계를 표현하지 말고, 부모 옵션이 꺼지면 자식 옵션도 명확히 비활성화하고 이유를 보여준다.

### 3. 디자인 프리셋 카드와 색상 팔레트

아카이브에도 `기본`, `시험지`, `노트`, `교사용` 같은 소수의 출력 프리셋과 색상 팔레트를 추가할 만하다. 매스홀릭처럼 많은 썸네일을 처음부터 펼치기보다는 4~6개 프리셋을 먼저 보여주고 `더 보기`로 확장하는 편이 적합하다.

### 4. 템플릿 저장·재적용

매스홀릭의 `저장된 템플릿 적용`과 `추가`는 아카이브의 반복 출제와 잘 맞는다. 예를 들어 `중등 기본 4문항`, `시험 대비 2단`, `교사용 해설 포함` 같은 설정 묶음을 저장해 단원별 문제지에 재사용할 수 있다.

### 5. 결과 중심의 페이지 배치 선택

매스홀릭의 `2단`, `3단`, `스마트 정렬`, 여백 설정은 아카이브의 미리보기 단계에 차용할 가치가 있다. 다만 이름만 가져오지 말고 `4문항 / 2단`, `6문항 / 3단`처럼 결과를 직접 설명하는 옵션으로 재표현해야 한다.

### 6. 하단 고정 액션바

매스홀릭의 하단 `이전`·`학습지 생성` 구조는 아카이브의 단계 이동에도 적합하다. 아카이브는 여기에 `미리보기`, `일반 출력`, `학생 출제`를 단계별로 명확히 배치하면 된다.

## Do not borrow directly

- 제목·기간·문항 설정·디자인·정렬을 한 긴 화면에 모두 쌓는 방식
- 의미가 설명되지 않은 `스마트 정렬`과 썸네일 중심의 옵션명
- 회색 비활성 컨트롤만 보여주고 원인을 설명하지 않는 방식
- 아카이브가 이미 가진 소단원·난이도·출처 구조를 사이드바 안에 다시 복제하는 방식

## Sidebar finding

이번 사이드바를 보면 매스홀릭은 단순한 디자인 선택기가 아니라 다음 네 가지를 동시에 담당한다.

1. 학습지 메타데이터: 제목·부제목·QR
2. 교사용/학생용 산출물: 문제지·답안지·빠른정답·풀이·답안 작성 용지·문항 힌트
3. 출처·문항 정보: 난이도·대표 유형 영상 QR·교재 출처·해설지 출처
4. 시각·배치: 양면·제본 여백·테마·날짜 표기·색상·모눈·단 구성·스마트 정렬

강점은 출력 직전 조정력이 매우 높다는 점이다. 문제는 서로 다른 목적의 설정이 같은 세로 패널에 계속 이어져 **현재 화면이 무엇을 바꾸고 있는지, 출력물이 어떻게 달라지는지, 설정 간 충돌이 있는지**가 약해진다는 점이다.

특히 `답안지` 아래의 `빠른정답 / 풀이`, `교재 출처` 아래의 `문제지 / 해설지`처럼 종속 옵션이 들여쓰기만으로 표현되고, `답안 작성 용지 beta`, `문항 힌트 beta`, `대표유형 동영상 QR beta`는 상태와 효과가 충분히 설명되지 않는다. 이 영역은 기능을 줄이기보다 **그룹·의존성·결과 미리보기**를 강화하는 편이 맞다.

권장 사이드바 구조는 다음과 같다.

```text
출력물
  문제지 / 답안지 / 빠른정답 / 풀이
문항 정보
  난이도 / 교재 출처 / 시험지 출처 / 힌트 QR
페이지 설정
  단 구성 / 스마트 정렬 / 양면 / 제본 여백 / 모눈
표지·제목
  제목 / 부제목 / 날짜 / QR
디자인
  테마 / 색상
```

각 그룹 헤더 옆에는 `현재 적용: 문제지·답안지·QR` 같은 요약을 두고, 옵션 변경 시 오른쪽 문제지 미리보기와 하단 `예상 페이지·출력물 수`를 즉시 갱신하는 것이 좋다. 이 사이드바는 아카이브의 출제 조건을 대체하지 않고, 아카이브에서 확정된 `selection snapshot`을 받아 최종 산출물을 꾸미는 역할로 제한하는 것이 구조적으로 가장 안정적이다.

## Strengths

- 매스홀릭: 제목·기간·회차·템플릿·색상·여백·페이지 배치·QR·출처 표시까지 최종 산출물 제어력이 높다.
- 아카이브: 학년→과목→대단원→소단원→난이도→문항 수의 계층이 명확하고, 조건별 가용 문항 수를 보여준다.
- 아카이브: `빠른 구성`과 `세부 조합`을 분리해 초보 경로와 고급 경로를 나눈다.
- 아카이브: 미리보기 단계에서 실제 문제지와 출제 요약을 함께 보여주어 생성 전에 신뢰를 만든다.

## UX risks in the attached flow

1. **출제 조건과 인쇄 설정이 한 화면에서 섞인다.** 매스홀릭의 제목·기간·분할·회차와 디자인·정렬·표시 옵션이 연속으로 노출되어, 선생님이 “어떤 문제를 뽑는가”와 “어떻게 인쇄하는가”를 번갈아 판단해야 한다.
2. **현재 119개라는 숫자만으로는 결과를 예측하기 어렵다.** 소단원별·난이도별 가용 수, 중복 여부, 분할 후 문제지 수, 미분류·검토 필요 문항이 보이지 않는다.
3. **생성 버튼이 마지막에 바로 있다.** 실제 결과 확인 전에 `학습지 생성`을 누르게 되어, 의도하지 않은 문항 구성이나 페이지 배치를 뒤늦게 발견할 수 있다.
4. **비활성 상태의 원인이 보이지 않는다.** `서술형 출제 안내`, `분할생성`의 일부 입력이 회색으로 보이지만, 왜 비활성인지와 무엇을 켜야 하는지가 화면에 설명되지 않는다.
5. **스마트 정렬의 의미가 학습되지 않는다.** `1문제씩`, `2문제씩`, `4문제씩` 썸네일은 보이지만 실제 페이지 결과와 어떤 차이가 있는지 즉시 이해하기 어렵다.
6. **디자인 선택지가 풍부하지만 선택 결과의 확인점이 약하다.** 템플릿·색상은 많지만 현재 선택된 디자인이 문제지 미리보기에 어떻게 반영되는지 한 번에 확인하기 어렵다.

## Engine strategy and upgrade scope

### 결론

아카이브의 최적 방향은 범용 학습지 편집기가 아니라 **아카이브 기반 문제지 오케스트레이터**다. 교사가 원하는 단원·출처·소단원·난이도·문항 수를 입력하면, 검증된 원본 문항을 deterministic하게 조합하고, 같은 결과를 미리보기·인쇄·정답/해설·학생 출제로 이어 주는 것이 핵심 제품 가치다.

매스홀릭에서 차용할 것은 선택 화면 전체가 아니라 다음의 **출력 프로필 개념**이다.

```text
문항 선택 엔진        → 어떤 문항을 뽑을지 결정
문제지 매니페스트     → 선택 결과를 고정하고 재현
출력 프로필            → 제목·QR·답안·해설·페이지·디자인 결정
렌더/배포 엔진         → 미리보기·인쇄·학생 출제 실행
```

출력 프로필이 문항 선택을 다시 건드리면 안 된다. 반대로 소단원·난이도·출처 조건을 디자인 사이드바에 복제해서도 안 된다.

### 현재 엔진에서 확인된 구조적 결손

1. `unit-past-exams.js`는 `unit-past-exams-core.js`의 `selectByBlueprint()`를 사용하고, `mixer.html`은 자체적인 난이도/블루프린트 선택 흐름에서 `ArchiveMixerSelector`를 호출한다. 두 경로가 같은 선별 계약을 공유하지 않는다.
2. 단원별 흐름은 선택 결과를 `mixedQuestions_*`와 `mixedMeta_*`로 저장하지만, 믹서는 `mix_${Date.now()}` 키와 최소 메타데이터를 만든다. 따라서 같은 조건을 다시 실행하거나 결과의 선택 근거를 완전히 복원하는 공통 매니페스트가 없다.
3. `mixed_engine.html`은 시험지·정답표·해설지·QPP·QR·헤더를 이미 담당한다. 지금 필요한 것은 새 렌더러가 아니라, 이 출력 기능을 버전 있는 프로필로 묶어 모든 출제 경로에서 동일하게 사용하는 일이다.
4. 단원별 흐름에는 부족 문항·인접 난이도·미분류 완화가 있지만, 믹서·학교/연도 묶음 출제까지 같은 정책과 진단 형식으로 통합되어 있지 않다.

### 먼저 만들 공통 계약

```js
PaperSpec {
  source: { profileId, courseKey, unitKeys, subUnitKeys, scope, schools, years },
  selection: { mode, blueprintRows, count, batchCount, seed, relaxationPolicy },
  output: { title, subtitle, qpp, columns, order, outputs, qr, sourceLabels, templateKey, theme },
  provenance: { indexRevision, metadataRevision, selectorVersion }
}

SelectionSnapshot {
  snapshotKey, questionUids, papers, requested, actual,
  diagnostics, sourceSummary, seed, selectorVersion, createdAt
}
```

`PaperSpec`는 교사의 의도이고 `SelectionSnapshot`은 엔진이 확정한 결과다. 미리보기·인쇄·학생 출제는 모두 같은 `SelectionSnapshot`을 읽어야 한다. 지금의 `mixedQuestions_*`는 임시 payload로 유지하되, 그 앞에 이 매니페스트를 두는 방식이 안전하다.

### 업그레이드 우선순위

#### P0 — 엔진 신뢰성 통합

- `unit-past-exams-core.js`와 `ArchiveMixerSelector`를 하나의 `selectPaper(spec)` 계약 아래 묶는다.
- hard constraint, 후보 수, 부족 사유, 선택 수, 중복 UID, 난이도/소단원/출처 분포를 공통 `diagnostics`로 반환한다.
- seed만 저장하지 말고 selector 버전·index revision·metadata revision까지 저장해 동일 결과를 재현한다.
- `strict → 문항 수 축소 → 인접 난이도 → 미분류 포함` 완화 정책을 명시적인 순서로 만들고, 자동 완화하지 않는다.
- 단일 문제지뿐 아니라 여러 문제지/회차를 하나의 batch manifest로 생성해 문제지 사이 UID 중복과 분포를 검증한다.
- 미리보기는 순수 렌더, 인쇄·학생 출제·출제 이력 등록은 명시적 commit으로 분리한다.

#### P1 — 매스홀릭에서 차용할 출력 계층

- `OutputProfile`을 만들고 문제지·정답표·빠른 정답·해설지·QR·출처 표시를 한 묶음으로 저장한다.
- `기본 / 시험 대비 / 교사용 해설` 정도의 저장 프리셋과 최근 사용 프로필을 제공한다.
- QPP만이 아니라 2단/3단, 페이지 여백, 정렬 정책, 제목·부제·날짜·회차, 색상/테마를 프로필로 통합한다.
- 출력 프로필 변경은 선택 결과를 재선정하지 않고 같은 snapshot을 재렌더한다.

#### P2 — 아카이브의 차별화 확장

- 학교·연도·시험 종류·출처 다양성·최근 사용 문항을 batch selection의 제약으로 승격한다.
- 문제지 이력과 재출제 제외 목록을 snapshot 기준으로 연결한다.
- 학생 출제 결과/오답 데이터와 `questionUid → 단원·소단원·개념·유형·난이도`를 연결해 다음 출제의 근거로 사용한다.
- 메타데이터 미분류·검토 필요·해설/이미지 누락을 생성 전 품질 게이트로 표시한다.

### 구현하지 말아야 할 순서

- 먼저 매스홀릭처럼 템플릿 수를 늘리는 것
- 선택 엔진을 건드리지 않은 채 믹서·단원 화면에 필터를 더 붙이는 것
- 출력 화면을 새로 만드는 것
- `스마트 정렬` 같은 이름만 복사하고 결과 차이를 정의하지 않는 것

즉, 1차 목표는 `더 예쁜 생성기`가 아니라 **어느 진입점에서 만들어도 같은 조건이면 같은 문제지 결과와 근거가 나오는 엔진**이다. 그 위에 매스홀릭식 사이드바와 저장 프리셋을 얹는 순서가 아카이브에 가장 적합하다.

## Priority recommendations

### P0 — 먼저 바꿀 것

- `학습지 생성`을 바로 실행하지 말고 `미리보기로 이동`을 1차 CTA로 둔다.
- 화면 상단 또는 우측에 다음 요약을 고정한다: `출처 · 단원 · 소단원 · 난이도 · 사용 가능 문항 · 선택 문항 · 예상 페이지 · 원본 시험지 수`.
- 부족하거나 비활성인 조건은 이유와 해결책을 함께 표시한다.
- 생성 전에 `문항 중복 없음`, `미분류 n개`, `서술형 n개`, `페이지 수`, `QR 포함 여부`를 확인시킨다.

### P1 — 작업 속도를 높일 것

- `빠른 설정`에는 프리셋·문항 수·페이지당 문항 수만 두고, 분할·회차·서술형·정렬 규칙은 `고급 설정`으로 접는다.
- 최근 학습지 복제와 저장 템플릿을 첫 화면 상단에 배치한다.
- 아카이브에서 선택한 조건을 생성기로 넘길 때, 별도 재선택 없이 `출처 요약`을 읽기 전용으로 보여준다.
- 분할 생성은 `문제지 3장으로 나누기`, `각 20문항`, `회차마다 중복 없이`처럼 결과 중심 문구로 바꾼다.

### P2 — 이해도와 완성도를 높일 것

- 스마트 정렬을 `페이지 배치`로 이름을 바꾸고, 각 옵션에 작은 실제 페이지 미리보기를 붙인다.
- 디자인 템플릿 선택 시 오른쪽 미리보기를 즉시 갱신하고, 색상·여백·표시 옵션을 한 묶음의 `현재 디자인`으로 요약한다.
- 체크박스·라디오·비활성 텍스트의 대비와 키보드 포커스를 점검한다. 현재 스크린샷만으로 WCAG 준수 여부를 확정할 수는 없다.

## Implementation boundary

아카이브의 단원별 출제 화면은 이미 이 방향의 기반을 갖고 있다. 출제 조건 계층과 빠른/세부 구성 분리는 [구현 계획](../archive/archive/docs/UNIT_PAST_EXAMS_SUBUNIT_DIFFICULTY_UX_IMPLEMENTATION_PLAN.md:13), 실제 소단원·난이도·프리셋 구성은 [unit-past-exams.js](../archive/unit-past-exams.js:887), 확인 단계의 미리보기·요약·출력/학생 출제는 [unit-past-exams.js](../archive/unit-past-exams.js:951)에서 확인된다.

권장 구현은 아카이브의 문항 선택 로직은 그대로 유지하고, 확인 단계의 `출제 요약`을 매스홀릭식 설정 사이드바로 확장하는 것이다. 문항 분류·난이도·중복 방지 기준은 아카이브에 남기고, 출력물·페이지·디자인 설정만 사이드바에서 제어하면 된다.

## Evidence limits

- 매스홀릭은 제공된 정적 화면만 확인했으므로 실제 클릭 흐름, 반응형 동작, 키보드 순서, 오류 처리, 생성 시간은 검증하지 못했다.
- 아카이브는 로컬 화면에서 단원 선택→세부 조합→실제 미리보기까지 확인했지만, 학생 출제의 외부 연동 제출 결과는 실행하지 않았다.
