# ALIVE 유사·심화 문항 + 시각 에셋 재생성 강화 규칙 v1.0
## Similar / Advanced Follow-up + Deterministic Visual Regeneration Specification
### Manual Production Edition — 2026-08-20

---

# 0. 문서 목적

이 문서는 ALIVE 정본 체계에서 **기출·원문 기반 유사문제와 심화문제를 직접 제작할 때 적용하는 보강 실행 규칙**이다.

목표는 다음과 같다.

1. 단순 숫자갈이 수준의 유사문제를 피한다.
2. 원문과 같은 핵심 개념·유형을 유지하면서 독립된 새 문항을 만든다.
3. 심화문제는 계산량 증가가 아니라 실제 판단 구조를 한 단계 상승시킨다.
4. 시각자료가 포함된 원문은 기존 에셋을 억지로 재사용하지 않고, 새 문항의 수치·좌표·조건에 맞는 **새 에셋을 결정론적으로 재생성**한다.
5. 문항과 에셋을 따로 확정하지 않고 하나의 Candidate로 묶어 검증하고 FREEZE한다.
6. 최종 산출물은 JS아카이브에서 바로 사용할 수 있는 JS + 필요한 PNG/SVG 에셋으로 만든다.

이 문서는 생산기·API·DB·Queue 구현을 전제로 하지 않는다.
수동 작업에서도 동일한 생성·검증 원칙을 적용하기 위한 작업 규칙이다.

# 2. 작업 유형 강제 분리

유사문제와 심화문제를 같은 규칙으로 만들지 않는다.

## 2-1. STRICT_VARIANT — 순수 변형

적용:
- 원문 골격·유형·난도·풀이구조를 그대로 유지하면서 숫자·상수·변수만 바꾸는 작업
- 사용자가 “숫자만 바꿔”, “같은 구조 그대로”, “완전 동일 유형 변형”을 명시한 경우

LOCK:
- questionFormat
- concept
- problemType
- solutionEntry
- solutionGraph
- 발문 논리 순서
- 출제 의도
- 난도 역할
- 시각 구조
- curriculum generation

CHANGE:
- 수치
- 상수
- 변수명
- 새 수치에 따른 보기·정답
- 새 수치에 종속되는 시각 라벨·좌표

금지:
- 난도 상승
- 조건 추가
- 풀이 진입 변화
- 새로운 판단 지점 추가
- 유형 개선
- 형식 변경

중요:
**STRICT_VARIANT의 “시각 구조 LOCK”은 기존 이미지 파일을 그대로 재사용하라는 뜻이 아니다.**
새 수치가 그림에 반영되어야 하면 동일한 시각 topology를 유지하면서 에셋을 다시 생성한다.

## 2-2. EXAM_FOLLOWUP 확인 — 기본 유사문제

사용자가 일반적으로 “유사문제”를 요청할 때의 기본 작업 유형이다.

필수:
- 원문 concept 유지
- problemType 유지
- solutionGraph 핵심 유지
- 핵심 decision 수 유지
- curriculum boundary 유지
- questionFormat 유지
- 난도 동치
- 독립 문항
- 단순 숫자갈이에만 그치면 FAIL

허용:
- 수치·좌표·상수 재설계
- 원문과 다른 문장 표현
- 같은 풀이 구조 안에서 조건 제시 방식 변화
- 오답 경로 재설계
- 시각자료 전체 재생성
- 원문의 시각 구조를 보존하면서 좌표·라벨·길이·배치의 수치적 재설계

유사문제의 기준은
**“같은 핵심 사고를 요구하지만 학생이 원문 답이나 수치를 기억해서 풀 수 없는 독립 문항”**이다.

---

## 2-3. EXAM_FOLLOWUP 심화 — 실제 심화문제

심화문제는 단순 계산 증가로 만들지 않는다.

필수:
1. 새로운 중간 판단 지점 `+1` 이상
2. 발문 목표 또는 풀이 진입 방식 중 최소 1개 변화
3. 원문 핵심 판단 최소 1개 유지
4. A~F 인지 상승 유형 최소 1개 적용
5. QUALITY A
6. 교육과정 범위 준수
7. 새 시각자료가 필요하면 문항 설계와 동시에 재생성

A~F의 정의는 Master Rulebook §13을 정본으로 사용한다. 이 Spec에서는 해당 유형을 최소 1개 적용했는지만 확인한다.

금지:
- 숫자만 크게 만들기
- 계산 항만 늘리기
- 근호·분수만 복잡하게 만들기
- 원문 풀이를 그대로 복사해 끝까지 풀리는 문제
- 상위 교육과정 개념을 끌어와 억지로 어렵게 만들기

# 3. “강화 유사문제”라는 작업명 사용 규칙

`강화 유사문제`는 사용자용 작업명으로 사용할 수 있으나 ALIVE의 새 MODE로 정의하지 않는다.

판정:

- 핵심 decision 수가 원문과 같고 난도 동치 → `EXAM_FOLLOWUP 확인`
- 새로운 판단 지점이 실제로 +1 이상 → `EXAM_FOLLOWUP 심화`
- 수치만 바뀌고 구조가 완전히 같음 → `STRICT_VARIANT`

즉 “강화”라는 이름만으로 심화 판정을 주지 않는다.
실제 solutionGraph와 decision 변화량으로 분류한다.

# 5. visualDependency 판정 강화

각 문항을 다음 중 하나로 분류한다.

## NONE
그림 없이도 원문과 동일한 문제 의미·풀이가 완전하게 유지된다.

## OPTIONAL
그림이 이해를 돕지만 발문 텍스트만으로도 정답이 완전히 확정된다.

## ESSENTIAL
그림·그래프·도형·표의 정보가 문제 조건 또는 풀이 판단에 직접 필요하다.

다음 중 하나라도 해당하면 원칙적으로 ESSENTIAL이다.

- 좌표·점 위치를 그림에서 읽어야 함
- 길이·각·평행·수직·접선·교점 등 관계를 그림이 제공함
- 그래프의 모양·교점·이동 관계를 읽어야 함
- 그림 내부 라벨이나 수치가 발문의 일부 역할을 함
- 표 내부 값이 문제 조건임
- 도형 topology 자체가 풀이 조건임

ESSENTIAL인데 새 에셋이 없으면 최종 완료 금지.

# 6. NEW ASSET MANDATORY GATE — 새 에셋 의무 생성 조건

다음 중 하나라도 해당하면 기존 원문 에셋을 재사용하지 않고 새 에셋을 만든다.

1. 그림 내부 좌표가 변경됨
2. 길이·각도·비율·수치가 변경됨
3. 점 이름 또는 변수명이 변경됨
4. 그래프의 함수식 또는 변환량이 변경됨
5. 도형의 위치·크기·대응 관계가 변경됨
6. 원문 이미지의 숫자나 라벨이 새 발문과 충돌함
7. 새 문항의 오답/정답 판단에 그림의 새 정보가 필요함
8. 심화 과정에서 보조점·분기·추가 구조가 필수로 생김
9. 기존 이미지를 쓰면 학생에게 원문 정답 또는 원문 수치를 노출함
10. 새 문항과 기존 이미지가 100% 의미 동치인지 확정할 수 없음

예외적 재사용 허용:
- 그림이 순수 개념 설명용이고
- 수치·좌표·라벨이 새 문항과 독립적이며
- solutionGraph와 정답에 영향을 주지 않고
- 재사용해도 원문 정답·수치가 노출되지 않을 때

애매하면 재사용하지 않고 새로 만든다.

# 7. VISUAL STRUCTURE LOCK — 시각 구조 LOCK의 정확한 의미

시각 구조 LOCK은 “같은 이미지 픽셀 사용”이 아니다.

LOCK 대상:
- component 종류
- component 개수
- 점·선·축·도형의 semantic role
- 선 연결 관계
- 대응 관계
- 그래프/도형의 기본 topology
- 문제에서 시각자료가 수행하는 정보 역할
- 핵심 표시 방식
- questionFormat과의 관계

변경 가능:
- 좌표
- 수치
- 길이
- 각도
- 평행이동량
- 대칭이동량
- 변수명
- 점 라벨
- 캔버스 내 배치
- 축 범위
- 보기 쉬운 비율 조정

단, 변경 결과가 solutionGraph를 바꾸면 STRICT_VARIANT가 아니라 EXAM_FOLLOWUP으로 재분류한다.

# 8. SEMANTIC OWNERSHIP LOCK — 라벨·표식 소유권 잠금

새 에셋에서 모든 시각 요소는 의미 소유권을 가져야 한다.

확인 대상:
- 점 라벨이 정확한 점에 붙었는가
- 길이 수치가 정확한 선분을 가리키는가
- 각도 표식이 정확한 각에 붙었는가
- 직각 표식이 실제 수직 관계에만 존재하는가
- 점선이 실제 보조 관계를 나타내는가
- 좌표 라벨이 실제 점 좌표와 일치하는가
- 축 숫자가 실제 scale과 일치하는가
- 함수/도형 이름이 올바른 component를 가리키는가

다음은 HARD FAIL:
- 라벨 위치가 다른 점을 의미하게 됨
- 수치가 다른 선분에 붙음
- 실제로 수직이 아닌데 직각 표식 존재
- 실제로 평행이 아닌데 평행 표식 존재
- 그래프 위치와 좌표축 눈금이 불일치
- 변형 전 원문의 라벨이 일부 남아 새 문항과 충돌

# 9. 문항 + 에셋 역설계 순서

시각문항은 그림부터 그리지 않는다.

강제 순서:

```text
원문 Fingerprint
↓
목표 사고 결정
↓
정답 형태 결정
↓
solutionGraph 설계
↓
조건·수치·좌표 역산
↓
발문/보기 Candidate 작성
↓
visualSpec 작성
↓
수학 exact 검증
↓
에셋 결정론적 생성
↓
문항-에셋 정합성 검증
↓
Candidate + Asset 동시 FREEZE
```

금지:
- 보기 좋은 도형을 먼저 만든 뒤 문제를 끼워 맞추기
- 에셋에서 우연히 나온 좌표를 발문 조건으로 채택하기
- 정답이 안 맞는다고 그림 숫자만 사후 수정하기
- FREEZE 후 보기 또는 정답만 바꿔 통과시키기

대상:

- 직선
- 원
- 포물선
- 함수 그래프
- 교점
- 수선의 발
- 내분/외분점
- 대칭점
- 평행이동
- 길이·각도·비율이 중요한 도형
- 좌표 기반 삼각형·사각형
- 반사/최단거리 문항

Python에서 최소 확인:
- 핵심 점 좌표

- 기울기

- 반지름

- SVG/PNG 좌표 변환값

눈대중 배치만으로 수학적 위치를 결정하지 않는다.

# 11. GENERATIVE ASSET BAN

수학 문항의 도형·그래프·표 에셋에는 생성형 이미지 모델을 사용하지 않는다.

금지:
- AI 이미지 생성으로 좌표도형 제작
- 스타일 변환으로 원본과 비슷한 수학 그림 만들기
- 생성형 inpainting으로 선·점·라벨을 비결정적으로 복원
- 원문 또는 visualSpec 없이 보기 좋은 그림 임의 생성

허용:
- Python 계산
- SVG/vector 직접 생성
- deterministic raster rendering
- HTML/table deterministic 생성
- 정확한 수치 기반 PNG 렌더링

새 유사·심화문제의 에셋도 “재현”이 아니라 **새 문항의 visualSpec을 결정론적으로 렌더링한 결과물**이어야 한다.

# 12. SVG / PNG 선택 규칙

## SVG 우선
다음은 SVG 또는 vector 기반 생성 우선:
- 단순 좌표평면
- 선분도형
- 삼각형/사각형
- 원
- 단순 함수 그래프
- 수선/직각 표식
- 점선/축/라벨

## PNG 우선
다음은 PNG 허용 또는 권장:
- 여러 component가 겹친 복합 그림
- 인쇄 안정성이 SVG보다 중요한 경우
- JS아카이브 기존 image 자산 구조와 맞춰야 하는 경우
- 최종 렌더를 하나의 고정 자산으로 보존하는 것이 안전한 경우

원칙:
- 복잡하다는 이유로 수학 조건을 생략하지 않는다.
- PNG라도 원천 좌표와 관계는 deterministic 계산 결과를 사용한다.

# 13. 그래프 생성 규칙

함수 그래프는 눈대중 Bezier로 만들지 않는다.

필수:
- 함수식을 실제 계산
- 정의역 확인
- 교점/절편/꼭짓점/점근선 계산
- 필요한 구간 sampling
- 축 범위와 scale 명시
- 실제 수치와 그래프 위치 일치

점근선이나 불연속점이 있으면 그래프 segment를 분리한다.

그래프가 정답을 과도하게 시각적으로 노출하는 경우:
- scale 조정
- 불필요한 눈금 제거
- 필요한 정보만 표시

단, 문제 풀이에 필요한 정보는 제거하지 않는다.

---

# 14. 도형 생성 규칙

도형은 원문의 topology와 문제의 핵심 역할을 유지한다.

필수:
- 꼭짓점 좌표 또는 기하 관계 확정
- 선분 연결 전수 확인
- 수직/평행/접선/중점/내분 조건 exact 확인
- 라벨 전수 확인
- 상대 위치가 문제 의미와 충돌하지 않는지 확인
- 원본과 같은 유형에서 불필요한 보조선 추가 금지

주의:
도형은 반드시 실제 축척일 필요는 없다.
그러나 축척을 일부러 왜곡해서 발문 조건과 모순되게 보이게 만들면 안 된다.

---

# 15. 에셋이 정답을 누설하지 않는 규칙

Visual Validator에서 반드시 확인한다.

금지 사례:
- 정답 점만 유독 강조됨
- 실제 정답 비율이 눈금으로 바로 읽힘
- 원래 계산해야 할 길이가 그림에 수치로 표시됨
- 정답에 해당하는 교점만 좌표 라벨 제공
- 오답 후보는 그림상 명백히 불가능하게 과도하게 배치
- 심화문제의 새 판단을 그림이 대신 해버림

시각자료는 조건을 제공해야지 정답을 대신 말하면 안 된다.

---

# 16. 유사문제 난도 유지 규칙

EXAM_FOLLOWUP 확인 문제의 동치 판정은 Master Rulebook §11의 정량 기준을 따른다.

유지:
- decisionCount
- branchingLoad
- interpretationLoad
- abstractionLoad의 핵심 수준
- solutionGraph 깊이

허용:
- 계산 숫자 변화
- 근호/분수 정도의 자연스러운 변화
- 표현 방식 변화
- 오답 함정 변화

금지:
- 원문보다 명백히 쉬워짐
- 판단을 하나 제거함
- 그림이 계산을 대신해줌
- 새 조건 때문에 실제 decision +1이 발생했는데 유사문제로 계속 분류함

인지 핵심 축의 `delta > 0`이 발생하면 심화문제로 재분류하고, `delta < 0`이면 동치가 아니므로 재설계한다.

---

# 17. 심화문제 난도 상승 규칙

심화는 Master Rulebook §13의 G09 판정과 V3 검증을 적용하며, 다음 중 최소 하나의 인지 축이 실제 상승해야 한다.

```text
decisionCount
branchingLoad
interpretationLoad
abstractionLoad
```

다음은 단독으로 심화 근거가 될 수 없다.

```text
algebraLoad 증가
큰 숫자
긴 계산
복잡한 분수
복잡한 근호
보기 숫자 확대
```

G09 공식과 임계값은 Master Rulebook §13이 정본이다. 이 Spec에서는 그 결과를 Sidecar code `FAKE_ADVANCEMENT_G09`로 기록한다.

# 18. 객관식 Distractor 강화 규칙

오답은 실제 오류 경로에서 만든다.

금지:
- 정답 주변 숫자 나열
- 단순 부호만 바꾼 4개 보기
- 의미상 같은 보기 중복
- 그림과 즉시 충돌하는 무의미한 보기

권장 오답 경로:
- 부호 실수
- 이동 방향 반대로 해석
- 좌표 변환 역관계 오류
- 절댓값 누락
- 내분비 가중치 반대
- 기울기/법선벡터 혼동
- 대칭 축 혼동
- 여집합 포함관계 방향 오류
- 조건 하나 누락

객관식은 최종적으로 보기 5개를 모두 직접 판정한다.
정답은 정확히 1개여야 한다.

# 19. Candidate + Asset 동시 FREEZE

시각문항에서는 다음을 하나의 Candidate로 본다.

```text
content
choices
answer
solution
visualSpec
asset
image path
```

다음이 모두 확정된 뒤 FREEZE한다.

- 수학 성립
- 정답 유일성
- 교육과정 적합
- Fidelity 적합
- 시각자료 정합
- 이미지 경로 정상

FREEZE 후 다음 중 하나라도 바뀌면 재검증한다.

- content
- choices
- answer
- 핵심 좌표
- 핵심 수치
- visualSpec
- asset topology

문항 조건 또는 정답에 영향을 주는 변경이면 V1 독립 풀이부터 다시 시작한다.

# 21. JS아카이브 연결 규칙

최종 JS는 기존 JS아카이브 기본 스키마를 유지한다.

시각자료가 필요한 문항은 가능하면:

```js
image: "assets/images/{examTitle}/q{id}.png"
```

구조를 사용한다.

규칙:
- JS의 `image` 경로와 실제 파일이 일치해야 한다.
- 새 파생 시험지의 `examTitle`이 달라지면 asset 폴더도 같은 기준으로 맞춘다.
- 기존 원문 시험지 폴더의 PNG를 새 문항이 참조하지 않도록 한다.
- 새 수치가 들어간 문항은 새 asset 파일을 사용한다.
- 고아 이미지가 남지 않게 한다.
- `tags`에는 실제 시각요소에 맞게 `"도형"`, `"그래프"`, `"표"` 등을 유지한다.
- 시각자료 때문에 `layoutTag`나 `wide`를 자동 변경하지 않는다.

# 24. 시각문항 대표 변형 기준

## 24-1. 점과 직선 사이 거리 / 수선의 발형
유지:
- 점 P
- 직선 l
- 수선의 발 H
- 직각 관계
- 핵심 공식 유도 구조

변경 가능:
- 직선 계수
- 점 좌표
- 변수명
- 절편 위치
- 빈칸 구성

새 에셋:
- 변경된 직선 방향·절편
- P/H 위치
- 직각 표식
- 라벨

---

## 24-2. 도형 이동 / 두 도형 대응형
유지:
- 원도형과 이동도형의 대응
- 이동·대칭 핵심 구조
- 변수 치환 사고

변경 가능:
- 좌표
- 이동량
- 대칭축/방식이 원유형을 훼손하지 않는 범위의 구성
- 도형 크기와 배치

새 에셋:
- 두 도형의 대응 좌표를 exact 계산해 생성
- 대응점이 실제 변환과 일치해야 함

---

## 24-3. 좌표 삼각형 / 각의 이등분선형
유지:
- 삼각형 좌표
- 두 변 길이 비교
- 각의 이등분선 정리
- 내분점 계산

변경 가능:
- 세 점 좌표
- 변 길이비
- 교점 좌표

새 에셋:
- 새 좌표를 기준으로 삼각형 생성
- 길이비 exact 확인
- 좌표축과 점 라벨 재생성

---

## 24-4. 직사각형 / 대칭·반사 최단거리형
유지:
- 직사각형 경계
- 내부 점
- 변에 대한 반사 관계
- 경로 길이 변환

변경 가능:
- 직사각형 폭·높이
- P/Q 좌표
- 반사점
- 접점 위치

새 에셋:
- 직사각형·P 좌표 새로 생성
- 각 반사선이 실제 해당 변 segment와 만나는지 exact 확인
- 단순히 직선 연장선과만 만나는 경우 FAIL

# 26. 최종 산출물 최소 기준

유사·심화 작업 완료본은 최소 다음을 가진다.

1. 파생 JS 파일
2. 필요한 새 PNG/SVG 에셋

10. 새 에셋 실제 재오픈 확인

Sidecar/Runtime 로그는 자동 생산기를 실제 운용하지 않는 동안 필수 산출물로 강제하지 않는다.
단, 내부 검증 원칙은 동일하게 적용한다.

# 27. 절대 금지

- 유사문제를 단순 숫자갈이로 끝내기
- 심화를 계산량 증가로 대체하기
- 시각자료가 바뀌었는데 원문 asset 재사용
- 새 발문과 이미지 좌표 불일치
- 그림 먼저 생성 후 문제 끼워맞추기
- 생성형 이미지 모델로 수학 에셋 제작
- 눈대중 좌표로 SVG 제작
- 실제로 수직이 아닌데 직각 표식
- 실제로 평행이 아닌데 평행 표식
- 원문 라벨 일부 잔존
- 정답에 맞춰 보기나 그림만 사후 수정
- FREEZE 후 부분 끼워맞추기
- 상위 교육과정으로 억지 심화
- 검산하지 않은 문항 PASS
- 그림이 정답을 직접 노출
- 고위험 문항 단일 검산
- 시각자료 때문에 layoutTag/wide 임의 변경

# 28. 최종 판정 원칙

최종 우선순위:

`수학적 무결성 > 교육과정 적합성 > 유형 충실도 > 시각 정합성 > 학습 가치 > 검증 가능성 > 다양성 > 출력 편의성 > 속도`

유사문제 PASS:
- 원문 핵심 사고 유지
- 숫자갈이에만 그치지 않음
- 난도 동치
- 독립 문항
- 필요한 새 에셋 생성
- 문항·에셋 exact 정합
- 정답 유일

심화문제 PASS:
- 원문 핵심 판단 유지
- 실제 새 판단 +1 이상
- A~F 최소 1개
- QUALITY A
- G09 아님
- 필요한 새 에셋 생성
- 시각자료가 심화 판단을 대신하지 않음
- Math/Curriculum/Fidelity/Visual 모두 통과

# 29. 한 줄 실행 원칙

> **문항을 먼저 수학적으로 설계하고, 새 조건을 exact 검증한 뒤, 그 조건을 시각적으로 충실하게 표현하는 새 에셋을 결정론적으로 생성한다. 문항과 에셋은 하나의 Candidate로 검증하고 함께 FREEZE한다.**
