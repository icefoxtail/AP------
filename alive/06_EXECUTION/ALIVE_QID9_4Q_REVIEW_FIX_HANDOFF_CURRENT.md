# ALIVE QID9 — 4개 원본 × 9문항 공개답 검수·핀포인트 수정 핸드오프

**실행 지시:** 이 문서에 따라 대상 시험지의 **다음 연속 4개 원본 qid(기본 36문항)**를 끝까지 검수하고, **검수에서 발견한 모든 타당한 지적사항을 직접 수정·영향부 재검·통합 브랜치 커밋·원격 재조회**까지 완료하라. 보고만 하고 수정은 다음 창에 미루지 않는다.

## 1. 자동 대상 선택 및 정본
- **노션 필독:** `GPT 작업 전 필독 라우터` → `Archive 2.0 / JS Archive 시작 페이지` → `Archive 전체 작업 생명주기`. 해당 페이지에서 최신 ALIVE/Visual/Meta/수정·출시 규정을 확인한다.
- **Git 최신 확인:** `main`의 `AGENTS.md`(하위 AGENTS 포함), `alive/06_EXECUTION/ALIVE_GPT_QID9_ONE_SOURCE_CURRENT.md`, 해당 학교 `GPT_QID9_EXAM_MANIFEST.json`, 원본 기출·생성 shard·Blueprint·CREATE ledger·Generated 확장 registry·SVG를 읽는다.
- **범위는 파일로 자동 결정:** 시험지 manifest와 **이전 검수·수정 원장**을 함께 확인하여 다음 연속 미검수 블록을 고른다. 금당고 진행 예: **q09~q12 → q13~q16 → q17~q20 → q21~q22**. 각 qid는 A1~C3 9문항. `reviewStatus=PENDING` 하나만으로 과거 수정 완료 블록을 재검수하지 않는다.
- 제작자가 아직 만들지 않은 qid는 완료로 꾸미거나 건너뛰지 말고 **해당 블록의 잔여 대상**으로 기록한다. 다음 블록으로 임의 점프하지 않는다.

## 2. 공개답 품질 검수 (대상 UID 전부)
- **발문 우선:** 학생에게 보이는 발문·보기·그림만 다시 읽어 학교 내신식 자연스러움, 조건의 충분성, 우회풀이·정답 노출, 출제 의도와 실제 풀이의 일치를 확인한다.
- **수학·보기:** 정답 유일성, 해설의 모든 핵심 계산·경계·정의역, 오답 4개 **각 보기 번호와 실제 잘못된 풀이 경로 1:1**를 확인한다. 복잡하거나 의심스러운 문항은 독립 재계산한다. 생성문항은 공개답 검수이며 기출 R1/R2 blind 검수가 아니다.
- **분류·시각:** 원본 Primary L3 HARD LOCK, L4·CrossConcept·Condition·Integration·PT/TPL·난이도, 문제용/해설용 SVG 필요성 **각각** 확인. 실제 SVG 내용·좌표·경로와 학생용 참조를 대조한다. 브라우저 미실행을 PASS로 기록하지 않는다.

## 3. 검수 완료 후 반드시 직접 수정
- **확정 오류뿐 아니라 검수에서 지적한 타당한 개선점 전부** 포함: 발문 품질, 보기 배열·오답 설계, 난이도, 해설, Meta, SVG. 정상 UID는 억지 수정하지 않는다.
- 바뀐 UID만 `source JS → Blueprint → 검수/CREATE ledger → Generated 확장 registry → manifest`의 **실제 영향 필드**를 동기화한다. 정답/보기 변경 시 **5지 유일성·정답번호·해설 결론·오답 4경로·정답분포**를 새 최종본으로 다시 검증한다.
- Canonical 키 우선 확인 후 필요한 Generated-only 키는 **parent·evidence·UID**와 함께 확장 등록한다. RPM LOCKED/원본 기출/기존 UID·provenance는 보존한다. SVG는 실파일 존재·`assets/...` 상대경로·좌표·흰 배경·문제/해설 의미 일치를 확인한다. 수식 이스케이프와 **진짜 줄바꿈**(`\\n` 문자 잔류 금지)도 점검한다.
- 수정 완료 상태를 **별도 검수·수정 원장**에 `UID / 지적 / 수정 전·후 / 영향 필드 / 재검 결과 / 미실행 기술검사`로 남긴다. 제작자의 `SELF_CHECKED`를 독립 GPT 검수 PASS로 바꾸어 쓰지 않는다.

## 4. Git 마감·보고
- **시험지당 한 통합 브랜치**를 유지한다. 다른 창이 뒤 qid를 만드는 중이므로 변경 직전 최신 HEAD를 다시 읽고, **해당 UID·관련 원장만** 독립 커밋한 뒤 원격 SHA/readback을 확인한다. 충돌 시 최신 HEAD에 핀포인트 재적용; 다른 작업자의 문항 덮어쓰기·`add .` 금지.
- 이번 핸드오프 기본 마감은 **검수 → 수정 → 영향부 재검 → 브랜치 커밋·원격 확인**이다. 별도 출시에 해당하면 최신 정본대로 Consumer/index/main/실제 Chrome까지 기술 마감한다. **미실행 검증은 NOT_TESTED, main 미병합은 MAIN_DONE 금지.**
- 사용자 보고는 간결히: `대상 qid/분모 · 원검수 결과 · 수정 UID/핵심 변경 · HOLD/잔여 · 새 commit SHA · 원격 확인 · 실제 테스트 범위 · 다음 qid 블록`.

**완료 조건:** 지정 블록에서 사용 가능한 모든 A1~C3를 검수하고 **발견한 결함을 실제 원격 파일에서 해소**했음을 확인한다. 정본 충돌·소스 부재는 정확히 남기되, 검수보고서만 작성하고 끝내지 않는다.
